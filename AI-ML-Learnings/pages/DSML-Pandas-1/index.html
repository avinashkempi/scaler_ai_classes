1The hook

Why Pandas?

Suppose you have a spreadsheet with 1,700 rows about countries — population, life expectancy, GDP. Using only pure Python, you'd reach for a list of dictionaries or a dictionary of lists. That works, until someone asks "give me the average life expectancy for every country in Asia."

Suddenly you're writing loops, tracking indices by hand, handling missing values manually. It gets painful fast. Pandas fills exactly this gap — it gives you a table object where that question becomes one short line.

📌 Rule of thumb
Use plain Python for a handful of values. The moment your data looks like a table with rows and columns of mixed types, reach for Pandas.
🌉 Business problem: McKinsey survey data
You're a Data Analyst at McKinsey. The firm has collected survey data from many countries across several years — country, population, life expectancy, and GDP per capita. The goal: analyze the relationship between GDP per capita and life expectancy. This exact dataset is used throughout the lecture.

7Column operations

      
Renaming columns

      
python — two equivalent ways
df.rename({"country": "Country"}, axis=1)           # using axis=1
df.rename(columns={"country": "Country"})            # using columns=

      

        
⚠️ rename() returns a copy — the original is unchanged

        

          
💾
rename() without inplace
"Save As" — new version, original untouched

          
vs

          
✏️
rename(inplace=True)
edits the original in place — permanent

        

      

      
python — make it permanent
df.rename({"country": "Country"}, axis=1, inplace=True)
df.head()   # confirm: column is now "Country"

      
The inplace=True/False behavior applies to rename, drop, reset_index, and many other operations. The default is always inplace=False (return a copy).

    


    
    

      
8Column operations

      
Dropping columns

      
python — two equivalent ways
df.drop('continent', axis=1)              # axis=1 means columns
df.drop(columns=['continent'])            # using columns= parameter

      
Like rename, these return a copy. To modify the original:

      
python — permanent deletion
df.drop('continent', axis=1, inplace=True)


      

        
axis — which direction does the operation act?

        

          

            
axis = 1 (columns →)

            
rename, drop a column
operates across ↔ columns

          

          

            
axis = 0 (rows ↓)

            
drop a row
operates down ↕ rows

          

        

        

          
💡 Rule of thumb

          Removing or renaming a column → axis=1. Removing a row → axis=0.
        

      

    


    
    

      
9Column operations

      
Creating new columns

      
Derive a new column by operating on existing ones — no loop needed. Pandas applies the operation element-wise across the entire column.

      
python
# Simple derivation
df["year+7"] = df["year"] + 7

# Combining two columns (McKinsey's total GDP request)
df['gdp'] = df['gdp_cap'] * df['population']

# Supplying your own values (length must equal number of rows)
df["Own"] = [i for i in range(1704)]

      

        
💡 No loops needed

        df['gdp'] = df['gdp_cap'] * df['population'] is Pandas' vectorized equivalent of:
        
# pure Python equivalent (don't do this with Pandas)
for i in range(len(df)):
    df.at[i, 'gdp'] = df.at[i, 'gdp_cap'] * df.at[i, 'population']

        Pandas does the loop internally, in optimized C code — orders of magnitude faster.

Quiz 1

        
Given a DataFrame with 5 columns, which is the correct code to drop the 3rd column from the start?

        

          
A) df.drop(df.columns[-3], axis=1)

          
B) df.drop(df.columns[3], axis=1)

          
C) df.drop(df.columns[-3], axis=0)

          
D) df.drop(df.columns[3], axis=0)

        

        
Columns are dropped with axis=1 — this rules out C and D. Columns are 0-indexed, so the 3rd column from the start is index 2 (not 3). With 5 columns, df.columns[-3] counts backwards from the end (4, 3, 2) and lands on index 2 — the 3rd column. Answer A is correct.

      

    


    
    

      
10Row operations

      
Explicit and implicit indices

      
Rows, like columns, carry labels. By default those labels are 0, 1, 2, …. You can change them:

      
python
df.index = list(range(1, df.shape[0] + 1))   # start from 1 instead of 0

      
This reveals a fundamental distinction:


      

        

          
Explicit index

          
The labels you see and can change. df.index. Can be integers, floats, strings — anything.

        

        

          
Implicit index

          
The hidden Python-style position (always 0, 1, 2, … from the top), regardless of what the explicit labels say.

        

      


      

        
🎫
Explicit (seat label)
number printed on your train ticket — railway can assign any label

        
vs

        
📍
Implicit (position)
"the 1st seat, 2nd seat, 3rd seat" counting from the door — always 0-based

      


      

        
After reindexing to start from 1 — label ≠ position

        

          

            
Explicit label (df.index)

            
1
→
Afghanistan 1952

            
2
→
Afghanistan 1957

            
3
→
Afghanistan 1962

          

          

            
Implicit position (0-based)

            
0
→
Afghanistan 1952

            
1
→
Afghanistan 1957

            
2
→
Afghanistan 1962

          

        

        
After reindexing: label 1 is at position 0. loc[1] and iloc[1] return different rows.

      

    


    
    

      
11Row operations

      
Indexing and slicing in a Series

      
python
ser = df["Country"]

ser[12]     # single value → uses explicit label → 'Afghanistan'
ser[5:15]   # slice → uses implicit position → rows at positions 5 through 14

      

        
⚠️ The mixed-behavior trap

        On a plain Series: a single value uses the explicit label, while a slice uses the implicit position. Same object, two different rules. This inconsistency is exactly why Pandas gives us loc and iloc.
      

    


    
    

      
12Row operations

      
Indexing a DataFrame with plain brackets

      
python
df[0]       # → KeyError: 0   (looks for a COLUMN named 0)
df[5:15]    # → works! selects rows at positions 5–14

      

        
⚠️ The number-one beginner mistake

        df[x] means "give me the column x" — not a row. But df[start:stop] selects rows. Same brackets, two different behaviors. Use loc and iloc to eliminate the ambiguity.
      

    


    
    

      
13Row operations

      
loc and iloc — the definitive selectors


      

        

          
loc — by label

          
Always references the explicit index. End of range is inclusive.

        

        

          
iloc — by position

          
Always references the implicit index. End of range is exclusive (like Python slicing).

        

      


      
python — loc: label-based
df.loc[1]        # row with LABEL 1  → Afghanistan 1952
df.loc[1:3]      # labels 1, 2, 3 (end INCLUSIVE)
df.loc[9::-3]    # start at label 9, step -3 → 9, 6, 3, 0


      
python — iloc: position-based
df.iloc[1]       # row at POSITION 1  → Afghanistan 1957 (2nd row)
df.iloc[0:2]     # positions 0 and 1 (end EXCLUSIVE)
df.iloc[[1, 10, 100]]  # non-consecutive positions in a list
df.iloc[-1]      # last row ✓

df.loc[-1]       # → KeyError: -1 (no row labeled -1)


      

        
⚠️ The inclusive/exclusive difference

        df.loc[1:3] → rows labeled 1, 2, 3 (3 included)

        df.iloc[1:3] → positions 1, 2 (position 3 excluded)


        iloc[-1] works (position −1 = last). loc[-1] fails (no label −1).

Quiz 2

        
After reindexing df so labels start at 1, what does df.loc[9::-3] return?

        

          
A) Rows 0, 3, 6, 9 in that order

          
B) Rows 9, 6, 3, 0 in that order

          
C) A KeyError — negative step not allowed with loc

        

        
The slice 9::-3 starts at label 9, has no explicit stop, and steps by −3. So it walks backward: 9 → 6 → 3 → 0. Since loc is inclusive and steps are negative, it yields rows in descending order: 9, 6, 3, 0.

      

    


    
    

      
14Row operations

      
Boolean masking and filtering

      
McKinsey's real questions sound like "show me only records where life expectancy is above 70" — selecting rows by condition. This is the Pandas equivalent of SQL's WHERE clause.


      
Step 1 — create a boolean mask

      
python
df['life_exp'] > 70
# 0    False
# 1    False
# ...
# 1703 True
# dtype: bool

      
A condition on a column returns one True/False per row — a boolean mask. The dtype: bool is the tell-tale sign.


      
Step 2 — feed the mask into loc

      
python
df.loc[df['life_exp'] > 70]   # keeps only rows where mask is True


      
Combining conditions

      
python
df[(df['life_exp'] > 70) & (df['year'] == 2007)]  # AND
df[(df['life_exp'] > 70) | (df['year'] == 2007)]  # OR
df[~(df['life_exp'] > 70)]                         # NOT

      

        
⚠️ Always wrap each condition in parentheses

        Dropping the inner parentheses raises a confusing TypeError — it's the most common filtering mistake. This is because Python's operator precedence runs & before >, so without parentheses the comparison never happens correctly.
      

      
python — match against a list of values (SQL IN)
df[df['Country'].isin(['India', 'China'])]
# ≈ SELECT * FROM df WHERE Country IN ('India', 'China')

      

        
🌉 SQL bridge

        df.loc[df['life_exp'] > 70] ≈ SELECT * FROM df WHERE life_exp > 70;

15Index management

      
set_index and reset_index

      
Looking rows up by a plain integer is awkward. Promoting a column to be the index lets you look up by meaningful labels — like country names.


      
python
temp = df.set_index("Country")   # country names become the row labels
temp.loc['Afghanistan']           # all rows for Afghanistan, directly


      
python — resetting to integers
df.reset_index()              # old labels become a new "index" column
df.reset_index(drop=True)     # discard old labels — clean restart

# Make it permanent:
df.reset_index(drop=True, inplace=True)

      

        
⚠️ reset_index() without drop=True creates an extra column

        The old index becomes a column called index. Pass drop=True to discard it and just rebuild plain integer labels.
      


      

        
Quiz 3

        
What does this print?

a = pd.Series(['a', 'b', 'c'], index=[1, 2, 2])
print(a[2])

        

          
A) Both 'b' and 'c' (as a Series)

          
B) Only 'b'

          
C) Only 'c'

          
D) Error

        

        
Label 2 is assigned to two entries ('b' and 'c'). When a label is not unique, indexing returns every entry carrying that label — both 'b' and 'c' come back as a Series. This is why keeping unique indices is generally advisable.

16Rows + columns together

      
Adding and deleting rows


      
Adding a row — concat() (preferred)

      
python
new_row = {'country': 'India', 'year': 2000, 'population': 13500000,
           'continent': 'Asia', 'life_exp': 37.08, 'gdp_cap': 900.23}

df = pd.concat([df, pd.DataFrame([new_row])], ignore_index=True)

      
ignore_index=True rebuilds a fresh 0, 1, 2, … index for the combined result. Without it, you can end up with duplicate labels. concat() always returns a new DataFrame — reassign to keep it.


      
Adding a row — loc at a new label

      
python
new_row_vals = ['India', 2000, 13500000, 'Asia', 37.08, 900.23]
df.loc[len(df.index)] = new_row_vals   # append at the next available position

      

        
⚠️ iloc cannot add rows

        df.iloc[len(df.index)] = [...] → IndexError: iloc cannot enlarge its target object
        
iloc can only address positions that already exist. To overwrite an existing row, iloc works. To append a new one, use loc or concat.
      


      

        
💡 Rule of thumb: adding rows

        Append a brand new row → concat() or loc.

        Overwrite an existing row → iloc.
      


      
Deleting a row — drop()

      
python
df = df.drop(3, axis=0)            # drop row with LABEL 3
df.drop([1, 2, 4], axis=0)        # drop multiple labels at once

# After dropping, reset for clean labels:
df.reset_index(drop=True, inplace=True)


      
drop() uses labels, not positions. After removing rows, label gaps appear — the row now labeled 4 is no longer at position 4:

      
python — loc vs iloc after a gap
df = df.drop(3, axis=0)   # removes label 3; gap at position 3

df.loc[4]    # row LABELED 4 (year 1972)
df.iloc[4]   # row at POSITION 4 — now the one LABELED 5 (year 1977)


      

        
✓ The clearest demonstration of loc vs iloc

        After removing row 3, loc[4] returns the record for year 1972 (labeled 4). iloc[4] returns the record for year 1977 (labeled 5, now sitting at position 4). Same brackets, completely different rows. This is why using the right tool matters.
