A real-life classification problem

Picture a conveyor belt that sorts fish automatically. A scanner reads certain parameters off each fish — weight, size, color, shape — and sends that data to a model, which predicts the fish's type and routes it to the right bucket.

Automating a task that currently needs a human requires labelled data: examples where the correct answer is already known, so a model can learn the pattern connecting inputs to outputs.

Features, targets, and labels

In a labelled dataset, every row is one example, and every column plays one of two roles:

Features (independent variables)

The measurable parameters — e.g. a fish's weight, size, and color — collected directly, often by a sensor.

Target / label (dependent variable)

What we're trying to predict — e.g. the fish's species. Given a new data point, the model's job is to predict its label.

Plotting two features (say, height and width) against each other on a scatter plot shows the classes forming visually separable clusters — and immediately raises the central question of this entire module: out of infinitely many possible dividing lines, which one is best?

More classification examples

Predicting which of two teams wins a cricket match is a binary classification problem — but unlike the fish example, the best decision boundary here is often a curve rather than a straight line. Such a boundary is called a classifier or decision boundary.

Predicting a T-shirt size (S, M, L, …) involves more than two classes, so one single decision boundary isn't enough — this is a multi-class classification problem, typically solved with multiple classifiers working together.

How an ML algorithm gets built

Across every example so far, the same pipeline recurs: collect features, visualize the relationship between features and target, and then search for parameters that define the best possible decision boundary. Later modules build on this with techniques like dimensionality reduction (PCA) to simplify high-feature datasets before this search even begins.

Coordinate geometry of lines

Slope-intercept form

y = mx + c

Here x is the independent variable, m is the slope (the angle the line makes with the x-axis), and c is the y-intercept. The slope between two points is tan θ = (y₂ − y₁)/(x₂ − x₁).

Since tan(90°) = ∞, the slope-intercept form can never represent a line perfectly perpendicular to the x-axis — a limitation the general form fixes.

General form — and its ML translation

Ax + By + C = 0   ⟶⟶   w₁x₁ + w₂x₂ + w₀ = 0
Coordinate geometryMachine learning term
A, BWeights (w₁, w₂) — learned by the model
x, yFeatures (x₁, x₂)
CBias (w₀)

"Learning," in this framing, means nothing more than finding the best values for the weights and bias. Setting w₂ = 0 produces a line perfectly perpendicular to the x-axis — something slope-intercept form could never express.

Parallel lines

Two lines are parallel exactly when they share the same slope: m₁ = m₂.

Perpendicular lines

Two lines are perpendicular exactly when the product of their slopes is −1: m₁·m₂ = −1.

Beyond 2D: hyperplanes

The same equation generalizes directly to any number of dimensions: a line in 2D, a plane in 3D, and a hyperplane in 4D and beyond — called "hyper" precisely because we can no longer visualize it.

Halfspaces

Any line divides 2D space into two halves; any plane divides 3D space into two halves; the same holds for a hyperplane in n dimensions. This matters enormously for classification: to classify a new point, we simply check which halfspace it falls into.

Use case: orange vs. tangerine

Given a dataset of fruit weight, diameter, and color, oranges and tangerines form two visually separable clusters: high-diameter/low-weight fruits tend to be oranges, while low-diameter/high-weight fruits tend to be tangerines. Many different lines could separate them — the question that opened this post.

Fit a line by hand: orange vs. tangerine

Manually tuning m and c by trial and error works for small, simple datasets — but it doesn't scale. This is exactly the gap machine learning fills: automatically finding the best-fitting parameters.
