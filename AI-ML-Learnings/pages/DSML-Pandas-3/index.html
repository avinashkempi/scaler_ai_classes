Group Operations & Hierarchical Indexing

From the McKinsey single-table world to real two-file IMDB data — merging, applying functions row-by-row, splitting into groups, aggregating, filtering groups, and working with multi-level column structures.

merge() join types groupby basics Boolean masking & isin() drop_duplicates / sort_values
1Scenario

The IMDB scenario

In Lectures 1 and 2 we worked with the McKinsey survey — a single neat table. Real analytical work is rarely that tidy. Today's data comes from IMDB, split across two separate files — exactly how data arrives in practice.

📋 What the client wants
An analytics firm client wants to understand movie trends. Questions range from simple to deep:
  • Top 10 most popular movies (by popularity column)?
  • Highest rated movies (by vote_average)?
  • How many movies released per year?
  • Who are the most productive directors? ← the deep question we build toward today
  • Which directors produce high-budget films? ← the other deep question
The first three need only sort_values and basic filtering. The last two need the full toolkit: merging, apply, and groupby.
2Setup

Loading the two datasets

python
import pandas as pd

movies    = pd.read_csv('movies.csv',    index_col=0)
directors = pd.read_csv('directors.csv', index_col=0)
💡 index_col=0
When a CSV was exported from a DataFrame, the first column is often just the row number saved as data (Pandas calls it Unnamed: 0). Passing index_col=0 tells read_csv to use that first column as the row index instead of a regular data column — so it never appears as a column in your DataFrame.
Shapes
movies.shape    → (1465, 11)
directors.shape → (2349, 3)

1465 movies, but the directors file has 2349 rows — one per director in the IMDB database. Not every IMDB director has a movie in our movies file, so the movies directors are a subset of the directors file.

3Pre-merge checks

isin() and nunique()

nunique() — count distinct values

python
movies['director_id'].nunique()   # → 199
directors['id'].nunique()         # → 2349

nunique() counts distinct values. unique() (from Lecture 1) lists them; nunique() just gives the count.

isin() — membership check across a whole column

Verify that every director_id in movies appears in the directors table:

python
movies['director_id'].isin(directors['id'])
# Returns True/False per row

movies['director_id'].isin(directors['id']).all()
# → True  (every director_id exists in the directors table)
Python in
Checks one element at a time against a list:
3 in [1,2,3] # True
vs
Pandas isin()
Checks every value in the column at once, returning a full boolean Series — the vectorised equivalent.
🌉 SQL bridge
movies['director_id'].isin(directors['id']) ≈ SELECT * FROM movies WHERE director_id IN (SELECT id FROM directors);

4Joining data

      
Merging the datasets

      
We need director details alongside movie details. The join type follows from the business requirement:

      
    
        
  • Every movie matters — keep all rows from movies ✓
    • 
        
  • Only directors who appear in our movies file — don't keep all 2349 directors ✓
    • 
        
  • → Left join with movies on the left.
    • 
      

      
python
data = movies.merge(directors, how='left', left_on='director_id', right_on='id')

# Both tables had a column called 'id' → Pandas disambiguates as id_x and id_y
# id_y is the same information as director_id → drop both
data.drop(['director_id', 'id_y'], axis=1, inplace=True)
data.head()

      

        
💡 Suffix disambiguation

        When both tables share a column name that isn't the merge key, Pandas appends _x (from the left table) and _y (from the right). Check for these after every merge — they're a sign of a column to investigate and likely drop.
      


      

        
Quiz 1

        
How do you filter movies released in 2015, 2016, or 2012?

        

          
A) movies['year'].isin([2015, 2016, 2012])

          
B) movies['year'].in([2015, 2016, 2012])

          
C) movies['year'] == ([2015, 2016, 2012])

        

        
isin() checks each value against a list and returns a boolean Series. Option B is invalid — .in is not a Pandas method (in is a Python keyword and cannot be called as a method). Option C compares the column to a list object, which doesn't produce row-wise membership — it compares shapes.

      

    


    
    

      
5Row-wise functions

      
apply() — run a function across every value

      
The client wants the gender column recoded: Male → 0, Female → 1. We know how to write a function for one value. apply() runs it across every value in the column — no loop needed.


      

        The assembly-line analogy: if the column is a stack of exam papers, apply(encode) is like handing the stack to a teaching assistant with the instruction "run each sheet through this grading rubric." Every sheet gets the same treatment; you get back a graded stack.
      


      
python
def encode(value):
    if value == "Male":
        return 0
    else:
        return 1

data['gender'] = data['gender'].apply(encode)

      
Every value in the column passed through encode, one by one, and the results replaced the original values.


      

        
🌉 SQL bridge

        data['gender'].apply(encode) ≈ SELECT CASE WHEN gender='Male' THEN 0 ELSE 1 END AS gender FROM data;
      

    


    
    

      
6Row-wise functions

      
apply() with axis= — column vs row direction

      
When you apply to multiple columns, axis= decides whether the function runs down each column or across each row.


      

        

          
axis=0 (default) — collapse rows within each column

          
Function receives one entire column at a time. Result: one value per column.

data[['revenue','budget']].apply(sum)
→ total revenue, total budget

        

        

          
axis=1 — collapse columns within each row

          
Function receives one entire row at a time. Result: one value per row.

data[['revenue','budget']].apply(sum, axis=1)
→ revenue+budget for each movie

        

      


      
python — profit column (custom function, axis=1)
def prof(row):
    return row['revenue'] - row['budget']

data['profit'] = data[['revenue', 'budget']].apply(prof, axis=1)

      
Each row passes through prof with axis=1. Within each row, row['revenue'] and row['budget'] are that row's values — so each movie gets its own profit calculation.

7Group operations

      
groupby(): Split-Apply-Combine

      
apply() processes one row at a time. When the question shifts to "do something to each group of rows" — "how many movies per director?", "average rating per director?" — we need groupby().


      

        

          
Split

          

            
Break the DataFrame into groups by column values

            

              Nolan: [Inception, Dark Knight]
              Spielberg: [Jaws, ET, …]
              Allen: [Annie Hall, Manhattan, …]
            

          

        

        

          
Apply

          
Compute something within each group independently — count, mean, max, custom function

        

        

          
Combine

          
Stitch all group results back into a single output

        

      


      

        Teacher analogy: A stack of mixed-subject exam papers. Split: sort into piles by subject. Apply: grade each pile, count each pile, find the top scorer in each pile. Combine: produce one report with all results.
      


      
python — creating a GroupBy object
data.groupby('director_name')
# → DataFrameGroupBy object — groups created, nothing computed yet

data.groupby('director_name').ngroups      # → 199
data.groupby('director_name').groups       # dict: group name → row indices
data.groupby('director_name').get_group('Christopher Nolan')  # single group as DataFrame

      

        
💡 GroupBy object ≠ DataFrame

        data.groupby('director_name') returns a DataFrameGroupBy object — think of it as the sorted piles of exam papers, waiting for you to decide what to do with each pile. Nothing is computed until you chain an operation like .count(), .mean(), or .filter().
      

    


    
    

      
8Group operations

      
Group-based aggregation

      
Aggregation collapses each group to a single summary number.


      
python — count movies per director
data.groupby('director_name')['title'].count()

      
Output (excerpt)
director_name
Adam McKay                      6
Woody Allen                    18
Steven Spielberg               26
...
Name: title, Length: 199, dtype: int64


      
python — multiple aggregations in one call
# First and last year each director released a movie
data.groupby('director_name')['year'].aggregate(['min', 'max'])

# Multi-column aggregation with a dict
data.groupby('director_name').agg({'vote_average': ['mean', 'min', 'max']})

      

        
💡 .agg and .aggregate are the same method

        Use whichever you prefer. .agg is just the shorter alias.
      

      

        
🌉 SQL bridge

        data.groupby('director_name')['title'].count() ≈ SELECT director_name, COUNT(title) FROM data GROUP BY director_name;

How do you calculate the average monthly_rating for each employee?

        

          
A) data.groupby('emp_id')

          
B) data.groupby('monthly_rating')

          
C) data.groupby('emp_id')['monthly_rating'].mean()

Group by emp_id (not rating), select monthly_rating within each group, apply .mean(). Option A only creates groups without computing anything. Option B groups by the column we want to average (wrong column). Option D groups by the rating value itself, which makes no sense.

What does data.groupby('director_name')['duration'].mean() return?

        

          
A) The average duration for each unique director

          
B) The DataFrame sorted alphabetically by director_name

          
C) The average duration for all movies combined

9Group operations

      
Group-based filtering

      
Group-based filtering keeps or discards entire groups based on a condition — not individual rows. Client definition: a high-budget director has at least one movie with budget over $100 million.


      

        VIP pass analogy: Each director (group) is checked: "Does this director have at least one film costing over $100M?" If yes, the entire group (all their films) gets the VIP pass into our result. If no, all their films are excluded.
      


      
Three-step approach

      
python
# Step 1: max budget per director
data_dir_budget = data.groupby("director_name")["budget"].max().reset_index()

# Step 2: names of high-budget directors
names = data_dir_budget.loc[data_dir_budget["budget"] >= 100_000_000, "director_name"]

# Step 3: filter full dataset to those directors only
data.loc[data['director_name'].isin(names)]


      
One-line approach with filter() + lambda

      
python — equivalent in one line
data.groupby('director_name').filter(lambda x: x["budget"].max() >= 100_000_000)

      
What happens:

      
    
        
  • The DataFrame is grouped by director.
    • 
        
  • .filter() evaluates the lambda on each group x.
    • 
        
  • Groups returning True (≥1 movie with budget ≥ $100M) pass through.
    • 
        
  • Groups returning False are discarded entirely.
    • 
        
  • The result is a regular flat DataFrame — not a GroupBy object.
    • 
      

      

        
🌉 SQL bridge

        .filter(lambda x: x["budget"].max() >= 100M) ≈ SELECT * FROM data WHERE director_name IN (SELECT director_name FROM data GROUP BY director_name HAVING MAX(budget) >= 100000000);

10Group operations

      
Group-based apply — risky movies

      
Aggregation collapses each group to a number. Filtering keeps or drops groups. Group apply runs a custom function inside each group and writes the result back — so every row gets a value derived from its group's aggregate.

      
The question: which movies are risky — meaning their budget exceeded the average revenue of that director's other movies?


      
python
def func(x):
    # x is one director's group of movies
    # revenue.mean() is that director's average revenue — group-level
    # budget is each movie's individual budget — row-level
    x["risky"] = x["budget"] - x["revenue"].mean() >= 0
    return x

data_risky = data.groupby("director_name", group_keys=False).apply(func)


      

        
💡 group_keys=False

        Setting group_keys=False prevents the group key (director name) from appearing as an extra index level in the result. Without it, the director name becomes an outer index layer on top of the normal row index.
      


      
What the function does step by step:

      
    
        
  1. x["revenue"].mean() — computes the mean revenue for this director's movies only (group-level)
    2. 
        
  2. x["budget"] - ... — subtracts that mean from each individual movie's budget (row-level)
    3. 
        
  3. ≥ 0 — if the movie cost more than the director's average revenue, it's flagged risky
    4. 
        
  4. return x — returns the modified group; Pandas combines all groups back into one DataFrame
    5. 
      


      
python — view risky movies
data_risky.loc[data_risky["risky"]]

11Hierarchical indexing

      
Multi-index — hierarchical column structure

      
When you aggregate multiple columns with multiple functions, the result naturally has a two-level column structure. This is a Multi-Index DataFrame.


      
python — multi-column, multi-function aggregation
data_agg = data.groupby(['director_name'])[["year", "title"]].aggregate(
    {"year": ['min', 'max'], "title": "count"}
)

data_agg.columns
# MultiIndex([( 'year',   'min'),
#             ( 'year',   'max'),
#             ('title', 'count')], )

data_agg["year"]  # returns both sub-columns (min and max) under 'year'


      

        

          

            director_name
            year
            title
          

          

            min
            max
            count
          

          
Christopher Nolan200820102

          
James Cameron199720092

          
Woody Allen197719803

        

      


      

        Filing cabinet analogy: A normal DataFrame has one label per drawer (column name). A multi-index DataFrame has two labels: the cabinet section (year, title) and the drawer within that section (min, max, count).
      

    


    
    

      
12Hierarchical indexing

      
Flattening multi-index columns

      
Two-level column names are useful for grouping but awkward for further computation. Flatten to single-level names like year_min, year_max, title_count.


      
Approach 1 — join tuple elements with underscore

      
python
data_agg.columns = ['_'.join(col) for col in data_agg.columns]
# Each column name is a tuple like ('year', 'min')
# '_'.join turns it into 'year_min'
data_agg.head()


      
Approach 2 — named aggregation (specify output names directly)

      
python
data.groupby('director_name')[['year', 'title']].aggregate(
    year_max=('year', 'max'),
    year_min=('year', 'min'),
    title_count=('title', 'count')
)

      
Both approaches produce flat column names. Named aggregation is more explicit; the list-comprehension approach is useful when you already have a multi-index result and need to flatten it retroactively.


      

        
⚠️ reset_index() without inplace

        After a groupby aggregation, the grouping column becomes the row index. data_agg.reset_index() promotes it back to a column — but like rename() and drop(), it returns a copy. The original is unchanged unless you reassign or pass inplace=True.

13Putting it together

      
Calculating director productivity

      
Productivity definition: movies per year of active career. Steven Spielberg made the most movies overall — but does a long career make him more productive than a director who made fewer films in a shorter time?


      
python — full pipeline
# 1. Count movies and career span per director
data_agg = data.groupby(['director_name'])[["year", "title"]].aggregate(
    {"year": ['min', 'max'], "title": "count"})
data_agg.columns = ['_'.join(col) for col in data_agg.columns]
data_agg = data_agg.reset_index()

# 2. Career span in years
data_agg["yrs_active"] = data_agg["year_max"] - data_agg["year_min"]

# 3. Productivity rate
data_agg["movie_per_yr"] = data_agg["title_count"] / data_agg["yrs_active"]

# 4. Rank directors
data_agg.sort_values("movie_per_yr", ascending=False)


      

        
⚠️ Division by zero

        A director whose films all landed in one year has yrs_active = 0, making movie_per_yr infinite (inf — Pandas doesn't crash, it just stores infinity). A quick fix: yrs_active = (year_max - year_min) + 1, treating a single active year as 1 rather than 0, or filter out single-year directors before ranking.
      


      
Conclusion: Tyler Perry turns out to be the most productive by this measure — the highest number of movies per year of active career. Steven Spielberg made the most movies overall, but his long career reduces his per-year rate.
