Coding gradient descent

Gradient descent can be implemented with just two small functions: one that numerically estimates a derivative, and one that performs a single update step.

Numerical derivative — approximate f'(x) using a tiny step δ:
derivative(x, f):
  delta = 0.0001
  return (f(x + delta) − f(x)) / delta
One gradient-descent step — move x against the gradient, scaled by the learning rate:
one_step_gd(x, f, lr):
  grad = derivative(x, f)
  new_x = x − lr * grad
  return new_x, f(new_x), grad

Running this repeatedly from a starting guess (e.g. x₀ = −5, learning rate 0.1, on f(x) = x²) traces a path of points that march steadily toward the minimum at x = 0, with each step's tangent line visibly flattening as the walk approaches the bottom of the curve.

Gradients of vector functions

Two patterns recur so often in machine learning that they're worth memorising directly.

Linear form: f(x̄) = āᵗx̄

Expanding gives a₁x₁ + a₂x₂ + a₃x₃ + …. Each partial derivative ∂f/∂xᵢ is simply aᵢ, so the full gradient collapses to the vector itself:

∇x̄ (āᵗx̄) = ā

Squared-norm form: f(x̄) = x̄ᵗx̄

This is x₁² + x₂² + … + x_d². Each partial derivative is 2xᵢ, so the gradient is just twice the vector:

∇x̄ (x̄ᵗx̄) = 2x̄
These mirror the single-variable rules exactly — d/dx[ax] = a and d/dx[x²] = 2x — just lifted into vector form.

The classifier's optimisation problem

Recall the classifier's gain function, which measures how well a separating line divides the two classes of points, normalised by the length of the weight vector w̄:

G(D, w̄, w₀) = Σᵢ ( w̄ᵗx̄ᵢ + w₀ ) / ‖w̄‖

The goal is to maximise this gain — equivalently, to minimise its negative, the loss function L = −G.

The division by ‖w̄‖ = √(w₁² + w₂² + … + w_d²) makes this function awkward to differentiate directly — a square root sitting in the denominator complicates every derivative that touches it.

The key realisation: when computing a gradient, only the direction it points in matters for the optimisation — and a vector's direction, with its magnitude normalised away, is exactly what a unit vector captures. That observation motivates fixing ‖w̄‖ = 1 as an explicit constraint, turning a messy unconstrained problem into a cleaner constrained one.

From unconstrained to constrained optimisation

Adding the constraint ‖w̄‖ = 1 changes the search: instead of hunting for a minimum across the whole space of possible w̄ values, the search is now restricted to only the w̄ vectors that satisfy the constraint.

Geometric intuition: for f(x) = x² − 3x + 3, the unconstrained minimum sits at x = 1.5. Adding a constraint curve — say f(x) = 2x² − 3x + 1 — means only the points where the two curves intersect are candidates; the search space shrinks from the entire curve down to just those intersection points.

A constrained optimisation problem is written using "s.t." (subject to, or "such that"):

minx̄ f(x̄)   s.t.   g(x̄) = 0

The Lagrange multiplier method

To solve a constrained problem, fold the constraint directly into the objective using a new variable λ (lambda), the Lagrange multiplier:

minx̄ f(x̄) + λ · g(x̄)

This turns the constrained problem into an ordinary unconstrained one, just with one extra variable (λ) to solve for. For several constraints, each one is added the same way, each with its own multiplier.

Worked example: minimise f(x) = x² − 3x − 3, s.t. −x² + 2x + 3 = 0 +
Step 1 — Lagrangian: fold the constraint in with a multiplier λ, giving a new function h(x, λ) of two variables.

Step 2 — gradient to zero: at a minimum the gradient is zero, so take ∂h/∂x and ∂h/∂λ, set both to 0, and solve the resulting system of two equations in two unknowns.

Result: the function is minimised at x = 3, where its value is −3.

Summary

This lecture connected the mechanics of coding gradient descent to the harder problem of a loss function with an unwieldy square-root denominator. Fixing the weight vector's norm to 1 turned that into a constrained optimisation problem, which the Lagrange multiplier method converts back into an ordinary unconstrained one — ready to be solved with the same gradient-descent update rule used throughout this series.
