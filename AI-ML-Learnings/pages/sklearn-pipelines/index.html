Concept
Introduction to Regularization
⏱ 10 min

The Problem with Large Weights

Recall the Linear Regression loss function (MSE):

Loss = Σ (yᵢ − ŷᵢ)² = Σ (yᵢ − (w₁x₁ + w₂x₂ + w₀))²

To minimize this loss, the optimizer tries to make ŷᵢ as close as possible to yᵢ. One way it can do this is by inflating the weights w₀, w₁, w₂ to very large values. This causes overfitting — the model fits training data perfectly but fails on new data.

🤔 The Analogy: Roof Leakage

Imagine a leaking roof. You have three fix options:

SolutionLeakage StoppedCost
Bandage1000 mL remains₹1
Shingles10 mL remains₹1,000
Titanium0 mL remains₹1,00,000

You want minimize(Leakage + Budget) simultaneously. This tug-of-war is exactly what regularization does in ML — balancing prediction error against model complexity.

Adding a Penalty Term

We modify the objective from minimizing only the loss, to minimizing:

minimize ( Loss + Regularization Penalty )

The penalty term discourages large weights. When the optimizer tries to increase wⱼ to reduce loss, the penalty term grows too — pushing back against that increase. This keeps weights small and the model generalized.

λ
Concept
The λ Hyperparameter — Controlling Regularization
⏱ 3 min

If we penalize too aggressively, all weights get pushed to zero and the model underfits. We need a dial to control how much the penalty matters:

minimize ( Loss + λ × Regularization Term )

λ (lambda) is a non-negative scalar that controls the strength of regularization. It's a hyperparameter — set by you before training, not learned from data.

λ valueEffectRisk
λ = 0No regularization — standard linear regressionOverfitting
λ = moderateControlled penalty — weights shrink but stay non-zeroBalanced ✓
λ = ∞Penalty dominates — all weights pushed to zeroUnderfitting
📌 Parameters vs Hyperparameters
Parameters (weights wⱼ) are learned by the model during training. Hyperparameters (like λ) are chosen by you before training and control the learning process itself. Tuning hyperparameters is a key part of building good models.

Techniques
Ridge, Lasso & Elastic Net
⏱ 3 min
🔵
Ridge (L2)
λ · Σ wⱼ²
Penalizes the square of each weight. Shrinks all coefficients toward zero but rarely to exactly zero. Best when all features are somewhat relevant.
⚡
Lasso (L1)
λ · Σ |wⱼ|
Penalizes the absolute value of each weight. Can force irrelevant feature weights to exactly zero — performing automatic feature selection. Produces sparse models.
🔀
Elastic Net
λ₁·Σ|wⱼ| + λ₂·Σwⱼ²
Combines L1 and L2. Gets the sparsity of Lasso plus the stability of Ridge. Useful when there are correlated features.

Quiz 1
L1 vs L2 Regularization
⏱ 1 min
Which statement best describes the difference between L1 and L2 regularization?
  • L1 sets all coefficients to zero equally.
  • L2 completely removes unimportant features.
  • L1 can make some coefficients exactly zero, while L2 usually only shrinks them.
  • Both always produce identical models.
💡 Explanation
L1 (Lasso) performs feature selection by driving irrelevant coefficients to exactly zero. L2 (Ridge) reduces the magnitude of all coefficients but typically keeps them non-zero — it reduces overfitting without discarding features.

Extract Company Name from CarName

The CarName column contains the full model name (e.g., "alfa-romero giulia"). We only need the company name — the part before the first space:

import re
p = re.compile(r'\w+-?\w+')
cars['car_company'] = cars['CarName'].apply(lambda x: re.findall(p, x)[0])
cars = cars.drop('CarName', axis=1)

Fix Misspelled Company Names

Several car companies have data entry errors (e.g., "vw" and "vokswagen" should both be "volkswagen"). Fix before any encoding:

cars.loc[cars['car_company'].isin(["vw","vokswagen"]), 'car_company'] = 'volkswagen'
cars.loc[cars['car_company'] == "porcshce",  'car_company'] = 'porsche'
cars.loc[cars['car_company'] == "toyouta",   'car_company'] = 'toyota'
cars.loc[cars['car_company'] == "Nissan",    'car_company'] = 'nissan'
cars.loc[cars['car_company'] == "maxda",     'car_company'] = 'mazda'
📌 Why Fix This First?
If "vw" and "volkswagen" are treated as different companies, one-hot encoding creates two separate dummy columns for the same manufacturer. This introduces noise and inflates the feature space unnecessarily. Clean first, encode after.

Data Cleaning Before Preprocessing
⏱ 1 min
Why is it good practice to complete data cleaning before applying preprocessing techniques like scaling or encoding?
  • Scaling automatically fixes incorrect values.
  • Cleaning ensures transformations are applied on consistent and reliable data.
  • Encoding removes duplicate rows.
  • Pipelines only work after scaling.
💡 Explanation
Preprocessing techniques assume the input data is already clean. Missing values, inconsistent labels, and typos should be resolved first — otherwise scaling and encoding produce meaningless or misleading results.

Column Transformers
⏱ 10 min

A ColumnTransformer applies different preprocessing operations to different subsets of columns — all in parallel, in a single step. Instead of writing separate loops for each transformation, you define them once and let Sklearn handle the rest.

🎮

↓ split & process in parallel ↓
📊 Standard Scaler

📐 Min-Max Scaler

🔢 Max Abs Scaler

Code

from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import StandardScaler, MinMaxScaler, MaxAbsScaler

scaling_transformer = ColumnTransformer(
    transformers=[
        ('Standard Scaler',   StandardScaler(), ['car_ID','carwidth','enginesize','compressionratio','citympg']),
        ('Min-Max Scaler',    MinMaxScaler(),   ['wheelbase','carheight','boreratio','horsepower','highwaympg']),
        ('Max Absolute Scaling', MaxAbsScaler(),['carlength','curbweight','stroke','peakrpm','price'])
    ],
    remainder='drop'
).set_output(transform='pandas')

scaled_num_cols = scaling_transformer.fit_transform(cars)

Key Parameters

ParameterValueMeaning
remainder'drop'Columns not listed in any transformer are discarded
remainder'passthrough'Unlisted columns are kept as-is
verbose_feature_names_outFalseStrips transformer prefix from output column names
set_output(transform='pandas')—Returns a DataFrame instead of a NumPy array

Encoding Transformer (for Categorical Columns)

from sklearn.preprocessing import OrdinalEncoder, OneHotEncoder

OE_categories = [
    [-2,-1,3,2,1,0],                           # symboling order
    ['two','three','four','five','six','eight','twelve']  # cylinder order
]

encoding_tf = ColumnTransformer(
    transformers=[
        ('Ordinal encoder', OrdinalEncoder(categories=OE_categories),
         ['symboling','cylindernumber']),
        ('One Hot Encoder', OneHotEncoder(sparse_output=False),
         ['symboling','fueltype','aspiration','doornumber','carbody',
          'drivewheel','enginelocation','enginetype','cylindernumber',
          'fuelsystem','car_company'])
    ],
    remainder='passthrough', verbose_feature_names_out=False
).set_output(transform='pandas')
📌 Ordinal vs One-Hot
Ordinal encoding preserves order (e.g., two < three < four cylinders). Use it when the category has a natural ranking. One-hot encoding treats categories as independent — no implied order. Use it for nominal categories like fuel type or car company.

Pipelines in Sklearn
⏱ 10 min

A Pipeline chains multiple steps — each one takes output from the previous step as input. The final step is usually the model. Everything runs in a fixed sequence with a single fit() call.

from sklearn.pipeline import Pipeline

pipeline = Pipeline(steps=[
    ('Encoding', encoding_tf),

FeatureUnion — Parallel Merging

When two people work on different column subsets independently, FeatureUnion merges their results horizontally (like a column-wise concat), unlike Pipeline which chains sequentially:

from sklearn.pipeline import FeatureUnion

# encoder pipeline: categorical columns → encode
encoder_pipeline = Pipeline(steps=[('Encoding', encoding_tf)])

# scaler pipeline: numerical columns → scale
scaler_pipeline  = Pipeline(steps=[('Scaling', scaling_tf)])

feature_union = FeatureUnion(transformer_list=[
    ('encoder', encoder_pipeline),
    ('scaling', scaler_pipeline)
]).set_output(transform='pandas')

transformed_data = feature_union.fit_transform(cars)

What is the primary purpose of using a Scikit-learn Pipeline?
  • To increase the amount of training data.
  • To execute preprocessing and model training in a fixed sequence using one object.

Ridge Regression — Model Building & Evaluation
⏱ 12 min

With the data cleaned, encoded, scaled, and split, we now build a Ridge Regression model. Ridge's alpha parameter is equivalent to λ — controlling regularization strength.

Fit Ridge with alpha = 10

from sklearn.linear_model import Ridge

ridgeReg = Ridge(alpha=10)
ridgeReg.fit(X_train, y_train)

train_score = ridgeReg.score(X_train, y_train)
test_score  = ridgeReg.score(X_test, y_test)

print(f"Train R²: {train_score:.4f}")
print(f"Test R²:  {test_score:.4f}")
Output
Train R²: 0.9589 Test R²: 0.9224
MetricValueAssessment
Train R²0.959Excellent fit on training data
Test R²0.922Strong generalization — model works well on new data
Gap (Train − Test)0.037Small gap — minimal overfitting, regularization working
✅ Interpreting This Result
A train-test gap of only 3.7 percentage points tells us the regularization is doing its job — it's preventing the model from memorizing training data at the cost of generalization. Without regularization (Ridge with alpha=0), the test R² would likely be lower.

Quiz 5
Pipeline Advantage over Manual Preprocessing
⏱ 1 min
Why is training a model using a Pipeline generally preferred over manually performing preprocessing before training?
  • Pipelines always produce higher accuracy.
  • Pipelines eliminate the need for feature engineering.
  • Pipelines ensure the exact same preprocessing is consistently applied during both training and prediction.
  • Pipelines only work with linear regression.
💡 Explanation
The key benefit is consistency. When you call pipeline.predict(), it applies the exact same scaling parameters and encoding scheme learned during training. Without a pipeline, it's easy to accidentally apply different (or no) preprocessing at inference time — a common and dangerous source of bugs.
