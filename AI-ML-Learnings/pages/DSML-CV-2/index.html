    01

    Overfitting, and where we left off

    Last time we introduced Computer Vision, its applications and why it is hard. We saw that replacing the first dense layer of an MLP with a Conv + MaxPool block clearly improved accuracy on our clothing images, and we built intuition for the CNN components: kernels, channels, padding, stride, pooling and flattening.

    That CNN scored only about 50% on the test set and showed a big gap between training and validation accuracy. The fix is to fight overfitting, improving the model one change at a time and measuring the effect of each change.

    What overfitting is

    Overfitting is a model with too much capacity for too little data: it memorizes the training set instead of learning patterns that generalize. The sign is training accuracy that keeps rising while validation accuracy stalls or drops.

    Loading the data, step by step
    
  
    Why not read images from disk every epoch? The dataset is small (3,781 images across the three splits), so decoding JPEGs every epoch would be the slowest part of training. Instead we resize every image to 128 × 128 once and keep everything in memory as a tensor. Each epoch is then fast, which makes it practical to run many experiments.

    Diagnosis
    
  
    The most apparent issue: training accuracy keeps climbing while validation accuracy stalls, and validation loss turns upward. That is overfitting. The model memorizes the 3,068 training images instead of learning general clothing features.
    Overfitting means many trainable parameters, few training samples, and the summary above showed exactly where the parameters are.
    

    

    


    

    
  04
  
    Modification 1: a deeper network and Global Average Pooling
    
  
    Simply removing layers would hurt performance, since the network is already small. The real problem is the huge Flatten → Dense connection. So the first modification has two parts.
    
  
    
    
    Go deeper
    Stack more Conv + ReLU + MaxPool blocks. Each block halves the image size (128 → 64 → 32 → 16 → 8) while the number of channels grows (16 → 32 → 64 → 128 → 256). Later layers see larger parts of the image and learn richer features.
    
    
    Replace Flatten with Global Average Pooling
    Instead of unrolling an 8 × 8 × 256 map into 16,384 numbers, average each channel’s 8 × 8 map into one number, giving 256 numbers for the next dense layer.
    
  
    
  
    
  
    Here is the new architecture. Select a block in the picture to follow the shrinking maps and growing channels, and watch where the parameters now live.

  06
  
    Modification 3: Batch Normalization and Dropout
    
  
    
    
    Batch Normalization
    Normalizes a layer’s activations using the mean and variance of the current batch. It stabilizes and speeds up training and adds a slight regularizing noise. It sits between the convolution and the ReLU: Conv → BatchNorm → ReLU.
    
    
    Dropout
    Randomly switches off a fraction of the neurons at each training step (here 50% in the dense layer), so the network cannot rely on any single neuron. It is active only in model.train() mode and disabled in model.eval().
    
  
    
  
    
  
    
  
    With the flexible class, this is just two arguments: CNN(use_bn=True, dropout=0.5). The extra BatchNorm layers add only a handful of parameters.
    
  
    
  
    The total grows from 460,970 to 462,474 parameters: the BatchNorm layers add 1,504 in all (two per channel or unit).

    The training run: jagged curves
    
  
    
  
    Something looks off: the curves are very jagged. This is partly expected. Every regularizer injects randomness into training (dropout switches off 50% of the neurons at random every step), and the validation set is small (341 images), so its accuracy is naturally noisy. But a “heartbeat” pattern is also a typical sign that the learning rate is too high near the end of training.
    
  
    Note on the logged run: its first epoch already shows 89.9% training accuracy, much higher than the first epoch of the other runs (23–35%). The lecture does not explain this, so read this run as an illustration of jagged curves rather than a like-for-like comparison. The run has no reported test accuracy.
    

    

    


    

    
  07
  
    Modification 4: learning-rate scheduler and early stopping
    
  
    
    
    ReduceLROnPlateau
    When the validation loss has not improved for a while (patience=5 epochs), multiply the learning rate by 0.3. Big steps early, small careful steps later.
    
    
    Early stopping
    If the validation loss has not improved for patience=10 epochs, stop training. We no longer guess the number of epochs: we set a generous maximum (60) and let the model tell us when to stop.
    
  
    
  
    Replay the logged runs below. Each epoch’s validation loss feeds both counters; when the scheduler’s counter runs out the learning rate drops, and when the early-stopping counter reaches 10 training ends and the best weights are restored.

  08
  
    Modification 5: regularizing the loss with L1 and L2
    
  
    Another way to stop weights from growing wildly is to add a penalty on the weights to the loss:
    
  
    total loss = data loss + λ · penalty(weights)
    
  
    
    
    PenaltyEffect
    
    
      
    L1 (Lasso)λ · Σ|w|pushes many weights to exactly 0, giving a sparse model that acts like feature selection
    
      
    L2 (Ridge)λ · Σw²shrinks all weights towards (but not exactly) 0, giving small, smooth weights
    
        
  
    
  
    Example, predicting car prices: L1 may set the weight of an unimportant feature (say, fuel-tank size) to exactly 0, while L2 would keep it but make it small.
    
  
    

  
    In PyTorch
    
  
    The idiomatic way to get L2 is the optimizer’s weight_decay argument, which shrinks every weight a little on each update. L1 has no built-in flag; you add λ * sum(p.abs().sum() for p in model.parameters()) to the loss yourself.
    
  
    Implementation notes
    
  
      
    
    • With Adam, weight_decay adds weight_decay * w to the gradient. This is L2 regularization in spirit, but it is not numerically identical to Keras’ kernel_regularizer=l2(λ) (which adds λ·Σw² to the loss), and it applies to all parameters, including biases and BatchNorm parameters.
      • 
    
    • With adaptive optimizers like Adam, the penalty gets rescaled by the adaptive step sizes. AdamW applies the weight decay in a decoupled way and is usually preferred in practice.
      • 
    
    • The right strength is data-dependent; the lecture uses a small value, 1e-4.
      •

  09
  
    Modification 6: data augmentation
    
  
    Now the data pipeline. Augmentation artificially increases the amount (and diversity) of training data by generating new samples from existing ones with small, label-preserving changes: flips, shifts, rotations, brightness changes and so on.
    
  
    
  
    Why it helps: the model sees a slightly different version of every image in every epoch, so it cannot simply memorize them and must learn features that are robust to these changes.
    
  
    
    
    Rule 1 · Training set only
    Apply augmentation to the training set only. Validation and test sets measure performance on realistic, un-augmented data.
    
    
    Rule 2 · Realistic and label-preserving
    A vertically flipped shirt is not a realistic product photo.
    
  
    
  
    Common augmentations: flips, rotation, translation, cropping, zooming, brightness / contrast / colour jitter, grayscale, noise and random erasing. In PyTorch we use torchvision.transforms (composable, applied automatically when a sample is requested). For one-off control on a single image there is also torchvision.transforms.functional (for example TF.rotate, TF.hflip).

  10
  
    Putting it all together
    
  
    Each experiment adds one change on top of the previous one and records its test accuracy. Which single change gave the biggest jump? Which made little difference on their own? Remember that some of these differences are within the noise of a small test set.
    
  
    
  
    The biggest jump came from fixing the architecture: the deeper network with Global Average Pooling, trained for 30 epochs (+18.28 points, with far fewer parameters). The L2 step (+1.08 points, roughly four test images) is small enough to be within noise.
