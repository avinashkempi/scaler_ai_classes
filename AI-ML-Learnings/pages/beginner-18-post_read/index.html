§ 1

Claude Projects & Memory

⏱ 14 min

Before you write a single instruction, you need to know what actually carries over between conversations — and what quietly doesn't.

Claude Project

A named workspace on claude.ai that holds three things every new chat inside it starts with: project instructions (your standing rules, up to roughly 8,000 characters), knowledge documents (files you upload — PDFs, sheets, notes, up to a generous shared limit), and the conversations themselves, kept together. Open a fresh chat inside the Project and Claude already has the instructions and the documents — you never re-paste them.

Projects are available on every plan, including free — up to five Projects on a free account. That's the good news everything else builds on.

🗄️
The Analogy

A plain chat is a conversation with someone you flag down on the street — smart, helpful, and they forget you the moment you walk away. A Project is a filing cabinet with a desk clerk who works only on Chapter One's account. You put the shop's facts in the cabinet once. Every visitor who sits at that desk — even a completely new conversation — reads the same files before they say a word.

✓ What actually persists

Project instructions. Uploaded knowledge documents. Nothing else needs re-explaining — a brand-new chat in the Project can already answer "how many seats on Saturday?"

✗ What does NOT persist

Anything said only inside one conversation. A fact you tell Claude mid-chat stays in that chat — it doesn't write itself back into the Project's instructions or files unless you put it there yourself.

🎙 Instructor Says

"This trips people up constantly, so say it back to yourself: talking to Claude is not the same as teaching a Project. If Nikhil tells Claude mid-chat that Saturday's 4pm session is now full, that fact dies when the chat ends unless he goes and edits the Project's instructions or documents. Memory in this sense is something you configure, not something that accumulates on its own."

Q1. Nikhil tells Claude, mid-conversation inside the Chapter One Project, "actually the Tuesday session got cancelled this week." A week later he opens a brand-new chat in the same Project and asks about Tuesday's session. What happens?
AClaude already knows Tuesday was cancelled — anything said inside a Project's chats is remembered forever.
BClaude has no idea — that fact lived only in that one conversation. It never updated the Project's instructions or documents, so it didn't carry forward.
CClaude asks Nikhil to re-upload his knowledge documents before it can answer.
Correct answer: B. Only project instructions and uploaded documents persist across chats — not things merely said inside one conversation. If Nikhil wants that fact to stick, he has to go edit the Project itself.
§ 2 · Build 1

claude.md — Configure the Shop Once

⏱ 18 min

The set of standing instructions that turns "explain everything every time" into "already knows."

claude.md

Not a special file format — a naming habit. In Claude Code (the developer tool), a file literally called CLAUDE.md sitting at the top of a project folder is loaded automatically into every session in that folder. On claude.ai, the same idea has a friendlier home: a Project's "Project instructions" box — plain text, no file needed, loaded into every chat in that Project. Same job, same habit, different door.

The hands-on version here uses Project instructions — it's free on every plan and needs nothing installed. The Claude Code CLAUDE.md file works identically in spirit, but Claude Code itself needs a paid plan (more in §5).
🛠 Instructor Does

Open a free claude.ai account → New Project → name it "Chapter One" → open Project settings → paste a short instructions block into Project instructions. Keep it under ten lines. Example, word for word:

# Chapter One — reading club
Context: Bengaluru bookshop, Saturday reading club, 10 sessions x 6 seats.
Always: format any roster or list as a table (Name, Session, Status).
Never: include phone numbers in anything meant to be shared or posted.
Tone: short, friendly, sign off with "— Chapter One".
🎙 Instructor Says

"Watch what just happened. That's five lines. No description of the shop, the number of seats, or the formatting rule shows up in the next message — one real question, and it already knew. That gap — five lines written once versus re-explaining every Friday — is the entire return on investment of claude.md."

SIM 2 · Write the claude.md, Watch the Output Change

Toggle a rule above to see the recap change.
Ravi, reading over your shoulder: "Don't put personal phone numbers in a document that lives in a shared Project — anyone with Project access reads project instructions and outputs. That's not a formatting rule, that's a privacy leak, written down and made permanent."
What's actually happening under the hood: a real claude.md never runs deterministic logic like the sim's toggles — it's a natural-language instruction Claude reads and follows with high but not perfect consistency. The sim makes the effect visible instantly; treat the real thing as "strong guidance," not a hard rule engine, and check its output occasionally rather than assuming it every time.
Q2. What's the actual difference between typing a rule into one chat message versus putting it in Project instructions?
AThere's no real difference — Claude treats both the same way.
BA rule in Project instructions is loaded into every new chat in that Project automatically; a rule typed into one message only applies to that message's conversation.
CProject instructions can only contain formatting rules, never context or tone.
Correct answer: B. That's the whole mechanism — Project instructions are the "always loaded" layer. One-off chat rules are exactly that: one-off.
§ 3 · Build 2

skill.md — Package a Task, Not a Fact

⏱ 18 min

claude.md is "always know this." skill.md is a different job: "when I ask for X specifically, follow these exact steps."

skill.md (a Claude Skill)

A small, named, reusable task definition — a short description that tells Claude when to reach for it, and a body of instructions for what to do once it's triggered. Unlike claude.md, a skill is not loaded into every conversation — only its one-line description sits quietly in context, and the full instructions load only when a request actually matches. That's why you can have fifty skills without slowing anything down, but a giant claude.md does slow things down.

🧰
The Analogy

If claude.md is the staff handbook pinned to the wall — everyone reads it, all the time — a skill is a labelled recipe card in a drawer. Nobody reads "Saturday Roster Recap" until someone actually asks for the Saturday roster recap. Then the whole card comes out, gets followed step by step, and goes back in the drawer.

Genuinely free — with one switch to flip first: creating, uploading, and running your own custom Skills works on every plan, including free. The only prerequisite is turning on Code execution under Settings → Capabilities — Skills run inside that same sandbox. Once that's on, Customize → Skills is where you upload and test them. (Claude Code, the developer tool, still needs a paid plan — more in §5. The skill.md file format is identical either way.)
🛠 Instructor Does

Four steps, all on claude.ai: 1) Settings → Capabilities → turn on Code execution. 2) Write a skill.md — a file has exactly two required parts: frontmatter (name + description — this is the trigger) and a body (the steps). 3) Save it inside a folder and zip that folder. 4) Customize → Skills → upload the zip, enable it, and test it in a real chat. Here's the whole file for the Saturday recap, short on purpose:

---
name: saturday-roster
description: Use when asked to build or send the weekly Saturday reading-club roster or recap.
---

1. Pull this week's sign-ups, grouped by session time.
2. Flag any session over its 6-seat capacity.
3. Draft a short WhatsApp recap — no phone numbers.
🎙 Instructor Says

"That description line is doing almost all the work. It's the only part of the skill Claude keeps in view all the time — the rest stays folded away until a request actually matches. Write a vague description and the skill never fires when it should, or fires when it shouldn't. That's exactly what the next sim makes you feel."

Q3. You add the trap piece — "description: use for any question about the weather this weekend" — to the same skill file as the roster steps. Someone asks "will it rain Saturday?" What's the actual risk?
ANothing — Claude ignores descriptions that don't match the file name.
BThe skill fires on the weather question too, because its description now matches, and runs the roster/recap steps against a question that has nothing to do with them.
CThe file becomes invalid and skill.md files never load again.
Correct answer: B. A skill triggers off its description text, not its filename or your intent — a mismatched or over-broad description makes it fire on the wrong requests. Same lesson as an over-broad automation rule, just at the skill layer.
§ 4 · Build 3

Claude Artifacts — a Live Tool, Not a Chat Reply

⏱ 18 min

Everything so far configures what Claude knows. An Artifact is what Claude hands you — something that runs, on its own, outside the chat.

Artifact

A self-contained interactive output — a small working app, calculator, chart, or table — that renders in its own pane next to the chat, and can be downloaded as one self-contained HTML file. Ask for one in plain language; Claude writes the code behind it, and you never see or touch that code unless you want to.

🧮
The Analogy

A chat answer is a waiter describing the dish to you. An Artifact is the waiter bringing you the plate — something you can actually poke at, that responds when you touch it, that you can hand to someone else at the table.

🛠 Instructor Does

One short prompt, in the Chapter One Project: "Make a small interactive calculator: I enter how many seats are free across today's 10 sessions, and it shows total free seats plus a simple bar." Claude returns a working Artifact — type a number, the bar and total update instantly, no chat back-and-forth needed. Click Download and you get one self-contained .html file — send that file to Tara directly (WhatsApp, email, Drive) and she opens it like any other file, no Claude account needed on her end. That's the whole build.

Artifacts are free on every plan — HTML, tables, simple interactive widgets, charts, and downloading the finished file all work with no upgrade. Skip the in-app Publish button on free — Anthropic's own docs describe it as available on every plan, but hands-on testing found it only offers a download, not a working hosted link. Download-and-send-the-file is the dependable path; treat any hosted public link as a paid-plan nicety, not something to promise. Persistent saved data and "Live" artifacts that call outside services are a paid-tier ceiling, not needed for anything here.

Q4. What's the real difference between asking Claude "how many seats are free if 4 people cancel from a 6-seat session?" as a chat question, versus asking for a small Artifact calculator that does the same math?
AThe chat answer is a one-time number for one situation; the Artifact is a reusable tool anyone can re-run with new numbers, and can be shared as a file.
BThere's no difference — both require the same amount of re-explaining every time.
CArtifacts can only display static text, never do live calculations.
Correct answer: A. That reusability-plus-shareability is the entire point of an Artifact over a chat reply — you build the tool once, other people use it without ever talking to Claude.

§ 7

Putting It All Together

⏱ 8 min

Everything above lived in its own box, taught one layer at a time. Watch what happens when a Project, its instructions, a Skill, and an Artifact all fire in the same request.

🛠 Instructor Does — start to finish

New Project — "Chapter One — Monthly Reports", separate from the reading-club Project in §2, with its own short instructions:

# Chapter One — Monthly Reports
Context: monthly supplier-cost review, four suppliers, prepared for Sarita.
Always: currency in ₹, one decimal place.
Always: charts use Chapter One's colours — terracotta bars on cream.

Next, click on the '+' icon, go to Skills → import a ready-made skill instead of writing one from scratch — a small "chart-style" skill someone else already built and shared, the same way you'd pull in any community skill collection — download statistical_chart.md and upload it directly. It works identically whether you wrote it (like the roster skill in §3) or imported it: Claude only cares that a SKILL.md with a matching description sits in Customize → Skills, enabled. Then one short prompt: "Make a bar chart artifact comparing this month's four supplier costs: Riverside Paper ₹18,400, Deccan Binders ₹12,900, Lakeview Print ₹9,600, Northgate Supplies ₹15,200." Claude pulls the Project's context, the imported skill's styling rules, and the numbers in the prompt — and hands back one properly-styled Artifact. Nobody typed a colour, a currency symbol, or a decimal rule in this message. That configuration was already sitting there, waiting.

TAKE-HOME

Three Challenges

⏱ homework

Two are single layers, drafted from scratch. The third asks you to do exactly what §7 just did — combine a Project, a Skill, and an Artifact into one real result, on your own life, not the bookshop.

01

Write your own claude.md

›
Mission

Create a free Claude Project for something you actually do repeatedly — a job, a hobby, a household routine. Write 5–8 lines of Project instructions covering context, one always-rule, and one never-rule. Test it by opening a brand-new chat and asking a question you'd normally have to set up first.

02

Build and upload a real skill.md

›
Mission

Pick one task you do the same way every time (a weekly summary, a specific kind of reply, a checklist). Write the frontmatter — name + a description precise enough that it wouldn't fire on the wrong request — plus 3–5 numbered steps. Turn on Code execution in Settings → Capabilities, zip the folder, upload it under Customize → Skills, and test it with the exact phrase you'd actually use.

03

Combine all three, the way §7 did

›
Mission

This one isn't a draft — build it end to end, on something real in your own life. Open a fresh Project with its own short instructions (context + one formatting rule). Enable or import one Skill into it — reuse Challenge 02's skill, or grab a ready-made one and just enable it. Then send one prompt that gives Claude the actual data, and ask for a small Artifact (a chart, table, or calculator) as the result. If it comes out styled or formatted correctly without you repeating any rule from the Project or the Skill, you've done it right. Download the file and send it to one other person.

Key Takeaways

1. Talking to Claude and configuring Claude are different acts. Only Project instructions and documents persist automatically across chats.

2. claude.md is "always on," skill.md is "on when asked." That's not a style choice — it's why one giant instructions file slows things down and fifty small skills don't.

3. An Artifact is a thing you hand someone, not a thing you tell someone. On free, "hand someone" means downloading the self-contained file and sending it directly — not the in-app Publish link the docs describe.

4. Check the free line before you plan a workflow around a tool name. Three of today's four capabilities are free outright, including Skills once Code execution is switched on; only the Claude Code app itself needs a paid seat. Verifying which is which, in advance, is what kept today honest.

Last class, Ravi asked where the sixty-one phone numbers actually were. Nobody in the shop knew what the answer would even look like. Now it's a table, behind one rule, in a Project nobody has to re-explain.
