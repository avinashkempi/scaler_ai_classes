FoundationsWhy programming languages exist

Can you talk to a computer in English? No. A computer only understands electrical signals — "High" and "Low." The language it truly understands is binary: made up of 0s and 1s, where 1 is high and 0 is low.

Writing instructions directly in binary is punishing for humans. So we need a translator — a program that converts a human-readable language into binary the machine can run.

A high-level language + a translator lets humans skip writing raw 0s and 1s.

A high-level language is one that's human-readable — Python, Java, JavaScript, Ruby, and others. Each has its own syntax: the set of rules or grammar for writing valid code, just like English has grammar.

◆SQL is a high-level language too

SQL is high-level, but specialized for querying databases. Python is general-purpose: it does what SQL does and much more — take user input, build logic, automate workflows, train ML models, build applications. Think of SQL as a specialist doctor and Python as a general physician who can also specialize.

Question 1Displaying output with print()

#First, what's this # symbol?

A line starting with # is a comment — a note written by the programmer, for humans to read. Python completely ignores any line that starts with #. Think of it as a sticky note on your code. You'll see comments throughout these examples; they never affect how the program runs.

ƒAnd what's a "function"?

You're about to meet print(), and later type(), input(), int(), float(), and str(). Each is a function: a reusable, named piece of code that performs an action. The value(s) you place inside the parentheses are called arguments — they tell the function what to work on. For now, just get comfortable with the name(argument) pattern.

The print() function displays output on the screen. ◆ Like SELECT — when you write SELECT 20+30; in SQL, it evaluates and shows 50. print() does the same in Python.

✦Error messages are your friend

You just saw your first error — a SyntaxError. The screen turns red and it can feel alarming. Here's the truth: errors are Python trying to help you, not punish you. Every error tells you exactly two things: what went wrong (the error type — SyntaxError, NameError, TypeError) and where (the line number). Professional programmers see errors every single day. Don't panic — read it, find the line, and use it as a clue.

Question 2Python's five core data types

We printed 20+30 and got maths, but "I love you all 3000!" stayed as text. How does Python know the difference? It comes down to data types — how Python classifies every piece of information it works with.

◆Familiar from SQL — with one big difference

SQL has INT, FLOAT, VARCHAR, BOOLEAN, NULL. Python has the same ideas with simpler names — and you don't declare the type upfront. Python figures it out automatically.

int — whole numbers

Positive or negative whole numbers: 1, -4, 8, 0, 323434242. Python handles arbitrarily large integers, limited only by available memory — so no overflow to worry about, unlike some other languages. ◆ Banking tie-in — a principal of 100000 is an integer.

float — decimals

Numbers with a decimal point, stored internally as floating-point approximations: 0.3, 0.123, -2.4.

?Is 9 the same as 9.0?

In real life, same value. In Python, different types: 9 is an int, 9.0 is a float. Also note: both .5 and 0.5 are valid floats — the leading zero is optional. In the banking problem, a rate of 7.5 is a float.

str — strings (text)

Anything inside quotes is a string. Use either double quotes " " or single quotes ' ' — but you must start and end with the same kind.

  • "Hello everyone" — valid
  • 'hello' — valid
  • "hey everyone' — invalid (mixed quotes)

In the banking tool, the heading "Simple Interest Calculator" is a string.

bool — Boolean

Two possible values: True or False. This ties back to binary: True ↔ 1 (high), False ↔ 0 (low). We use booleans when comparing things.

◆ Like a WHERE clause — when SQL checks WHERE price > 100, it evaluates to true/false per row. Python does the same comparison, but can also print or store the result.

NoneType — the absence of a value

Has a single value: None. It represents nothing — an empty or absent value. Ask a user for a middle name they don't have: instead of an empty string, Python can store None to mean "no value was provided at all." ◆ This is Python's NULL — same purpose as NULL in SQL.

◇Quick check · Quiz 2

Which of the following values is of type float in Python?

.2 is a float (same as 0.2; the leading zero is optional). "2.3" and '3.14' look decimal but are in quotes → they're strings (a very common trap). -3 is a whole number → an integer.

The key takeaway: quotes change everything. The moment you wrap something in quotes, Python treats it as text — regardless of what's inside. Same as SQL, where 2.3 is a FLOAT but '2.3' is a VARCHAR.

The toolChecking types with type()

When a value comes from somewhere else and you're not sure what it is, Python gives you a built-in tool: the type() function tells you the type of any piece of data.

!In a script, wrap it in print()

In a standard IDE or Python shell, type() alone may not display anything — wrap it in print(). In Jupyter/Colab, the last expression in a cell is shown automatically, so type("hello") works without print(). To be safe and consistent, always use print(type(...)).

The <class 'str'> output tells you the object belongs to the str (string) class. Don't worry about the word "class" for now — that comes in Python-2.

◆Static vs dynamic typing

In SQL, a column's type is fixed when you create the table (static typing) — price DECIMAL(10,2) stays that way. In Python you can check the type anytime with type(), and the type can even change when you reassign a value. That flexibility is a big reason Python is so beginner-friendly.

Question 3Storing values in variables

In the banking problem the customer gives a principal of 100000, a rate of 7.5, a time of 3 — and we reuse each value several times. Typing 100000 everywhere would be tedious and error-prone. A variable lets us store a value and refer to it by name. It's a named container pointing to a reserved spot in memory.

What does = mean in Python?

You might read a = 3 as "a equals 3," like in maths. That's not what it means. In Python, = is the assignment operator: "take the value on the right, and store it into the variable on the left." Think of it as an arrow pointing left.

a = 3 ⟶ put into ⟶
a3
"Put the value 3 into the box called a." A single = stores; it does not compare.

This is different from maths, where a = 3 asserts equality. So later, x = x + 1 is not a contradiction — it means "take the current value of x, add 1, and store the result back into x." To compare two values, Python uses == (double equals), which you'll meet in a later session. For now: single = stores, it doesn't compare.

◆Like a SQL alias — but it persists

In SQL you wrote SELECT price * quantity AS total_cost FROM orders;. In Python you'd write total_cost = price * quantity. The difference: a Python variable persists — you can reuse it, update it, and refer to it anywhere below in your code. A SQL alias only lives inside that single query.

int() on a float truncates — it does not round

You already know int("3.14") errors because "3.14" is a string with a decimal point. But what if you pass an actual float?

Surprising? Python doesn't round — it truncates, dropping everything after the decimal point no matter how large:

Predict the output (input is 10 then 3.5).

input() always returns a string → type(a) is <class 'str'>. Then int("10") → 10 and float("3.5") → 3.5. Adding an int and a float promotes the result to float: 10 + 3.5 = 13.5, of type <class 'float'>.

This automatic promotion (int + float = float) matters: Python moves to the "wider" type to avoid losing precision.
