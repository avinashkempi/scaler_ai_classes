Deciding how much detail a number is made of

Every number in a Tableau view is built at some level of detail. Understand granularity first, then use Level of Detail expressions to calculate at a level the view isn't showing.

Foundation

What is data granularity?

Data granularity is a measure of the level of detail in a data structure — in simple terms, how detailed the data is.

  • The more detailed, the higher the granularity — and the more rows of data you will have.
  • The less detailed, the lower the granularity — and the fewer rows of data you will have.
  • Granularity depends on what you place in the view.

  • In time-series data, the granularity of measurement might be based on intervals of years, months, weeks, days, or hours.
  • The name field could represent the full name, or have separate entries for first name, middle name, and last name.

The trade-off

Granularity vs aggregation

Granularity and aggregation work opposite of each other.

In Tableau, when you bring dimensions and a measure into the view, the measure is aggregated by whatever dimensions are on the view. As you remove and add dimensions you are decreasing and increasing the granularity — the more dimensions or details on the view, the more granular it is.

Why granularity matters

Determines the analysis

The level of data granularity determines what analysis can be performed, and whether results from that analysis lead to appropriate conclusions.

Carries a cost

The more granularity, the more information is available for analysis — but at the cost of increased storage, memory and required computing resources.

Leads to LOD

Some analysis requires information at a higher level, which means aggregating the underlying detail up. This is where Level of Detail comes into the picture.

The tool

Level of Detail expressions

LOD expressions let you define the granularity at which Tableau performs a calculation, regardless of what's present in the view.

{ FIXED [Dimension List] : AGGREGATE }

Keyword

FIXED, INCLUDE or EXCLUDE — how the calculation relates to the dimensions already in the view.

Dimension list

The dimension or dimensions that define the level of detail for this calculation.

Aggregate

The aggregation performed at that level, such as SUM([Sales]).

Three business problems follow. Each starts from a requirement the view cannot satisfy on its own, shows the SQL you would write for the same result, then the LOD expression that solves it in Tableau.

The highlighted column repeats: every state inside West shows 650, every state inside East shows 750.

If you drag State onto your chart, Tableau automatically groups all math by State.

  • A standard SUM(Sales) will only show the state's total.
  • You need a way to say: calculate the total for the whole Region, and repeat that number for every state inside it.
WITH state_sales AS (
  SELECT
    region,
    state,
    SUM(sales) AS state_sales
  FROM orders
  GROUP BY region, state
)

SELECT
  region,
  state,
  state_sales,
  SUM(state_sales) OVER (PARTITION BY region) AS region_total_sales
FROM state_sales
ORDER BY region, state;

In SQL you explicitly tell the database to calculate the total at the Region level, then display that same value for every State within the region. The Tableau requirement is conceptually the same: ignore the current level of detail in the view and calculate at the Region level instead.

Note: a FIXED LOD is the visual equivalent of a correlated subquery or a window function.

  1. Create the calculation. Right-click anywhere in the Data pane and select Create Calculated Field. Name it Regional Sales (Fixed), enter { FIXED [Region] : SUM([Sales]) }, click OK.
  2. Build the granular view. Drag Region to Rows, then State to Rows to the right of Region. Drag the standard Sales measure to Text on the Marks card — this becomes your state sales.
  3. Add the fixed comparison. Drag Regional Sales (Fixed) from the Data pane onto Text on the Marks card.

1 · FIXED LOD

  • It computes a value using the specified dimensions, without regard to the dimensions in the view.
  • It allows you to create a calculation that is independent of the view's level of detail.
  • For example, to calculate a total sales value regardless of the filters applied to the view.

{ FIXED [Dimension List] : AGGREGATE }

How FIXED works, step by step

FIXED calculates the value once at the level you specify, then repeats that same value for every row in the view. These six orders are used again in the comparison later on.

Use FIXED when you want
  • A value that stays the same regardless of other dimensions in the view
  • Percent of total within a specific level
  • Consistent rankings or benchmarks
  • Comparisons to a total
Remember
  • FIXED is independent of the dimensions in the view
  • It only depends on the dimension or dimensions specified inside the FIXED expression

The conflict

When you drag Sub-Category into the view, Tableau automatically slices all calculations by that specific dimension. You need a calculation that says: look at the chart, find the Sub-Category dimension, and ignore it so you can give me the higher-level Category total.

The same idea in SQL

WITH sub_cat_sales AS (
  SELECT
    category,
    sub_category,
    SUM(sales) AS sub_category_sales
  FROM orders
  GROUP BY category, sub_category
)

SELECT
  category,
  sub_category,
  sub_category_sales,
  SUM(sub_category_sales) OVER (PARTITION BY category) AS category_total_sales
FROM sub_cat_sales
ORDER BY category, sub_category;

In the FIXED problem we pinned the calculation to a specific level regardless of the view. Here we don't want to pin anything — we simply want Tableau to ignore one dimension that's currently in the visualization while keeping everything else the same. That is what EXCLUDE LOD does.

2 · EXCLUDE LOD

  • It computes a value using the specified dimensions, but excludes those dimensions from the view.
  • It allows you to remove dimensions from the computation while maintaining the original level of detail.
  • For example, to calculate the sales for each product category, excluding the customer dimension from the view.

{ EXCLUDE [Dimension List] : AGGREGATE }

When to use it
  • When you want the calculation to ignore a specific dimension in the view
  • When you want a value computed at a higher level, but displayed at a lower level
  • For share-of-total calculations that exclude one dimension
Key takeaway

EXCLUDE removes the specified dimensions from the calculation. It calculates at a higher level — without that dimension — then repeats the result for each value of the excluded dimension in the view.

Build the EXCLUDE view in Tableau
  1. Create the calculation. Right-click in the Data pane, select Create Calculated Field, name it Category Sales (Excluding Sub-Cat) and enter { EXCLUDE [Sub-Category] : SUM([Sales]) }.
  2. Build the granular view. Drag Category to Rows, then Sub-Category to Rows to the right of Category. Drag the standard Sales measure to Columns.
  3. Add the excluded metric. Drag Category Sales (Excluding Sub-Cat) onto Label (or Text) in the Marks card.

Check yourself

If we have State and City in the view, but we want Sales aggregated over State only, what should the calculated field be?

ExplanationThe view contains both State and City, making the granularity State → City. To aggregate Sales at the State level only, City must be removed from the calculation. EXCLUDE removes a dimension from the current level of detail, making this the correct solution.

The calculation derives the average sales per city, despite the city dimension not being displayed in the view.

The conflict

If you drag Region to Rows and Sales to Columns and change the measure to Average, Tableau calculates the average of every individual row — a transactional average.

  • To find the City Average, you must first sum all sales for each City, and then take the average of those city totals.
  • You want to see this at the Region level without cluttering the view with thousands of City names.
Two averages, two answersRow-level average
RegionHow it is computedResult

In the previous problem we asked Tableau to remove a dimension from the calculation. This one is the opposite: City isn't even present in the view, yet we still want Tableau to calculate at the City level before rolling the result up to Region. This is exactly what INCLUDE LOD is designed for.

3 · INCLUDE LOD

  • It computes a value using the specified dimensions, but includes the dimensions in the view.
  • It allows you to add additional dimensions to the computation while maintaining the original level of detail.
  • For example, to calculate the sales for each product category, even when other dimensions are included in the view.

{ INCLUDE [Dimension List] : AGGREGATE }

When to use it
  • When you need a percent of total within a higher level
  • When the calculation should respect the dimensions in the view while also including additional dimensions
Key takeaway

INCLUDE adds the specified dimensions to the calculation. It calculates at that finer level first, then aggregates further based on the dimensions in the view.

Build the INCLUDE view in Tableau
  1. Create the INCLUDE LOD. Name it Average Sales per City (Include) with the formula { INCLUDE [City] : SUM([Sales]) }.
  2. Build the view. Drag Region to the Rows shelf.
  3. Add the measure. Drag the new calculation to Columns, then right-click the pill, select Measure, and change it to Average.

Why results surprise you

Tableau's order of operations

The stage at which an LOD expression is evaluated determines whether it respects or ignores filters. Tableau applies filters and calculations in a specific order, from top to bottom.

FIXED

Evaluated after Context Filters but before Dimension Filters. Regular dimension filters therefore do not affect a FIXED calculation unless they are added to Context.

INCLUDE and EXCLUDE

Evaluated after Dimension Filters, so they automatically respect the dimension filters applied to the view.

What to carry forward

1

Granularity is the level of detail your data sits at, and in Tableau it is decided by what you place in the view. More dimensions on the view means more granular marks and less aggregation.

2

LOD expressions let a calculation run at a level of detail different from the view — which is how a state row can display a regional total, or a region bar can carry a per-city average.

3

FIXED locks the level, EXCLUDE zooms out one level, INCLUDE peeks inside a finer level and rolls the answer back up.

4

When an LOD result looks wrong, check the order of operations before the formula. Filters are the usual explanation.
