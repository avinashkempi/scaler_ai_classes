Are the three tiers equally represented?

Operations suspects that most stores sit in the Moderate tier. A quick count of stores per tier shows that the tiers are not equally represented. This is called class imbalance, and we will deal with it later.

Imbalance matters because it can make a poor model look good. A “lazy” rule that predicts the biggest tier for every store is right exactly as often as that tier is common.

Why logistic regression is not an ideal fit

A natural first idea is Logistic Regression. It runs into two problems on this data.

  • It draws straight boundaries. To handle overlapping, non-linear tiers we would need polynomial features to bend the boundary, and finding the right polynomial degree takes a lot of tuning.
  • It is a two-class model. To handle three tiers we would use One-vs-Rest, which trains one model per tier.

Now imagine Orbit Express later has 50 tiers instead of 3. That means 50 separate models, which is expensive and slow.

Is there a simpler idea? There is, and you already use it in everyday life.

Ask your neighbours

Imagine a new dark store is about to open in a locality. You have no forecast, but you do know the 5 most similar stores already running nearby, and 4 of them are High traffic. Your best guess: the new store will also be High traffic.

That is the entire idea behind kNN (k-Nearest Neighbours).

To classify a new point, find the k points closest to it and let them vote.

kNN needs no straight lines and no polynomial features, and it handles 3 tiers or 50 tiers in exactly the same way.

How kNN works

For every new point xq, kNN follows four steps:

  1. Distance: measure how far xq is from every training point.
  2. Sort: order the training points from nearest to farthest.
  3. Select: keep the first k points (k is a number we choose).
  4. Vote: the class that appears most among those k points is the prediction.

How do we measure “close”?

With two features, the straight-line (Euclidean) distance between points (a1, a2) and (b1, b2) comes from the right triangle formed by the gap in each feature.

d = √(a1 − b1)² + (a2 − b2)²

With 7 features, we simply add 7 squared differences under the square root.

The steps by hand on a toy example

To see every step, shrink the problem to 2 features (f1, f2) and 6 known stores. A new store xq sits at (2, 4). Work through the four steps below. You can also drag the star to see how the neighbourhood changes.

At the starting position (2, 4) with k = 3, the three nearest stores are S5 (Class 2, distance 1), S6 (Class 2, distance 2) and S1 (Class 1, distance √5 ≈ 2.24). Class 2 collects two of the three votes, so the new store is predicted to be Class 2 (Moderate).

Choosing k, and what to do about ties

k is a number you choose, and different values of k can give different answers. Operations has a rule of thumb: “Always pick an odd k, then there can never be a tie.” Is that true when there are three tiers? Test it on the toy example.

At the starting position (2, 4), k = 4 produces a tie: 2 votes for Class 1 and 2 votes for Class 2. That is the classic even-k problem. But k = 5 is odd, and it still produces a tie between Class 1 and Class 2, because the five votes split 2, 2 and 1.

An odd k avoids ties for two classes. With three or more classes, ties can still happen.

What do we do about a tie?

Common tie-breakers include:

  • Pick randomly among the tied classes.
  • Pick the class of the nearest neighbour among the tied ones.
  • Reduce k by one and vote again.

The from-scratch function we build later makes its own tie-breaking choice, so watch for it. The tie lab above lets you compare what each rule decides.

Class imbalance means the majority tier has more voters in every neighbourhood. SMOTE creates new synthetic stores for the smaller tiers by mixing existing ones, until all tiers are equally sized.

Where kNN struggles

kNN quietly assumes that the neighbourhood of a point is homogeneous: the neighbours look like the query. It works well when that is true. It struggles when:

  • there is noise or outliers: a few odd stores near the query can flip the vote;
  • features are not scaled: one feature dominates the distance;
  • the data is very large: for every new store, we measure the distance to every stored store.

Key takeaways

  1. kNN classifies a new point by a majority vote among its k nearest neighbours.
  2. The steps are: measure distance, sort, select k, vote.
  3. Euclidean distance is the straight-line distance, computed from the gap in every feature.
  4. Ties can happen even with an odd k when there are 3 or more classes, so we need a tie-breaking rule.
  5. Unlike Logistic Regression, kNN handles multi-class and non-linear data without polynomial features or one model per class.
  6. Data preparation matters: split, scale and balance, in that order, learning from the train set only.
  7. The test set is opened only once, at the very end.
  8. kNN assumes a homogeneous neighbourhood and is hurt by noise and unscaled features.
  9. Predictions are slow because every new point is compared with all stored points.
