§ 1

Brains, Tools & Chaining

⏱ 12 min

Quick recap, then two genuinely new ideas: which brain gets plugged in, and what it actually means for an agent to use more than one tool in a row.

🎙 Instructor Says

"Class 13 introduced the AI Agent node as a first look — concept only. Class 14 built one, wired to two directory connectors inside Claude. This class is different in one specific way: the brain gets connected by hand, by API key, with a deliberate choice about what it's allowed to reach for. That's the difference between using someone else's finished assistant and actually building the agent from its parts."

The Brain

The actual language model doing the reasoning — attached to the Agent node by an API key, not built in. The build runs on Groq, the fast-inference API. Swap the key and model name later, and the rest of the build doesn't change — that's the whole point of the Agent/Model split.

Tool Chaining

An agent calling more than one tool in a single run, using what one tool returned to decide what to do next — not a fixed sequence written in advance. Search first, then write, only because the brain decided that order made sense for this task.

🕵️
Hiring A Researcher, Not Buying A Search Engine

A search engine gives you links back. What gets built here is closer to hiring a junior researcher: give them a mind (the brain), a search subscription and a stack of blank documents (the tools), and a notepad (memory) — then hand them a topic and let them decide, on their own, what to look up first and when they've got enough to write something up.

Beginner Note — getting a free brain: Groq's free tier at console.groq.com is rate-limited, not a dollar credit, so nothing expires — sign up with email, Google, or GitHub, no card, and an API key is ready in under two minutes. The model used throughout is GPT-OSS 20B — Groq's cheapest, fastest option, plenty capable for research-and-summarize work, and comfortably inside the free tier's limits for a whole classroom. Model names shift fast in this industry; if that exact name isn't listed, whichever is the current cheapest/fastest Groq model works the same way.
Concept preview — sub-workflow as a tool: n8n lets an entire separate workflow be wired in as a single callable tool for an agent — handy for reusing a complex routine across several builds without redrawing it each time. That's a "what's next" idea rather than something built here — keep it in mind once this shape feels familiar.

Quiz 1 · In this build, what's the actual difference between "the Chat Model" attached to the AI Agent node, and "a Tool" attached to it?

AThey're two names for the exact same connection
BThe Chat Model is what reasons and decides what to do; a Tool is a capability it can call to actually act on the world
CA Tool is required for the Agent to run at all; the Chat Model is optional
DOnly one Tool can ever be attached to a single Agent node
Why B? The Model port is the brain — it's what thinks, plans, and decides which tool (if any) a step needs. The Tool port is the hands — each attached tool is one specific capability (search the web, write a doc, do math) the brain can choose to invoke. Neither is optional and neither is a stand-in for the other: no Model means nothing can reason at all; no Tools means the brain can only talk, never act.
§ 2

Build 1 — n8n's Smallest Research Agent

⏱ 18 min

Smallest thing that genuinely works: a trigger, a brain, one tool. That runs before anything else gets added.

Two Free Accounts

Two signups, a few minutes total, no card either way. Groq (the brain) at console.groq.com — sign up with email, Google, or GitHub, land straight on a dashboard with a free, rate-limited tier already active, then open API Keys → Create API Key and copy it. SerpApi (the search tool) at serpapi.com — free signup, roughly 100 searches a month on the free plan, plenty for a session, with the Private API Key sitting right on the dashboard.

Beginner Note — real cost check: GPT-OSS 20B on Groq's free tier costs nothing to run — it's metered in requests-per-minute, not dollars. A room of 40 people each running this two or three times stays well inside the limit.

The Build

Starting from the Class 14 workflow's existing Chat Trigger and AI Agent node, the Agent's Chat Model connector gets a Groq Chat Model node — new credential, Groq API key pasted in, model set to openai/gpt-oss-20b (or whichever is the current cheapest/fastest Groq model). The Agent's System Message becomes: You are Groundwire's research assistant. When asked to search a topic, search for current, real information and summarise it clearly with sources. Then the Agent's Tool connector gets a SerpApi node, its own new credential holding the SerpApi key.

One detail matters more than it looks: on the SerpApi tool node, Search Query (q) is set to "Defined automatically by the model," and under Additional Fields a jsonRestrictor field is added with something like organic_results[1:2]. Without it, SerpApi's full unfiltered JSON response goes straight to the LLM and can blow past its token limit, causing errors — limiting the response at the API level avoids that entirely. A quick test message in the chat (Search for "Herbivorous" and tell me what you find.) confirms the wiring works.

What to watch for (the ReAct loop, running for real): the Agent names the tool it's about to call before calling it (Think), the SerpApi node lights up as it runs (Act), and the reply that comes back references specific results rather than a vague, generic summary (Observe feeding the final answer). This is Class 13's loop, on a real topic, for the first time.

Build 2 — Give It Hands & A Notebook

⏱ 16 min

One new idea, in two small pieces: somewhere to actually write the output, and somewhere to remember what's already been found.

Google Docs — Downstream, Not A Tool

A plain Google Docs node connects to the AI Agent node's own main output — the same kind of connection Chat Trigger → AI Agent uses, not the Tool/Memory ports underneath. It points at one blank doc created ahead of time (operation Update Document, the doc's URL pasted in), and its Text field maps to the Agent's finished reply via {{ $('AI Agent').item.json.output }}. SerpApi stays the Agent's only Tool; Google Docs now runs automatically, once, right after the Agent finishes replying — not something the Agent decides to invoke.

Why not just add it as a second Tool — the actual bug this avoids: when a big-output node like Google Docs sits on the Agent's Tool port, the model has to reproduce the entire document body as an escaped string argument inside its own tool-call JSON — regenerating the whole brief a second time, inside a function call, instead of just handing off text it already wrote. That's exactly where long research briefs blow past what a fast, smaller model like Groq's oss-20b can reliably produce — the call comes back truncated or malformed, and nothing lands in the doc. This is a well-documented n8n community pain point, not a one-off mistake. Wiring Docs downstream instead means the already-finished text just flows through as ordinary node data — no regeneration, no JSON-escaping, and no token ceiling on the write step at all.

Short-Term Memory

A Simple Memory node on the Agent's Memory connector, no configuration beyond the default — exactly the short-term memory node from Class 14's memory section, a scratchpad for this run, gone once the session ends.

Testing It

A topic prompt in the test chat produces a reply and, automatically, a Google Doc holding it. A follow-up in the same chat — "add a one-line caveat about the biggest adoption blocker, and give me the complete updated brief" — without repeating the topic, still resolves correctly and re-triggers Google Docs with the updated version.

Advanced Note — that follow-up only worked because of memory: without Simple Memory, "add a one-line caveat" is a sentence fragment with no topic attached — the Agent has no idea what to caveat, let alone what the "complete updated brief" should contain. With it, the scratchpad still holds the topic and what it already found, so the follow-up resolves correctly and the Docs step downstream has a full, fresh brief to save. This is short-term memory earning its keep, not just a theory slide.
Beginner Note — not every action needs to be a Tool: SerpApi sits on the Tool port because the Agent genuinely has to decide, mid-run, whether and when to search. Saving the finished brief doesn't need that kind of judgment call — it happens every time, after the Agent is done. Treating it as a deterministic step instead of a Tool is what makes it reliable.

Quiz 2 · SerpApi is wired to the Agent's Tool port; Google Docs is wired to the Agent's main output instead. Why the different wiring for the two?

An8n only allows one Tool per Agent node, so Docs had nowhere else to go
BSerpApi needs the Agent to actively decide, mid-run, whether and when to call it — but writing the finished brief is a fixed last step, and making the model regenerate the whole document inside a tool-call argument is exactly what caused the token-limit failures
CGoogle Docs isn't compatible with AI Agent workflows in n8n at all
DWiring position is arbitrary — both ports behave identically either way
Why B? A Tool is for something the model needs to reason about calling — SerpApi, because search is only useful if and when the Agent decides it needs fresh information. Google Docs doesn't need that judgment call; it always runs once the Agent is done. Putting it on the Tool port anyway forces the model to reproduce the entire finished document as a JSON argument inside its own tool call — regenerating text it already wrote, which is exactly where longer briefs exceeded what the model could reliably output. Downstream wiring passes the same text through as plain node data instead — same result, without the regeneration step that was breaking it.
§ 4

Build 3 — Make It Reliable

⏱ 14 min

No new node types — just settings that decide what happens when something actually goes wrong, plus deliberately breaking it to check.

Max Iterations & Retry On Fail

Max Iterations, set to 8 on the AI Agent node's Options, caps how many tool calls a single run can make before the Agent is forced to stop and return whatever it has — the same safeguard from Class 11's Build 3, now protecting a build that can genuinely loop on ambiguous research tasks. Retry On Fail, toggled on with Max Tries at 3 on both external-service nodes (SerpApi and Google Docs), means a single dropped connection or slow API response no longer kills the whole run.

Breaking It On Purpose

Two deliberate test prompts prove the settings actually work. An empty-results test — researching a startup that doesn't exist — should have the agent report it couldn't find credible information rather than invent numbers to fill the gap. A too-broad test — "research artificial intelligence" — is vague enough to trigger many searches; Max Iterations should cut it off with a partial, honest answer rather than spiralling.

Concept only — sub-workflow as a tool: a whole separate n8n workflow (say, a 10-step fact-checking routine) can be wired in as one callable tool via the Execute Workflow Tool node type — the Agent calls it exactly like it calls SerpApi. Not built here — it's a take-home extension.

Quiz 3 · Max Iterations is set to 8 and someone asks a genuinely impossible research question. What should actually happen?

AThe agent keeps trying indefinitely until the tab is closed
BThe whole n8n workflow crashes and needs to be rebuilt
CAfter 8 tool calls, the agent stops and returns whatever it has instead of looping indefinitely
DMax Iterations only limits chat length, not how many tools it calls
Why C? Max Iterations is a hard ceiling on tool calls within one run, not a chat-length limit and not a crash trigger. Hitting it forces a graceful stop — the agent reports back with whatever it's got, honestly incomplete, rather than looping forever chasing an answer that may not exist.
§ 5

Relevance AI — Same Shape, Drag-and-Drop

⏱ 14 min

Same trigger-brain-tool shape as Builds 1 and 2 — but the whole agent lives inside one object instead of separate wired nodes.

Beginner Note — this is genuinely free: Relevance AI's Free plan gives 200 Actions a month plus 1,000 one-time Vendor Credits, no credit card to sign up. That easily covers a single agent and a handful of test runs.

Building It

A blank agent at relevanceai.com (Create Agent, not a template), the exact same system prompt from Build 1 pasted into its Goals/Prompt Template, the built-in Google Search tool added from the Tools panel, then a run through Test Agent with the same prompt used in Build 1. The vocabulary differs — Relevance AI calls a Tool an "Action" — but the shape underneath (a brain, one search capability, a topic) is identical to what n8n just built.

Interface details and free-tier limits verified August 2026: Relevance AI is a funded, fast-moving product — exact menu labels can shift between when this is written and when it's taught. The underlying shape (agent, goal/prompt, one search action) is the stable part.
§ 6

Stack AI — A Third Canvas, Same Shape

⏱ 8 min

The third comparison point — lighter touch than n8n's build, but built on the exact same three ideas.

Beginner Note — this is genuinely free too: Stack AI's Free plan covers 500 runs a month, 2 projects, 1 seat, no card. The next tier up is a large jump straight to Enterprise, so Free is the honest comparison point for a solo builder.

The Shape, Not A Full Rebuild

Stack AI gets a guided walkthrough rather than a full parity build: an LLM node holding the brain and the same system prompt, a Web Search node as the one tool, wired trigger-to-brain-to-tool exactly like the other two canvases, then run on the same topic. The point isn't depth here — it's recognising the identical three-part shape (brain, tool, topic) under a third, differently-labelled interface.

Take-Home — Build It Yourself

⏱ 6 min

Three ways to practice what this post-read actually built. Pick any one, or do all three.

01

Swap The Topic

▸
MISSION

Pick a real topic you actually care about, rerun the n8n build (or Relevance AI) on it, using your own signups.

WATCH FOR

Does it name real, checkable sources? What happens if the topic is more obscure than flood-warning tech — does it admit uncertainty, or start guessing?

02

Finish Relevance AI Or Stack AI

▸
MISSION

Go back into whichever of the two lighter-touch builders wasn't fully finished, and get it running end-to-end solo, including a second action/tool.

WATCH FOR

Where the vocabulary trips things up — what n8n calls a Tool, Relevance AI calls an Action, Stack AI calls a node.

03

Wire In A Sub-Workflow As A Tool

▸
MISSION

Build a small second n8n workflow (even 2-3 nodes) that does one useful thing, then use an Execute Workflow Tool node to wire it into the Build 3 agent as a callable tool.

WATCH FOR

Whether the Agent decides to call the sub-workflow on its own, the same way it decides whether and when to reach for SerpApi.

Wrap-Up — Key Takeaways

⏱ 6 min

One brain, real tools, three canvases — and a research agent that can actually show its work.

Six Things You Can Now Do

Brain vs. toolsExplain the difference between the Model port and the Tool port on an Agent node

Key Takeaways

A brain is not a tool, and a tool is not a brain. The Model port reasons; the Tool port acts. Mixing those up is the fastest way to misunderstand why an agent did what it did.

Chaining means the agent decides the order. Search-then-write wasn't wired in advance — it was reasoned, live, from what the agent had already observed.

Reliability is settings, not new nodes. Max Iterations and Retry On Fail turn a demo into something worth trusting unattended.

Free doesn't mean unlimited. Groq, SerpApi, Relevance AI, and Stack AI are all genuinely free — but every one of them meters usage somewhere, and a shared classroom account finds that ceiling faster than a solo builder does.

No single builder wins on everything. n8n gives flexibility and any node/API as a tool; Relevance AI and Stack AI trade that for speed — the right pick depends on which requirement isn't up for compromise.

The research was real. Every source the agent cited, every doc it produced, exists on the actual internet — that's what makes it worth trusting, not just convenient.
