Foundations

What is Data Visualization?

It's the graphical representation of information and data. By turning numbers into charts, graphs, and maps, visualization gives you an accessible way to spot trends, outliers, and patterns — because humans are simply better at deriving knowledge from pictures than from tables of numbers.

why-visualization-matters.twbx

Hover a bar to see how a shopkeeper drowning in bills and receipts turns four months of raw sales records into a clear, actionable read: which product sells best, and where demand is slipping.

① Raw Data

Thousands of bills and numbers — hard to understand, hard to find a trend in.

② Visualization

The same data, organized into charts and graphs — clear and scannable.

③ Insight → Action

Patterns become decisions: double down on what's working, fix what isn't.

Why Choose Tableau?

Tableau is one of the most in-demand business intelligence tools precisely because it trades the flexibility of code for drag-and-drop speed — but that trade comes with real limitations worth knowing up front.

✓ Quick & Interactive

Drag-and-drop visualization — no coding required.

✓ High Performance

Handles large datasets while staying responsive.

✓ Mobile Friendly

Dashboards adapt to smaller screens automatically.

✓ AI-Assisted

Natural-language queries via Tableau Agent / Tableau AI.

✕ Requires Clean Data

Struggles with genuinely messy source data.

✕ Limited Data Modeling

Lacks robust data-dictionary tooling.

✕ No Version Control

Collaboration features are limited.

✕ Visualization-Focused

Data transformation power is limited (Prep helps, but it's a separate tool).

Data Connections

Live vs. Extract Connections

Before building a single chart, Tableau needs to know how to reach your data — in real time, or through a saved copy. This choice directly affects dashboard performance and data freshness.

Data Connections

Connecting to Data & Cleaning It

Most analysts start with flat files. Tableau is highly optimized for the Microsoft ecosystem and standard exports:

  • Excel (.xlsx, .xls) — best for structured, multi-sheet data. You can drag individual sheets onto the canvas and join or union them if they share common headers.
  • CSV / Text (.csv, .txt) — the "universal language" of data, often faster to load than Excel since there's no formatting metadata to parse.
💡
Pro tip: If your Excel file has headers starting on row 3, or empty "intro" rows for visual spacing, use the Data Interpreter (left sidebar, after connecting) to auto-clean the sheet.

The Data Interpreter

Spreadsheets are built for humans to read — titles, stacked headers, notes, deliberate blank rows for whitespace, multiple tabs. All of that readability makes a sheet hard for Tableau to parse directly. The Data Interpreter detects titles, notes, footers, and empty cells, and bypasses them to find the actual fields and values underneath.

Availability Data Interpreter works with Microsoft Excel, Text (.csv), PDF, and Google Sheets. For Excel, the file must be in .xls or .xlsx format.

Data Source Filters

A Data Source Filter restricts which rows get loaded into Tableau in the first place — reducing load, improving performance, and keeping the workbook focused only on relevant data. It applies on both live and extract connections.

Example from the World Bank CO₂ dataset used in this module: to analyze only meaningful emitters, a filter of CO2 (kt) ≥ 2,000 loads only the rows that matter for that analysis, instead of the entire table.

Data Source Filter ≈ WHERE clause in SQL
Shaping Data

Pivoting: Wide → Tall

Tableau prefers data to be "tall" rather than "wide." In the World Bank CO₂ dataset, each year from 1960–2011 is stored as its own column — 56 fields, 248 rows. That's easy for a human to scan in Excel, but Tableau would need 56 separate measures dragged onto a shelf just to plot a trend line.

Pivoting reshapes those year columns into two fields — Year and CO2 (kt) — so Tableau can treat Year as a single, ordinary dimension.

World_Bank_CO2.xlsx — CO2 (kt) RAW DATA · 56 fields, 248 rows

Note: pivoting rows-to-columns is not available in Tableau Public; only columns-to-rows (shown above) is supported there.

The Basics

Dimensions vs. Measures

This is the single most important distinction in Tableau. Everything about how a chart is built flows from it.

Dimension

An independent variable — qualitative, categorical information. This is what you "slice and dice" by: which product, which country, which date. Discrete dimensions draw headers, shown in blue.

Measure

A dependent variable — numeric, quantitative information. This is what you're measuring: sales, profit, quantity. Continuous measures draw axes, shown in green.

SELECT Region, SUM(Sales) FROM Orders GROUP BY Region;
  → Region = Dimension  ·  SUM(Sales) = Measure

Rule of thumb: the measure is the number; the dimension is what you slice that number by.

The Basics

Discrete (Blue) vs. Continuous (Green)

Discrete and continuous are mathematical terms describing how a field's values behave — and Tableau colors fields accordingly, regardless of whether the field is a dimension or a measure.

Discrete

"Individually separate and distinct." Countable, sortable, with gaps between values. Example: cars sold — 10 in 2020, 15 in 2021; there's no such thing as 12.5 cars.

Continuous

"Forming an unbroken whole." Measurable, with infinite possible values in a range. Example: a person's weight — 81.5 kg, 82.47 kg, any value is possible.

Knowledge Check · 1
In Tableau, what is the primary visual difference between a Discrete (Blue) field and a Continuous (Green) field when placed on the Rows or Columns shelf?
Discrete (blue) fields partition data into distinct categories and display a header for each value. Continuous (green) fields represent a range of values and generate an axis — the distinction that tells you whether Tableau is treating your data as categorical or quantitative in that view.

    Aggregation Basics

    The underlying data never changes — but how you summarize it depends entirely on the business question. Tableau automatically aggregates measures based on the dimensions in your view. Try each function below against the same small order table.

    Order IDCustomerSalesDiscount %
    1001Alice$25010%
    1002Bob$40020%
    1003Alice$35030%
    1004Charlie——
    • SUM — adds every value together (e.g., Total Sales).
    • AVG — finds the mean value (e.g., average discount given).
    • COUNT — counts every row of data (e.g., number of orders).
    • COUNTD (Count Distinct) — counts only unique items, ignoring repeats (e.g., unique customers).
    SUM aggregation ≈ SUM(column_name) in SQL
    Knowledge Check · 4
    You want to find out how many unique customers made a purchase, ignoring repeat customers. Which aggregation function should you use?
    COUNTD counts only unique values in a field. For customer purchases, that means each customer is counted once no matter how many orders they placed — an accurate read on unique customers rather than transactions.
    Core Visual Analytics · Extending the Superstore analysis

    Going Further: Scatter Plots & Heat Maps

    Two more views built from the same Global Superstore data, for two different questions.

    Do higher Sales always lead to higher Profit? (Scatter Plot)

    Scenario: Management wants to see the relationship between how much is sold and how much is actually earned, and flag products with high sales but very low — or negative — profit.

    1. Drag Sales to Columns and Profit to Rows. At first you'll see just one dot — Tableau is summing everything into a single point.
    2. Drag Product ID onto Detail in the Marks card — the single dot "explodes" into one mark per product.
    3. Drag Category onto Color to see which categories run more or less profitable.

    Illustrative recreation of the pattern: most products cluster near modest sales and profit, with a handful of high-sales outliers and a few products that lose money despite reasonable sales — exactly the kind of outlier a scatter plot is built to surface.

    Where are shipping costs highest? (Heat Map)

    Scenario: The Logistics Manager wants to see which Ship Modes are costing the most, across which Markets, to spot overspending on premium shipping.

    1. Drag Market to Columns and Ship Mode to Rows.
    2. Drag Shipping Cost onto Color, and Quantity onto Size.
    3. Set the Mark Type to Square so each intersection reads as a distinct cell.

    Illustrative recreation: Standard Class carries the largest volumes across every market, and APAC stands out with the highest shipping cost concentration — the pattern a grid of color and size is built to reveal at a glance.

    Wrap-up

    Key Takeaways

    Blue = DiscreteHeaders, categories, sortable
    Green = ContinuousAxes, ranges, measurable
    Rows + ColumnsStructure the view
    Marks cardEncodes color, size, detail
    • Data visualization turns raw, hard-to-parse records into patterns a person can act on.
    • Every Tableau field is either a dimension (what you slice by) or a measure (what you quantify) — and separately, discrete (blue) or continuous (green).
    • Live connections stay current but query slower; extracts are fast and portable but need refreshing.
    • Wide data needs pivoting into tall data before Tableau can treat time as a single dimension.
    • The right chart follows from the question: comparison → bar, trend → line, parts-of-a-whole → pie, correlation → scatter, two-dimensional pattern → heat map.
    • The same numbers can mean different things depending on the aggregation applied — SUM, AVG, COUNT, or COUNTD.
