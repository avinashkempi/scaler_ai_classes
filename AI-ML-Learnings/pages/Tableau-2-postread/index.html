Filters & Calculations

Building a chart is the easy part. The real skill is controlling exactly which rows reach that chart, and shaping the numbers once they arrive. This module covers four tools that do that work: Sets, Parameters, Filters, and Calculated Fields — plus one subtle rule that quietly breaks views when it's ignored: the order filters run in.

Dimension Measure
01 · Sets

Carving a subset out of a bigger list

A Set is a custom field that keeps a subset of data based on a rule. Every member is either In the set or Out of it — nothing in between.

Set, in one line: if you know SQL, a Set is the visual equivalent of a subquery or an IN operator. It doesn't move or copy data — it just labels each row as In or Out.
  • In — members that satisfy the set's condition
  • Out — everyone else
Business problem

Who are our most profitable customers?

The marketing team is planning a "Thank You" campaign for the 10 most profitable customers, and needs to know exactly who they are and how much profit each one contributed.

🗄 SQL — subquery
WITH Top_Customers AS (
  SELECT Customer_Name, SUM(Profit)
  FROM Orders
  GROUP BY 1
  ORDER BY 2 DESC
  LIMIT 10
)
SELECT * FROM Top_Customers;

02 · Parameters

Letting the viewer change the rule, not just the view

A Parameter is a workbook variable — a user-supplied value that isn't attached to any row in the dataset — that can replace a constant inside a filter, calculation, or reference line.

Business problem

"Top 10" isn't one-size-fits-all

After seeing the VIP list, the marketing manager wants flexibility: Top 5 "Super-VIPs" for one campaign, Top 20 or Top 50 for a bigger mailing list — without anyone re-editing the Set by hand every time.

💡
Sets vs. Parameters: a Set decides which rows are In or Out. A Parameter supplies the number (or text, or date) that a Set, filter, or calculation uses to make that decision. They're built to work together.
03 · Filters

Five filters, five different jobs

A filter limits which records participate in the analysis without touching the underlying dataset. Tableau gives you five filter types, each applied at a different stage and for a different reason.

  • Pulls a smaller subset of data from the original source and stores a local copy in Tableau's repository.
  • Reduces the number of live queries Tableau has to run.
  • Can be narrowed further with measure or dimension filters applied to the extract itself.
  • Tableau Public always works from an extract — it doesn't expose the Live/Extract choice at all. Tableau Desktop (paid) supports both.
  • Restricts sensitive data from viewers and reduces the volume fed into the workbook.
  • Applies directly to the source, before any worksheet sees the data.
  • Not linked to the extract filter — switch back to a live connection and the data source filter still holds.
Business problem

Only the Europe market matters

The manager only cares about the Europe market. Every other region needs to disappear from the entire workbook, so the file stays clean and runs faster.

  • Open the Data Source tab and click Add in the Filters section.
  • Choose the field Market.
  • Check the box for EU and click OK — the preview grid now shows European orders only.
⚙️
Why here instead of the Filters shelf? Performance — the query itself gets smaller and faster — and focus, since you don't have to re-apply the same filter on every sheet.
Quiz 1

Which filter type is primarily used to restrict sensitive information from viewers and reduce the volume of data fed into Tableau by applying the filter directly to the source data?

A Data Source Filter limits the data available to the workbook before it reaches any worksheet. It's commonly used for security and to improve performance by reducing how much data gets loaded into Tableau.
  • By default, every filter in a view runs independently — each one scans all rows, ignoring the others.
  • A Context Filter becomes the independent filter; every other filter becomes dependent, processing only what survives the context filter first.
  • Adds real value for scoped analysis, but if the context filter doesn't shrink the data much, the computation cost can climb fast.
Business problem

Top 10 products — but only within Technology

The goal is the Top 10 most profitable products, restricted to the Technology category. Tableau needs to be told: filter for Technology first, then find the Top 10 from that group.

Puzzle — order changes the answer

Two perfectly reasonable filters — Top 5 products and Category = Furniture — stacked on the same view. Toggle the order below and watch the bar count change with no error, no warning.

ProductProfitValue

Why it happens: without context, Tableau finds the global Top 5 products across every category, then throws out anything that isn't Furniture — which can leave two or three bars instead of five. Adding Category to context forces Tableau to filter to Furniture first, then compute the Top 5 from that smaller, already-correct group.

  • Right-click the Category pill on the Filters shelf.
  • Select Add to Context — the pill turns gray, marking it as the "boss" filter.
  • Every other filter on the shelf now runs against the reduced, Furniture-only data.
Quiz 2

If you want to create a "dependent" filter that only processes the data that has already passed through a primary, "independent" filter, which type of filter should you use?

A Context Filter creates a subset of data that other filters then operate on. It's used when one filter needs to depend on another — improving performance and guaranteeing a specific execution order.
  • Non-aggregated filters — the fields used are the blue, discrete pills.
  • Four selection modes: General, Wildcard, Condition, and Top/Bottom.
  • Condition and Top/Bottom modes can run off a custom formula against a measure.
Business problem

North Asia, minus Office Supplies

The North Asia regional manager wants profitability by sub-category, but only for Furniture and Technology — Office Supplies belongs to a different team.

🗄 SQL equivalent
SELECT Sub_Category, SUM(Sales)
FROM Global_Superstore
WHERE Region = 'North Asia'   -- dimension filter 1
  AND Category IN ('Furniture', 'Technology') -- dimension filter 2
GROUP BY 1;
  • Sub-Category on Rows, Sales on Columns.
  • Drag Region (blue pill) to Filters, select North Asia.
  • Drag Category (blue pill) to Filters, check Furniture and Technology, leave Office Supplies unchecked.
  • Applies to quantitative measure fields using an aggregate function — sum, average, median, standard deviation, and so on.
  • Aggregated filters always run after non-aggregated (dimension) filters, no matter what order they sit in on the Filters shelf.
  • Four selection modes: Range, At least, At most, and Special (null / non-null).
Business problem

Which sub-categories clear $500K in sales?

The sales director wants only the sub-categories whose total sales exceed a threshold, to focus inventory planning on high-volume products.

🗄 SQL equivalent — HAVING
SELECT Sub_Category, SUM(Sales)
FROM Global_Superstore
GROUP BY Sub_Category
HAVING SUM(Sales) > 500000;  -- measure filter

A Measure Filter is the visual equivalent of SQL's HAVING clause — it filters after the aggregation has already been computed.

04 · Order of Operations

Tableau always runs filters in the same sequence

Every one of the five filter types you just saw fires in a fixed order. Get a filter into the wrong stage and the numbers can be silently wrong — no error, no warning. Click each stage below.

1
Extract Filters
Shrink the data at the source, before Tableau even loads it.
2
Data Source Filters
Applied directly to the source connection — restricts sensitive data.
3
Context Filters
The "boss" filter — sets the scope every later filter has to respect.
4
Dimension Filters
Non-aggregated filters on discrete (blue) fields.
5
Measure Filters
Aggregated filters on continuous (green) fields — always after dimension filters.
6
Table Calculation Filters
Computed last, on whatever data survived every earlier stage.
Extract filters run before Tableau even loads the data — they shrink the dataset at the source, which is why they're the cheapest and fastest filters to apply.
⚠️
Adding a filter to Context forces it to execute earlier — this is the one move that changes a filter's place in the sequence above. Without it, a Top N filter and a category filter both sit at stage 4, and Tableau still has to pick an internal order between them, which is exactly what produced the Furniture puzzle earlier.
Quiz 3

According to the Tableau order of operations, which of the following is the correct sequence in which filters are executed?

Tableau applies Extract Filters first, then Data Source Filters, then Context Filters. Knowing this order helps you troubleshoot unexpected results and improve performance.
05 · Calculations

Building the metrics your data doesn't already have

Real business questions — profit margin, average order value, customer segments — rarely exist as ready-made columns. A Calculated Field creates a brand-new field in the data source, driven by a formula you control.

Fields

The dimensions or measures — columns — pulled from your data source.

Operators

Symbols that denote an operation: +, >, AND, and so on.

Functions

Built-in statements that transform the values or members in a field.

Literal expressions

Constant values used exactly as written — like "Profitable".

Calculated fields are useful for more than one thing: segmenting data, converting a field's type, aggregating values, filtering results, and computing ratios all lean on the same mechanism.

Operators

Arithmetic

+ - * / % ^

e.g. [Sales] - [Cost], [Profit] / [Sales]

Comparison

== != > < >= <=

e.g. [Sales] > 100000

Logical

AND OR NOT

e.g. [Profit] > 100 AND [Region] = 'EU'

Row-level vs. aggregate-level

Basic expressions come in two flavors, and the difference matters: one runs once per row, the other runs once per group in the view.

Business problem

How many days does each order actually take to ship?

Operations wants "Days to Ship" calculated for every single order — from the moment it's placed to the moment it leaves the warehouse.

🗄 SQL
SELECT *, DATEDIFF(day, Order_Date, Ship_Date) AS Days_to_Ship
FROM Orders
📊 Calculated field
Days to Ship
DATEDIFF('day', [Order Date], [Ship Date])

Because it references no aggregate function, this formula runs independently for every row in the underlying data — a true row-level calculation.

Business problem

What percentage of sales is actual profit?

The CFO wants a Profit Ratio that stays accurate no matter what level of detail is on the view — Country, Region, or Category.

🗄 SQL
SELECT Category, SUM(Profit) / SUM(Sales) AS Profit_Ratio
FROM Orders GROUP BY Category;
📊 Calculated field
Profit Ratio
SUM([Profit]) / SUM([Sales])

Wrapping the fields in SUM() tells Tableau this is an aggregate-level metric — it recalculates correctly as dimensions are added or removed from the view.

Ship ModeAvg. Days to ShipValue

Average "Days to Ship" by Ship Mode — an aggregate calculation summarized per category. Values approximate the source chart.

Quiz 4

What is the fundamental difference between a row-level calculation and an aggregate-level calculation in Tableau?

Row-level calculations evaluate each record independently, while aggregate calculations summarize data at the level of detail defined by the dimensions in the view. [Sales] * 0.1 is row-level; SUM([Sales]) is aggregate-level.
🤖 Tableau Agent — ask in plain language
Show me the Top 10 Products by Profit within the Technology category only. Sort them from highest to lowest profit.
I've created a bar chart to display the top 10 products by profit within the Technology category, sorted from highest to lowest profit.

Tableau Agent can build a view like this from a plain-language prompt — but the underlying mechanics are exactly what you just learned: filter to Technology, then compute the Top 10 from that scoped group.

06 · Functions

Nine families of built-in functions

Every calculated field leans on one or more of these categories. You won't need all of them on day one — but knowing the map makes it much faster to find the right tool later.

Perform computations on numerical field values — rounding, arithmetic, statistical operations.

Manipulate text data — splitting, trimming, searching, and reformatting strings.

Manipulate dates in the data source — differences, truncation, and part extraction (like DATEDIFF).

Convert a field from one data type to another — string to date, string to number, and so on.

Determine whether a condition is true or false — the backbone of IF/CASE-style calculations.

Summarize or change the granularity of data — SUM, AVG, COUNTD, and similar.

Build user filters or row-level security so published views show only what a given viewer should see. Not available in Tableau Public.

Compute on values already in the table — running totals, rank, percent of total.

Perform spatial analysis and combine spatial files with data from text files or spreadsheets.

Three ways to build a calculation:
  • Basic expressions — row-level or aggregate-level, covered in this module.
  • Level of Detail (LOD) expressions — compute at a more granular level (INCLUDE), a less granular level (EXCLUDE), or a fully independent level (FIXED). Covered next.
  • Table calculations — transform values only at the level of detail already in the view, like a running total over time. Covered in an upcoming module.
07 · Wrap-up

What carries into the next module

Every calculation built in this module matched the level of detail already in the view — Region on Rows produced numbers per region, straightforward. But what happens when a chart needs to show each region's share of a national total? Two different levels of detail, one view. That's the exact problem Level of Detail (LOD) expressions solve next.

Sets

A subset of data marked In or Out by a rule — Tableau's visual equivalent of a SQL subquery.

Parameters

A workbook variable that lets a viewer swap out a constant in a filter, calculation, or reference line.

Filter types

Extract, Data Source, Context, Dimension, Measure — each applied at a different stage for a different reason.

Order of filters

Extract → Data Source → Context → Dimension → Measure → Table Calculation. Adding a filter to Context forces it to run earlier.

Calculated fields

Built from functions, fields, operators, and literal expressions — new columns driven entirely by your logic.

Row vs. aggregate

Row-level calculations run per record; aggregate-level calculations summarize at the view's level of detail.
