Sheet · Overview

Why dashboards exist

A manager doesn't want twelve separate charts about how the business is doing this month — they want an answer. That gap between "here is some data" and "here is what's happening" is exactly what a dashboard is built to close.

The same idea shows up every time you drive. A car doesn't hand you five separate instruments to check one at a time — it puts speed, fuel, engine temperature, RPM, and navigation in a single field of view, so you know within a second whether anything needs attention. A business dashboard does the same job for people who don't have time to open a dozen separate reports.

The golden rule

A dashboard is not created to impress people. It is created to help people make decisions. If you can't answer the question it was built for within about ten seconds, it isn't working yet — no matter how it looks.

Sheet · Design Principles

Eight principles before you touch the canvas

Assembling objects on a dashboard is a mechanical skill. Deciding what belongs there, and where, is the design skill that decides whether the dashboard gets used. These eight principles separate the two.

People scan a dashboard in a Z-pattern or an F-pattern — top-left first, then across, then down. Put the single most important KPI or summary at the top-left, and let supporting detail follow below or to the right.

Lead with high-level numbers — total revenue, profit, order count — then a trend, then a detailed breakdown. Think: Summary → Trend → Detail.

Top row — KPI cards (Sales, Profit, Orders)
Middle row — monthly trend line
Bottom row — category breakdown / table

Every color should encode meaning. The same category should always get the same color, and a rainbow palette is rarely necessary. A neutral base color, with one color reserved to flag what needs attention — red for below-target — usually communicates more than twelve colors.

A dashboard with ten charts is harder to read than one with four well-chosen ones. Ask whether each chart answers a distinct question — if two charts answer the same one, consolidate them.

Empty space between elements isn't wasted — it's what lets the eye separate one section from the next. Charts placed edge-to-edge feel overwhelming even when each one is well made.

Charts, titles, and filters should sit on a shared grid. Misaligned elements look unprofessional and make a dashboard harder to scan, even when the analysis underneath is solid.

If a KPI card already shows Total Sales, labeling that same number again on a bar chart doesn't add insight — it adds clutter.

It's tempting to add a filter for every dimension, but most people will never use more than two or three. Add a filter because a real analytical question needs it — not because the field happens to exist.

Sheet · The Dashboard Workspace

Inside the dashboard workspace

A dashboard is a collection of worksheets, arranged so you can compare several views at once — instead of clicking between separate worksheet tabs to see the same reports you check every day.

Worksheets and dashboards stay connected in one direction: change a chart type, add a field, or edit a calculation on a worksheet, and every dashboard containing it updates automatically. The reverse usually isn't true — resizing the dashboard, moving containers, or adding objects doesn't touch the worksheet itself. The one exception is a dashboard-level filter or action: apply one, and the target worksheet's displayed data changes within that dashboard's context.

Sheet · Actions & Interactivity

Actions: what makes a dashboard interactive

Static charts sitting side by side are still just separate charts. Actions are what turn a set of sheets into one connected dashboard — clicking, hovering, or selecting in one view changes what appears in another.

▽Filter action

Uses the data selected in one view to filter another, guiding the viewer's analysis.

✺Highlight action

Calls attention to marks of interest by coloring them and dimming everything else.

↗Go to URL action

Creates a hyperlink out to an external resource — a web page, a file, or another worksheet.

⇥Go to sheet action

Simplifies navigation between worksheets, dashboards, or stories.

Parameter & set actions

Two further actions go one step deeper. A Change Parameter action lets a click update a parameter's value directly from a mark on the view — no dropdown required. A Change Set Values action does the same for set membership: clicking a mark adds or removes it from a set.

Sheet · Story

Stories: a sequence, not a snapshot

A single dashboard is a snapshot. A story is a sequence — a way of walking someone through how one finding led to the next, the way an analyst actually investigates a problem. Each story point can hold a different dashboard or sheet, or the same visualization revisited at different stages with different filters and annotations.

Sheet · Performance

Keeping dashboards fast

Every worksheet, filter, calculation, and record a dashboard has to process adds to how long it takes to load. None of the fixes below are exotic — they're mostly about giving Tableau less unnecessary work to do.

  • Minimize the number of fields
  • Minimize the number of records
  • Optimize extracts
  • Practice guided analytics rather than showing everything at once
  • Remove unneeded dimensions
  • Let people drill in, rather than rendering every mark up front
  • Reduce the number of filters in use
  • Use an include filter instead of exclude
  • Use a continuous date filter
  • Prefer Boolean or numeric filters
  • Use parameters and action filters instead of quick filters where you can
  • Perform calculations in the database where possible
  • Reduce the number of nested calculations
  • Reduce the granularity of LOD or table calculations — more granular means slower
  • Use MIN or MAX instead of AVG where it fits
  • Prefer Boolean or numeric calculations over string calculations
  • Blend on low-granularity dimensions
  • Minimize joined tables and assume referential integrity where valid
  • Remove custom SQL where a native connection will do
  • Reduce dashboard scope to what's actually used
  • Delete or consolidate unused worksheets and data sources
Sheet · Box & Whisker Plot

Reading a box-and-whiskers plot

A box plot is a compact X-ray of a distribution — five statistics that summarize a whole set of values for a measure, so you can compare groups side by side without plotting every individual point.

Reading one, in four questions

Where's the median?

Centered → roughly symmetric. Near Q1 → right-skewed. Near Q3 → left-skewed.

How tall is the box?

Tall → high variability in the middle 50%. Short → tightly clustered values.

How long are the whiskers?

Long whiskers → spread-out values beyond the middle 50%. One whisker much longer than the other → skew.

Are there outlier dots?

Points beyond 1.5× the IQR. Worth investigating — data errors, exceptional cases, or real business anomalies.

Applied to the workbook: comparing average discount by segment across regions showed the West region's median sitting near zero across all three segments — at least half its transactions carried no discount at all — while Central and East had taller boxes, meaning more variable discounting, and some regions still showed individual outlier transactions with unusually high discounts worth a closer look before drawing a conclusion.

Use a box plot when…
  • Comparing a measure's distribution across several categories
  • You want to spot outliers quickly
  • You need median, spread, and skew in one compact visual
Skip it when…
  • The audience isn't familiar with quartiles or IQR — a histogram or bar chart of averages may land better
  • There are very few data points per category
  • The question is about totals, not distribution — use a bar chart
Sheet · Bullet Chart

Bullet charts: performance against a target

A bullet graph is a bar with extra encoding layered on — a reference line and background bands — to show progress against a goal or performance compared with another measure.

Business problem: compare 2016 and 2017 sales for each product sub-category. Two calculated fields make this possible:

IF YEAR([Order Date])=2016 THEN [Sales] END // Sales 2016
IF YEAR([Order Date])=2017 THEN [Sales] END // Sales 2017
Anatomy of a bullet graph — Sub-Category: Binders

The background bands mark 25 / 50 / 75% of the reference year's total sales, and the vertical tick marks that year's total exactly. Swapping is a single click in Tableau — right-click the axis and choose Swap Reference Line Fields — and it's built into the demo above.
