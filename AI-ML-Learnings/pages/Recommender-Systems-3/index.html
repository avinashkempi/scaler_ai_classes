Matrix Factorization — The Netflix Story

Five ideas, each one built because the last one hit a wall — from asking who Netflix's users even are, to a million-dollar contest, to vectors that quietly power search and ads across the whole company.

5 sections 5 knowledge checks 2 interactive visualizers

Imagine you've just joined Netflix's recommendations team. Your manager's first ask isn't "build me a recommender" — it's "help me understand who our users even are." That single question walks through five ideas, each one arriving because the previous idea hit a concrete wall.

1 Segmenting users

Matrix factorization as a generalization of clustering

Why start here Before Netflix can recommend anything, the team wants a coarse read on its users — are there natural taste-groups, like thriller binge-watchers, kids'-content households, or prestige-drama viewers? That's a clustering question. It turns out clustering is a special case of the same matrix factorization idea that powers recommendations, which is why it's the entry point rather than a detour.

K-Means, revisited

Take the classic K-Means setup: a dataset of points xᵢ (n of them) with no labels. We want cluster centroids Cⱼ (for j = 1…k) that minimize the total distance from every point to its own cluster's centroid — the intra-cluster distance.

minCⱼ Σₖⱼ₌₁ Σxᵢ∈Sⱼ ‖xᵢ − Cⱼ‖² Sⱼ = the set of points in cluster j

Think of every viewer as a dot on a map of "taste space." A centroid is the average taste-profile of everyone grouped together. K-Means asks: if every group had to be described by one typical viewer, how do you draw the groups so no real viewer sits too far from their group's typical viewer?

Turning it into matrix form

Define a matrix Z where Zᵢⱼ = 1 if point xᵢ belongs to cluster Sⱼ, and 0 otherwise — dimensions n × k. This is the cluster assignment matrix: a spreadsheet where each row is a Netflix user and each column is a taste-cluster, a 1 marking "this user belongs here." It's a one-hot encoding of group membership, nothing more exotic.

The optimization becomes:

minCⱼ,Zᵢⱼ Σⁿᵢ₌₁ Zᵢⱼ ‖xᵢ − Cⱼ‖²

Whenever Zᵢⱼ = 1, the distance between point xᵢ and centroid Cⱼ counts; whenever it's 0, it drops out. Two constraints follow naturally: Zᵢⱼ can only be 0 or 1, and each point is assigned to exactly one centroid — every row of Z sums to 1.

Stack the data points xᵢ as the rows of a matrix X (n×d), and the centroids Cⱼ as the columns of a matrix C (d×k). After the matrix manipulation, the objective becomes:

minC,Z ‖Xn×d − Zn×k·Cᵀk×d‖²F F = Frobenius norm

What is the Frobenius norm?

A squared vector norm sums the square of every element. Extend that to a matrix and you get the Frobenius norm — flatten every entry into one long vector and take its length: ‖X‖F = Σᵢ Σⱼ X²ᵢⱼ. When we write ‖X − Z·Cᵀ‖²F, we're flattening the leftover error matrix and measuring its total squared size — the same spirit as ordinary least-squares error, just applied to a whole matrix instead of a single vector.

So K-Means clustering is, underneath, just decomposing X as a product of two matrices:

X ≈ Z · Cᵀ

Where Z (n×k) is the cluster allocation matrix and C (k×d) is the cluster centroid matrix. K-Means clustering is a special case of matrix factorization.

Hard vs. soft membership: does GMM count too?

A Gaussian Mixture Model is clustering with soft assignment — instead of belonging 100% to one taste-cluster, a user can be "60% thriller-binger, 40% documentary-watcher." GMM is also a case of matrix factorization: the only change is that the constraint forcing Zᵢⱼ to be 0 or 1 disappears. The row-sums-to-1 constraint still holds — the "percentages of membership" still add up to 1.

Choosing d: the hyperparameter behind every factorization

Back to the recommender setup — matrix completion. Given a sparse ratings matrix A (n×m) from n users to m items, decompose it into a user matrix and an item matrix, each with a shared inner dimension d:

An×m = Bn×d · Cᵀd×m minimizing only over the non-empty cells of A

Just like k in clustering, d is a hyperparameter — not something we optimize directly, only Bᵢ and Cⱼ are. It must satisfy d > 0 and d ≤ min(n, m). As d grows, the vectors carry more information, so the product fits A more closely and the loss decreases.

One approach: plot loss vs. d and pick the elbow — the point past which more dimensions buy little extra fit. It risks overfitting, though teams do use it in practice. A better approach, since we have ground-truth ratings: train on 80% of the non-empty values of A, test on the remaining 20%, and pick the d that generalizes best — proper hyperparameter tuning via stochastic gradient descent or coordinate descent.

Test RMSE vs. d — a real run of the elbow method
200 users × 150 items, synthetic ratings with noise, 80/20 train-test split

For small d, RMSE is high — the vectors are too short to capture real structure (underfitting). As d grows, RMSE drops until it flattens around d = 8, the elbow the team would pick in practice; pushing d further barely helps and can even creep the error back up.

There is no interpretability in the value of d itself — it's just an embedding, and no individual number inside Bᵢ or Cⱼ means anything on its own. Interpretability comes back only through a projection: run UMAP or t-SNE on the d-dimensional user vectors down to 2 dimensions, and each point becomes a user you can actually visualize and cluster.

Knowledge check 1

In the matrix form of K-Means, minC,Z ‖X − ZCᵀ‖²F, what does the Frobenius norm compute?

The Frobenius norm sums the squares of every entry across all rows and columns — the matrix analogue of a vector's squared length. It's exactly what lets the K-Means objective be written as one clean matrix-factorization error term.
2 Explainable segments

Non-negative matrix factorization

Why move here Once the team has taste-clusters via MF, a stakeholder asks the obvious next question: "can you tell me why a user is in this cluster?" Plain MF factors can go negative, which is hard to explain in plain English — nobody has "-0.7 units of comedy." That pushes the team toward a version of MF that behaves.

Recall the MF setup: decompose A (n×m) into B (n×d) and C (d×m). In non-negative matrix factorization (NMF), we additionally require the elements of B and/or C to be non-negative — Bᵢⱼ ≥ 0 and/or Cᵢⱼ ≥ 0.

Why non-negative?

MF for clustering. Recall the constraints on Z, the cluster assignment matrix: during hard assignment, Zᵢⱼ = 1 if xᵢ ∈ Sⱼ, else 0 — so Z is implicitly non-negative already. That non-negativity constraint applies only to Z here; C can still hold negative values. This makes NMF a generalization of clustering, itself a special case of MF:

MF ⊇ NMF ⊇ K-Means

Visualizing images. Images are stored as RGB values per pixel — inherently non-negative. Think of NMF on images the way you'd think of building a face out of parts: a nose-shape, an eyebrow-shape, a jaw-shape. You can only add parts together — you can never subtract a nose from a face. That's the intuition behind why non-negativity yields interpretable, "parts-based" factors instead of abstract combinations that cancel each other out.

NMF isn't always necessary: for plain ratings-matrix completion, nobody cares what Bᵢ or Cⱼ individually mean — only that their product approximates A well. NMF earns its keep specifically when a human needs to read the factors, not just consume the predictions.

Knowledge check 2

Why does the cluster assignment matrix Z require non-negative — in fact 0-or-1 — values, while the centroid matrix C does not?

Zᵢⱼ answers a yes/no membership question, so its values are constrained to "in" (1) or "out" (0). C stores centroid positions in an abstract feature space, and coordinates there can be positive or negative like any point in space — there's no membership semantics attached to them.
3 Three signals, one engine

Recommending from likes, watches, and dislikes

Why move here So far we've treated "the ratings matrix" as one clean signal. It isn't. Netflix actually observes several different behaviors — what a user explicitly liked, what they watched most of, and what they disliked or abandoned. Folding three matrices into one recommendation engine is a genuinely different problem from anything solved so far.

Suppose you're a data scientist at Netflix with three separate matrices, all n × m: L — titles users have liked, W — titles users have watched more than 50% of, and D — titles users have disliked. Given all three, how do you recommend a new title to user uᵢ?

Add L, W, D together and run matrix completion on the sum. This doesn't hold up: liked and disliked titles are opposite signals. Adding them blindly lets a strong dislike cancel out a real like with no principled meaning — the two aren't on the same axis to begin with.

Assign each matrix its own weight before combining, then factorize as usual:

α₁L + α₂W + α₃D = A

A workable starting point: α₁ (likes) strongly positive, around 1; α₂ (watches) a smaller positive weight, around 0.1; α₃ (dislikes) strongly negative, around -1. The real challenge is finding these weights well.

Factorize L, W, D on their own and get three separate user/item vector pairs. These become user profiles describing what a person likes and dislikes — cosine similarity finds similar users or similar items directly. We'd favor titles the user tends to like, avoid ones they tend to dislike, and weight the watched matrix W lower than the liked matrix L.

For matrix completion specifically: to estimate a missing cell like L₁₀₀,₁₀, compute u₁₀₀ᵀ · v₁₀. If the vectors are unit-length, this is exactly cosine similarity — since they represent user and title profiles, the two approaches land in similar territory.

Knowledge check 3

Why is Idea 1 — simply adding the liked, watched, and disliked matrices — considered flawed?

Liked and disliked titles are opposite feedback, and watched-time is a separate, weaker signal altogether. Adding all three with an implicit weight of 1 treats a strong dislike as numerically equal and opposite to a like, with no real justification — hence deliberately chosen weights (Idea 2) or independent factorization (Idea 3).
4 Turning it into a science

The Netflix Prize

Why move here Weighting signals by hand and hoping the weights are right doesn't scale, and it doesn't say whether predictions are actually getting better. Netflix hit this exact wall — and instead of guessing internally, opened the problem to the world. This is the centerpiece of the story: the moment MF for recommendations became rigorous.

Around 2008–09, Netflix ran a worldwide competition inviting machine learning practitioners to improve its recommendation engine, offering a million-dollar incentive to attract collaboration. The loss metric was RMSE, and the task was a 10% improvement on it.

The eventual winning solution stacked roughly 30–40 models with their own hyperparameters, plus bagging and boosting — powerful, but messy enough that it was never productionized as-is. Even so, a great deal of the research that came out of the competition is exactly why matrix factorization became the standard approach for recommender systems.

Notation from here on: pᵤ is the d-dimensional representation for user u, qᵢ for item i, and rᵤᵢ is the rating user u gave item i.

The base formulation

Split the data into train and test sets. The simplest formulation sums, over all users and items, the squared difference between the actual rating and the predicted one, minimized over the pᵤ's and qᵢ's — with no constraints, since interpretability isn't the concern here:

minpᵤ,qᵢ Σu,i (rᵤᵢ − qᵢᵀ·pᵤ)²

Adding regularization

A high d risks overfitting the training data, so a regularization term with coefficient λ is added:

minpᵤ,qᵢ Σu,i (rᵤᵢ − qᵢᵀ·pᵤ)² + λ(Σᵢ‖qᵢ‖² + Σᵤ‖pᵤ‖²)

Regularization penalizes vectors that grow unnecessarily large just to memorize training noise — the model is told to explain the ratings, but not get too clever about it, or it fails on new data.

Solving with SGD

With error term eᵤᵢ = rᵤᵢ − qᵢᵀ·pᵤ and learning rate γ, each step updates:

qᵢ = qᵢ + γ(eᵤᵢ·pᵤ − λ·qᵢ)
pᵤ = pᵤ + γ(eᵤᵢ·qᵢ − λ·pᵤ)

Adding biases

Three factors drive any given rating: the average rating across the whole platform (μ), the average rating of that specific movie — a movie bias bᵢ, since some movies are just broadly beloved — and the average rating that specific user tends to give — a user bias bᵤ, independent of the movie:

rᵤᵢ = μ + bᵤ + bᵢ + qᵢᵀ·pᵤ

Instead of freezing μ, bᵤ, bᵢ, they become part of the optimization itself — from a regression standpoint, qᵢᵀ·pᵤ is a quadratic term, bᵤ and bᵢ are linear terms, μ is a constant:

minpᵤ,qᵢ,μ,bᵤ,bᵢ Σu,i (rᵤᵢ − μ − bᵤ − bᵢ − qᵢᵀ·pᵤ)² + λ·Σ(‖qᵢ‖² + ‖pᵤ‖² + μ² + bᵤ² + bᵢ²)

Temporal dynamics

None of this captures how a user's preferences change over time. Temporal dynamics treats the rating as a function of time — and this single addition delivered the most significant RMSE improvement in the actual competition:

rᵤᵢ(t) = μ + bᵤ(t) + bᵢ(t) + qᵢᵀ·pᵤ(t)
  • μ, the global average, stays independent of time
  • bᵤ(t): a user's rating bias can drift — the same person's baseline generosity changes
  • Tastes shift: someone watching Tom and Jerry today may be watching James Bond a few years later
  • bᵢ(t): an item's bias can drift too — older movies get rediscovered and rated higher than at release
  • qᵢᵀ·pᵤ: the item and user vectors themselves evolve with time

Rather than treating these parameters as constant across ten years of data, they're modeled as time-series, trained in chunks of time rather than all at once.

Two more design questions

Imagine building a time-sensitive recommender at Netflix's scale. Idea 1: update bᵤ, bᵢ, qᵢ, pᵤ periodically — valid, and doable. Idea 2: weight recent data more heavily:

minpᵤ,qᵢ,μ,bᵤ,bᵢ Σu,i wᵤᵢ(rᵤᵢ − μ − bᵤ − bᵢ − qᵢᵀ·pᵤ)² + λ·Σ(‖qᵢ‖² + ‖pᵤ‖² + μ² + bᵤ² + bᵢ²)

Here wᵤᵢ is a weight matrix built so more recent ratings carry more influence.

How it plays out in production

Some recommendations are purely recency-based similarity to what's playing now, found via K nearest neighbours — fast enough to run in real time. Others come from historical taste, computed entirely offline as a nightly batch process, with more weight given to recent watch history. Every night, MF runs, refreshing the item vectors and item bias (qᵢ, bᵢ); once done, the system picks the top titles worth recommending based on the user's history.

Knowledge check 4

In the bias formulation rui = μ + bu + bi + qiᵀpu, what does bu represent?

bᵤ is the user bias term — it captures whether a particular user habitually rates generously or critically, separate from anything about the specific movie (bᵢ) or the interaction between the user's and movie's taste vectors (qᵢᵀ·pᵤ).
5 From ratings to everything

MF as feature engineering

Why move here The Netflix Prize left the team with something more valuable than accurate ratings alone — it left them with well-trained pᵤ and qᵢ vectors. The natural next question: since the cost of training them is already paid, can other teams reuse them instead of building their own from scratch? That reuse question closes the story.

Reusing user and item vectors

In the Netflix recommendation problem, what matters most are the d-dimensional user and item vectors — using them, the ratings matrix can be completed and recommendations generated. MF is, implicitly, doing feature engineering: pᵤ's are sensible user features because similar users end up with similar vectors, and the same holds for item vectors qᵢ. Those features can then feed classification, regression, visualization, or clustering models elsewhere — user and item features, essentially out of thin air.

Traditional feature engineering builds interpretable features like "what country is the user from." MF-derived features have no such interpretability — they're algorithmically engineered numbers — but they can still be visualized with UMAP or t-SNE, the same as before.

Search: someone searches "true crime documentary." The search team takes the item vectors built by the recommendations team, finds the most relevant title first, then finds all items similar to it via K nearest neighbour, and returns those. Ads: a click model needs P(click | user, ad, website, …), which needs user- and item-level features. The same d-dimensional vectors built for recommendations get reused here — even though predicting ad clicks is a completely different goal from recommending a title.

For text data

Suppose the corpus is every article on Wikipedia, and the goal is a d-dimensional representation for words — not documents — that doesn't need to be interpretable but should be sensible: similar words should cluster together when visualized. Build a matrix A where each of n rows is an article, each of m columns is a word, and Aᵢⱼ stores the count of word j in document i. Decompose:

An×m = Bn×d · Cd×m

The jth column of C becomes the d-dimensional representation of word wⱼ; the ith row of B becomes the representation of document dᵢ — both dense vectors. These can find similar documents (Kindle, Google News, blog platforms — though most such sites now lean on deep learning rather than plain MF) or, given a word, find similar words (product search, Grammarly).

The co-occurrence matrix approach

An alternate route: build a square m × m matrix X where Xᵢⱼ counts how often word wⱼ occurs in the context of word wᵢ — within some neighborhood distance, say 10 words. Words like "principal" and "analysis" mean very different things individually, but appearing close together, they likely signal the concept "PCA" — two words with very different standalone meanings gaining a very different, combined meaning through co-occurrence.

X is naturally symmetric. Since it's square and symmetric, PCA could apply, but here we use MF: X = B·C, where both B and C are, since X's rows and columns both represent words, d-dimensional word vectors — giving two separate representations for every word.

Truncated SVD

Decompose the co-occurrence matrix with SVD instead: X = U·Σ·Vᵀ, where U holds the left singular vectors, Σ is diagonal with singular values s₁ ≥ s₂ ≥ … ≥ sₘ, and Vᵀ holds the right singular vectors. Since m (the vocabulary size) is very large, the smallest singular values end up tiny — a lot of computation for very little payoff.

The fix: keep only the top k singular values, discarding the rest — along with only the first k columns of U and first k rows of Vᵀ:

Xm×m ≈ Ûm×k · Σ̂k×k · V̂ᵀk×m

This is truncated SVD, with k as a hyperparameter. The word vector for wⱼ is simply the jth row of Û — dimensions m×k. Even truncated SVD can be expensive given the sheer size of a vocabulary; one common shortcut is restricting to the top n words by IDF score from TF-IDF, rather than the full vocabulary.

For images: Eigenfaces

The same MF idea extends to face recognition — relevant, for instance, to how Netflix might personalize thumbnails or handle content-side image data. A 2D image is a matrix with r rows and c columns — say 64×64, giving 4096 total cells. Stack the rows one after another into a single vector of dimension r·c — row-major order, or flattening.

With 400 raw images, the data matrix X has n=400 rows and d=r·c=4096 columns. This workflow — using PCA for face recognition — is called Eigenfaces, historically important but since replaced by convolutional neural networks. Since PCA needs a square matrix, it can't run on X directly — instead, compute the covariance matrix S (d×d) first, then apply PCA there: S = W·Λ·Wᵀ. Reduce dimensionality from d to k by keeping the top k eigenvectors, Wₖ (d×k).

Multiplying X·Wₖ gives a k-dimensional vector per image. With that in hand, an image can be un-flattened back into 64×64 format to reconstruct it — the same compress-then-reconstruct pattern seen across ratings, clusters, words, and now faces.

Knowledge check 5

In the Eigenfaces workflow, why do we first compute the covariance matrix S (d×d) before applying PCA on the image data matrix X (n×d)?

PCA operates on a square matrix — it needs eigenvectors and eigenvalues, which are only defined for square matrices. The raw image matrix X is 400×4096, not square, so the d×d covariance matrix S is computed first, which is square by construction, and PCA runs there instead.

Closing the loop on the Netflix story

1
Who are Netflix's users?

MF for clustering showed that clustering is just MF with hard 0/1 assignments.

2
Make the clusters explainable

Non-negative MF gave interpretable, "parts-based" factors instead of ones that cancel each other out.

3
One signal became three

Naive addition of likes, watches, and dislikes fails; weighting or independent factorization combines them properly.

4
The real Netflix Prize

Regularization, user/item biases, and — the biggest lift of all — temporal dynamics to model taste that changes over time.

5
Vectors as reusable features

The pᵤ and qᵢ vectors this whole story produced don't just power ratings — they get reused by search, ads, text-similarity, and even image recognition across the company.

The single thread throughout: every new technique showed up because the previous one hit a concrete, explainable wall — not because we were jumping between unrelated topics.
