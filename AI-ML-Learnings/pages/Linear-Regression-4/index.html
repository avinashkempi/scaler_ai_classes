Concept
The 5 Assumptions of Linear Regression
⏱ 1 min

Linear Regression makes five core assumptions about your data. Violating them doesn't always break the model — but it means your predictions, coefficients, and p-values may not be trustworthy.

1
Critical

Linearity

The relationship between each feature and the target must be linear.

2
Critical

No Multicollinearity

Input features must not be linearly dependent on each other.

3
Important

Normally Distributed Errors

Residuals should follow a bell-shaped (Gaussian) distribution.

4
Important

Error Independence

Residuals must not show patterns or correlate with each other.

5
Important

Homoscedasticity

Residuals must have roughly constant variance across all predicted values.

📈
Assumption 1
Linearity
⏱ 2 min

Linear Regression assumes the relationship between each independent variable and the target is a straight line. If your data follows a curve, an exponential, or a wave — a straight line cannot capture it.

How to Check

  • Scatter plots of each feature vs. the target
  • Residual plots — if a pattern exists in the residuals, linearity is violated

How to Fix

When the linearity assumption is violated, we use Polynomial Regression — transforming features into higher-order terms to model curved relationships. We'll cover this in detail later in this lecture.

📌 Examples of Non-Linear Relationships
  • Electricity consumption vs. year (follows an S-curve)
  • Sales vs. advertising spend (diminishing returns)
  • Blood pressure vs. BMI (non-linear health relationship)
🔗
Assumption 2
No Multicollinearity
⏱ 3 min

Multicollinearity occurs when one or more of your independent features can be predicted from other independent features. In other words, the features are not truly "independent."

Why Is This a Problem?

Consider four features x₁, x₂, x₃, x₄. The model tries to find the unique contribution of each. But if:

x₂ = 3·x₃ + 2·x₄

Then x₂ carries no new information — it's already explained by x₃ and x₄. The model can't isolate x₂'s true effect, so its coefficient becomes unreliable and unstable.

Real-World Example

In the Cars24 dataset, year and age are almost perfectly correlated — age is simply the current year minus the model year. Including both confuses the model about which one actually drives the price.

🤔 Think about it
Should there ever be a dependency among independent variables? No — by definition, if x₁ can be derived from x₂ and x₃, then x₁ is not truly independent. One of them is redundant.

Symptoms of Multicollinearity

  • Coefficients that are unexpectedly large or have the wrong sign
  • High standard errors for coefficients despite a good overall R²
  • A high Condition Number in the StatsModels summary (e.g., > 1000)
🔬
Implementation
VIF — Detecting & Fixing Multicollinearity
⏱ 20 min

How VIF Works

The Variance Inflation Factor (VIF) measures how much each feature can be predicted by all the others. For each feature xⱼ, it:

1

Treat xⱼ as the target

Build a regression model using all other features as inputs to predict xⱼ

2

Record the R²

A high R² means xⱼ is well-explained by the others — it's redundant

3

Compute VIF

VIF = 1 / (1 − R²). High R² → VIF approaches infinity

4

Repeat for all features

Remove the highest-VIF feature and recalculate until all VIFs are acceptable

VIF = 1 / (1 − R²ⱼ)

VIF Thresholds

VIF ValueInterpretationAction
> 10Very High MulticollinearityRemove this feature
5 – 10High MulticollinearityConsider removing
< 5AcceptableKeep the feature

Initial VIF Calculation

from statsmodels.stats.outliers_influence import variance_inflation_factor
import statsmodels.api as sm
from sklearn.preprocessing import StandardScaler
from sklearn.model_selection import train_test_split

X = df[df.columns.drop('selling_price')]
y = df["selling_price"]

X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, random_state=2)

scaler = StandardScaler()
X_tr_scaled = scaler.fit_transform(X_train)

vif = pd.DataFrame()
X_t = pd.DataFrame(X_tr_scaled, columns=X_train.columns)
vif['Features'] = X_t.columns
vif['VIF'] = [variance_inflation_factor(X_t.values, i) for i in range(X_t.shape[1])]
vif['VIF'] = round(vif['VIF'], 2)
vif = vif.sort_values(by="VIF", ascending=False)
print(vif)
Output — sorted by VIF
Features VIF year 1392.20 ← Remove first model 120.72 make 85.64 engine 12.42 max_power_hp 9.47 km_driven 2.88 fuel_type 2.33 seller_type 1.98 transmission 1.92 owner_type_Second 1.29 owner_type_Third 1.13 ...

year has a VIF of 1392 — nearly perfectly predicted by age (which is derived from it). Remove it first.

Iterative Elimination Loop

vif_thr = 5
r2_thr  = 0.85
feats_removed = ['year']

while True:
    X_t = pd.DataFrame(X_tr_scaled, columns=X_train.columns)[cols2]
    vif['VIF'] = [variance_inflation_factor(X_t.values, i)
                  for i in range(X_t.shape[1])]
    vif = vif.sort_values(by="VIF", ascending=False)

    cols2 = vif["Features"][1:].values   # drop highest VIF
    X2    = pd.DataFrame(X_tr_scaled, columns=X_train.columns)[cols2]
    X2_sm = sm.add_constant(X2)
    sm_model = sm.OLS(list(y_train), X2_sm).fit()

    if (vif.iloc[0]['VIF'] < vif_thr) or (sm_model.rsquared_adj < r2_thr):
        print('Reached threshold')
        break

    feats_removed.append(vif.iloc[0]['Features'])
Output — stopping condition reached
Reached threshold Highest VIF remaining : max_power_hp = 4.99 Final Adj. R² : 0.8997 Features removed : ['year', 'model', 'make']
✅ Result
We removed 3 features (year, model, make) with no meaningful drop in R². The model went from 15 features down to 9, with all remaining VIFs below 10 and Adjusted R² still at ~90%.

VIF elimination is iterative — you run it many times. Having an LLM auto-summarize the result at each stage helps communicate decisions to stakeholders without requiring them to read regression tables.

Assumption 3
Errors Are Normally Distributed
⏱ 5 min

The residuals (errors) of a well-specified linear regression model should follow a bell-shaped (Gaussian) distribution centered at zero. This ensures that our statistical tests (p-values, confidence intervals) are valid.

📌 Why Does This Matter?
If residuals are not normally distributed, it often signals the presence of outliers, a skewed target variable, or a misspecified model (e.g., a linear model on non-linear data).

Check with a Histogram of Residuals

X_sm   = sm.add_constant(X_tr_scaled)
sm_model = sm.OLS(y_train, X_sm).fit()

Y_hat  = sm_model.predict(X_sm)
errors = Y_hat - y_train

import seaborn as sns
sns.histplot(errors)
plt.xlabel("Residuals")
plt.title("Histogram of Residuals")

A histogram that looks roughly bell-shaped and symmetric around zero is a good sign.

Confirm with the Shapiro-Wilk Test

from scipy import stats
res = stats.shapiro(errors)
print(res.statistic)
Output
0.8500353693962097
Shapiro-Wilk StatisticInterpretation

0.85 – 0.95Moderate normality — acceptable in large datasets
Below 0.8Significant departure from normality — investigate outliers

Our value of 0.85 indicates a high enough level of normality for the Cars24 dataset.

🔀
Assumption 4
Error Terms Must Be Independent
⏱ 2 min

If you plot a scatter of residuals vs. the target variable, there should be no visible pattern. Random scatter around zero is ideal.

When Is This Violated?

This assumption is most commonly violated in time series data, where errors at time t are correlated with errors at time t−1 (called autocorrelation). For cross-sectional datasets like Cars24, this is rarely an issue.

📌 Check: Durbin-Watson Test
The Durbin-Watson statistic in StatsModels output tests for autocorrelation in residuals. A value close to 2.0 indicates no autocorrelation. Values near 0 or 4 suggest a problem. Our Cars24 model returned 2.000 — perfect.

We'll explore autocorrelation and its remedies in depth when we cover Time Series Analysis later in the course.

Assumption 5
Homoscedasticity — Constant Error Variance
⏱ 6 min

Homoscedasticity means the residuals have roughly the same spread (variance) across all levels of the predicted values. Its opposite — heteroscedasticity — is when variance increases or decreases as predictions grow.

Visual Check: Residuals vs. Predicted Values

Y_hat  = sm_model.predict(X_sm)
errors = Y_hat - y_train

sns.scatterplot(x=Y_hat, y=errors)
plt.xlabel("Predicted Selling Price")
plt.ylabel("Residuals")
plt.title("Predicted Values vs Residuals")

A good plot shows a horizontal band of roughly constant width. If the band fans out (cone shape), heteroscedasticity is present.

For our Cars24 data: the spread of errors stays approximately constant from left to right — the assumption is satisfied.

Goldfeld-Quandt Test

Beyond visual inspection, the Goldfeld-Quandt Test formally tests for heteroscedasticity by comparing the variance of residuals in the lower half vs. the upper half of the data:

from statsmodels.compat import lzip
import statsmodels.stats.api as sms

name = ['F statistic', 'p-value']
test = sms.het_goldfeldquandt(y_train, X2_sm)
lzip(name, test)
Output
[('F statistic', 1.000), ('p-value', 0.353)]
MetricValueInterpretation
F statistic1.00Variance is equal between groups — no heteroscedasticity
p-value0.353Above 0.05 → fail to reject null → homoscedasticity holds
🔧 If You Find Heteroscedasticity
  • Apply transformations to the target: log(y), √y, or Box-Cox
  • Remove outliers — they often inflate variance in specific regions
  • Consider weighted least squares regression

Technique
Polynomial Regression
⏱ 8 min

When data follows a curve — not a straight line — Linear Regression's first assumption (linearity) is violated. We need to model non-linear patterns.

Examples of Non-Linear Real-World Data

  • US Electricity Consumption vs. Year — follows an S-curve, not a line
  • Seasonal sales vs. month — sinusoidal pattern with peaks and troughs
  • Blood Pressure vs. BMI — non-linear health relationship

The Idea: Transform Features

Instead of using raw features x directly, we create polynomial features — new columns that are powers of the original:

ϕ(x) = [1, x, x², x³, … , xᵈ]

Then we fit a regular Linear Regression on these transformed features. The model equation becomes:

ŷ = w₀ + w₁x + w₂x² + w₃x³ + … + wₐxᵈ
📌 Key Insight
Polynomial Regression is still Linear Regression — linear in the parameters (the w values). The non-linearity comes from the transformed features, not the model structure. This means we can still use the same OLS / Gradient Descent machinery.

Choosing the Degree

DegreeEquation FormShape
1w₀ + w₁xStraight line (standard LR)
2w₀ + w₁x + w₂x²Parabola (quadratic curve)
3w₀ + w₁x + w₂x² + w₃x³Cubic curve (inflection point)
n…Increasingly flexible — but risks overfitting
⚠️ The Danger of High Degrees
A very high-degree polynomial can perfectly fit training data (R² ≈ 1) but fail dramatically on test data. This is overfitting — the model memorized the training noise instead of learning the true pattern.
💻
Implementation
Polynomial Regression — US Electricity Consumption
⏱ 7 min

Dataset: US electricity consumption from 1949–1999 (51 rows, 2 columns: Year and Consumption). The data follows a non-linear upward curve.

Load and Split

import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
from sklearn.preprocessing import PolynomialFeatures
from sklearn.linear_model import LinearRegression
from sklearn.pipeline import Pipeline
from sklearn import metrics

elec_cons = pd.read_csv("total-electricity-consumption-us.csv")

# Split by index (every 5th point → test)
size  = len(elec_cons.index)
index = range(0, size, 5)
train = elec_cons[~elec_cons.index.isin(index)]
test  = elec_cons[ elec_cons.index.isin(index)]

X_train = train.Year.values.reshape(-1, 1)
y_train = train.Consumption
X_test  = test.Year.values.reshape(-1, 1)
y_test  = test.Consumption

print(f"Train: {len(train)} rows | Test: {len(test)} rows")
Output
Train: 40 rows | Test: 11 rows

Fit Degrees 1, 2, and 3

degrees = [1, 2, 3]
r2_train, r2_test = [], []

for degree in degrees:
    pipeline = Pipeline([
        ('poly', PolynomialFeatures(degree=degree)),
        ('model', LinearRegression())
    ])
    pipeline.fit(X_train, y_train)
    r2_train.append(metrics.r2_score(y_train, pipeline.predict(X_train)))
    r2_test.append(metrics.r2_score(y_test,  pipeline.predict(X_test)))

for d, tr, te in zip(degrees, r2_train, r2_test):
    print(f"Degree {d}: Train R² = {tr:.3f}, Test R² = {te:.3f}")
Output
Degree 1: Train R² = 0.963, Test R² = 0.966 Degree 2: Train R² = 0.999, Test R² = 0.999 Degree 3: Train R² = 0.999, Test R² = 0.999
Degree 1
ŷ = w₀ + w₁·year
Train R²0.963
Test R²0.966

Straight line — misses the curvature

Degree 2 ✓
ŷ = w₀ + w₁·year + w₂·year²
Train R²0.999

Degree 3

✅ Lesson
Degree 2 is the sweet spot here. Degree 3 adds complexity without any gain — and at higher degrees it would start overfitting. Always evaluate on test data to find the right degree.

Concept
Bias-Variance Tradeoff
⏱ 12 min

This is one of the most fundamental concepts in all of machine learning. Every model navigates a tension between two types of error:

The Student Analogy

🎓 The Over-Studier (Overfitting)

  • Memorized every question in the textbook
  • Performs perfectly on practice problems
  • Fails when the exam has new question variants
  • Train R² = high, Test R² = low

😴 The Under-Studier (Underfitting)

  • Only skimmed chapter headings
  • Can't answer even the practice problems
  • Fails both practice and the exam
  • Train R² = low, Test R² = low

In Model Terms

ScenarioTrain R²Test R²Problem
UnderfittingLowLowModel too simple — misses the real pattern
OverfittingHighLowModel too complex — memorizes training noise
Just RightGoodGoodGeneralizes well to new data

Bias vs. Variance

🎯

Low Bias, Low Variance

Aiming at the right spot and hitting it consistently. This is the goal.

🎯

High Bias, Low Variance

Consistently hitting the wrong spot. Underfitting — model is too simple.

🎯

Low Bias, High Variance

Aimed correctly but scattering all over. Overfitting — model is too sensitive to training data.

🎯

High Bias, High Variance

Wrong spot and inconsistent. The worst case — both errors compound.

Connecting to Polynomial Degree

Recall our polynomial model with one feature x and four powers:

ŷ = w₀ + w₁x + w₂x² + w₃x³ + w₄x⁴
ModelNon-zero weightsComplexityRisk
M1w₁, w₂, w₃, w₄ ≠ 0HighestOverfitting
M2w₁, w₂ ≠ 0; w₃ = w₄ = 0MediumBalanced
M3w₁ ≠ 0; w₂ = w₃ = w₄ = 0LowestUnderfitting

The more non-zero higher-order weights, the more the model can contort to fit training data — increasing variance and risking overfitting.
