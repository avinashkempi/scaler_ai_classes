Distance between two parallel planes

Two lines (or planes) only have a well-defined "distance between them" when they're parallel — otherwise they intersect, and there's no single distance to speak of. Parallel lines share the same weight vector w, differing only in their bias: l₁: w̄ᵗx̄ + 5 and l₂: w̄ᵗx̄ + 3.

Each line's distance from the origin is already known (−w₀/‖w̄‖), so the distance between the two lines is simply the difference:

d = d₁ − d₂ = (5 − 3)/‖w̄‖ = 2/‖w̄‖

Which halfspace does a point belong to?

Splitting the plane into four quadrants relative to the weight vector and the line, the angle between a point's vector and w determines sign consistently: angles between 0°–90° and 270°–360° give cos θ > 0 (positive halfspace); angles between 90°–270° give cos θ < 0 (negative halfspace).

In binary classification, class labels are deliberately chosen as +1 / −1 (rather than 1/0) specifically so a point's label matches the sign of its distance from the classifier.

Building the loss function

For a dataset D = {(x̄ᵢ, yᵢ)}ᵢ₌₁ⁿ where each yᵢ ∈ {+1, −1}, the natural goal is to maximise the total distance of every point from the classifier — captured by a gain function:

G(D, w̄, w₀) = Σᵢ ( w̄ᵗx̄ᵢ + w₀ ) / ‖w̄‖

The sign problem

Raw signed distances from different halfspaces can cancel each other in the sum — e.g. a point at +2 and a point at −3 total −1, even though both are "far" from the boundary in a good way. Three fixes are possible: take the absolute value (not differentiable at 0), square the distances (complicates later differentiation), or — the one actually used — multiply each distance by its true label yᵢ, which flips negative-halfspace distances positive exactly when the point is correctly classified:

G(D, w̄, w₀) = Σᵢ yᵢ · ( w̄ᵗx̄ᵢ + w₀ ) / ‖w̄‖
The loss function is simply the negative of the gain function, L = −G. Maximising gain is the same task as minimising loss — and minimising loss is the universal goal of every ML algorithm, regardless of which specific loss function it uses.

The perceptron learning algorithm

When a point is misclassified, the line (via its weight vector) needs to rotate so the point lands in the correct halfspace. Two directions are possible — clockwise or counter-clockwise — and one is always more direct than the other.

The point should be in the positive halfspace but landed in the negative one. Rotating w counter-clockwise fixes it fastest. Using vector algebra (placing −x̄ at the tip of w_old and adding):

w_new = w_old − x̄

The point should be in the negative halfspace but landed in the positive one. Rotating w clockwise fixes it fastest:

w_new = w_old + x̄

The unified update rule

Both cases collapse into a single rule once the actual label yᵢ (+1 or −1) is folded in directly:

w_new = w_old + yᵢ · x̄ᵢ

The bias updates similarly, just without the vector multiplication — moving by the sign of the label alone: w₀_new = w₀_old + sign(yᵢ).

Non-linear boundaries: the circle

A decision boundary doesn't have to be a straight line. If points inside a circle belong to one class and points outside belong to another, the boundary is the circle equation itself:

(x − x꜀)² + (y − y꜀)² = r²   →   centered at origin: x² + y² = r²

Classifying a new point is the same sign test as before, just with a different equation: substitute the point's coordinates in, and read the sign.

ResultMeaning
PositivePoint lies outside the circle
NegativePoint lies inside the circle
ZeroPoint lies exactly on the circle
Adding squared versions of existing features as new columns lets a boundary that's geometrically circular still be expressed as something linear in the (expanded) feature space — a trick that extends far beyond circles.
