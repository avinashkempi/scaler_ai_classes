Last class you sent it out to check one thing. Today, seven things land at once. The loop, the pillars, the failure modes from Class 13 all still hold. § 1

Tool Types — Search, Code, Browser, API

⏱ 14 min

Four different kinds of hands. Every one of Advait's seven tips needs exactly one of them — the trick is knowing which.

🎙 Instructor Says

"Forget 'the AI uses a tool' as one vague idea. There are four genuinely different jobs hiding inside that phrase, and mixing them up is exactly how you get a stale answer that sounds confident."

🔎
TYPE ONE

Search

Ask the open web something general — not tied to one specific page. Good for background, patterns, "is this usually true."

🌐
TYPE TWO

Browser

Go to one specific, known webpage and read exactly what's on it right now. Good for "what does this page say today."

🔌
TYPE THREE

API Call

Ask another system directly for a live number or status, no page in between. Good for "what's true right now, precisely."

🧮
TYPE FOUR

Code

Do math, counting, or combining numbers — the job a spreadsheet formula would do. Good for "add these up."

🗞️
The One Analogy

Search is asking a well-read colleague what they generally know. Browser is walking over to a specific noticeboard and reading today's posting. API call is calling a hotline that gives you the live number directly, no noticeboard involved. Code is doing the arithmetic on your own notepad once you have the numbers.

Intermediate Note: Browser and API call get confused constantly, and the difference matters. A live DOT road-status feed answering "flooded: yes/no" in one clean value is an API call — precise, structured, built for machines to read. Loading the city's press page to see what it currently says about a briefing time is a Browser job — you're reading a page meant for humans, not a clean status feed. Search a live status page in general and you'll often get a cached, out-of-date copy — which is exactly the trap.

🧺 SIM 1 · The Tip Tray

Tips keep arriving. Click a waiting card, then click the tray it belongs in. Let more than four pile up unsorted and the newsroom misses deadline — sort correctly, fast, and clear all eight.

CalmBusyOverflow

Quiz 1 · Priya asks: "Add up this week's total storm-related 911 calls from the two spreadsheets I sent." Which tool type handles this?

ASearch — look up general 911-call statistics online
BBrowser — open the city's emergency-services webpage
CCode — combine the numbers already sitting in two files
DAPI call — ask 911 dispatch for a live count
Why C? The data already exists, sitting in two spreadsheets Priya sent — nothing needs to be looked up or fetched from anywhere. The job is purely arithmetic: open both, add the relevant numbers, report the total. That's Code's entire job description. The moment you catch yourself reaching for "look it up" when the numbers are already in hand, that's the tell you wanted Code, not Search or Browser.
§ 2

Tool Selection & Routing Logic

⏱ 13 min

Four tools on the shelf doesn't mean the agent magically grabs the right one. Something has to decide — and that something is a set of plain rules, checked in order.

🎙 Instructor Says

"There's no mystery inside 'the agent decides which tool to use.' Under the hood it's closer to a checklist: check this condition first, and if it matches, use that tool — otherwise check the next condition. Nothing fancier than that. Which means the order you write those checks in actually changes the outcome."

Routing Logic

The set of rules an agent checks, in order, to decide which tool a given task needs. The first rule that matches wins — so a rule sitting higher up the list quietly overrides one sitting lower, even for tasks the lower rule was actually written for.

🎙 Instructor Says

"If this feels familiar, it should — this is Class 10's Condition node, doing the exact same job: check a rule, and if it matches, stop and act; if not, check the next one. 'Routing logic' is just what that same idea is called when the checks decide between multiple tools instead of one path."

🧭 SIM 2 · Build The Router

Four rules, four incoming tips. Reorder the rules with the arrows, then run all four tips through and see which tool each one lands on — first matching rule wins.

    Advanced Note: the general principle the sim is teaching: put the rule that catches something specific and live above the rule that catches something general. "Needs a live status right now" should out-rank "could plausibly be found on some webpage," which should out-rank "is this generally true." Specific beats general, checked top to bottom.

    Quiz 2 · A newsroom agent has two routing rules, checked in this order: Rule 1 — "If it could plausibly be answered with a general web search → Search." Rule 2 — "If it needs a live, specific status right now → API call." A new tip arrives: "Is the power back on in Zone 4 right now?" — which could plausibly match either rule. What happens with the rules in this order?

    AThe task fails outright, since two rules both matched it
    BIt gets routed to Search first — possibly a stale, cached answer — even though a live API exists for exactly this question
    CThe agent automatically picks whichever tool would give the more accurate answer
    DRule order has no effect here — both rules lead to the same tool anyway
    Why B? First matching rule wins, top to bottom — nothing evaluates accuracy before picking. Rule 1 is broad enough to catch almost anything "look-up-able," including tasks a sharper, more specific rule was written for. Sitting a general rule above a specific one means the general rule quietly wins by default. The fix is ordering: the live/specific check should sit above the general one, so the sharper match wins on purpose instead of by accident of list position.
    § 3

    Memory — Short-Term vs. Long-Term

    ⏱ 14 min

    Seven tips at once isn't only a tools problem — it's just as much a memory problem, and it's worth separating two different kinds.

    🎙 Instructor Says

    "Last class, 'memory' meant one thing: don't call the same number twice in the same afternoon. Today we split it in two, because a newsroom doesn't reset every morning — some things are worth remembering past today."

    Short-Term Memory

    A scratchpad that lasts for this run only. Keeps track of what's already been checked today, so tip six doesn't repeat tip two's phone call. Gone the moment the session ends.

    Long-Term Memory

    A notebook that survives past today. Facts worth keeping — a verified address, a source that turned out reliable, a number that rarely changes — so tomorrow morning doesn't start from zero on things that are already settled.

    📓
    Or, Think Of It As Two Different Notebooks

    Short-term is today's page — torn out and binned at the end of the shift. Long-term is the newsroom's standing reference binder, added to over months, that any reporter can flip open instead of re-discovering the same fact from scratch.

    🗄️ SIM 3 · The Memory Bank

    Same three tips from this morning. Flip either switch and watch what the agent actually does — and what ends up sitting in each notebook.

    Short-Term MemoryRemembers within this morning's run
    Long-Term MemoryRemembers across mornings, permanently
    WHAT HAPPENS THIS MORNINGBOTH ON
    📝 Today's Scratchpad (short-term)
    🗄️ Newsroom Notebook (long-term)
    Advanced Note — the odd combination: long-term on, short-term off is a real and sneaky-broken shape. It might recall the shelter address instantly from a past morning, yet still lose track of what it already checked within today's own run — because that's exactly what short-term memory is for. Long-term memory is not a substitute for a working scratchpad; they do different jobs.

    Quiz 3 · An agent re-verifies the exact same shelter address from scratch on three separate mornings, even though nothing about the shelter has changed. Which memory type is missing?

    AShort-term — it should remember more within a single run
    BTools — it clearly can look the address up
    CLong-term — nothing persists past a single morning
    DAutonomy — it decided to check on its own
    Why C? The pattern is specifically across separate mornings, not within one run — that rules out short-term, which was never meant to survive past a session anyway. The tool clearly works (it keeps successfully finding the address) and nobody's stopping it from deciding to check. What's missing is a notebook that carries a settled fact forward from one day into the next — that's long-term memory's entire job.
    § 4

    Model Context Protocol — The USB-C Idea

    ⏱ 14 min

    Four tool types, sensible routing, two kinds of memory — Zara still has to actually connect each tool. This section is about what makes that fast instead of painful.

    🎙 Instructor Says

    "Here's the problem nobody's said out loud yet: every one of those tools — Gmail, Drive, a DOT status feed, a shelter database — used to need its own custom-built connection to every single agent that wanted to use it. Three agents, four tools, and you're hand-building twelve separate connections. Zara isn't a developer. She was never going to build twelve of anything."

    MCP — Model Context Protocol

    One shared, standard way for any agent to plug into any outside tool — instead of a custom-built connection per tool, per agent. Think of it as the agreed shape of the plug, not the tool itself.

    🔌
    The USB-C Analogy

    Before USB-C, every phone, camera, and headphone had its own proprietary cable — a drawer full of tangled, incompatible cords. USB-C didn't make any single device better; it gave every device the same plug, so any cable worked with any device. MCP does exactly that for agents and tools: it's not a smarter model, it's a standard port — and once a tool speaks it, every agent that also speaks it can use it immediately, no custom cable required.

    Here's the part that should actually surprise you: Anthropic introduced MCP in November 2024. Within a year, OpenAI and Google DeepMind — Anthropic's most direct competitors — both adopted the exact same standard for their own tools. That basically never happens in this industry. When competitors agree on a shared plug, it's because everyone independently hit the same N×M wall you're about to see in the sim.

Anthropic's own connector directory lists hundreds of ready-made tools (Google Drive, Gmail, Slack, Notion, and far more), and other builders — including n8n, covered a few sections down — speak the same protocol.

    Quiz 4 · What problem does MCP mainly solve for someone like Zara, a no-code builder?

    AIt makes the underlying AI model itself smarter
    BIt replaces the need for external tools entirely
    CIt gives every agent one shared, standard way to plug into outside apps, instead of a custom connection per app per agent
    DIt only works if you already know how to build an integration yourself
    Why C? Nothing about the model's intelligence changed — MCP is purely about the connection, not the reasoning. And it's the opposite of D: the entire appeal for a no-code builder is that you connect a tool once, through a shared standard, without writing an integration at all. That's what turns "twelve custom connections" into "seven total, and every new tool works with every agent immediately."
    § 5

    MCP In Claude — Connecting Real Tools

    ⏱ 13 min

    From concept to the actual settings screen. Worth doing this yourself on your own account, at your own pace.

    Beginner Note — this is genuinely free: Claude's directory connectors (Google Drive, Gmail, Notion, and hundreds more) are unlimited on the free plan — connect as many as you want. The "only one connector" limit you may have read about online applies to a completely different thing: custom, self-hosted MCP servers you'd point Claude at yourself.

    Connecting Google Drive & Gmail

    These two power the hands-on task in the next section, and most people already have both under one Google login — no new account needed. From claude.ai, open Settings → Connectors → Browse connectors, search for the tool by name, click Connect, sign in with your Google account, and approve the requested access. Google Drive and Gmail are two separate connectors even though they're the same underlying account, so you'll repeat the same short flow for each. Back in a chat, the + icon shows both under Connectors with a toggle switch next to each — that toggle is what tells you a connector is live and available to that conversation.

    Optional Third — Notion

    If a newsroom keeps notes in Notion instead of Drive, the same flow applies: browse connectors, search "Notion," connect, then approve access to the specific pages or workspace Claude should be able to read.

    What about Slack? It's in the same free directory and technically works the same way — but it only has something useful to search once a workspace already has real message history in it, which most fresh accounts won't. Worth knowing conceptually even without connecting it live — the same call the series made about Telegram back in Class 11: reliability beats completeness.
    § 6

    Hands-On — Two Tools, One Multi-Step Task

    ⏱ 16 min

    First real build since Class 12. Everything up to here has been leading to this one prompt.

    The Task

    Ask Claude, in one message: "Check my Gmail for Advait's tip about the flooded underpass. Then check the 'Verified Sources' doc in my Drive to see if that road has flooded before. Draft a two-line note back to me with what you find."

    Watch the shape of what happens: Claude names the first tool it's about to use — Gmail — before calling it, which is Think, out loud. It shows the actual email it found and asks for approval before reading it — every connector action needs explicit okay, every time. Once it has the tip, it decides on its own to check Drive next; nobody told it that second step, which is the routing and autonomy from earlier sections now running for real. It reads the Verified Sources doc, cross-references the road name, and only then drafts the two-line note — Observe feeding back into what it writes.

    Why the approval clicks matter: that "approve this action" prompt isn't friction for its own sake. Below are two real 2025 incidents where an agent's connection to a tool was used to reach further than anyone intended.
    🗞️ Real Incident, May 2025

    A single GitHub issue exfiltrated private repo data through an MCP connector

    Researchers at Invariant Labs showed that a free GitHub account and one maliciously worded public issue were enough to redirect an AI agent connected via GitHub's MCP server — the developer did nothing unusual beyond asking their assistant to review open issues. Hidden instructions in the issue text told the agent to pull private repository contents, including personal data, and post them publicly. Nothing was "hacked" — the agent just followed instructions it found while doing its job, with more access than that task needed.

    🗞️ Real Vulnerability, Nov 2025

    A flaw in a WhatsApp MCP integration exposed entire message histories

    Security researchers found that a WhatsApp MCP integration could be made to hand over full conversation histories — far more than any single task should have needed to touch. Like the GitHub case, the danger wasn't a dramatic break-in; it was a connection that had been granted broader reach than the job in front of it required.

    Quiz 5 · Zara's Claude was granted "Send email on your behalf," but today's task never sent anything. What's the actual risk in granting it anyway?

    ANone — a permission that's never used can't cause any problem
    BIt will definitely send a spam email at some point
    CEvery permission granted is a capability something could misuse later — only granting what a task actually needs limits what a bad prompt or a flawed connector can reach
    DIt means the connector itself is broken and needs reinstalling
    Why C? Nothing needs to go wrong immediately for unused access to be a real risk — it's exactly the shape of both real incidents above: reach that was granted but not needed by the actual task, later used for something else. "It hasn't caused a problem yet" and "it can't cause a problem" are different claims. Least privilege means granting only what today's specific task needs, not everything a connector is capable of.
    § 7

    Same Idea, No-Code Canvas — n8n's MCP Client Tool

    ⏱ 10 min

    One more place the exact same idea shows up — drawn as boxes on a canvas instead of hidden inside a chat window.

    🎙 Instructor Says

    "You've seen this shape before — Class 13's AI Agent node, with a Tool port and a Model port. Today it gets a Memory port too, and instead of hand-building an HTTP Request Tool node for every single external service, one MCP Client Tool node can plug into any MCP server that's already speaking the standard. Same USB-C idea, same canvas you already know how to read."

    The shape: a Chat Trigger node feeds an AI Agent node, same as Class 13's build. A Simple Memory node attaches to the Agent's Memory port — that's the short-term scratchpad from Section 3, now wired into a real build so the Agent doesn't lose track of the conversation turn to turn. An MCP Client Tool node attaches to the Agent's Tool port, pointed at whichever MCP server the build needs — its Endpoint URL is just the live address the server keeps open for streaming responses, and Authentication is usually "None" for a public server. The node's Tools to Include setting lets a builder pick "Selected" rather than "All" and choose just the specific tool a task needs — the same least-privilege instinct as the consent screen a section back. Once wired, opening the test chat and asking something that needs that tool lights up the MCP Client Tool node — the same Act step from the loop, just reached through the standard plug instead of a bespoke HTTP node.

    Beginner Note: notice this is the exact N×M problem from Sim 4, live in a tool you already know. Without MCP, adding a fifth external service means hand-building a fifth HTTP Request Tool node, one field at a time. With the MCP Client Tool node, it's one node pointed at one URL — and if that server later adds a sixth tool, this canvas gets it for free, with zero new nodes.

    Wrap-Up — Key Takeaways

    ⏱ 6 min

    Seven tips, four tool types, two kinds of memory, and one standard plug tying it all together.

    Six Things You Can Now Do

    SkillWhat you can now do
    Tool typesTell Search, Browser, API call, and Code apart by what job each actually does
    Routing logicExplain why rule order changes which tool a task gets sent to
    Short vs. long-term memoryDiagnose which one's missing when an agent repeats itself, today or across days
    MCP, the conceptExplain the USB-C idea to someone who's never heard of it
    MCP In ClaudeConnect a real directory connector yourself and read a consent screen critically

    Key Takeaways

    Tools aren't one thing. Search, Browser, API call, and Code are four different jobs — reaching for the wrong one gets you a confident, stale, or flatly wrong answer.

    Routing is just an ordered checklist. First matching rule wins — so put the specific, live check above the general one, on purpose.

    Memory splits into two. Short-term keeps today from repeating itself; long-term keeps tomorrow from starting at zero. Neither substitutes for the other.

    MCP is a plug, not a brain upgrade. It doesn't make the model smarter — it makes connecting a new tool a one-time job instead of a per-agent, per-tool rebuild.

    Every granted permission is a capability, used or not. The two real incidents here happened through access that was granted but not needed — least privilege isn't paranoia, it's just matching access to the task in front of you.
