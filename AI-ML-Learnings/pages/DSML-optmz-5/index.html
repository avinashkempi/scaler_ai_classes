Variants of gradient descent

Plain ("vanilla") gradient descent sums over every data point before taking a single update step. With a dataset of 10 million points, that single step becomes extremely expensive — its time complexity per update is O(n), where n is the dataset size.

Uses the entire dataset for every single update. Time complexity O(n) per step. The resulting accuracy-vs-step curve is the smoothest of the three, but each step is slow and resource-heavy.

Uses just one random data point per update — O(1) time complexity, so updates happen very fast. The trade-off: one point is a poor sample of the whole dataset, so each step's direction is noisy, and the path to the minimum has high variance — some steps even move the wrong way.

Uses k data points at a time (1 < k < n) — a compromise that updates frequently (unlike vanilla GD) while still averaging over several points for a more reliable direction (unlike pure SGD). The accuracy-vs-step curve is smoother than SGD's but less smooth than vanilla GD's.

Unifying rule: let k be the batch size out of n total points.
k valueAlgorithm
k = 1Stochastic Gradient Descent (SGD)
1 < k < nMini-batch Gradient Descent
k = nVanilla (Batch) Gradient Descent
An epoch is one complete pass through the entire dataset. With 100 data points and a batch size of 10, one epoch takes 10 iterations (updates); 10 epochs at that batch size means 100 iterations in total.

Dimensionality reduction

A dataset is written as D = {(xᵢ, yᵢ) : xᵢ ∈ ℝᵏ}, where each point lives in d dimensions. As d grows:

Visualisation

Humans can't visually interpret more than 3 dimensions directly.

Training time

Adding even one feature can blow up computation time dramatically (recall the brute-force complexity blow-up from earlier in this series).

Resources & complexity

More dimensions demand more computational resources and make the underlying mathematics harder to work with.

Principal Component Analysis (PCA) addresses all of this by reducing a dataset from d dimensions down to a smaller d′ dimensions — ideally while preserving as much of the original information as possible.

Viewed as a black box, PCA takes in data of dimension d and returns data of a strictly smaller dimension d′ (d′ < d) — never the same or larger.

When PCA works: the correlation requirement

PCA only reduces dimensions well when the original features are correlated.

Height vs. Age — weak correlation

Height rises with age only up to a point, then plateaus — a non-linear relationship with low correlation. Reducing this pair to one dimension loses meaningful information.

Height vs. Weight — strong correlation

These two features move together roughly linearly, so one combined axis can represent most of what both features capture.

Without strong correlation between features, the variance ends up spread roughly evenly across every axis — there's no single "best" direction to keep, and PCA's main benefit disappears.

The geometry of PCA

PCA proceeds in a sequence of geometric moves:

1. Center the data at its mean +
Subtract the mean point m̄ from every data point. This shifts the origin to sit exactly at the dataset's mean, so the cloud of points is now centered around (0, 0).
2. Rotate the axes to align with the data +
Find the direction along which the (mean-centered) points spread out the most, and rotate the coordinate axes so one new axis points along that direction. Call the rotated axes x_new and y_new.
3. Keep the axis with the most variance +
Projecting the points onto x_new still clearly separates the two groups (e.g. "shorter/lighter" vs. "taller/heavier" people); projecting onto y_new mixes them together. Mathematically, x_new has far higher variance — so it's kept, and y_new is dropped, achieving the dimensionality reduction.

A correlated height/weight-style point cloud. Rotate the candidate axis and watch how the variance of the projected points changes — PCA picks the angle that maximises it.

The maths behind PCA

To find the best axis mathematically, PCA looks for a unit vector ū that maximises the variance of the data once projected onto it.

x′ = (x̄ᵢ · ū) / ‖ū‖     Var(x′) = (1/n) Σ (x′ᵢ − μ)²

Since the data is mean-centered, μ = 0, simplifying variance to (1/n) Σ (x̄ᵢᵗū)². Adding the constraint ‖ū‖ = 1 and applying the Lagrange multiplier method (as covered in the previous post) turns this into an unconstrained maximisation problem.

Rewriting with matrices

Stack every data point as a row of a matrix X (shape n × d). Multiplying X·ū gives a vector v whose entries are exactly the dot products x̄ᵢᵗū — so ‖v‖² = vᵗv = ūᵗXᵗXū captures the whole sum at once:

ū* = argmaxū   (1/n)·ūᵗXᵗXū + λ(‖ū‖² − 1)

Using the identity ∇ū(ūᵗSū) = (S + Sᵗ)ū for any matrix S, and the fact that XᵗX is symmetric (so (XᵗX)ᵗ = XᵗX), the gradient simplifies to:

∇ū f(ū) = (2/n)(XᵗX)ū + 2λū

Setting this gradient to zero and rearranging produces the defining equation of PCA:

(XᵗX)ū = λ′ū  —  this is exactly the eigenvalue equation. The vector ū that maximises variance is an eigenvector of the matrix XᵗX.

What is an eigenvector?

For a square matrix S, a vector x̄ is an eigenvector if multiplying it by S only scales it — it never changes direction:

S·x̄ = λ·x̄

Here λ (the eigenvalue) is just a number that stretches or shrinks the vector; the direction of x̄ stays exactly the same before and after the multiplication.

Eigenvector vs. ordinary vector

Toggle between a vector whose direction survives multiplication by a stretching matrix (an eigenvector) and one whose direction doesn't.

Every eigenvector of a matrix has an associated eigenvalue. To reduce from d to d′ dimensions, PCA sorts all eigenvalues in descending order and keeps the d′ eigenvectors with the largest eigenvalues — these are the directions carrying the most variance.

How much information is retained?

retained = (λ₁ + λ₂ + … + λ_d′) / (λ₁ + λ₂ + … + λ_d)

For example, keeping two eigenvectors with eigenvalues 0.5 and 0.3 out of a total that sums to 1.0 retains 80% of the dataset's information while discarding the remaining 20% along with the dropped dimension.

Implementing PCA

Step-by-step pipeline:
  1. Standardise every column: subtract the column mean and divide by its standard deviation.
  2. Compute the covariance-like matrix XᵗX from the standardised data.
  3. Eigen-decompose that matrix to get its eigenvalues and eigenvectors.
  4. Select the eigenvector(s) with the largest eigenvalue(s) and project the standardised data onto them to get the reduced-dimension result.

In practice this is implemented either manually with NumPy's linalg.eig on the XᵗX matrix, or directly via scikit-learn's decomposition.PCA, which performs the same standardisation, eigen-decomposition, and projection internally.
