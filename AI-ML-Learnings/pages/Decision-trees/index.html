Review
Recap from Lecture 8
⏱ 4 min

Last session we extended KNN and tackled imbalanced data:

  • KNN for multiclass — same majority vote, no modifications needed
  • Outliers and KNN: larger K is more robust, small K memorizes noise
  • KNN-based imputation: find K similar rows, average their missing-column values
  • Imbalanced data — Weighted Loss, Undersampling, Oversampling, SMOTE
  • Decision Tree intuition: axis-parallel splits → interpretable if/else rules
📌 Why Move Beyond KNN?
KNN requires comparing every new point against the entire training set at inference time — O(n·d). For large-scale production systems, that's prohibitively slow. Decision Trees learn the split rules during training and apply them in O(depth) at prediction time.

Business Context
Use Case: Employee Attrition at Jio
⏱ 4 min

You are a Data Scientist at Jio. The company is losing employees at an alarming rate — employee attrition is costing significant resources:

  • New hires demand higher salaries
  • Training new employees takes time and money
  • Searching for and evaluating candidates is expensive

Two Business Goals

  1. Predict which employees are likely to leave, so targeted retention efforts can be applied before they decide
  2. Identify key factors driving attrition — overtime? salary? manager relationships? — so the company can take structural action
🤔 Why Not Rely on Assumptions?
We might assume employees leave due to mandatory office days or toxic culture. But assumptions can be wrong. Data analysts rely on data — not intuition. Let's find the real drivers from the dataset.

Decision Tree Intuition & Axis-Parallel Splits
⏱ 6 min

Consider attrition data plotted on two axes: Age and OverTime. The data is non-linearly separable — Logistic Regression can't handle it. KNN can, but can't be productionized at scale.

Instead, we ask a sequence of simple yes/no questions that slice the feature space with axis-parallel hyperplanes:

  • Is Age < 29? → Left branch
  • Does the employee work Overtime ≥ 2.5 hrs? → Further split

Each split creates two homogeneous subregions, each containing mostly one class. These regions are then converted into if/else rules — the decision tree.

Why Decision Trees Are Interpretable

Each path from root to leaf is a plain-English rule. Example conclusion from the attrition tree:

"Employees younger than 29 who work overtime ≥ 2.5 hours are more likely to churn."

The HR team can directly act on this: incentivise overtime for young employees or reduce their workload.

What Does the Tree Learn?

Training a DT means automatically learning the best split conditions from data. To do this, we need a way to measure how good any given split is. That requires quantifying node purity.

💎
Concept
Node Purity — Why It Matters
⏱ 4 min

When a new data point reaches a leaf node, the Decision Tree predicts the majority class of that node. So prediction confidence equals the majority class fraction.

  • Node with 90 negative, 10 positive → predicts Negative with 90% confidence
  • Node with 50 negative, 50 positive → predicts Negative with only 50% confidence (pure guessing)

Choosing the Better Split

✅ Preferred

Option 1 — More Homogeneous

Each child node is dominated by a single class. The model predicts with high confidence.

⚠️ Avoid

Option 2 — Mixed Nodes

Child nodes still have 60/40 splits. Model is only 60% confident — barely better than guessing.

Objective: Always choose the split that creates the purest child nodes. We measure purity using Entropy.

🌡️
Math
Entropy — Measuring Node Impurity
⏱ 8 min

Entropy (borrowed from Information Theory) quantifies how uncertain or heterogeneous a node is. High entropy = mixed classes = low prediction confidence.

Formula — Binary Classification

H(Y) = −p · log₂(p) − (1−p) · log₂(1−p)

where p = P(Y = 1) = fraction of positive class samples in the node.

The Jar Analogy

Imagine 4 jars of red and blue balls. You must pick a ball and predict its colour:

🫙
Jar 1
50 red, 50 blue
Entropy = 1 (max)
🫙
Jar 2
70 red, 30 blue
Entropy ≈ 0.88
🫙
Jar 3
0 red, 100 blue
Entropy = 0 (min)
🫙
Jar 4
100 red, 0 blue
Entropy = 0 (min)

Jars 3 and 4 are pure — you're 100% certain what you'll pick. Jar 1 is maximally uncertain. A DT tries to create nodes like Jars 3 and 4.

Key Properties

WhenEntropy ValueMeaning
p = 0 or p = 1 (pure node)0Perfectly homogeneous — maximum confidence
p = 0.5 (equal classes)1Maximum uncertainty — worst case for prediction
0 < p < 1Between 0 and 1Partial purity

When Is Entropy Minimum?
⏱ 1 min
In which of the following cases will the entropy be minimum?
  • A node with all datapoints belonging to one class only.
  • A node with datapoints belonging to both classes equally.
  • A node with 100 datapoints where only one belongs to the positive class.
  • Entropy is independent of the proportion of datapoints.
💡 Explanation
Entropy = 0 only when p = 0 or p = 1 — i.e., all points belong to a single class (pure node). Even one point from the other class raises entropy above 0.

Math
Information Gain — Choosing the Best Split
⏱ 10 min

With 100 datapoints and 2 features (Gender, Age<35), the root node has high entropy (≈ 0.97). We need to decide which feature to split on first.

The Algorithm

1

Calculate parent entropy

H(parent) — the current node's impurity before any split

2

Try splitting on each feature

For each candidate feature, compute the resulting child nodes

3

Compute weighted child entropy

Weight each child's entropy by the proportion of points it contains (not a simple average — larger children should count more)

4

Calculate Information Gain

IG = H(parent) − Weighted H(children). Higher IG = better split.

5

Pick the feature with maximum IG

This becomes the split criterion for the current node

IG = H(parent) − Σⱼ (nⱼ/n) × H(childⱼ)

Worked Example

FeatureParent EntropyWeighted Child EntropyInformation Gain
Gender0.970.880.091
Age < 350.970.710.257 ← pick this

Age<35 has higher IG → it becomes the root split. The tree then recursively repeats this process on each child node until leaves are sufficiently pure (or stopping criteria are met).

Quiz 4
Information Gain — Which Statement Is False?
⏱ 1 min
Which of the following statements about Information Gain is false?
  • Information Gain is defined as the reduction in entropy.
  • We want to maximize Information Gain.
  • It is calculated by subtracting the weighted child entropy from the parent entropy.
  • It is calculated by subtracting the parent entropy from the weighted child entropy.
💡 Explanation
IG = Parent entropy − Weighted child entropy (not the other way around). This gives a positive number when splitting reduces entropy, which we want to maximize.
🔢
Concept
Splitting on Numerical Features
⏱ 3 min

For categorical features, the DT splits on each distinct category. For numerical features (like Age, MonthlyIncome), it uses a threshold-based approach:

  1. Sort the feature values in ascending order: n₁ ≤ n₂ ≤ … ≤ nₙ
  2. Try each value as a threshold: f < nᵢ vs f ≥ nᵢ
  3. Compute IG for each possible threshold
  4. Pick the threshold that maximizes IG
⚠️ Time Complexity Problem
For a feature with 1,000 unique values, this requires computing 1,000 different IGs at every node — very expensive. Solution: bin the values first (e.g., Age → [20,30), [30,40), [40,50), [50,60]) to reduce the number of thresholds to evaluate.
⚡
Math
Gini Impurity — A Faster Alternative
⏱ 3 min

Entropy requires computing log at every node for every feature — computationally expensive. Gini Impurity is a faster approximation:

Gini(Y) = 1 − Σ p(yᵢ)²

For binary classification: Gini = 1 − p² − (1−p)²

IG Using Gini

IG = Gini(parent) − Σⱼ (nⱼ/n) × Gini(childⱼ)
PropertyEntropyGini Impurity
Range[0, 1][0, 0.5]
ComputationRequires log — slowerNo log — faster
Sklearn defaultOpt-in (criterion='entropy')✅ Default (criterion='gini')
ResultsUsually very similar in practice

Implementation
Sklearn Implementation
⏱ 5 min

Train a Default DT (No Depth Limit)

from sklearn.tree import DecisionTreeClassifier

model = DecisionTreeClassifier(criterion='entropy')
model.fit(X_train, y_train)

print("Test accuracy: ", model.score(X_test, y_test))
print("Train accuracy:", model.score(X_train, y_train))
Output
Test accuracy: 0.7527 Train accuracy: 1.0000
🚨 Classic Overfitting Signal
Train accuracy = 100%, Test accuracy = 75%. The model has memorized every single training point. It needs regularization via depth control.

Visualize the Tree

from sklearn.tree import plot_tree
import matplotlib.pyplot as plt

plt.figure(figsize=(14, 14))
plot_tree(model, filled=True)
plt.show()

An unconstrained tree with entropy criterion can grow very deep — sometimes 20+ levels — creating a highly complex structure that overfits the training data.

⚖️
Concept
Overfit vs Underfit in Decision Trees
⏱ 4 min

Why Does Deep = Overfit?

As the tree grows deeper, each leaf receives fewer data points. Eventually, leaves may contain only 1–2 points — which could be outliers or noise. The tree memorizes them as genuine patterns.

  • Deep tree: pure leaves → 100% train accuracy → memorizes noise → high variance → overfits
  • Shallow tree (Decision Stump, depth=1): one split → too few boundaries → high bias → underfits
  • Right depth: balanced bias-variance → generalizes well
Tree TypeTrain AccuracyTest AccuracyBiasVariance
Deep (unconstrained)100%75%LowHigh
Tuned depth~85%~83%MediumMedium ✓
Shallow (depth=1)~60%~58%HighLow

HyperparameterDefaultEffect

min_samples_split2Min samples needed to split a node. Higher = shallower tree.

Finding Best max_depth via 10-Fold CV

from sklearn.tree import DecisionTreeClassifier
from sklearn.model_selection import KFold, cross_validate

kfold = KFold(n_splits=10)
depths = [3, 4, 5, 9, 11, 13, 15]

for depth in depths:
    clf = DecisionTreeClassifier(random_state=7, max_depth=depth)
    cv = cross_validate(clf, X_train, y_train, cv=kfold,
                        scoring='accuracy', return_train_score=True)
    print(f"depth={depth}  Train: {cv['train_score'].mean()*100:.1f}%  Val: {cv['test_score'].mean()*100:.1f}%")
Output (abbreviated)
depth=3 Train: 78.3% Val: 75.1% depth=4 Train: 82.1% Val: 76.2% depth=5 Train: 85.9% Val: 79.6% depth=9 Train: 97.1% Val: 82.8% ← val plateaus depth=11 Train: 98.9% Val: 82.8% depth=13 Train: 99.8% Val: 82.5% depth=15 Train: 100% Val: 82.9%

Validation accuracy plateaus around depth=9. Train accuracy keeps climbing toward 100% — a sign of overfitting without meaningful generalization gain. Best choice: max_depth=4 (good balance, lower variance, not overfit).

AI-Assisted Diagnosis

💡 Practical Tip
When a model shows Train=100%, Val=76%, you can ask an LLM: "My DT achieved Training Accuracy 100%, Validation 76%. What does this indicate and which hyperparameter should I tune first?" — it will correctly identify overfitting and suggest reducing max_depth first.

Interpretation
Feature Importance
⏱ 3 min

Recall our second business goal: identify which factors actually drive attrition. Decision Trees give us this directly through Feature Importance.

How It's Calculated — Normalized Information Gain

If feature fᵢ is used at two splits in the tree:

  • Split 1: n₁ = 5,000 points, IG₁ = 0.3
  • Split 2: n₂ = 500 points, IG₂ = 0.5
Importance(fᵢ) = (n₁ × IG₁ + n₂ × IG₂) / total_n

This normalized IG weights each split's contribution by how many samples it affected. Features used early (on more data) and with higher IG are naturally scored higher.

import numpy as np

importances = tree_clf.feature_importances_
indices = np.argsort(importances)[::-1]
names   = [X_train.columns[i] for i in indices]

plt.figure(figsize=(15, 7))
plt.title("Feature Importance")
plt.bar(range(X_train.shape[1]), importances[indices])
plt.xticks(range(X_train.shape[1]), names, rotation=90)
plt.tight_layout()
plt.show()
📌 Business Value
The feature importance bar chart directly answers our second business goal — it tells HR which attributes (OverTime? Age? MonthlyIncome?) are the strongest predictors of attrition, guiding concrete retention policies.

Reference
Interview Questions on Decision Trees
⏱ 8 min
Terminology
What are Deep Tree, Shallow Tree, and Decision Stump?
Deep Tree: many levels → pure leaves → overfits. Shallow Tree: few splits → few boundaries → underfits. Decision Stump: depth=1 (one split only).
Outliers
Where do outliers have more impact — deep or shallow trees?
Deep trees — a deep leaf may contain only the outlier itself, causing the tree to memorize it as a real pattern. Shallow trees have many points per leaf, diluting the outlier's impact.
Imbalanced Data
Is DT affected by class imbalance?
Yes — it will bias splits toward the majority class. Fix: use class_weight in sklearn DT, or apply Oversampling/SMOTE before training.
Standardization
Does DT require feature scaling?
No. DT splits based on thresholds (relative ordering of values). Standardizing a feature doesn't change which points are above/below any threshold — so entropy and IG are unaffected.
Multiclass
Can DT handle multiclass problems?
Yes — naturally. At a leaf with y1=300, y2=20, y3=10, it predicts y1 (majority class). No OvR strategy needed — entropy generalizes to K classes.
Same Column Twice
Can the same feature be used for multiple splits?
Yes. Age<35 might split at the root, and Age<29 might appear again deeper in the tree (a different threshold). This is valid and happens when the feature is highly informative at multiple scales.

Space & Time Complexity

Space
O(m)
m = number of nodes stored in memory
Prediction Time
O(d)
d = depth — follow one root-to-leaf path
Build Time
O(n·log(n)·f)
n = samples, f = features — sort each feature at each node

Decision Trees for Regression

For continuous targets (e.g., predicting student marks), DT uses MSE instead of Entropy/Gini as the impurity measure. The predicted value at each node is the mean of all target values in that node. Splitting still maximizes the reduction in MSE (weighted average of children's MSE).

Wrapping Up
⏱ 3 min
DTs split feature space into homogeneous regions via axis-parallel hyperplanes
Interpretable: each root-to-leaf path is a plain-English rule
Node purity = how dominated by a single class
Entropy: 0 (pure) to 1 (maximally impure at p=0.5)
IG = Parent entropy − Weighted child entropy
Always pick the split that maximizes IG
Weighted child entropy (not simple average) accounts for node sizes
Gini Impurity: no log, faster — default in sklearn
Numerical features: try every threshold, pick max IG
Deep → overfit (low bias, high variance)
Shallow → underfit (high bias, low variance)
Tune max_depth via cross-validation on validation set
DTs don't need feature scaling — threshold splits are scale-invariant
Feature importance = normalized weighted IG across all splits
Regression DT: MSE as impurity, mean as prediction
Prediction time: O(depth) — production-friendly
Decision Trees are powerful and interpretable — but prone to overfitting. Next lecture: Random Forests combine many trees to produce models that are more robust, more accurate, and less prone to overfitting than any single tree.
