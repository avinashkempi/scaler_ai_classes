What to noticeEach problem has a planned outcome. A bad row is quarantined, a broken rule is resolved by policy, a missing source stops the run, and an outside failure is retried and then reported. Nothing is guessed, and nothing disappears.

What happens to a bad row?The loader refuses itIt is quarantined with its file, line, category, reason and raw row

    
How do we know no row was lost?We do not checkaccepted + quarantined == input, proved on every file

    
What if a file is mostly bad?The run carries onThe quality gate halts above 5 percent, and an empty file halts too

    
What if a required file is missing?A crash with a long tracebackA clear HALTED: message on stderr, and exit code 2

    
What if the same batch runs twice?Everything is done againA batch ID finds the finished batch, and no work or model call is repeated

    
What if the model call fails?A recorded answer fills inBounded retries, then UNAVAILABLE with the reason. The facts stay in the report

    
How big is the golden set?10 cases12 cases, with an AMBIGUOUS and an INSUFFICIENT case added

  


  

    
How the class climbed, in order

    
    
      
  1. Name the failuresFour kinds: a malformed record, a broken rule, a missing source, and an outside service failure. Each has its own error name and its own outcome.
    2. 
      
  2. Read each field carefullytry, except, else and finally, plus raise ... from, so the original cause is never lost.
    3. 
      
  3. Quarantine, then countBad rows go to quarantine.csv before any gate runs. Then the quality gate and the reconciliation check do the sums.
    4. 
      
  4. Name the batchA batch ID from the files and settings, an attempt ID per run, an add-only log, and summary.json written last.
    5. 
      
  5. Retry with limitsOnly timeouts, rate limits and server errors are retried, with growing, random waits and a hard cap on attempts.
    6. 
      
  6. Never invent an answerOK, ABSTAINED, INVALID_REPLY or UNAVAILABLE. Eight failure checks prove all of it with no key.
    7. 
    

  

  
The sentence to rememberCount every row, stop when the batch is not trustworthy, and say unavailable instead of guessing.

Why this order?Required files come first, because there is nothing to count without them. Quarantine is written before the gates, so a halted run still leaves a worklist. The model is only called after the batch has passed, and summary.json is written last, because it means "finished".

The gates and the model statuses

  

  

    
You wantRemember

    
The order of the gatesRequired files, then the quality gate (limit 5 percent, empty file halts), then reconciliation

    
The sum that must holdaccepted + quarantined == input rows

    
A batch nameB- plus 12 characters from a hash of the date, the rules and the files
