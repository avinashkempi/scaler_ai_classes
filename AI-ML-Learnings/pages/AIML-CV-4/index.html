How computers compare pictures: why pixel matching fails, how embeddings describe images, how a pretrained CNN becomes a feature extractor, and what Inception and ResNet contribute.

01

Same backbone idea, a different question

In the transfer-learning post we kept a pretrained backbone and trained a new head to answer "Which of these 10 landmarks is this?", which needed labelled data for every class. Today's question is different: "Which images look most like this one?" Nobody gives us labels for "looks like".

There is also a loose end: VGG16's fully connected layers hold about 124M of its 138M parameters, which makes it heavy. We will meet lighter, stronger backbones (GoogLeNet and ResNet) and pick one.

The bridge idea

At the end of the backbone, every image has already been turned into a long list of numbers that describes it. Before, we passed that list to a classifier. What if we stop there and compare the lists directly? Two images with similar lists should look alike. Will two photos of different dogs be closer than a dog and a car? Probably yes, because the backbone was trained to tell such things apart; we will test it rather than assume it.

02

What is image similarity?

Image similarity measures how alike two images are. Using it to search a collection for pictures that look like a query picture is called reverse image search or visual search.

Problem statement

You are a data scientist at a Pinterest-like company. Given a query image, return the most similar images from millions of others, with no hand-written tags.

Use caseWhat it does
Visual search (Google Images, Pinterest, shopping apps)"Show me products that look like this photo."
"Celebrity look-alike" appsCompare a face to a gallery of faces.
Browsing and clusteringGroup an unlabeled archive, or an online shop's items, by visual similarity.
Duplicate removalFind duplicate or near-duplicate images in a training set. Duplicates cause leakage between train and test.
Recommendation"If you liked this, you may like these."
03

Why not just compare pixels?

The obvious idea: subtract two images pixel by pixel and sum the squared differences. Test it on a tiny example. Image A has a white disc on the left. Image B has the same disc, shifted. Image C is completely black. Which is "closer" to A in pixel distance, B or C?

A pixel-by-pixel difference compares positions, not content. Moving an object a little, rotating it, changing the lighting, or cropping differently changes almost every pixel, even though a human sees "the same thing". The meaning of an image lives in how pixels relate to each other, not in individual pixel values.

So we need a description of the image's content that does not change when the object moves a little. That description is what a CNN's feature extractor already computes.

04

Embeddings

A vector is an ordered list of numbers, like [0.2, -1.5, 3.1]. Its dimension is how many numbers it has: this one has 3. Computers are good with numbers, so we want each image to become one vector.

Definition

An embedding is a vector that captures the meaning of an image, so that images with similar content get vectors that are close together. For a CNN we take the output of the backbone, the part just before the head; for ResNet-50 it has 2048 numbers.

Think of it as GPS coordinates for meaning: two nearby coordinates mean two nearby places, and two nearby embeddings mean two images with similar content. Real embeddings have 2048 dimensions, which we cannot draw, so here is a 2-D toy version.

    05

    Two ways to measure “close”

    Let a and b be two embeddings.

    • Euclidean distance is the straight-line distance between the two points: sqrt(sum((a_i − b_i)²)). Smaller means more similar.
    • Cosine similarity measures the angle between the vectors, ignoring their lengths: (a · b) / (|a| |b|). It ranges from −1 to 1, and bigger means more similar. The dot product is sum(a_i × b_i) and |a| is the vector's length.

    L2 norm and L2 normalization

    The L2 norm |a| = sqrt(sum(a_i²)) is the vector's length. L2 normalization divides a vector by its length so every vector has length exactly 1; only the direction is left. Two embeddings can point in the same direction but have different lengths, for example because of image brightness or contrast.

    The takeaway

    After L2 normalization, Euclidean distance and cosine similarity produce the same ranking for nonzero vectors normalized to unit length: smaller Euclidean distance means greater cosine similarity. For unit vectors, squared Euclidean distance equals 2 − 2 × cosine similarity. Remember: their numerical values are not the same; only their rankings are equivalent.

    Code and output 
    a = np.array([3.0, 1.0])
b = np.array([6.0, 2.0])  # Same direction as a, but twice as long
c = np.array([1.0, 3.0])  # Different direction

def euclid(u, v): return float(np.linalg.norm(u - v))
def cosine(u, v): return float(u @ v / (np.linalg.norm(u) * np.linalg.norm(v)))
def l2n(u): return u / np.linalg.norm(u)

    06

    From classifier to feature extractor: remove the head

    A classification CNN has a backbone (convolutional layers that turn an image into a feature vector) and a head (a classifier that turns that vector into one score per class). For similarity we cut the network just before the head and use the vector as the embedding. Using the model only to produce outputs, with no training, is called inference.

    Visualizer · Keep the head, or cut it?

    Image classificationImage similarity
    OutputOne of a fixed set of labelsA vector, then a ranked list of neighbors
    Information keptOnly what separates the known classes; the rest is thrown awayMuch more: colour, shape, texture, scene, many aspects at once
    New categoriesNeed retrainingWork without retraining, since we only compare vectors
    Labels neededYesNo (only to evaluate)

    That is why the vector before the head is richer than the final label: the head squeezes it down to a few class scores.

    07

    Choosing a backbone: why not VGG16?

    VGG16 is slow and large: about 138M parameters, most of them in the three fully connected layers at the end. For a search system that must embed millions of images we want a backbone that is smaller, faster and more accurate. Do you expect the most accurate model to be the one with the most parameters? Look at the numbers, read from torchvision's record of each pretrained model.

    Visualizer · Four ImageNet backbones

    ModelParams (M)Top-1 %Top-5 %Embedding length
    • Top-1 accuracy = the fraction of images where the model's single best guess is correct; top-5 = where the right answer is among its five best guesses.
    • VGG16 uses by far the most parameters, yet ResNet-50 is more accurate with about a fifth of them, and GoogLeNet comes close with roughly a twentieth. Bigger is not better by itself; the design matters.
    • The numbers come from torchvision's weights, so they may differ slightly from the original papers.

    Embedding length and storage

    With the head cut off, each backbone gives a vector of a different length. Shorter vectors are cheaper to store and search.

    Visualizer · Storage for an image collection

    Stored as float32 (4 bytes per number).

    How did they get smaller? Global average pooling

    Most of VGG16's weight sits in its fully connected layers. GoogLeNet and ResNet avoid them with global average pooling (GAP): for each channel (feature map), take the average of all its values. A map of size C × 7 × 7 becomes just C numbers. No big fully connected layer is needed, and the output length no longer depends on the image size.

    Inception (GoogLeNet): look at several scales at once

    GoogLeNet won the 2014 ImageNet competition. Its name, Inception, is a joke on the film: researchers wanted to "go deeper".

    How big should a filter be? An object that fills the picture (a field of wheat) is best seen with a large filter; a small detail (a bird) with a small one. Instead of choosing, let the network use several at once and keep what helps. An Inception module runs four branches in parallel on the same input, then concatenates their outputs along the channel axis (puts the stacks of maps side by side).

    The 1×1 convolution: the cheap channel mixer

    A 1×1 convolution sounds silly: a kernel of one pixel just multiplies each pixel by a number. But on an input with many channels, it gives each channel its own weight and adds them up at every pixel. That is a learned mix of channels, and it can change how many channels there are. This makes it a bottleneck: squeeze the channels first with a cheap 1×1 convolution, then apply the expensive 3×3 or 5×5 convolution to the thinner stack.

    09

    ResNet: how to go very deep without breaking training

    Inception showed that smart design beats raw size. The natural next question: accuracy rose as networks got deeper, so why not build a 500-layer network?

    The problem: vanishing gradients

    Training adjusts every weight using its gradient: how much the loss changes if that weight changes. Gradients are computed by backpropagation, which starts at the last layer and passes the signal backward, multiplying by a number at every layer. If those numbers are mostly below 1, the signal shrinks at every step; after many layers it is almost zero, so the earliest layers hardly learn. This is the vanishing gradient problem. If the numbers are above 1, the signal blows up: the exploding gradient problem.

    Visualizer · Gradient signal through depth

    Each layer multiplies the backward signal by the same number m. The chart shows log₁₀ of the signal at each layer counted from the output.

    The fix: the skip connection

    ResNet (Microsoft Research, winner of ImageNet 2015) adds a skip connection (a shortcut): the block's input is added directly to its output.

    output = F(x) + x

    Here F(x) is what the block's convolutions compute. A block built this way is a residual block. Two things follow:

    1. The block only has to learn the residual F(x) = desired output − x, the small correction to the input. If the best thing is to change nothing, it can learn F(x) ≈ 0.
    2. During backpropagation the gradient has a direct path back through the + x, so it does not have to pass through every layer's multiplication.
