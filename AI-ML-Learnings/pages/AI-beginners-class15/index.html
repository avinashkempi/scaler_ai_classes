§ 1

Concept — Brains, Tools & Chaining

⏱ 12 min

Quick recap, then two genuinely new ideas: which brain you're plugging in today, and what it actually means for an agent to use more than one tool in a row.

🎙 Instructor Says

"Class 13 introduced the AI Agent node as a first look — concept only. Class 14 built one, wired to two directory connectors inside Claude. Today's different in one specific way: you're connecting the brain yourself, by API key, and choosing what it's allowed to reach for. That's the difference between using someone else's finished assistant and actually building the agent from its parts."

The Brain

The actual language model doing the reasoning — attached to the Agent node by an API key, not built in. Today's brain runs on Groq, the fast-inference API. Swap the key and model name later, and the rest of the build doesn't change — that's the whole point of the Agent/Model split.

Tool Chaining

An agent calling more than one tool in a single run, using what one tool returned to decide what to do next — not a fixed sequence you wrote in advance. Search first, then write, only because the brain decided that order made sense for this task.

🕵️
Hiring A Researcher, Not Buying A Search Engine

A search engine gives you links back. What you're building today is closer to hiring a junior researcher: give them a mind (the brain), a search subscription and a stack of blank documents (the tools), and a notepad (memory) — then hand them a topic and let them decide, on their own, what to look up first and when they've got enough to write something up.

Getting Groq's API key — do this now, it takes two minutes: go to console.groq.com, sign up with email, Google, or GitHub (no credit card needed), and you land straight on the dashboard — Groq's free tier is rate-limited, not a dollar credit, so there's nothing that expires. Open API Keys → Create API Key and copy it somewhere safe; it's shown to you exactly once. We'll use it in Build 1.
Beginner Note — which model: Groq hosts several open-weight models on its own fast-inference hardware; today we're using GPT-OSS 20B — the cheapest, fastest option in the lineup, plenty capable for research-and-summarize work, and comfortably inside the free tier's rate limits for a whole classroom. Model names shift fast in this industry — if you don't see that exact name, pick whichever is listed as the cheapest/fastest current Groq model.
Concept preview — sub-workflow as a tool: n8n lets an entire separate workflow be wired in as a single callable tool for an agent — handy for reusing a complex routine across several builds without redrawing it each time. We're not building this today (it's Build 3's closing concept note), but keep it in mind as "what's next" once today's shape feels familiar.

Quiz 1 · In today's build, what's the actual difference between "the Chat Model" attached to the AI Agent node, and "a Tool" attached to it?

AThey're two names for the exact same connection
BThe Chat Model is what reasons and decides what to do; a Tool is a capability it can call to actually act on the world
CA Tool is required for the Agent to run at all; the Chat Model is optional
DYou can only ever attach one Tool to a single Agent node
Why B? The Model port is the brain — it's what thinks, plans, and decides which tool (if any) a step needs. The Tool port is the hands — each attached tool is one specific capability (search the web, write a doc, do math) the brain can choose to invoke. Neither is optional and neither is a stand-in for the other: no Model means nothing can reason at all; no Tools means the brain can only talk, never act.
§ 2

Build 1 — n8n's Smallest Research Agent

⏱ 18 min

Smallest thing that genuinely works: a trigger, a brain, one tool. Get this running before anything else gets added.

Two Free Accounts You Need First

▸ Do this live, together — takes about 4 minutes total
  1. Groq (the brain): at console.groq.com, sign up with email, Google, or GitHub — no card. You land on a dashboard with a free, rate-limited tier already active. Open API Keys → Create API Key and copy it.
  2. SerpApi (the search tool): at serpapi.com, sign up free — no card. The free plan covers roughly 100 searches a month, plenty for today. On your dashboard, copy the Private API Key.
Beginner Note — real cost check: GPT-OSS 20B on Groq's free tier costs nothing to run — it's metered in requests-per-minute, not dollars. A room of 40 people each running this two or three times stays well inside the limit — nobody needs to worry about the bill today.

The Build

▸ Node by node
  1. Open the n8n workflow you already built in Class 14 — do not start a new one. That workflow has a Chat Trigger and an AI Agent node on it already; today's build extends it with a real search tool. If you genuinely don't have it (missed that class, or it's gone), only then create a new workflow and add a Chat Trigger node — same hosted test-chat window from Class 13, no account needed.
  2. Confirm an AI Agent node is connected after the Chat Trigger. It should already be there from Class 14 — if not, add one now.
  3. Click the dangling connector under the Agent labeled Chat Model. Search Groq, add the Groq Chat Model node. Create a new credential, paste your Groq API key, save. Set the model to openai/gpt-oss-20b (or whichever is listed as the current cheapest/fastest Groq model).
  4. In the Agent's System Message / prompt field, replace whatever's there with: You are Groundwire's research assistant. When asked to search a topic, search for current, real information and summarise it clearly with sources.
  5. Click the Agent's Tool connector, search SerpApi, add it as a Tool. Create a new credential with your SerpApi key, save.
  6. On the SerpApi tool node, set Search Query (q) to Defined automatically by the model, and set its description to The query that the user is asking. Then open Additional Fields and add a new field named jsonRestrictor; in its input box write something like organic_results[1:2]. This tells the search API not to return its entire JSON result — just a small slice of it. Without this, the full unfiltered response goes straight to the LLM and can blow past its token limit, causing errors. Limiting the response at the API level avoids that entirely.
  7. Open the test chat (top bar) and type something simple to confirm the wiring works, e.g. Search for "Herbivorous" and tell me what you find.
What to watch for (the ReAct loop, running for real): the Agent names the tool it's about to call before calling it (Think), the SerpApi node lights up as it runs (Act), and the reply that comes back references specific results rather than a vague, generic summary (Observe feeding the final answer). This is Class 13's loop, on a real topic, for the first time.
⏱ Compression flag: if signups are eating the clock, pre-create both accounts and share one demo API key pair with the room via chat — get everyone to a working test chat first, then circle back to "get your own key" as the very first take-home item.

Build 2 — Give It Hands & A Notebook

⏱ 16 min

One new idea, in two small pieces: somewhere to actually write the output, and somewhere to remember what it already found.

Add Google Docs — As A Step After The Agent, Not As A Tool

▸ Node by node
  1. If you haven't already connected a Google account in n8n (from Class 11 or 14), do that first — Credentials → New → Google Docs → sign in and approve.
  2. Don't click the Agent's Tool connector this time. Instead, drag a plain Google Docs node onto the canvas from the regular node panel, and connect it to the AI Agent node's own main output — the same kind of connection Chat Trigger → AI Agent uses, not the Tool/Memory ports underneath it.
  3. In your Drive, create one blank Google Doc yourself first (e.g. titled Research Brief) and copy its URL — this is the doc every run will write into. Set the node's operation to Update Document, not Create Document. In the Doc ID / URL field, paste that URL. Under its actions, add one action, and in Action Field 1's Text input, switch to Expression and map it to the Agent's finished reply: {{ $('AI Agent').item.json.output }}
  4. SerpApi stays the Agent's only Tool. Google Docs now runs automatically, once, right after the Agent finishes replying, updating that same document every time — not something the Agent decides to invoke.
Why not just add it as a second Tool — the actual bug you'll hit: when a big-output node like Google Docs sits on the Agent's Tool port, the model has to reproduce the entire document body as an escaped string argument inside its own tool-call JSON — it's regenerating the whole brief a second time, inside a function call, instead of just handing off text it already wrote. That's exactly where long research briefs blow past what a fast, smaller model like Groq's oss-20b can reliably produce — the call comes back truncated or malformed, and nothing lands in the doc. This is a well-documented n8n community pain point, not something you did wrong. Wiring Docs downstream instead means the already-finished text just flows through as ordinary node data — no regeneration, no JSON-escaping, and no token ceiling on the write step at all.

Add Short-Term Memory

▸ Node by node
  1. Click the Agent's Memory connector, search Simple Memory, add it. No configuration needed beyond the default.
  2. This is exactly the short-term memory node from Class 14's memory section — a scratchpad for this run, gone once the session ends.

Test It

In the test chat: "Research AI-powered flood early-warning systems — what's actually being deployed in 2026? Give me 3-4 key points with sources." Google Docs fires automatically once the Agent replies — open the doc whose URL you pasted and you'll see it now holds that reply. Then, without repeating the topic, follow up in the same chat: "Add a one-line caveat about the biggest adoption blocker, and give me the complete updated brief." That second reply triggers Google Docs again, writing the updated brief — caveat folded in — into that same document.

Advanced Note — that follow-up only worked because of memory: without Simple Memory, "add a one-line caveat" is a sentence fragment with no topic attached — the Agent has no idea what to caveat, let alone what the "complete updated brief" should contain. With it, the scratchpad still holds the topic and what it already found, so the follow-up resolves correctly and the Docs step downstream has a full, fresh brief to save. This is short-term memory earning its keep, not just a theory slide.
Beginner Note — not every action needs to be a Tool: SerpApi sits on the Tool port because the Agent genuinely has to decide, mid-run, whether and when to search. Saving the finished brief doesn't need that kind of judgment call — it happens every time, after the Agent is done. Treating it as a deterministic step instead of a Tool is what makes it reliable.

Quiz 2 · SerpApi is wired to the Agent's Tool port; Google Docs is wired to the Agent's main output instead. Why the different wiring for the two?

An8n only allows one Tool per Agent node, so Docs had nowhere else to go
BSerpApi needs the Agent to actively decide, mid-run, whether and when to call it — but writing the finished brief is a fixed last step, and making the model regenerate the whole document inside a tool-call argument is exactly what caused the token-limit failures
CGoogle Docs isn't compatible with AI Agent workflows in n8n at all
DWiring position is arbitrary — both ports behave identically either way
Why B? A Tool is for something the model needs to reason about calling — SerpApi, because search is only useful if and when the Agent decides it needs fresh information. Google Docs doesn't need that judgment call here; it always runs once the Agent is done. Putting it on the Tool port anyway forces the model to reproduce the entire finished document as a JSON argument inside its own tool call — regenerating text it already wrote, which is exactly where longer briefs exceeded what the model could reliably output. Downstream wiring passes the same text through as plain node data instead — same result, without the regeneration step that was breaking it.
§ 4

Build 3 — Make It Reliable

⏱ 14 min

No new node types today — just settings that decide what happens when something actually goes wrong, plus deliberately breaking it to check.

Max Iterations

Open the AI Agent node → Options (or Settings, depending on your n8n version) → find Max Iterations and set it to 8. This caps how many tool calls a single run can make before the Agent is forced to stop and return whatever it has — the same safeguard from Class 11's Build 3, now protecting a build that can genuinely loop on ambiguous research tasks.

Retry On Fail

On both nodes that call an external service (the SerpApi tool and the Google Docs step), open Settings → toggle Retry On Fail ON, set Max Tries to 3. A single dropped connection or a slow API response no longer kills the whole run.

Break It On Purpose

▸ Two deliberate test prompts
  1. Empty-results test: Research the 2026 quarterly filings of a startup called "Nexolume Grid Systems." — this company doesn't exist. Watch for the agent to report it couldn't find credible information, not invent numbers to fill the gap.
  2. Too-broad test: Research artificial intelligence. — vague enough to trigger many searches. Max Iterations should cut it off with a partial, honest answer rather than spiralling.
Concept only — sub-workflow as a tool: a whole separate n8n workflow (say, a 10-step fact-checking routine) can be wired in as one callable tool via the Execute Workflow Tool node type — the Agent calls it exactly like it calls SerpApi. Not building this today; it's take-home challenge 3.

Quiz 3 · Max Iterations is set to 8 and you ask a genuinely impossible research question. What should actually happen?

AThe agent keeps trying indefinitely until you close the tab
BThe whole n8n workflow crashes and needs to be rebuilt
CAfter 8 tool calls, the agent stops and returns whatever it has instead of looping indefinitely
DMax Iterations only limits how long you personally can chat, not how many tools it calls
Why C? Max Iterations is a hard ceiling on tool calls within one run, not a chat-length limit and not a crash trigger. Hitting it forces a graceful stop — the agent reports back with whatever it's got, honestly incomplete, rather than looping forever chasing an answer that may not exist.

Relevance AI — Same Shape, Drag-and-Drop

⏱ 14 min

Same trigger-brain-tool shape as Builds 1 and 2 — but the whole agent lives inside one object instead of separate wired nodes.

Beginner Note — this is genuinely free: Relevance AI's Free plan gives you 200 Actions a month plus 1,000 one-time Vendor Credits, no credit card to sign up. That easily covers today's single agent and a handful of test runs.

Build It

▸ Node by node
  1. Go to relevanceai.com and sign up free — no card.
  2. From the dashboard, click Create Agent (or "New Agent") and start from a blank agent rather than a template.
  3. Name it, then in its Prompt Template box, inside Goals, write the exact same system prompt from Build 1: You are Groundwire's research assistant. When asked to research a topic, search for current, real information and summarise it clearly with sources.

Key Takeaways

A brain is not a tool, and a tool is not a brain. The Model port reasons; the Tool port acts. Mixing those up is the fastest way to misunderstand why an agent did what it did.

Chaining means the agent decides the order. Search-then-write wasn't wired by you — it was reasoned, live, from what the agent had already observed.

Reliability is settings, not new nodes. Max Iterations and Retry On Fail turned today's build from a demo into something you'd trust running unattended.

Free doesn't mean unlimited. Groq, SerpApi, and Relevance AI are all genuinely free today — but every one of them meters usage somewhere, and a shared classroom account finds that ceiling faster than a solo builder does.

No single builder wins on everything. n8n gives you flexibility and any node/API as a tool; Relevance AI trades that for speed — the right pick depends on which requirement you're not willing to compromise on.

Today's research was real. Every source the agent cited, every doc it produced, exists on the actual internet — that's what makes it worth Priya's trust, not just Zara's.
