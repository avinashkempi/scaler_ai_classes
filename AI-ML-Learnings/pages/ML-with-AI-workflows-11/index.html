Logistic Regression, From Zero to One

How a hospital's no-show problem leads, step by step, to the sigmoid curve, the loss function behind modern language models, and a working classifier.

Reading level: intro machine learning Prerequisites: linear regression, gradient descent Includes: 6 checks, 4 interactive figures
01

The Problem at Sunrise General Hospital

Sunrise General Hospital runs a busy outpatient department. Every day, doctors set aside a fixed number of appointment slots — but a large fraction of patients who book a slot simply never show up. The slot goes to waste: no other patient can use it, and the doctor's time sits idle.

The hospital's operations team wants to identify, in advance, which booked patients are unlikely to show up — so the front desk can send an earlier reminder, or in high-risk cases, double-book the slot.

Notice the shape of this problem For every booked appointment, the outcome is one of exactly two things: the patient shows up, or they don't. There's no in-between value to predict. This is a classification problem, not a regression problem — and it's worth seeing exactly where regression falls short before reaching for something new.

A representative dataset

To work with this hands-on, we generate a synthetic dataset that mimics a real appointment log. Each row is one booked appointment; the columns are features the front desk already records at booking time.

  • days_lead_timeHow many days in advance the appointment was booked
  • distance_kmHow far the patient lives from the hospital
  • prior_no_showsHow many times this patient has missed an appointment before
  • reminder_sentWhether an SMS reminder was sent (1) or not (0)
  • ageThe patient's age
  • showed_upThe target — 1 if the patient showed up, 0 if they did not

n_patients = 800

days_lead_time  = rng.integers(0, 30, size=n_patients)

prior_no_shows  = rng.poisson(0.6, size=n_patients)
reminder_sent   = rng.integers(0, 2, size=n_patients)
age             = rng.integers(5, 90, size=n_patients)

# A hidden "true" relationship used only to generate labels realistically.
# Longer lead time, distance, and prior no-shows push toward NOT showing up.
# A reminder pushes toward showing up.
z_true = (
    1.8
    - 0.04 * days_lead_time
    - 0.05 * distance_km
    - 0.9  * prior_no_shows
    + 1.1  * reminder_sent
    + 0.01 * age
)
prob_show = 1 / (1 + np.exp(-z_true))
showed_up = rng.binomial(1, prob_show)

02

Why Not Just Use Linear Regression?

Linear regression predicts a continuous quantity as a weighted sum of features:

Linear regression's prediction ŷ = wTx + b

Here x is the feature vector for one patient, w is the learned weight vector, and b the learned bias. The output ŷ can be any real number, from −∞ to ∞.

Now look at the target: showed_up is either 0 or 1. Nothing in between. Run linear regression on it directly, and the model can output values like −2.3 or 4.7 — numbers that mean nothing as a class label.

What's needed is a function that takes the same weighted sum z = wTx + b linear regression already computes, and maps it into a range we can meaningfully read as belonging to one of two classes.

◆ Check your understanding
A hospital administrator fits plain linear regression directly on showed_up (1 for "showed up", 0 for "no-show"). For a particular patient, the model outputs ŷ = 1.34. What's the main issue?
Why: Linear regression has no built-in mechanism to keep its output between 0 and 1. Since the target is categorical (show / no-show), the model's output needs to be restricted to a meaningful range — ideally one that can be read as a probability.

A first attempt: thresholding

Analogy — the smoke detector A smoke detector continuously measures smoke density, but it doesn't report the exact reading — it does one of two things: stay silent, or sound the alarm. Below a threshold, silence; at or above it, alarm.

The same idea can be applied here: take the raw weighted sum z = wTx + b and pass it through a step function.

The step function f(z) = 1  if  z ≥ 0,   f(z) = 0  if  z < 0

z is the raw score computed from a patient's features; f(z) is the predicted class — 1 for "will show up," 0 for "will not."

◆ Check your understanding
What's the core mathematical problem with using the step function above, if we want to train the weights w and b with gradient descent?
Why: Gradient descent updates weights using the derivative of the loss with respect to the weights. The step function jumps suddenly at z = 0 and is flat everywhere else — its derivative is either zero or undefined, which gives gradient descent nothing to work with. What's needed is a smooth function instead of a hard switch.
03

The Sigmoid Function: a Smooth Switch

Analogy — the dimmer switch Instead of a smoke detector's hard on/off alarm, picture a dimmer switch on a light. As you turn the knob, the light doesn't jump instantly from off to fully on — it brightens smoothly and continuously. That smoothness is exactly what's needed: a function that transitions gradually from 0 to 1 as z increases.

This is exactly what the sigmoid function does — also called the logistic function, which is where "logistic regression" gets its name:

The sigmoid function σ(z) = 1 / (1 + e−z)

Here z = wTx + b is the same raw weighted score as before, e ≈ 2.718 is Euler's number, and σ(z) is always strictly between 0 and 1.

As z → ∞, σ(z) → 1. As z → −∞, σ(z) → 0. At z = 0, σ(z) = 0.5 exactly. The transition between these extremes is smooth and differentiable everywhere — exactly what gradient descent needs.

◆ Check your understanding
A patient's raw score is z = −8 — a very negative number, meaning the features strongly suggest they will not show up. What would you expect σ(z) to be?
Why: As z becomes a large negative number, e−z becomes very large, which makes the denominator 1 + e−z very large — pushing σ(z) close to 0. That matches intuition: a strongly negative raw score should mean a low predicted probability of showing up.

Reading sigmoid output as a probability

Because σ(z) always lies strictly between 0 and 1, it can be read directly as a probability: σ(z) is the model's estimate of the probability that the patient shows up, given their features.

If the model outputs σ(z) = 0.82 for a patient, that means an estimated 82% chance they show up — and correspondingly, 18% chance they don't. The front desk can then pick a threshold — say, call anyone whose predicted probability is below 0.4 — to prioritize reminder calls.

04

Likelihood vs. Probability

Before figuring out how to train w and b, two ideas that sound similar need to be told apart: probability and likelihood.

The locked suitcase, forward: Given a fixed 4-digit combination — say 4-2-7-1 — what's the chance a random guess opens it? Here the combination is fixed, and the reasoning is about the outcome.
The locked suitcase, reversed: Given that the suitcase just opened on a particular guess, how plausible is it that a particular combination was the true one? Here the outcome (it opened) is fixed, and the reasoning is about which explanation best accounts for it.

In logistic regression, the "combination" is the pair of parameters (w, b), and the "outcome" is the labeled data already collected — which patients showed up, which didn't. The question flips around: instead of assuming w and b and asking how probable the data is, ask — given the data already observed, which values of w and b make that data most plausible? This is Maximum Likelihood Estimation (MLE).

Setting up the likelihood

For a single patient i, let xi be their feature vector, yi the actual outcome (1 if shown up, 0 if not), and pi = σ(wTxi + b) the model's predicted probability they show up.

If yi = 1, pi should be large. If yi = 0, (1 − pi) should be large. Both cases collapse into one expression:

Per-patient likelihood P(yi | xi) = piyi · (1 − pi)1 − yi

Since each appointment's outcome is independent of the others, the likelihood of the entire dataset of n patients, for a given (w, b), is the product of every individual term:

Dataset likelihood L(w, b) = ∏i=1n piyi · (1 − pi)1 − yi

MLE says: choose the w and b that make L(w, b) as large as possible.

◆ Check your understanding
For a patient who actually showed up (yi = 1), the expression piyi(1−pi)1−yi simplifies to which of the following?
Why: When yi = 1, the exponent on pi is 1 and the exponent on (1−pi) is 1−1 = 0. Anything raised to the power 0 is 1, so the expression reduces to just pi — confirming that for patients who showed up, the goal is for pi itself to be large.
05

From Likelihood to Log-Loss

Multiplying together hundreds of probabilities, each less than 1, produces an extremely small number — awkward to work with numerically and to differentiate. So instead of maximizing L(w, b) directly, its logarithm is maximized instead. Since log is an increasing function, maximizing one is the same as maximizing the other — but the product turns into a far friendlier sum:

Log-likelihood log L(w, b) = Σi=1n [ yi log(pi) + (1 − yi) log(1 − pi) ]

By convention, loss functions are things we minimize, so the sign gets flipped. For a single patient i, this gives the log-loss — also called binary cross-entropy:

Log-loss (binary cross-entropy) Li = − [ yi log(pi) + (1 − yi) log(1 − pi) ]

Minimizing total log-loss over all patients is exactly equivalent to maximizing the likelihood — this is the loss function logistic regression actually trains on, in place of the squared error used in linear regression.

◆ Check your understanding
A patient did not show up (yi = 0), and the model predicted pi = 0.9 — very confident they would show up. What would you expect the log-loss for this patient to be?
Why: Substituting into the formula, the (1−yi)log(1−pi) term becomes log(1 − 0.9) = log(0.1), a large negative number — so the overall loss, after the negative sign, becomes large and positive. This is exactly the confident-wrong case the loss function is meant to penalize heavily.
06

Why Not Reuse Mean Squared Error?

A natural question: linear regression used Mean Squared Error (MSE) as its loss. Why not reuse it here, with the sigmoid output plugged in?

Analogy — two hiking trails Picture two trails down a mountain. One is shaped like a single smooth bowl — wherever you start, walking downhill always leads to the one true bottom. The other is full of small dips and false valleys — walking downhill might strand you in a shallow dip that isn't the true lowest point at all.

The first trail is what mathematicians call a convex function; the second is non-convex. Gradient descent is a "walk downhill" algorithm, so it's only guaranteed to find the true minimum when the loss surface is convex. Combine MSE with the sigmoid function, and the resulting loss surface becomes non-convex — riddled with false valleys gradient descent can get stuck in. Log-loss, paired with sigmoid, stays convex — which is precisely why it, not MSE, is the loss function logistic regression trains on.

Where else does this loss function show up?

The log-loss just derived isn't a niche formula for small two-class problems. In its generalized multi-class form — cross-entropy loss — it's the exact loss function used to train large language models.

When such a model predicts the next word in a sentence, it isn't choosing between two classes like "show" or "no-show" — it's choosing among tens of thousands of possible next tokens. But the underlying question is identical in spirit: given what the model predicted as probable, how surprised should we be by what actually occurred? A confident, correct prediction scores a very low loss; a confident, wrong prediction scores a very high loss — the same behavior seen above, just scaled from two classes to tens of thousands.

In one sentence Two-class logistic regression is, in this sense, the smallest possible version of the same mathematical idea that sits at the core of today's large language models.

Optimization: nothing new to learn

Because log-loss is convex and differentiable, the same gradient descent machinery built for linear regression — compute a gradient, update weights by a learning rate, iterate until convergence — applies here without modification. Only the loss function itself, and so the specific gradient formula, changes.

Analogy — the leash Just as with linear regression, a regularization term can be added to the loss to discourage weights from growing too large and overfitting to quirks in the training data. Think of it as a leash on each weight — it doesn't stop the weight from moving toward a useful value, but it resists it wandering unnecessarily far, which helps the model generalize to patients it hasn't seen before.
AI as a diagnostics partner Once a model like this is trained, it's increasingly common to paste a summary of its coefficients, feature list, and performance numbers into an AI assistant and ask it to help interpret the results — which features seem to be pulling predictions in which direction, whether a coefficient's sign matches domain intuition, and what additional features might be worth exploring. Used this way, the AI isn't replacing that judgment — it's a fast way to generate hypotheses worth double-checking against the data itself.

Evaluating the Model: Accuracy

With predictions in hand, the simplest way to score them is accuracy — the fraction of patients whose predicted class matched their actual outcome.

Accuracy Accuracy = (correctly predicted patients) / (total patients)
▸ Computing accuracyfrom scratch + sklearn 
def accuracy(y_true, y_pred):
    y_true = np.array(y_true)
    y_pred = np.array(y_pred)
    return np.mean(y_true == y_pred)

◆ Check your understanding
Recall the two classes in this dataset are imbalanced — more patients show up than not. Suppose 85% of all patients show up, and a lazy model simply predicts "will show up" for every single patient, regardless of features. What accuracy would this lazy model achieve, and what does that imply?
Why: Since 85% of patients show up regardless of what's predicted, a model that blindly always predicts "will show up" is correct 85% of the time by default. In imbalanced settings, a high accuracy number should always be checked against class balance — it doesn't by itself prove a model has learned anything about the minority class, which is often the group that matters most.

Key Takeaways

Why classification needs a new modelCategorical outcomes don't fit linear regression's unbounded output — a bounded, interpretable value is needed instead.
Step function, first tryBounds the output, but is non-differentiable — which breaks gradient-based training.
Sigmoid, the fixσ(z) = 1/(1+e⁻ᶻ) smoothly bounds output between 0 and 1, and is differentiable everywhere.
Sigmoid output = probabilityRead directly as the estimated probability of belonging to the positive class.
Likelihood vs. probabilityLikelihood asks which parameters best explain data already observed — the reverse of probability's fixed-parameter question.
MLE → log-lossTaking logs and flipping the sign turns Maximum Likelihood Estimation into the log-loss (binary cross-entropy) function.
Why log-loss, not MSELog-loss heavily penalizes confident, wrong predictions, and stays convex with sigmoid — unlike MSE.
The same idea, at scaleGeneralized to many classes as cross-entropy, this loss is the training objective behind modern large language models.
Optimization carries overGradient descent and regularization work unchanged from linear regression — only the loss function differs.
AI as a co-pilotUseful for interpreting a trained model's coefficients and behavior — not for replacing that judgment.
The full pipelineSplit → scale → fit → predict → evaluate, implemented end-to-end with sklearn.
Accuracy's limitsSimple, but can be misleading on imbalanced data — a model that ignores the minority class can still score deceptively high.
