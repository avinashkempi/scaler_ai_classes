Concept
Multiclass Classification with KNN
⏱ 3 min

KNN requires no modification to handle more than two classes. The majority vote simply counts across all class labels present among the K nearest neighbors — whichever class appears most often wins.

Handling Ties in Multiclass KNN

With K=5 and 3 classes, it's possible for two classes to tie (e.g., 2 votes each for Class A and Class B, 1 for Class C). Options:

  • Try a different K (odd K doesn't guarantee no ties with 3+ classes)
  • Fall back to the class of the single nearest neighbor
  • Use Weighted KNN to break the tie by distance
🤔 The Unreliable Neighbor Analogy
KNN trusts its neighbors blindly. If an outlier lives near your query point, it gets a vote — even if it doesn't truly represent its class. This is the core vulnerability of KNN: it cannot distinguish genuine neighbors from noise.
⚠️
Concept
Outliers and Their Effect on KNN
⏱ 4 min

Consider a dataset with 3 outliers near a query point x_q. Whether they affect the prediction depends entirely on K:

K valueEffect of OutliersReason
K = 1Both outliers affect predictionNearest neighbor could be the outlier itself
K = 3Partial effect2 outliers in neighborhood can still produce a wrong majority
K = 7No effectMajority of the larger neighborhood correctly labels x_q
📌 Key Takeaway
Larger K is more robust to outliers. But too large a K causes underfitting. The practical solution: clean outliers from the dataset before training, and tune K on validation data.

Technique
KNN-Based Imputation
⏱ 11 min

Mean/median imputation ignores the structure of the data — it gives every missing value the same fill regardless of what that row's other features say. KNN imputation personalizes the fill by asking: what do similar rows have in that column?

Why Values Go Missing

  • Equipment or sensor malfunction
  • Researcher or data-entry error
  • Unavailable respondents in surveys
  • Accidental deletion or accounting errors

The KNN Imputation Algorithm

1

Identify the missing dimension

For point xᵢ, dimension j is missing. We need to estimate xᵢⱼ.

2

Compute distances excluding j

Find K nearest neighbors for xᵢ using all dimensions except the missing one j.

3

Aggregate neighbor values

For numerical: take the mean of xⱼ from all K neighbors. For categorical: take the mode (most frequent value).

4

Fill the missing value

Set xᵢⱼ = aggregated neighbor value. Repeat for every missing entry.

⚠️ Scale Before Imputing
KNN Imputer uses distance — features on larger scales will dominate the neighbor search. Always normalize first (e.g., MinMaxScaler) before applying KNNImputer.

Numerical Imputation Code

from sklearn.impute import KNNImputer
from sklearn.preprocessing import MinMaxScaler
import pandas as pd

df_imp = pd.read_csv('knn_imputation.csv').drop('Unnamed: 0', axis=1)

# Scale first — KNNImputer is distance-based
scaler = MinMaxScaler()
df_imp = pd.DataFrame(scaler.fit_transform(df_imp), columns=df_imp.columns)

# Impute with K=5 neighbors
imputer = KNNImputer(n_neighbors=5)
df_imp = pd.DataFrame(imputer.fit_transform(df_imp), columns=df_imp.columns)

print(df_imp.isna().sum())  # should all be 0

Validating Imputation Quality

Two checks to confirm the imputation didn't introduce bias:

  • Mean check: The column mean before and after imputation should remain close — systematic shift means biased imputation.
  • Histogram check: The distribution shape should look the same before and after. If it shifts noticeably, the imputed values aren't representative.

Categorical Imputation

KNNImputer only works on numeric values. For categorical columns, encode them first:

df["gender_map"] = df.gender.map({"Male": 0, "Female": 1})

imputer = KNNImputer(n_neighbors=2)
df_filled = pd.DataFrame(
    imputer.fit_transform(df[["age", "gender_map"]]),
    columns=["age", "gender_mapping"]
)

Round the imputed gender_mapping back to 0 or 1, then reverse-map to "Male"/"Female".

What Is Imbalanced Data?
⏱ 3 min

Imbalanced data occurs when one class (the majority class) has far more samples than another (the minority class). Most real-world classification problems are imbalanced to some degree.

Balanced (50/50)
Slight (70/30)

Extreme (99/1)

Case Study
Case Study: Telecom Churn Prediction
⏱ 5 min

A telecom company wants to predict which customers will switch to a competitor (churn). Predicting churners lets the company proactively offer them deals before they leave.

Dataset: 3,333 customers, 21 features, no nulls, no duplicates.

🤔 Why Is This Imbalanced?
Only a small fraction of customers churn at any given time — most stay. Churn samples are far fewer than non-churn, making this a naturally imbalanced problem.

Finding Kbest on Imbalanced Data

from sklearn.neighbors import KNeighborsClassifier
from sklearn.preprocessing import StandardScaler
import numpy as np

scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)
X_val_scaled   = scaler.transform(X_val)

error = []

    knn = KNeighborsClassifier(n_neighbors=i, metric='euclidean')

    pred = knn.predict(X_val_scaled)
    error.append(np.mean(pred != y_val))

# Kbest = K with lowest validation error
# Result: Kbest = 2
knn = KNeighborsClassifier(n_neighbors=2, metric='euclidean')

📌 Accuracy vs F1 Gap
Accuracy = 88.3% sounds great. But F1-Score = 0.473 — terrible. The model is mostly predicting "not churn" and getting credit for it. This is the accuracy trap on imbalanced data.

Concept
Why Accuracy Fails on Imbalanced Data
⏱ 3 min

If 85.5% of the dataset is class 0 (non-churn), a model that always predicts 0 achieves 85.5% accuracy without learning anything useful. It would still fail every single churn customer.

⚠️ The Dumb Model Trap
Predicting the majority class for every observation is the laziest possible model — yet it "performs" well by accuracy on imbalanced data. Accuracy is blind to how badly it fails on the minority class.

The solution: use F1-Score, Precision, Recall, or ROC-AUC — metrics that require the model to actually identify minority class instances correctly. The choice depends on whether FP or FN is more costly for your use case.

❓

Preferred Metric for Imbalanced Data
⏱ 1 min
Which metric should be preferred for imbalanced data when giving equal importance to TP, FP, FN, and TN?
  • F1-Score
  • Accuracy
  • Precision
  • Recall
💡 Explanation
F1-Score is the harmonic mean of Precision and Recall — it cares about both false positives and false negatives equally. Accuracy ignores imbalance. Precision focuses only on FP. Recall focuses only on FN.

Technique
Handling Imbalanced Data — Four Approaches
⏱ 1 min
⚖️
Weighted Loss
Multiply the minority class's contribution to the loss function by a weight proportional to how underrepresented it is.
✅ Works on model parameters — no data change
🗑️
Undersampling
Randomly remove majority class samples until classes are balanced. Simple, but throws away real information.
✅ Use only when n is enormous (1B+)
📋
Oversampling
Duplicate minority class samples until classes are balanced. Preserves all data but repeats the same points.
✅ Better than undersampling; risk of overfitting
🧬
SMOTE
Synthetically generate new minority class points between existing ones using KNN. Smarter than naive oversampling.
✅ Best general-purpose approach
⚖️
Technique
Weighted Loss
⏱ 8 min

The Idea

The loss function normally treats every data point equally. We can add a class weight wᵢ to each term:

Loss = Σ (log-lossᵢ × wᵢ)

The minority class gets a higher weight, so the optimizer penalizes getting those examples wrong more severely.

Calculating Class Weights

With 850 negative samples and 150 positive samples:

  • Minority class (positive, y=1): w₁ = 850 / 150 ≈ 6
  • Majority class (negative, y=0): w₀ = 1

Every positive example now contributes 6× as much to the loss — the model is forced to take it seriously.

Code — Logistic Regression with Class Weights

from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import make_pipeline
from sklearn.metrics import f1_score

# Without weights: best validation F1 = 0.319
# With weights:
scaled_lr = make_pipeline(
    StandardScaler(),
    LogisticRegression(C=1/l_best, class_weight={0: 1, 1: 6})
)
scaled_lr.fit(X_train, y_train)
print("Test F1:", f1_score(y_test, scaled_lr.predict(X_test)))
Output
Without weights → Validation F1: 0.319 With weights → Validation F1: 0.466 Test F1 (weighted): 0.510
✅ Result
Weighted loss improved test F1 from ~0.32 to 0.51 — a 60% improvement, with zero data modification. This works directly on the loss function during training.

Calculating Class Weights
⏱ 1 min
We have 1000 samples: 200 positive (Y=1) and 800 negative (Y=0). What should the class weights (W₁, W₀) be?
  • W₁ = 4, W₀ = 1
  • W₁ = 1, W₀ = 4
  • W₁ = 5, W₀ = 1.25
💡 Explanation
The minority class (Y=1) gets weight = majority count / minority count = 800/200 = 4. The majority class (Y=0) gets weight = 1. This compensates for underrepresentation of positives in the loss.

Technique
Undersampling
⏱ 3 min

Randomly remove majority class samples until both classes have equal size.

from imblearn.under_sampling import RandomUnderSampler

undersampler = RandomUnderSampler()
X_us, y_us = undersampler.fit_resample(X_train_scaled, y_train)

# Before: 1718 non-churn, 281 churn
# After:  281 non-churn, 281 churn
Result
Training F1: 0.780 | Testing F1: 0.506
⚠️ The Information Loss Problem
Undersampling discards 1437 real training examples. The model never sees most of its available data — information that might help it learn better boundaries. This is why undersampling is only recommended when n is very large (hundreds of millions+), where data loss has negligible impact.
📋
Technique
Oversampling (Random)
⏱ 3 min

Duplicate minority class samples until both classes are equal — no data is discarded.

from imblearn.over_sampling import RandomOverSampler

oversampler = RandomOverSampler()
X_os, y_os = oversampler.fit_resample(X_train_scaled, y_train)

# Before: 1718 non-churn, 281 churn
# After:  1718 non-churn, 1718 churn (duplicates)
Result
Training F1: 0.749 | Testing F1: 0.505
📌 The Repetition Problem
Oversampling preserves data but the model sees the same 281 churn examples repeated 6+ times. It learns nothing new about the minority class — just memorizes those exact points. This can cause overfitting to the specific minority examples that happen to be in the training set.

The minority class is negative (100 samples). To balance without losing data, oversample the negative (minority) class to 200. Undersampling the majority would discard 100 positive examples.

Technique
SMOTE — Synthetic Minority Oversampling Technique
⏱ 10 min

SMOTE fixes oversampling's repetition problem by generating new synthetic minority points rather than copying existing ones — using KNN to guide where new points should appear.

How SMOTE Works

  1. Pick a random minority class point x₁
  2. Find its K nearest neighbors (within the minority class)
  3. For each neighbor x₂: compute the distance d(x₁, x₂)
  4. Pick a random scalar λ ∈ [0, 1]
  5. Generate: x_new = x₁ + λ × d(x₁, x₂)
  6. Add x_new to the dataset as a new minority class point
  7. Repeat for all K neighbors and for each minority point

Algorithm
Decision Trees — Intuition
⏱ 7 min

Why Not KNN or Logistic Regression?

Consider attrition data with features Age and Overtime — the scatter plot shows a non-linear, non-separable pattern:

  • Logistic Regression: can't fit — it assumes a linear boundary
  • KNN: can fit — but cannot be productionized at scale. At inference time it scans all training data. With millions of employees, this is far too slow.

A Better Approach: Axis-Parallel Splits

Instead of comparing to all training points, what if we just asked a sequence of simple yes/no questions?

  • Is Age > 35?
  • Does the employee work Overtime?

Each question splits the feature space into two regions along an axis. Recursively applying these splits creates homogenous rectangular regions — each region predominantly contains one class. Any new point just follows the same sequence of questions to reach its prediction.

Anatomy of a Decision Tree

🌱
Root Node
The topmost node — contains the first split question, applied to the full dataset
⚙️
Internal Node
Any node between the root and leaves — applies a split condition to its subset
🍃
Leaf Node
Terminal node — no further splits. Returns the majority class of points that reach it

Decision Tree vs KNN

PropertyKNNDecision Tree
Training phaseNone (lazy)Learns split conditions from data
PredictionO(n·d) — scans all training dataO(depth) — follows one path in the tree
InterpretabilityLow — "black box" distancesHigh — explicit if/else rules
Handles non-linear boundariesYesYes (axis-parallel)
Scalable to production❌ Slow at inference✅ Very fast at inference

Wrapping Up
⏱ 3 min
KNN handles multiclass via majority vote — no changes needed
Larger K = more robust to outliers (but risks underfitting)
KNN Imputation: fill missing values using K similar rows
Always MinMaxScale before KNNImputer
Validate imputation: means and histograms should match
Imbalance thresholds: 70/30 slight, 90/10 heavy, 95/5 extreme
Accuracy is useless on imbalanced data — use F1 or AUC
Weighted Loss: w₁ = majority_count / minority_count
Undersampling: discard majority — only for massive datasets
Oversampling: duplicate minority — no data loss but repeats
SMOTE: synthetic minority points via KNN interpolation
Decision Trees: axis-parallel splits → fast, interpretable, scalable
KNN is simple and powerful but slow at inference. Decision Trees solve that — they learn the decision rules once and apply them in O(depth) time, making them production-friendly for large datasets.
