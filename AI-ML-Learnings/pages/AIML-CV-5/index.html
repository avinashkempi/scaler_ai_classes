The whole pipeline at a glance

The takeaway of this post fits in one sentence: extract a vector with a pretrained CNN, normalize it, and retrieve images with nearby vectors, using the same model and preprocessing for indexed images and queries. A real system has two phases.

Build the embedding extractor with ResNet-50

Our choice is ResNet-50 pretrained on ImageNet, because it is accurate, about 5× smaller than VGG16, and produces a compact 2048-number embedding.

Code 
def embed_image(path_or_img):
    img = Image.open(path_or_img).convert("RGB") if isinstance(path_or_img, str) else path_or_img.convert("RGB")
    x = preprocess(img).unsqueeze(0).to(device)
    with torch.no_grad():
        v = model(x).cpu().numpy().ravel()
    return v / np.linalg.norm(v)

with torch.no_grad():

05

Similarity search with k-nearest neighbors

  1. Embed the query image the same way.
  2. Measure the distance from the query vector to every stored vector.
  3. Return the k images with the smallest distances. This is k-nearest neighbors (k-NN).

Comparing against every stored vector is brute force: simple and exact, but the work grows with the number of images. A k-NN “model” does no training: fitting just stores the vectors (9.5 ms in the recorded run) and all the work happens at query time, which is why it is called lazy learning. The query itself is always its own nearest neighbor, so it is dropped.

    How good is it? A fair measure

    Looking at a few examples is not evidence. We need a number, and we have labels we have not used yet. Neighbor accuracy is a proxy metric: for every image, look at its 4 nearest neighbors (not counting itself) and count the fraction that share its class label. It is a proxy because “same class” is only one idea of “similar”: a red car and a blue car are similar, and so are two very different-looking dogs.

    Visualizer · Neighbor accuracy for one query

    Click each of the 4 neighbours to flip it between same class and different class.

    Two baselines

    • Chance: guess a random neighbor. The expected accuracy is the sum of squared class proportions.
    • Raw pixels: shrink every image to 32×32 grayscale and use those 1,024 values as the “embedding”.

    Visualizer · Chance = Σ p²

    Enter image counts for four example classes. With imbalanced classes, chance is higher than 1 / number of classes.

    Visualizer · Top-4 neighbor accuracy, recorded results

    Reading the results

    • Embeddings are far above both chance and raw pixels, even though we never trained anything on these images: transfer learning at work.
    • The hardest classes and the confusions are informative: many “errors” are categories that really are close (faces versus a near-duplicate faces class, a whole animal versus its head), so a label-based metric is pessimistic for them.
    • The metric measures class agreement, not human-perceived similarity. Always pair a number with a look at actual results.
    Does the distance choice matter?

    On the real normalized embeddings, Euclidean and cosine gave the same top-6 neighbor set for 100.0% of 500 queries. This matches the earlier result: after L2 normalization their rankings are equivalent. Tiny differences, if any, come from ties and floating-point rounding.

    Code 
    def evaluate_neighbors(feats, k=4):
    nnm = NearestNeighbors(n_neighbors=k + 1, algorithm="brute", metric="euclidean").fit(feats)
    _, idx = nnm.kneighbors(feats)
    nb = np.stack([row[row != r][:k] for r, row in enumerate(idx)])      # drop self from each row
    same = labels[nb] == labels[:, None]
    return float(same.mean()), same.mean(axis=1), nb

    Seeing the embedding space: PCA and t-SNE

    Our embeddings live in 2048 dimensions and we cannot draw that. Dimensionality reduction squeezes long vectors into a few numbers while keeping as much structure as possible. Variance is how spread out the data is along a direction; PCA reports how much of the total variance each component keeps.

    Visualizer · PCA vs. t-SNE

    Reading the maps, and what not to read

    t-SNE separates the classes into visible clusters: nearby photos look alike. PCA with 2 components keeps only a sliver of the information, so classes overlap far more. In t-SNE, the distance between clusters and the size of clusters are not reliable, and the picture changes with the random seed and the perplexity setting. Trust local neighborhoods, not global layout. A 2-D plot is for looking, not a retrieval metric.

    08

    Making search fast, lever 1: shorter vectors

    Brute force compares the query against every vector, so time grows with both the number of images and the vector length. Each 2048-dimension float32 embedding takes about 8 KB; a million images need about 8 GB. The number of PCA dimensions is a hyperparameter: a setting we choose, not one the model learns. We pick it by measuring the trade-off between accuracy and time.

    Visualizer · How many PCA dimensions?

    Recorded sweep on 8,677 images. Move the slider to choose a size and read the trade-off.

    Each extra dimension keeps a little less new information (diminishing returns) but costs memory and time. On Caltech-101 the accuracy flattens long before 2048 dimensions, so 150 dimensions is a sensible choice here: roughly 14× smaller, with little loss. Back any choice with your own sweep, and repeat it on new data.

    Lever 2: approximate nearest neighbors

    Even with short vectors, brute force still touches every item. Approximate nearest neighbors (ANN) algorithms build an index in advance so a query looks at only a small, promising part of the data. The price: the answer may miss some true neighbors. We measure that price as recall: of the true top-k neighbors (from brute force), what fraction did the approximate search return?

    Visualizer · Recall@5

    The five true neighbours are fixed. Click one to mark it as missed by the approximate search.

    Annoy (“Approximate Nearest Neighbors Oh Yeah”, from Spotify) builds many random-projection trees; more trees give better recall but a bigger index and slower build. The number of trees is another hyperparameter. Other well-known libraries are Faiss (Meta) and ScaNN (Google).

    Visualizer · Annoy on 150-dimensional vectors

    Recorded results. Brute force took 16.60 ms per query on the same vectors.

    Which metric not to sacrifice blindly

    Recall (and the retrieval quality behind it): a faster answer that misses true neighbors is only a good trade if you have measured how much it misses.

    Code and output 
    FINAL_DIMS = min(150, pca_max)
pca_final = PCA(n_components=FINAL_DIMS, svd_solver="full", random_state=0).fit(feature_list)
Z = pca_final.transform(feature_list).astype("float32")

for n_trees in [1, 5, 20, 50]:
    idx_ann = AnnoyIndex(FINAL_DIMS, "angular")
    for i, v in enumerate(Z): idx_ann.add_item(i, v)
    idx_ann.build(n_trees)

    Putting it together: an end-to-end search function

    The offline phase embeds every image, compresses with PCA, and builds the index. The online phase embeds the query with the same model and preprocessing, applies the same PCA, and looks it up in the index. Use the diagram in section 1 to replay it, including what happens when settings are mixed: vectors from different models are not comparable, and search silently returns nonsense without raising an error.

    Test: a flipped photo

    Querying with a horizontally flipped copy of image #7041 (a revolver) returned the original at rank 1 of the top-5. Raw pixels would see a very different image; the embedding still recognises the content.

    Your own photos work too, but the index only contains Caltech-101 classes, so results are the nearest of those images.

    What a real system still needs

    VersioningIf you change the model or preprocessing, re-embed everything and rebuild the index.
    Domain fitAn ImageNet-pretrained embedding is a strong start, but for a special domain (fashion, medical) you may fine-tune it for similarity with labelled or paired data.
    Quality loopMonitor recall, latency and real user behaviour, and keep failure examples for review.
