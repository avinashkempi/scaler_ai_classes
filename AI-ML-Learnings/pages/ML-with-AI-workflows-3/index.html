Meet Meera and CoolCups

Meera runs a small fresh-juice stall chain called CoolCups in three neighbourhoods of the city. Every evening she notes down, by hand, in a notebook:

  • the day's maximum temperature
  • the footfall near her stall — how many people walked past between 4 PM and 8 PM
  • whether the day was a weekend
  • how many cups of juice she actually sold that day

Meera has been running her stalls on gut feeling for two years. On some days she over-stocks fruit and throws away unsold stock at closing time. On other days she under-stocks and has to turn customers away. She wants a system that looks at her notebook of past days and tells her, in advance, roughly how many cups she should prepare for tomorrow.

This is exactly the kind of problem Linear Regression is built for — and it's the problem we'll solve, one piece at a time.

What Linear Regression Is Trying to Do

Before opening Meera's notebook, let's align on the goal in one line:

The one-line goal

Linear Regression tries to find the best straight line — or, with more than one input factor, the best flat plane or hyperplane — that fits a set of past data points, so that line can predict an output value for a new, unseen input.

For Meera, the "points" are past days, and the "line" is a formula that turns temperature, footfall, and the weekend flag into a predicted number of cups sold. For a single day i, the model predicts:

$$\hat{y}_i = w_1 x_{1i} + w_2 x_{2i} + w_3 x_{3i} + b$$
$x_{1i}$
the temperature recorded on day i, in degrees Celsius
$x_{2i}$
the footfall recorded on day i — the number of people who passed the stall
$x_{3i}$
the weekend flag for day i (1 if Saturday or Sunday, 0 otherwise)
$w_1, w_2, w_3$
the weights, or coefficients, the model assigns to temperature, footfall, and the weekend flag — how strongly each factor pulls the prediction up or down
$b$
the bias, or intercept — the baseline number of cups the model would predict if every feature were zero
$\hat{y}_i$
the number of cups the model predicts for day i
$y_i$
the actual number of cups Meera sold on day i, as recorded in her notebook

The entire job of training a Linear Regression model is finding good values for $w_1$, $w_2$, $w_3$, and $b$.

The next few sections show exactly how those four numbers get found.

Reading the Coefficients

Suppose Meera's model has already been trained on her notebook, and it has learned the following values:

$w_1$ (temperature)
15.4
$w_2$ (footfall)
0.6
$w_3$ (weekend flag)
22.1
$b$ (bias)
10.2

What can Meera actually learn from these four numbers?

Analogy

Think of a recipe with several ingredients. If halving one spice barely changes how the dish tastes, that spice isn't doing much work at these quantities. If halving another ingredient changes the dish completely, that ingredient is doing a lot of work. A coefficient plays a similar role: it tells us how much the prediction moves when its input moves by one unit, holding everything else fixed.

Two things are worth noting:

  • The sign of a weight tells us direction. All three weights above are positive, so higher temperature, higher footfall, and a weekend all push the predicted number of cups sold upward.
  • The size of a weight tells us how much pull that factor has — but only if we're comparing features on a similar scale.

That second point is easy to get wrong. Footfall in Meera's notebook might range from about 100 to 900, while temperature usually ranges from about 20 to 40. So a weight of 0.6 for footfall isn't automatically "less important" than a weight of 15.4 for temperature, because footfall's raw values are so much larger to begin with. A fair comparison requires first bringing all features to a similar scale — a step called feature scaling — before comparing coefficient sizes.

Gradient Descent, Revisited

So Meera now knows how to read a trained model. But how does the model land on these exact numbers for $w_1, w_2, w_3$, and $b$ in the first place?

Walking downhill in the fog

Imagine Meera standing on a hillside at night, in thick fog, holding a torch that only lights the ground right around her feet. She can't see the whole hill, and has no idea where the lowest point of the valley is. All she can do is feel the slope under her feet and take a small step in whichever direction goes downhill fastest from where she's standing. She repeats this, step after step, until she reaches the bottom of the valley.

In this analogy:

  • The hill represents the cost function — a surface where "height" at any point represents how wrong the model's predictions currently are, for a given choice of $w_1, w_2, w_3$, and $b$.
  • The lowest point of the valley represents the combination of weights and bias that makes predictions closest overall to the true values in Meera's notebook.
  • The slope Meera feels underfoot is what we call the gradient.

Gradient, defined precisely

The gradient of a function at a given point tells us the direction in which the function increases most steeply at that point, and how steep that increase is. Gradient descent works by always stepping in the exact opposite direction — the direction of steepest decrease.

In gradient descent, the gradient of the cost function at a given point tells us:

The gradient only describes the local slope at the current position — it doesn't know where the overall minimum lies. Because we want to reduce cost, gradient descent moves opposite to the gradient at every single step, gradually working its way downhill.

Building the Prediction Function

Before computing the exact slope Meera's model should follow, we need to write down precisely what our model looks like in code, and what exactly we're trying to minimize.

We translate $\hat{y} = XW + b$ into code, where:

  • X is a table with one row per day and one column per feature (temperature, footfall, weekend flag)
  • W is a list of weights, one per feature
  • b is a single number, the bias

For $m$ days and $d$ features, X has shape $(m, d)$, W has shape $(d, 1)$, and the matrix multiplication $X \cdot W$ produces one predicted value per day, to which we add $b$.

The class shell

Python
import numpy as np

class LinearRegression:
    def __init__(self, learning_rate=0.01, iterations=100):
        self.learning_rate = learning_rate
        self.iterations = iterations

Predicting

This calculates $\hat{y} = XW + b$ for every day at once, using matrix multiplication instead of looping over individual days.

Python
def predict(self, X):
    return np.dot(X, self.W) + self.b

LinearRegression.predict = predict

Scoring with R²

The R² score tells us what fraction of the variation in cups sold the model can explain.

  • An R² of 1 means predictions match the actual values perfectly.
  • An R² of 0 means the model is no better than always predicting the average number of cups sold, regardless of temperature, footfall, or day.
Python
def r2_score(self, X, y):
    y_pred = self.predict(X)
    ss_res = np.sum((y - y_pred) ** 2)
    ss_tot = np.sum((y - y.mean()) ** 2)
    return 1 - ss_res / ss_tot

LinearRegression.score = r2_score

Formulating the Optimization Problem

We now have a way to make predictions and a way to measure how good they are. But we still haven't answered the central question: how do we find the values of $W$ and $b$ that make those predictions as good as possible?

Our goal is to find the hyperplane, in $d{+}1$ dimensions, that sits as close as possible to all of Meera's data points. For Meera, $d = 3$, so we're fitting a plane in four-dimensional space — impossible to draw on paper, but the same idea as fitting the best line through points on a simple 2D graph.

To decide whether one candidate line is "better" than another, we need a single number that tells us how wrong it currently is. That's the cost function, also called the loss function. We use the Mean Squared Error:

$$J(W, b) = \frac{1}{m}\sum_{i=1}^{m}(y_i - \hat{y}_i)^2$$
$m$
the total number of days in Meera's training data
$y_i$
the actual number of cups sold on day $i$
$\hat{y}_i$
the number of cups the model currently predicts for day $i$
$(y_i - \hat{y}_i)$
the error for day $i$ — how far off the prediction is
squaring the error
makes every error positive, and penalises large errors far more heavily than small ones — a mistake of 20 cups counts four times as much as a mistake of 10 cups, not just twice
summing and dividing by $m$
gives the average squared error across the whole notebook, so $J$ doesn't depend on whether Meera has 30 or 300 days of data

Training the model now becomes a precise mathematical goal: find the $W$ and $b$ that make $J(W,b)$ as small as possible. That's exactly what gradient descent does.

Check your understanding

Why does the MSE cost function square the error terms $(y_i - \hat{y}_i)$ instead of simply adding them up directly?

If we simply added up $(y_i - \hat{y}_i)$ without squaring, a day where the model over-predicts by 20 cups could cancel out a day where it under-predicts by 20 cups — making the model look better than it is. Squaring makes every term positive and grows faster for larger mistakes, exactly the behaviour we want from a cost function.

The Bowl of Loss

We now know precisely what we're trying to minimize. What does this cost function actually look like, geometrically — and why does gradient descent work on it at all?

If we simplify Meera's problem down to one feature — say temperature — and plot the cost function $J$ against a single weight $w_1$, the graph turns out shaped like a parabola: a smooth curve that dips to one lowest point and rises again on either side, much like the cross-section of a bowl.

Imagine placing a marble anywhere on the inside surface of this bowl and letting it go — gravity pulls it toward the single lowest point. Gradient descent does exactly the same thing to our cost function, except instead of rolling continuously, it takes a series of calculated steps using the slope it detects at each position.

With more than one feature, the same picture holds — the bowl exists in more dimensions than we can draw. With Meera's three features, it effectively lives in four-dimensional space: three weight dimensions plus the bias. The intuition stays identical: there's one lowest region, and gradient descent's job is to guide the marble there, step by step.

Calculating the Gradient

Knowing a lowest point exists is a good start, but gradient descent needs an exact formula that tells it, at any position on the bowl, precisely which direction is downhill. That comes from the gradient.

We differentiate $J(W,b) = \frac{1}{m}\sum_{i=1}^{m}(y_i - \hat{y}_i)^2$, where $\hat{y}_i$ itself depends on $W$ and $b$ through $\hat{y}_i = X_i \cdot W + b$. Working through the chain rule, the gradient with respect to the weights comes out to:

$$\frac{\partial J}{\partial W} = -\frac{2}{m}X^T(y - \hat{y})$$

and with respect to the bias:

$$\frac{\partial J}{\partial b} = -\frac{2}{m}\sum_{i=1}^{m}(y_i - \hat{y}_i)$$
$X^T$
the transpose of the feature matrix — needed purely so the shapes line up for matrix multiplication: X is $(m,d)$, the error is $(m,1)$, so transposing X to $(d,m)$ gives a result of shape $(d,1)$, exactly one gradient value per weight
$(y - \hat{y})$
the vector of errors across all $m$ days at once
the negative sign
tells us that moving each weight opposite to this gradient reduces the cost

Analogy

Meera's foot feels a slightly different slope depending on which direction she considers stepping in — north, east, or somewhere in between. The gradient is simply the combination of "how steep is it along the temperature-weight direction," "how steep along the footfall-weight direction," and so on for every weight, bundled into one set of numbers: one per weight, plus one for the bias.

Check your understanding

For a single training example, what's the correct partial derivative of the squared error with respect to the footfall weight $w_2$?

Differentiating $(y-\hat y)^2$ with respect to a specific weight $w_j$ brings down a factor of $-2(y-\hat y)$, multiplied by whichever input that weight multiplies in the prediction formula. For $w_2$, that input is footfall, $x_2$ — which is exactly why each weight's gradient depends on its own corresponding feature.

Updating the Weights

We now know exactly which direction is downhill. The only thing left to decide is how big a step to take — controlled by a single, important number: the learning rate.

Once we know the gradient, updating each weight is straightforward:

$$W := W - \alpha \frac{\partial J}{\partial W} \qquad\qquad b := b - \alpha \frac{\partial J}{\partial b}$$
$\alpha$ (alpha)
the learning rate — a small positive number, chosen before training, that controls how big a step we take downhill at each iteration
$\partial J/\partial W, \partial J/\partial b$
the gradients calculated in the previous section — telling us which direction is uphill
the minus sign
ensures we move opposite to that uphill direction — downhill, reducing the cost

Analogy, continued

If Meera takes very tiny steps down the hill (a very small $\alpha$), she'll eventually reach the bottom, but it could take a long time. If she takes very large strides (a very large $\alpha$), she risks overshooting the lowest point, landing on the opposite slope, and bouncing back and forth without ever settling — in severe cases ending up higher than where she started, called divergence. A common practical approach is to start with a slightly larger step and gradually shrink it, like jogging down the initial slope and taking smaller, careful steps as the valley floor approaches.

What's most likely to happen if the learning rate $\alpha$ is set far too large for the given problem?

A learning rate that's too large can cause each update to overshoot the lowest point repeatedly. Instead of settling near the minimum, the weights can swing between opposite sides of the bowl — and in severe cases the loss grows with every iteration instead of shrinking, a situation called divergence.

Bringing It Together: Training Meera's Model

We've covered every mathematical ingredient gradient descent needs: the cost function, the gradient, and the update rule governed by a learning rate. Now we implement the two remaining pieces our LinearRegression class needs — update_weights, which performs a single gradient descent step, and fit, which repeats it for a fixed number of iterations.

Python — a gradient step, and the training loop
def update_weights(self):
    y_pred = self.predict(self.X)
    error = self.Y - y_pred

    dW = -(2 * self.X.T.dot(error)) / self.m
    db = -2 * np.sum(error) / self.m

    self.W = self.W - self.learning_rate * dW
    self.b = self.b - self.learning_rate * db
    return self

LinearRegression.update_weights = update_weights

def fit(self, X, Y):
    self.m, self.d = X.shape
    self.W = np.zeros(self.d)
    self.b = 0
    self.X = X
    self.Y = Y
    self.error_list = []

    for i in range(self.iterations):
        self.update_weights()
        y_pred = X.dot(self.W) + self.b
        error = np.square(np.subtract(Y, y_pred)).mean()
        self.error_list.append(error)
    return self

LinearRegression.fit = fit

Key Takeaways

The concept

  • Linear Regression fits the best line, plane, or hyperplane through past data to predict a new value — for Meera, cups sold from temperature, footfall, and the weekend flag.
  • A coefficient's sign shows direction; its size shows pull — but sizes are only comparable once features are scaled.

The math

  • Gradient descent walks downhill on the cost function's bowl-shaped surface, using the gradient as its compass.
  • Mean Squared Error is the cost function; its gradient with respect to $W$ and $b$ tells us which way is uphill.
  • The learning rate sets the step size — too small is slow, too large can overshoot or diverge.
