01 — Introduction

The gap part one left open

The previous read ended with a working network: two hidden layers, trained with a library, reaching about 98.7% accuracy on the spiral dataset. It's easy to describe that network's architecture confidently — neurons, layers, activation functions. It's much harder to explain, honestly, how its weights ended up in the right place. Not what the network does. How it got there. That's the gap this read closes.

The loss landscape

Picture the loss as hilly terrain, and the current weights as a position on that terrain. The goal is the lowest point. The whole landscape isn't visible — only the slope underfoot. That slope is the gradient. Walking downhill, opposite to the slope, is gradient descent. How big a step is taken each time is the learning rate. A derivative gives exactly that: the slope at the current position, nothing more.

A toy example before any network is involved

The simplest possible loss to minimize: f(w) = (w − 3)². The minimum is obviously at w = 3, so it's possible to watch gradient descent find something already known.

def f(w):
    return (w - 3) ** 2

def grad_f(w):
    return 2 * (w - 3)

def gradient_descent_1d(lr, steps, w0=-5.0):
    w = w0
    history = [w]
    for _ in range(steps):
        w = w - lr * grad_f(w)
        history.append(w)
    return history

Output

learning rate 0.05 reaches the minimum in about 64 steps learning rate 0.4 reaches the minimum in about 5 steps

Same destination, wildly different step counts — purely because of step size. A smaller learning rate isn't "more correct," just more cautious: both runs reach the exact same minimum. The cost of extra caution is time, not accuracy — at least on a landscape this forgiving. Later sections show what happens on something much less forgiving than a single parabola.

Try it — three regimes, one slider

A very small learning rate (around 0.02–0.05) barely moves each step — technically correct, painfully slow. A moderate one (around 0.1–0.9) reaches w = 3 cleanly in a handful of steps. Push past roughly 1.0 on this particular function and each step overshoots further than the last — the point doesn't converge, it diverges. The same three regimes — too low, about right, too high — reappear later on a real network, where "too high" doesn't just waste time, it breaks the numbers entirely.

Check your understanding — 01

Both lr = 0.05 and lr = 0.4 eventually reached the same minimum, but lr = 0.4 got there in about 5 steps while lr = 0.05 took about 64. What does this best tell us about the learning rate?

The learning rate scales each step toward the minimum, so a larger but still safe value like 0.4 covers the same distance in far fewer updates than a cautious 0.05. Both settings converged to the exact same point, which rules out the idea that smaller is more accurate — and 0.4 clearly didn't diverge here.

02 — Core concept

Backprop, part one: one layer

Gradient descent says: take a step opposite the slope. But part one's SimpleNeuron had hand-picked weights. The actual slope of the loss with respect to each weight is needed — and the loss doesn't touch the weights directly. It goes through steps:

W  -->  Z = XW + b  -->  A = sigmoid(Z)  -->  Loss

Finding how the loss changes with W needs the chain rule: multiply how each step changes the next.

dLoss/dW = dLoss/dZ * dZ/dW

The one result worth memorizing the shape of

For sigmoid activation with binary cross-entropy loss, the messy calculus collapses into something remarkably simple:

dLoss/dZ = A - y

Prediction minus truth. That's the entire error signal.

Interactive — the error signal, dZ = A − y
dZ = A − y = -0.700

From dZ, two more steps finish the job: dW = Xᵀ · dZ / N (how much each weight contributed) and db = mean(dZ) (the bias gets the plain average error).

class SingleLayerNet:
    def __init__(self, n_features, seed=0):
        rng = np.random.RandomState(seed)
        self.W = rng.randn(n_features, 1) * 0.01
        self.b = np.zeros((1, 1))

    def forward(self, X):
        self.Z = X @ self.W + self.b
        self.A = 1 / (1 + np.exp(-self.Z))
        return self.A

    def backward(self, X, y):
        N = len(y)
        self.dZ = (self.A - y) / N   # prediction minus truth, averaged
        self.dW = X.T @ self.dZ
        self.db = np.sum(self.dZ, axis=0, keepdims=True)

    def step(self, lr):
        self.W -= lr * self.dW
        self.b -= lr * self.db

Output

Loss went from 0.6857 to 0.0134 Final accuracy: 100.00%

Why not just try this on the spiral?

Because a single layer's decision boundary is a straight line no matter how well it's trained — part one's hook already showed a linear-style boundary failing on a spiral. Training longer or better doesn't fix an architecture limitation. A decreasing loss confirms the direction of each update is right; it says nothing about whether the architecture is even capable of solving the actual problem.

Why does the gradient of sigmoid-plus-cross-entropy simplify to just "prediction minus truth"? ▾

Common weak answer: "It's just a formula you memorize."

Stronger answer

It's simple because cross-entropy loss and the sigmoid function were practically made for each other — when you chain-rule through both, the sigmoid's own derivative terms cancel out algebraically, leaving only the raw error. It's not a coincidence or an approximation; it's why this particular loss function is the standard pairing for this particular activation. The same cancellation happens for softmax with multi-class cross-entropy.

Check your understanding — 02

For a single-layer network, dZ = A − y for one training example where the true label is 1, but the network predicted A = 0.3. What does dZ tell us to do?

dZ = A − y = 0.3 − 1 = −0.7: the network gave only 30% confidence to a case that should have been 100% positive, so the error is negative and fairly large. A negative dZ pushes the relevant weights up, not down — the options starting from 1.3 or 0.3 both use incorrect arithmetic.

03 — Core concept

Backprop, part two: adding a hidden layer

One layer only draws a straight line. Solving the spiral needs a hidden layer. The chain gets one step longer:

W1  -->  Z1  -->  A1 = relu(Z1)  -->  W2  -->  Z2  -->  A2 = sigmoid(Z2)  -->  Loss

The output-layer math is unchanged: dZ2 = A2 − y, dW2 = A1ᵀ · dZ2, db2 = mean(dZ2). The new part is pushing the error signal one layer further back.

Step 1 — how much did the hidden layer's output (A1) contribute to the error?

dA1 = dZ2 . W2^T

Each hidden neuron gets blamed in proportion to how strongly it's connected, through W2, to the output that was wrong.

Step 2 — how much did the hidden layer's pre-activation (Z1) contribute?

dZ1 = dA1 * relu_derivative(Z1)

This is the genuinely new idea. relu_derivative(Z1) is 1 wherever a neuron fired during the forward pass, and exactly 0 wherever it didn't. A neuron that output 0 had zero influence on the prediction — so it gets zero blame for the error too, no matter how large dA1 is at that position. The error signal is gated by which neurons were actually switched on.

From there it's identical in shape to before: dW1 = Xᵀ · dZ1, db1 = mean(dZ1).

Field note — a bug that never crashes

An AI coding assistant, asked to write the backward pass for a two-layer network, produced a hidden-layer gradient that used dA1 directly as dZ1 — skipping the relu_derivative gate entirely. The shapes still match, so nothing errors. It trains to some degree and plateaus well below what the gated version reaches:

dZ1 = dA1 if buggy else dA1 * relu_deriv(Z1)   # the AI's version skips the gate

Output

AI's version, final accuracy: 65.33% With the relu_deriv gate restored, final accuracy: 98.67% AI's version was 65.33% -- the missing gate cost real accuracy, silently

Every hidden neuron gets blamed for the error whether or not it actually fired during the forward pass, producing gradients that are directionally noisy rather than outright broken. Some of the most costly real-world training bugs look exactly like this one: syntactically fine, numerically plausible, quietly worse. Comparing loss curves and accuracy — not just "did it run" — is part of debugging a network.

What happens to a hidden neuron's gradient if it never fires — Z1 stays negative — for every example in the dataset? ▾

Common weak answer: "It would get a very small gradient."

Stronger answer

Not small — exactly zero, every time, for every example. relu_derivative(Z1) is 0 wherever Z1 is negative, so that neuron's incoming error signal gets multiplied by 0 regardless of how large or informative dA1 is. Since the gradient is always exactly zero, the neuron's weights never update, and it stays dead forever unless something else about the network changes. This failure mode has a name — covered later in this read.

Check your understanding — 03

In the two-layer backward pass, dZ1 = dA1 × relu_derivative(Z1). For a hidden neuron whose pre-activation Z1 was negative for a given input, what happens to that neuron's gradient for that input?

relu_derivative(Z1) is 0 for any negative Z1, so multiplying dA1 by 0 zeroes out that neuron's gradient entirely — exactly what "a neuron that didn't fire gets no blame" means. Passing dA1 through unchanged is precisely the bug found in the AI-generated code above, and ReLU's derivative for negative inputs is a well-defined 0, not undefined.

04 — Closing the loop

Assembling the two-layer network

Every piece is now in hand. Assembled into one clean, trainable network and run on the actual spiral — this is the exact network from the first few minutes of part one, same architecture shape, same dataset.

class TwoLayerNet:
    '''Input -> hidden (ReLU) -> output (sigmoid).'''

    def __init__(self, n_features, n_hidden, seed=0):
        rng = np.random.RandomState(seed)
        # He initialization: scaled for ReLU so neurons don't start saturated or dead
        self.W1 = rng.randn(n_features, n_hidden) * np.sqrt(2.0 / n_features)
        self.b1 = np.zeros((1, n_hidden))
        self.W2 = rng.randn(n_hidden, 1) * np.sqrt(2.0 / n_hidden)
        self.b2 = np.zeros((1, 1))

    def forward(self, X):
        self.Z1 = X @ self.W1 + self.b1
        self.A1 = relu(self.Z1)
        self.Z2 = self.A1 @ self.W2 + self.b2
        self.A2 = sigmoid(self.Z2)
        return self.A2

    def backward(self, X, y):
        N = len(y)
        self.dZ2 = (self.A2 - y) / N
        self.dW2 = self.A1.T @ self.dZ2
        self.db2 = np.sum(self.dZ2, axis=0, keepdims=True)
        dA1 = self.dZ2 @ self.W2.T
        self.dZ1 = dA1 * relu_deriv(self.Z1)
        self.dW1 = X.T @ self.dZ1
        self.db1 = np.sum(self.dZ1, axis=0, keepdims=True)

    def step(self, lr):
        self.W1 -= lr * self.dW1; self.b1 -= lr * self.db1
        self.W2 -= lr * self.dW2; self.b2 -= lr * self.db2

Output — training for 6000 epochs, lr = 2.0, 128 hidden neurons

epoch 0 | loss 0.6976 | accuracy 53.67% epoch 1500 | loss 0.1909 | accuracy 96.00% epoch 3000 | loss 0.1848 | accuracy 91.00% epoch 4500 | loss 0.2046 | accuracy 90.67% Final training accuracy: 98.67%

This is the moment the loop actually closes.

Compared to part one's classical-ML plot — where Logistic Regression and Linear SVM both drew something close to a straight line through the middle — this boundary actually follows the spiral's arms. That's the hidden layer with a non-linear activation doing exactly the thing a single linear-style boundary can't.

05 — Core concept

Learning rate sensitivity

Same network, same architecture, same data across three runs below — only the learning rate changes: 0.001, 2.0, and 50.

Output

lr=0.001 -- loss after 3000 epochs: 0.6504 lr=2.0 -- loss after 3000 epochs: 0.1849 lr=50 -- loss after 2 steps: nan

lr = 0.001 barely moves — the loss stays close to where it started, the network essentially standing still. lr = 2.0 trends clearly downward and reaches a low loss, but the curve is spiky, with occasional sharp jumps upward before recovering — not a bug, but a learning rate aggressive enough to occasionally overshoot and briefly make things worse before correcting, while staying within the basin that converges. lr = 50 doesn't survive two full steps before the loss becomes NaN — the same NaN-loss failure mode from part one's loss-function section, now caused by something entirely different: a learning rate so large the weight updates overshoot catastrophically and the numbers blow up completely, rather than briefly.

Degree, not kind

lr = 2.0's overshoots are large but survivable — the next few steps pull the loss back down. lr = 50's overshoot is so large the weights leave any recoverable region entirely, and there's no next step to pull anything back. "Too high" isn't a single cliff edge; it's a spectrum, and a spiky-but-working curve is a sign of being closer to that edge than a smooth one.

The gradient descent playground from the start of this read uses the exact same mechanics on a much simpler function — pushing its learning rate slider past about 1.0 reproduces this same divergence pattern on a parabola, where it's easier to see why it happens.

Industry note — the most common real training bug

A learning rate off by an order of magnitude in either direction. Too low looks like "the model isn't learning" — a slow, undramatic failure easy to mistake for a data or architecture problem. Too high looks like "the model broke" — fast, dramatic, usually in the first few steps. That's exactly why experienced practitioners watch the loss closely at the very start of training, not just at the end.

Training a new model and the loss is NaN within the first few steps — what's the first hypothesis, and how would you check it? ▾

Common weak answer: "There's a bug in the code somewhere."

Stronger answer

A NaN loss in the very first few steps is the classic signature of a learning rate that's too high for this architecture and data, not necessarily a code bug — the fix to try first is simply lowering the learning rate by 10x and re-running before assuming anything else is wrong. It's a cheap, fast hypothesis to test, and it's right often enough that it should be the first thing checked, not the last.

Check your understanding — 04

The same network is trained twice. Run 1's loss barely moves after 3000 epochs. Run 2's loss becomes NaN after 2 epochs. What is the most likely explanation for each run, respectively?

A barely-moving loss over thousands of epochs is the signature of too small a learning rate — tiny steps make barely any progress. A loss that reaches NaN within a couple of epochs is the signature of too large a learning rate — the steps overshoot so badly the weights blow up. Random initialization alone doesn't produce such categorically different failure modes.

06 — Core concept

Optimizers: SGD, momentum, Adam

Everything so far has used the plainest possible update rule — and it's not what most real training actually uses. Every update so far has relied only on the current gradient, with no memory of previous steps. On bumpy or plateau-like loss surfaces, that means the same amount of hesitation every single step, even in a direction that's been consistently downhill for a while.

Momentum fixes this with one small change: keep a running average of recent gradients, and step in that averaged direction instead of the raw current one.

velocity = momentum * velocity + gradient
W = W - lr * velocity

Consistent downhill directions build speed; noisy, conflicting directions cancel out. It's the same intuition as a ball rolling downhill picking up momentum, rather than a hiker who stops and re-measures the slope from scratch at every step.

Output

plain gradient descent, final loss: 0.5955 with momentum, final loss: 0.2601

Adam goes one step further, and is the practical default in most modern training code: it keeps a running average of the gradient and a running average of the squared gradient, using the second to automatically shrink the effective step size for parameters getting noisy or large updates, and grow it for parameters getting small, consistent ones. The accounting gets fiddly fast — exactly the kind of thing a framework is built to absorb — but momentum alone already demonstrates the core idea.

Industry note — momentum and Adam aren't free

Adam in particular keeps two extra numbers in memory for every single parameter in the network — the running averages — which matters when a model has billions of parameters. For small networks the cost is irrelevant; at production scale, it's a real, deliberate trade-off between faster, more reliable convergence and extra memory and compute per step.

Check your understanding — 05

At the exact same learning rate, plain gradient descent plateaued while adding momentum kept improving over the same number of epochs. What does this demonstrate about momentum?

Momentum keeps a running average of past gradients, so consistent downhill directions build speed while noisy ones cancel out — exactly what let it escape the plateau plain gradient descent got stuck in, at the identical learning rate. It isn't secretly a larger learning rate, and it's still gradient descent, just with accumulated direction.

07 — Core concept

Overfitting: when training loss stops telling the whole story

Everything so far has judged the network only by training loss and training accuracy — an incomplete picture. A network can get better at the training set while getting worse at everything else. To see this honestly: a smaller training split, some corrupted labels mixed in, and a hidden layer oversized relative to how much clean signal is actually available — 512 hidden neurons for roughly 120 noisy training points, with 25% of training labels (not validation labels) deliberately flipped.

Output

validation loss bottomed out around epoch 1900

Training loss keeps falling for the full run. Validation loss falls for a while, bottoms out, then climbs back up — the network is increasingly memorizing the corrupted training labels rather than learning the spiral's actual shape, and that memorization actively hurts its performance on clean, unseen data.

What to actually do about it

Once validation loss starts climbing like this in production: stop training around where it bottoms out (early stopping), reduce the network's capacity, get more or cleaner training data, or add explicit regularization — not simply train for even longer.

Check your understanding — 06

Training loss kept falling for all 6000 epochs, but validation loss stopped falling partway through and then started rising. What should happen at that point?

Training loss falling while validation loss rises is the classic overfitting signature — the network is increasingly memorizing quirks of the training set rather than learning patterns that generalize. Training longer would widen the gap, not close it, and neither the learning rate nor the activation function addresses the actual problem, which is capacity relative to clean signal in the data.

08 — Core concept

Dying ReLU: a real diagnostic

The gating idea from earlier — a neuron that never fires gets exactly zero gradient — isn't just theory. Running the exact diagnostic on the network trained in the "build & train" section, nothing since has touched it:

Z1_check = X @ spiral_net.W1 + spiral_net.b1
dead_neurons = np.all(Z1_check <= 0, axis=0)

Output

54 out of 128 hidden neurons never fired for a single training example ...and yet the network still reached 98.7% accuracy
54 dead
74 alive

A substantial fraction of hidden neurons — roughly 40% in this run — are completely dead: zero output, zero gradient, for every single training example. They contributed nothing and can never update again. The network still performed well because it had enough surviving neurons to compensate — luck of having 128 to spare, not a guarantee.

Why this happens

If a neuron's weights and bias happen to push its pre-activation below zero for every input in the dataset, relu_derivative is 0 everywhere it's ever evaluated for that neuron. Zero gradient means zero update, forever — the neuron is permanently stuck, no matter how much more training happens. This is dying ReLU.

Leaky ReLU — the fix

Leaky ReLU replaces the flat zero on the negative side with a small non-zero slope, usually written as alpha (commonly around 0.01):

leaky_relu(z) = z            if z > 0
leaky_relu(z) = alpha * z    if z <= 0

The gradient on the negative side is now alpha instead of exactly 0 — small, but no longer nothing. A neuron pushed into the negative region still gets a faint update signal instead of being stuck permanently.

If dying ReLU only affects some neurons and the network can often still perform fine, why bother fixing it at all? ▾

Common weak answer: "It's best practice to always use Leaky ReLU instead of ReLU."

Stronger answer

It's a trade-off, not a strict upgrade — if only a small fraction of neurons die and the rest have enough capacity, performance may barely suffer, exactly what the diagnostic above shows. The risk is that it's silent and can compound: with a bad initialization, too high a learning rate early in training, or an unlucky combination of both, a much larger fraction of a network's neurons can die early and never recover, at which point there often isn't enough surviving capacity left to compensate. Leaky ReLU is a cheap insurance policy against that worse case, not a fix that's always necessary.

09 — Summary

Key takeaways

  1. 01Gradient descent is a search: the gradient gives direction, the learning rate gives step size, and both matter independently.
  2. 02For sigmoid plus cross-entropy, the entire error signal collapses to "prediction minus truth" — simple because of how the two functions were paired, not a coincidence.
  3. 03Extending backprop through a hidden layer adds exactly one new idea: gate the error by relu_derivative, so neurons that didn't fire get no blame.
  4. 04The network from part one's opening hook is no longer a mystery — it's the exact architecture built and trained by hand here.
  5. 05Learning rate has two failure modes, not one: too low stalls silently, too high explodes fast and loud. Both are diagnosable from the loss curve alone.
  6. 06Momentum and Adam don't replace gradient descent — they change how much memory an update has of previous steps, and that memory is what escapes plateaus plain gradient descent gets stuck in.
  7. 07Overfitting shows up as training and validation loss disagreeing, not as training loss alone looking bad. Dying ReLU shows up as neurons with a gradient of exactly zero, diagnosable directly on a trained network.

Self-check

Six questions pulled from across this read — no new facts here, just a chance to retrieve what's already covered.

Why does the gradient of sigmoid-plus-cross-entropy simplify to "prediction minus truth"?

Cross-entropy loss and sigmoid were practically made for each other — chain-ruling through both causes sigmoid's own derivative terms to cancel out algebraically, leaving only the raw error, A minus y.

What does the relu_derivative gate actually do during backpropagation?

It's 1 wherever a neuron fired (Z1 > 0) and exactly 0 wherever it didn't, so a neuron with zero output gets zero blame for the error, no matter how large the incoming error signal is.

What's the difference between a loss curve that's stalled versus one that's diverging?

A stalled curve barely moves over thousands of epochs — the learning rate is too small. A diverging curve blows up toward NaN within a handful of steps — the learning rate is too large and updates overshoot catastrophically.

Why does momentum help escape a plateau that plain gradient descent gets stuck on?

Momentum keeps a running average of past gradients. A consistent downhill direction builds speed across steps, carrying the update through a flat region that a single current-step gradient alone would barely move through.

What's the difference between training loss and validation loss telling different stories?

Training loss falling while validation loss rises means the network is memorizing quirks of the training set rather than learning patterns that generalize — the overfitting signature, best addressed with early stopping, regularization, or more/cleaner data.

How would you check a live network for dying ReLU, and what would you do about it?

Run the training inputs through the first layer and check whether any hidden neuron's pre-activation is negative or zero for every single example — that neuron is permanently dead. Leaky ReLU, a small non-zero slope on the negative side, is the standard fix.
