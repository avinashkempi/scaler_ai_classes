Hyperparameter tuning: finding better neural networks

A neural network that scores well on the data it trained on can still fail on new data. This read follows one delivery-delay model through diagnosis and four fixes: L2 regularization, dropout, batch normalization and early stopping.

The story: QuickCart

Meera is a data scientist at QuickCart, a grocery delivery startup. Her task: at the moment an order is placed, predict whether the delivery will miss its promised window, so operations can re-route early.

She already knows logistic regression, but this problem calls for a neural network because the features interact. A heavy order, plus rain, plus a new rider is not the sum of three separate effects.

This read follows her build step by step, and every time she hits the same wall.

Recap: overfitting

AnalogyA student memorizes the answers to a practice paper instead of learning the method. On that same paper they look brilliant. On a new paper they fall apart.

A network does the same when it has enough capacity: it fits the real pattern and the noise in the training set. The tell-tale sign is training accuracy far above validation accuracy. Everything that follows is a way to keep that gap small.

Prepping the data: categories to numbers

QuickCart's data mixes numeric features (distance, weight) with categorical ones (zone, delivery mode, rider tier). A neural network only accepts numbers, so Meera uses target encoding: each category is replaced by the historical average of the outcome for that category.

Why scale matters: standardization

Distance in kilometres next to weight in grams is like comparing height in metres to age in days. The features are not on the same footing. Unscaled features stretch the loss surface into a lopsided shape, and gradient descent zig-zags across it.

The fix is to z-score every feature.

z = x − μσ
x
raw value
μ
feature mean (training data)
σ
feature standard deviation (training data)

The result is a more symmetric bowl, which means faster and steadier convergence.

Baseline model and the right loss

Meera's baseline is a few dense layers. The final neuron is a sigmoid, so the network outputs a probability ŷ between 0 and 1. The true label y is either 0 or 1, so a continuous prediction is being compared with a hard label. The loss that fits this pairing is binary cross-entropy.

L = −1m mΣi=1 [ yi log(ŷi) + (1 − yi) log(1 − ŷi) ]
m
number of examples
yi
true label
ŷi
predicted probability

Binary cross-entropy punishes confident wrong predictions heavily. Compare it with mean squared error below.

Binary cross-entropy versus MSE

True label is 1 (late). Drag the marker toward 0 to make the model confidently wrong.

BCE gradient
MSE gradient
BCE is stronger by

Gradient signal is the size of dL/dz at the sigmoid neuron's input z. For binary cross-entropy that is |ŷ − y|. For MSE, defined as (y − ŷ)², it is 2|ŷ − y| · ŷ(1 − ŷ), which flattens out as ŷ nears 0 or 1.

Fix 1

L2 regularization

AnalogyEvery weight is a volume knob. Overfitting is a few knobs cranked way up for tiny quirks. L2 is a spring quietly pulling every knob back toward zero, unless the data really insists otherwise.
Lreg = L + λ2m Σ (WL)² WL := WL − η (dWL + λmWL)
λ
regularization strength (hyperparameter)
m
number of examples
WL
layer L's weights
η
learning rate
dWL
original gradient, before regularization

This is also called weight decay. Each update shrinks the weights a little, in addition to reducing error.

Fix 2

Dropout

AnalogyA team that only ever plays its five stars collapses if one is out. A coach who randomly benches players in practice forces everyone to become independently capable, and the team becomes more robust.

Dropout: train versus test

Masking happens only during training. At test time all neurons are active, with no masking and no further adjustment. This just works because the inverted scaling during training already calibrated the network for full-capacity behaviour.

Fix 3

Batch normalization

AnalogyA chef who recalibrates the kitchen scale before every use, versus a scale that silently drifts and forces constant guesswork.

The problem: as early layers update, the input distribution that later layers see keeps shifting, so they chase a moving target. The fix is to normalize each layer's input per mini-batch.

Batch meanμB = 1n Σ zi
Batch varianceσ2B = 1n Σ (zi − μB)²
Normalizeẑi = zi − μB√(σ2B + ε)
Scale and shiftyi = γ ẑi + β
n

zi

ε
tiny constant (avoids dividing by zero)
γ, β

Toy values with ε = 0.00001. With γ = σB and β = μB the layer recovers its original values, so normalization never removes what the layer could represent.

Fix 4

Early stopping

AnalogyA cake left in the oven past the right time does not get better. It just dries out.

Meera trains longer, expecting accuracy to keep climbing. Instead, validation accuracy peaks and then declines while training accuracy keeps rising. The model is back in overfitting.

The fix: after every epoch, check validation performance and save the best version so far. Stop once validation performance has stalled for a set number of epochs, called the patience.

Wrap-up

  • Overfitting is a train/validation gap caused by memorizing noise instead of pattern.
  • Target encoding and standardization prepare the data for stable training.
  • Sigmoid with binary cross-entropy fits a probability-versus-binary-label problem.
  • Automation extends this diagnostic process but does not replace it.
