Logistic Regression Intuition
⏱ 4 min

Linear Regression, Revisited

In linear regression we fit a line or plane to most of the points, then use that line to predict values for future inputs — like predicting the price of a car from its age. That plot looked like a good fit.

Now the Problem Changes

We want to identify classes, not continuous values. We have data points for two classes: class 1 (dot, means churned) and class 2 (cross, means not churned).

Given some new, unlabeled data points, how do we identify which class they belong to?

Approach

  • Observe the target variable: two different classes → this is a case of classification.
  • The simplest approach is to draw a line that separates the datapoints between the two classes.
  • Points on one side of the line are class 0; points on the other side are class 1.

We want a line (or plane) such that points fall on either side of it. This gives us the hyperplane:

z = w₀ + w₁x₁ + w₂x₂ + … + w_d x_d

You can also check how this plane separates the classes in 3D.

📐
Math
Hyperplanes
⏱ 4 min

A hyperplane is an n-dimensional generalization of a plane — an affine subspace of dimension n − 1 that splits an n-dimensional space.

In 3D space, a hyperplane is one dimension less than 3, i.e. a 2D plane. In 2D space, one dimension less is a single-dimensional line, and so on. Hyperplanes are the general entity — line, plane, or higher-dimensional separator depending on the number of dimensions.

Distance Implies Confidence

If we consider the line/plane as the separator, which points are more probable of being in class 1? The points that are farther away from the separator are more probable of being in that class.

So, the more the distance from the separator, the more the probability of belonging to that class.

📌 From Distance to Probability
A hyperplane gives us a distance score, telling us how far a point lies from the decision boundary. But distance alone is hard to interpret in business terms. Saying "there is an 85% chance this customer will churn" is far more useful than "distance = 4.2" — that's exactly why we need a function that converts raw scores into probabilities.

Can we use the linear function directly for predictions? Note that the true values yᵢ are {0, 1}, but our linear function z ranges over {−∞ to +∞}.

We need a filter/function to compress that range into 0–1. That function is the sigmoid function — also called the logistic function.

❓

  • True
  • False
💡 Explanation
It's the opposite. Distance and confidence are directly proportional — the farther a point lies from the hyperplane, the higher the probability that it belongs to that class, not lower.

Concept
Sigmoid Function & Thresholding
⏱ 6 min

We take the input z = w₀ + w₁x₁ + w₂x₂ + … + w_d x_d and pass it through the sigmoid (logistic) function, so the output lies between 0 and 1.

🎮
Interactive Visualizer
See how the sigmoid function compresses any input value:
Sigmoid Function — Input/Output Transformation →

The sigmoid function is probabilistic in nature — its output between 0 and 1 can be interpreted as the probability of belonging to class 1.

  • Sigmoid output of 0.7 → 70% probability of being in class 1
  • Sigmoid output of 0.2 → 20% probability of class 1, i.e. 80% probability of class 0
📌 From Probability to Decision
The model gives us probabilities, which is useful. But most business problems eventually need a hard yes/no decision — so we need a rule to convert probabilities into final class labels.

Thresholding

The actual labels yᵢ are exactly 0 or 1. But the predicted value ŷᵢ is somewhere between 0 and 1 — it may be 0.7, 0.2, or 0.34.

So we set a threshold, above which we assign one class and below which we assign the other.

The threshold is not always 0.5 — it can depend on the use case.

Why Is It Called "Logistic Regression" if We Are Doing Classification?
⏱ 2 min

The term "logistic regression" comes from the logistic (sigmoid) function.

  • At its base, it's doing regression only — we output a real value between 0 and 1 that we treat as a probability.
  • On top of that regression, we apply the logistic function — hence, logistic regression.
  • The true labels yᵢ are 0 or 1, but our predicted ŷᵢ ranges continuously between 0 and 1.

Comparing yᵢ vs ŷᵢ
⏱ 3 min
📌 Beyond Predicting Probabilities
Predicting probabilities is only half of model training. The next question is: how does the model know whether its predictions are good or bad during training?

We use Log-Loss as the loss function for classification.

📎 Reference
Log-loss comes from the principle of Maximum Likelihood Estimation. We won't derive it from probability theory here — instead we'll build intuition for why it makes sense and how it behaves.
📉
Math
Log-Loss Intuition
⏱ 5 min

Let's plot a graph between error and ŷ.

Case: yᵢ = 1

  • If ŷᵢ = 1 → error is very low, near 0.
  • If ŷᵢ = 0 → error is very high (say, infinity).
  • If ŷᵢ = 0.99 → error is slightly greater than when ŷᵢ was 1.
  • If ŷᵢ = 0.01 → error is slightly lesser than infinity.

This is exactly the plot of the equation:

−log(ŷ)

We don't worry about the part of the curve below ŷ = 0, since ŷᵢ is always between 0 and 1 — so the loss is always positive.

Case: yᵢ = 0

  • If ŷᵢ = 0 → error ≈ 0.
  • If ŷᵢ = 1 → error = ∞.

This curve is the plot of the equation:

−log(1 − ŷ)

So mathematically, we can define log-loss using these two cases:

📌 One Equation, Not Two
We now have two separate loss equations — one for when the actual class is 1, another for when it's 0. For optimization, working with a single unified equation is much more convenient.
➕
Math
Combining Both Cases into One Equation
⏱ 3 min

Using a small piece of clever math, we can combine both log-loss cases by simply adding them — one of the two terms always evaluates to zero for a given sample:

L = −y·log(ŷ) − (1−y)·log(1−ŷ)

When y = 1, the second term vanishes and we're left with −log(ŷ). When y = 0, the first term vanishes and we're left with −log(1−ŷ) — exactly the two cases we derived earlier.

💻

Summary

  • Log-loss decreases as ŷᵢ gets closer to yᵢ.
  • Log-loss increases as ŷᵢ gets farther from yᵢ.
  • This means we can use optimization techniques, like gradient descent, on the log-loss function to find the optimal weights of the logistic regression model.

Quiz 3
Log-Loss for a Confident, Correct Prediction
⏱ 1 min
Suppose the actual label is y = 1 and the predicted probability is ŷ = 0.8. What will the log-loss be?
  • Log-loss will be a very high value.
  • Log-loss will be a very low value.
  • Log-loss will be 0.
💡 Explanation
Since ŷ = 0.8 is fairly close to the actual label y = 1, the −log(ŷ) term stays small. The closer ŷ gets to y, the closer the log-loss gets to 0 — but it never reaches exactly 0 unless ŷ = 1.
🎯
Concept
Optimization
⏱ 3 min

So far we've only seen log-loss for the i-th sample. We define the full loss function for logistic regression as the sum of log-loss over all n samples:

L_all = Σᵢ [ −y·log(ŷᵢ) − (1−y)·log(1−ŷᵢ) ]

We use gradient descent to optimize this equation.

📌 Better Predictions → Lower Loss
Minimizing loss helps us fit the training data well — but fitting too well can become a problem of its own. This is where regularization, which we saw in linear regression, comes back into play.
🛡️
Concept
Regularisation
⏱ 4 min

Similar to regression, logistic regression can also use a regularizer. We optimize the weights (w_j) using the same regularization parameter λ.

📌 In Code
Sklearn takes a parameter C, which is the inverse of λ.
🤔 Ask Yourself

If there is no non-linear feature, should we still use regularization when performing min L?

Yes — to avoid overfitting the model.

We add an L2 regularization term to the loss function L. Gradient descent now performs gradients on:

min Σᵢ [ L + λ Σⱼ wⱼ² ]

Quiz 4
Choosing a Threshold for Cancer Detection
⏱ 1 min
You are building a model to predict whether a person has cancer. Your goal is to avoid missing any cancer patient, even if it means identifying some healthy people as cancer-positive. Which threshold should you choose?
  • If predicted probability > 0.5, classify as having cancer.
  • If predicted probability > 0.7, classify as having cancer.
  • If predicted probability > 0.9, classify as having cancer.
  • If predicted probability > 0.3, classify as having cancer.
💡 Explanation
Lowering the threshold makes it "easier" for a data point to be classified as cancer-positive. This increases recall — fewer actual cancer patients slip through as false negatives — at the cost of flagging more healthy people as false positives, which is an acceptable tradeoff here.

Performance Metric — Accuracy
⏱ 4 min
📌 From Training to Evaluation
So far, we've focused on training the model correctly. Once training is complete, the next question is: how do we evaluate whether the model is actually performing well?

Accuracy is calculated by dividing the number of correct predictions by the total number of samples.

Given data where y is the correct label, ŷ is the predicted output, and y-pred is the model's raw scalar output (before sigmoid) — entries where y and ŷ differ are called misclassifications.

🤔 Suppose 100 data points, 10 misclassified

How many are accurate? 90.

What is the accuracy? 90/100 = correct predictions / total predictions.

Accuracy = Correct Predictions / Total Predictions

Implementation
Sklearn Pipeline
⏱ 8 min

A Pipeline chains multiple processing steps into a single scikit-learn estimator, with the same fit, predict and score methods as any other estimator.

from sklearn.pipeline import make_pipeline
train_scores = []
val_scores = []
scaler = StandardScaler()
for la in np.arange(0.01, 12000.0, 100): # range of values of Lambda
  scaled_lr = make_pipeline( scaler, LogisticRegression(C=1/la))
  scaled_lr.fit(X_train, y_train)
  train_score = scaled_lr.score(X_train, y_train)
  val_score = scaled_lr.score(X_val, y_val)
  train_scores.append(train_score)
  val_scores.append(val_score)
  1. Initialize the range of values for λ.
  2. For each value of λ, create a pipeline of standardization + logistic regression.
  3. Fit the training data to the model.
  4. Record the train and validation scores.
📌 Note
The default scoring metric here is Accuracy.

plt.plot(list(np.arange(0.01, 12000.0, 100)), val_scores, label="val")
plt.legend(loc='lower right')

plt.xlabel("Regularization Parameter(λ)")
plt.ylabel("Accuracy")
plt.grid()
plt.show()

Validation accuracy rises to a peak and then decreases. As regularization increases, accuracy keeps decreasing since the model moves toward underfitting.

Picking the Best λ

We pick the λ where the validation score is maximum:

np.argmax(val_scores)

Validation score is maximum (76.2%) at index 23, so our best λ is:

l_best = 0.01 + 23 × 100

(since we step by 100 in each iteration). Let's train the final model with this best λ:

scaled_lr = make_pipeline( scaler, LogisticRegression(C=1/l_best))
scaled_lr.fit(X_train, y_train)

Now let's test this best model on the held-out test data:

test_score = scaled_lr.score(X_test,y_test)

📌 On the Scaler in the Pipeline
The scaler performs scaling first, then logistic regression runs. It uses the training data's mean and standard deviation during fit, and continues using those same statistics for validation and test data — since we only call .score() on them, never .fit().

Impact of Outliers
⏱ 3 min

Case I — Outlier on the Correct Side

Here ŷ = σ(zᵢ), and since the point sits on the correct side of the boundary, the loss is very small — the impact of this outlier is very low.

Case II — Outlier on the Wrong Side

Say zᵢ = −4.3, so ŷ becomes 0.01. Then:

L = −log(0.01) ≈ 4.6

This is a very large loss value — so the impact of this outlier on training is very high. It pulls the decision boundary toward itself in order to reduce that loss.

The best approach is to find such outliers and remove them, to get more accurate and stable results.

Summary
Wrapping Up
⏱ 1 min

Everything we've seen so far assumes binary classification — only two classes. But many real-world problems involve more than two possible outcomes.

Classification predicts discrete classes, not continuous values
A hyperplane z = w₀ + w₁x₁ + … separates classes
Sigmoid squashes z ∈ (−∞,∞) into a probability ∈ (0,1)
A threshold (not always 0.5) converts probability → class label
Log-loss: −y·log(ŷ) − (1−y)·log(1−ŷ)
Log-loss is minimized via gradient descent
L2 regularization (parameter C = 1/λ) prevents overfitting
Accuracy = correct predictions / total predictions
predict_proba exposes the underlying probabilities
Sklearn pipelines chain scaling + model into one estimator
Best λ maximizes validation accuracy while keeping train/test close
Outliers on the wrong side of the boundary distort it — remove them
That is what we'll tackle in the upcoming lecture: multi-class classification, followed by evaluating classification models with accuracy, precision, recall, and more.
