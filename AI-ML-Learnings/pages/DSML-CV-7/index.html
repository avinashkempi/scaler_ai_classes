    From “what is in this image?” to “what is where?”. We build a single-object gun localizer (a frozen ResNet-50 with a class head and a box head), score it with Intersection over Union, then see how detection handles many objects: sliding windows, non-max suppression, and the two-stage R-CNN family up to Faster R-CNN.

    01

    Classification vs detection

    Shootings in schools, malls and other public places have created demand for monitoring that spots danger early and raises an alert. Most security teams still rely on walk-through or handheld metal detectors, which only sense changes in a magnetic field. You are an ML Engineer at Omnilert AI, building an AI-powered visual gun detection system that triggers alerts and safety protocols: connect to existing surveillance cameras and recognise firearms quickly and reliably.

    So far, CNNs have told us what is in an image: one label and one probability for the whole picture. They don’t tell us where the object is, or how many there are.

    What

    Classification

    One label (and probability) for the whole image.

    Where

    Localization

    The class and a bounding box, for one object.

    How many

    Detection

    A class and a box for each object in the image.

    02

    The data and its annotations

    The dataset has 3,703 image files (1.jpg …) with a matching text annotation each. An annotation holds five numbers: class x_center y_center width height.

    • class: 1 = gun, 0 = no gun.
    • The four box values are fractions of the image width and height, so they lie between 0 and 1.
    • Images with no gun carry an all-zero box.

    Reading the pixel size from the image itself keeps the box in the right place even if an image isn’t 416 × 416.

  03
  
    A localization model: backbone + two heads
    
  
    To get a box as well as a class, take a classifier and add outputs at the end: one neuron for the class and four neurons for the box (a regression head).
    
  
    
  
    
    
    Class head
    One output, the gun logit.
    
    
    Box head
    Four outputs (x_center, y_center, width, height) through a sigmoid, so they stay between 0 and 1 like the normalized labels.
    
  
    
  
    
    
    1
    Frozen ResNet-50
    Pre-trained on ImageNet, global pooling and the final layer dropped. A 416 × 416 image becomes a 2048 × 13 × 13 feature map (the network shrinks the image by 32). Pooling is dropped on purpose because it would throw away where things are.
    
    
    2
    1 × 1 conv reduction
    Squeeze 2048 channels down to 32 while keeping the 13 × 13 layout, then flatten to 32 × 13 × 13 = 5,408 values.
    
    
    3
    Two small heads
    Each head is Linear(5408→128), ReLU, Linear(128→32), ReLU, Linear(32→out), with out = 1 (class) or 4 (box).
    
  
    
  
    
  
    The frozen backbone’s batch-norm statistics are kept fixed too: the model’s train method puts the backbone back in eval mode. The model expects pixel values 0–255 and normalizes them with the ImageNet mean and standard deviation inside forward.
    
  
    Code: dataset, backbone, GunLocalizer, sanity check
    

  
    Loss and training
    
  
      
    
    • Class head: binary cross-entropy on the gun logit.
      • 
    
    • Box head: mean squared error, only on images that contain a gun.
      • 
    
    • Total loss = 4.0 × box loss + 1.0 × class loss.
      • 
  
    
  
    
  
    
  
    Only the new layers go to the Adam optimizer (learning rate 1e-4). Batches have 32 images. run_epoch trains when train=True and only measures otherwise, tracking box error on gun images, class loss, accuracy, and the counts needed for recall and specificity. The test split doubles as validation data here so we can watch generalization; nothing is tuned on it.
    
  
    Code: loss, optimizer and run_epoch

  05
  
    Intersection over Union (IoU)
    
  
    MSE tells us how far apart the numbers are, not how well the boxes overlap. IoU measures overlap directly:
    
  
    IoU = area of overlap ÷ area of union. It runs from 0 (no overlap) to 1 (perfect match). A prediction usually counts as correct when IoU ≥ 0.5 (the PASCAL VOC convention).
    
  
    
  
    To compute it: convert boxes from centre format to corners, then take the overlap rectangle (clipped at zero) and divide by the union (sum of the two areas minus the overlap). Before trusting the function, the lecture tests it where the answer is known: identical boxes give 1, disjoint boxes 0, a same-size box shifted by half its width 1/3, and a box fully inside another at quarter size 0.25.
    
  
    
  
    
  
    
  
    Code: IoU functions, checks and a test image
    
  
    Mean IoU and correct detections
    
  
    No-gun images have no true box, so mean IoU is averaged over gun images only. A correct detection is a gun image where the model says gun (probability ≥ 0.5) and the box has IoU ≥ 0.5 with the truth. The lecture finds train: mean IoU 0.6081, 70.4% correct; test: mean IoU 0.5661, 63.7% correct. A big train/test gap usually means the box head is overfitting. The IoU of the single test example above is 0.645 (the box is clearly useful but far from perfect).
    

    

    


    

    
  06
  
    From one box to many
    
  
    A localization model outputs a fixed four numbers, so it can find only one object per image. Algorithms that classify and locate many objects, with a box around each, are called object detection algorithms.
    
  
    
  
    Sliding window
    
  
    Slide a box across the image and classify each crop (object or not). This turns detection into a classification problem. Objects come in different sizes, so we try windows of several sizes and scales.
    
  
    
  
    The catch is cost. Every crop goes through the CNN separately, so one image needs many forward passes. Fewer windows and a larger stride help. And one object gets detected several times, across neighbouring windows and scales. A fully convolutional network can do the sliding in a single pass.
    
  
    
  
    Lecture figures: fully convolutional sliding and duplicate detections
    

  
    Non-max suppression (NMS)
    
  
    NMS removes the duplicate boxes for each object.
    
  
      
    
    1. Pick the proposal with the highest confidence, remove it from the list and add it to the final list.
      2. 
    
    2. Compute its IoU with every remaining proposal.
      3. 
    
    3. Remove every proposal whose IoU with it is above a threshold N (between 0 and 1).
      4. 
    
    4. From what is left, pick the highest-confidence proposal, add it to the final list and repeat.
      5. 
    
    5. Stop when no proposals are left.
      6. 
  
    
  
    
  
    
  
    Code: overlap table, nms and the torchvision check
    
  
    
  
    
  
    Sliding windows let us treat detection as classification, but pushing so many positions and scales through a CNN is expensive. Can we do better? Yes: test fewer regions, and skip the regions where no object is present.
    

    

    


    

    
  07
  
    Two-stage detectors: R-CNN and Selective Search
    
  
    The R-CNN family (Regions + CNN) uses a separate region proposal method to find regions of interest, the places where an object might be. They are called two-stage because stage one proposes regions that may contain an object, and stage two classifies each region and refines its box.
    
  
    
  
    R-CNN (2013)
    
  
    Rich feature hierarchies for accurate object detection (paper). It works in three steps:
    
  
      
    
    1. Region proposals from an algorithm such as Selective Search.
      2. 
    
    2. Features: warp each proposal to the CNN input size and extract features with a pre-trained CNN such as VGG-16 or ResNet: one forward pass per proposal, about 2000 per image.
      3. 
    
    3. Classify and refine: each proposal with a Support Vector Machine (SVM), and refine its box with a bounding-box regressor, both fed by those features.
      4. 
  
    
  
    
  
    Selective Search
    
  
    A bottom-up region proposal algorithm:
    
  
      
    
    1. Over-segment the image into many small regions (Felzenszwalb and Huttenlocher’s graph-based method).
      2. 
    
    2. Add each region’s bounding box to the proposal list.
      3. 
    
    3. Merge the two most similar neighbouring regions (similarity combines colour, texture, size and shape).
      4. 
    
    4. Repeat from step 2 until one region covers the whole image.
      5. 
  
    
  
    The collected boxes are the proposals, and R-CNN keeps about 2000 per image. This is far cheaper than running sliding windows over an image pyramid. More on Selective Search.
    
  
    
  
    
  
    

    

    


    

    
  08
  
    Fast R-CNN and ROI pooling
    
  
    Fast R-CNN (2015, paper) still uses Selective Search for proposals, but runs the CNN once on the whole image to build a feature map instead of once per proposal. ROI pooling crops each proposal from that map and resizes it to a fixed size, and the SVMs are replaced by fully connected layers with two outputs: a softmax classifier and a box regressor.
    
  
    
  
    The big win: the network trains end to end (proposals still come from Selective Search). Input an image and its ground-truth boxes, extract the feature map, apply ROI pooling to get a feature vector per proposal, then two sets of fully connected layers output the class label and the box location for each proposal.
    
  
    What is ROI pooling?
    
  
    ROI pooling is max-pooling whose pool size adapts to the input, so the output is always the same size. We need that because fully connected layers expect a fixed-size input.
    
  
    
  
    A worked example
    
  
    Take a single 8 × 8 feature map, one region of interest and an output size of 2 × 2. The proposal’s (top-left, bottom-right) corners are (0, 3) and (7, 8) as (column, row), with the bottom-right exclusive, so the region is 7 columns wide and 5 rows tall. Splitting it into 2 × 2 sections (which need not divide evenly) and taking the max of each gives the pooled output. The same operation works for proposals of any width and height and always gives the same output size.
    
  
    
  
    
  
    Try the smaller gun at the top-right of the lecture figure by moving the region. If a region does not divide evenly, neighbouring sections can share a boundary row or column, and a hand split such as 3 + 4 columns can differ from the code’s rule if the max sits on the shared line, so decide your splitting rule before comparing.

  09
  
    Faster R-CNN and the Region Proposal Network
    
  
    In Fast R-CNN, proposals still come from Selective Search, which runs outside the network, doesn’t learn from the data and is slow. With Selective Search, Fast R-CNN takes about 1.8 s per image, most of it spent on proposals. To go faster, the network itself should produce the proposals.
    
  
    Faster R-CNN (2015)
    
  
    Towards real-time object detection with Region Proposal Networks (paper). The main idea: use the last convolutional layers of the backbone to predict region proposals. It has two modules: the RPN, which produces rectangles from deep convolutional features, and the Fast R-CNN detector, which pools each proposal with ROI pooling, classifies it and refines its box.
    
  
    
  
      
    
    1. Take a CNN pre-trained on ImageNet as the backbone.
      2. 
    
    2. Get feature maps from its last convolutional layer.
      3. 
    
    3. Train a region proposal network that decides whether each location holds an object and proposes a box.
      4. 
    
    4. Turn RPN outputs into proposals: apply the box offsets to the anchors, drop low-scoring boxes, run NMS and keep the top few hundred (300 in the paper).
      5. 
    
    5. Pass the proposals to ROI pooling, as in Fast R-CNN.
      6. 
    
    6. Send the pooled features to fully connected layers for classification and box refinement.
      7. 
  
    
  
    Region Proposal Network (RPN)
    
  
    A fully convolutional network that predicts object bounds and an objectness score at every position, trained end to end. The RPN and Fast R-CNN share convolutional features, so they merge into one network: the RPN tells the detector where to look. Anchor boxes at several scales and aspect ratios serve as references, so there is no need for image pyramids or multiple filter sizes.
    
  
      
    
    1. Features from a pre-trained CNN such as VGG-16 or a ResNet.
      2. 
    
    2. Anchors: k = 9 at each feature-map position (3 scales × 3 aspect ratios; the paper uses areas of 128², 256² and 512² pixels with ratios 1:1, 1:2 and 2:1).
      3. 
    
    3. Labeling anchors: positive if it has the highest IoU with some ground-truth box, or IoU above 0.7 with any; negative if IoU below 0.3 with every ground-truth box; all others ignored.
      4. 
    
    4. Box regression: for each anchor, an objectness score and four offsets (tx, ty, tw, th).
      5. 
  
    
  
    
  
    
  
    A common mix-up. The RPN uses 0.7 / 0.3 to label anchors. The 0.5 and 0.1 thresholds belong to the second stage, where Fast R-CNN samples foreground ROIs with IoU ≥ 0.5 and background ROIs with IoU in [0.1, 0.5). And the RPN predicts four offsets relative to the anchor, not “width, height and depth”: images are 2D.
    
  
    The RPN loss is a weighted sum of a classification term (log loss on objectness) and a regression term (smooth L1, counted only for positive anchors); see Equation 1 in the paper. In short: the image goes through the CNN to get a feature map; at each position there are anchor boxes, and for each anchor the RPN predicts the probability that an object is there, plus the box offsets to apply if so.
    
  
    
  
    

  
    Training Faster R-CNN
    
  
    The paper trains the RPN and the detector with a 4-step alternating scheme so they end up sharing convolutional layers. Joint training in one pass also works. A jointly trained model has four losses: RPN classification (object or not), RPN box proposal, Fast R-CNN classification (the object class) and Fast R-CNN box regression (refines the proposal).

    Key takeaways
    
  
      
    
    • A single-object localizer is a frozen pre-trained backbone with a class head and a box head, trained with a box loss on gun images only.
      • 
    
    • Evaluate with accuracy, recall, specificity and IoU: 99.8% test accuracy against a 73.0% baseline, but only 63.7% correct detections (class and IoU ≥ 0.5).
      • 
    
    • NMS removes duplicate detections of the same object.
      • 
    
    • Detection grew from sliding windows to the R-CNN family: R-CNN (a CNN pass per proposal), Fast R-CNN (one shared feature map and ROI pooling) and Faster R-CNN (proposals from the Region Proposal Network).
