🏨 CASE, IF() & Conditional Aggregation

What this covers: A reflective recap of how to turn raw column values into business-readable labels using Simple CASE, Searched CASE, and IF() — and how to combine those labels with COUNT and SUM to build full pivot-style reports in a single query. All examples use the leela_palace hotel dataset (staff, salary_grades, staff_salaries).

🗄️

Opening Hook — Labels the Database Doesn't Have 🤔

Every hotel staffing report is built on business "buckets" — Permanent Staff, Contractual Staff, Inactive. None of these labels live in the raw table. The employment_type column only ever stores 'full-time' or 'contract'.

MANAGER
Can you give me a headcount breakdown by employment category? I want: Permanent Staff, Contractual Staff, and Inactive — not the raw values.
ANALYST
'full-time' and 'contract' are the values in the column. But 'Permanent Staff' and 'Contractual Staff' don't exist anywhere in the database.
MANAGER
Then create them.

That single instruction — "then create them" — is exactly what CASE WHEN does. It runs row by row, just like any other expression in SELECT, translating raw values into analyst-defined categories.

By the end of this recap, you should be able to:

  • Label hotel staff as 'Permanent' / 'Contractual' / 'Inactive' based on columns.
  • Classify staff salaries into 'Entry' / 'Mid' / 'Senior' bands.
  • Count how many staff fall in each band — in a single query.
  • Split total payroll by department in one row using conditional SUM.
  • Answer any "how many of X are Y?" questions without writing five separate queries.
CASE WHEN is the bridge between raw column values and the business buckets a manager actually asks for
⭐ CASE WHEN turns raw column values into analyst-defined categories. If you can describe it, you can write it.

Simple CASE — Match a Column to Exact Values 🎯

Simple CASE compares one column against a fixed list of exact values — much like a switch statement in programming. It is the right tool whenever raw values need a direct, one-to-one label swap.

MANAGER
The employment_type column has 'full-time' and 'contract'. I want a clean display column showing 'Permanent' and 'Contractual' instead.
📄 Query 2.1 — Simple CASE for employment type label
SELECT  staff_id,
        first_name,
        last_name,
        employment_type,
        CASE employment_type
          WHEN 'full-time'  THEN 'Permanent'
          WHEN 'contract'   THEN 'Contractual'
          ELSE 'Unknown'
        END  AS  emp_category
FROM    leela_palace.staff
LIMIT   10;
🗣️ Reads as: For each staff member, look at employment_type. If it says 'full-time' — return 'Permanent'. If 'contract' — return 'Contractual'. For anything else — return 'Unknown'.
Simple CASE: one target column, exact string matches, an ELSE fallback, and END AS to name the result
📄 Query 2.2 — Simple CASE on role_level
SELECT  grade_id,
        grade_name,
        role_level,
        CASE role_level
          WHEN 'Manager'   THEN 'Mid-Management'
          WHEN 'Director'  THEN 'Senior Leadership'
          ELSE 'Not Defined'
        END  AS  level_label
FROM    leela_palace.salary_grades;
🗣️ Reads as: For each salary grade, replace the raw role_level value with a readable label.
KeywordRole in Simple CASE
CASE column_nameWhich column to look at
WHEN exact_valueIf the column equals this value exactly
THEN return_thisReturn this label
ELSE fallback_valueReturn this if no WHEN matched (optional but recommended)
ENDCloses the CASE expression — the whole block is treated as one column

Matching exact words works well — but what happens when the requirement is a flexible range, like checking whether a monthly salary falls between two numbers? Simple CASE cannot express a range. That is where Searched CASE takes over.

3

Searched CASE — Write a Condition, Not Just a Value 🔍

Searched CASE drops the column-after-CASE pattern. Instead, every WHEN branch carries a full condition — greater than, less than, BETWEEN, LIKE, IS NULL. Anything writable in a WHERE clause is writable inside a Searched CASE.

MANAGER
Classify all staff salary records into bands: Entry (below ₹100,000), Mid (₹100,000 to ₹250,000), Senior (above ₹250,000).
📄 Query 3.1 — Searched CASE for salary band
SELECT  salary_id,
        staff_id,
        monthly_salary_inr,
        CASE
          WHEN monthly_salary_inr < 100000              THEN 'Entry'
          WHEN monthly_salary_inr BETWEEN 100000
                          AND 250000        THEN 'Mid'
          WHEN monthly_salary_inr > 250000             THEN 'Senior'
          ELSE 'Uncategorised'
        END  AS  salary_band
FROM    leela_palace.staff_salaries
LIMIT   10;
🗣️ Reads as: For each salary record, evaluate three conditions in order. Return the label of the first condition that is true.
Searched CASE maps continuous ranges of monthly_salary_inr into discrete labels — something Simple CASE cannot do
🎮 SIMULATOR — Build Your Own Salary Bands!
Drag the two boundary sliders. Watch every staff salary record get re-labelled live — this is Searched CASE running row by row.
📄 Query 3.2 — Searched CASE with multiple column conditions
SELECT  staff_id,
        first_name,
        employment_type,
        status,
        CASE
          WHEN status = 'active'
           AND employment_type = 'full-time'   THEN 'Core Staff'
          WHEN status = 'active'
           AND employment_type = 'contract'    THEN 'Active Contractor'
          WHEN status = 'inactive'             THEN 'Alumni'
          ELSE 'Review Required'
        END  AS  workforce_segment
FROM    leela_palace.staff
LIMIT   10;
🗣️ Reads as: Evaluate two columns together — status AND employment_type — to produce a single workforce label per staff member.
⚠️ Order matters — SQL stops at the first TRUE match

SQL reads each WHEN branch top to bottom and returns on the first match. Once a branch matches, all remaining branches are skipped. Always order conditions from most specific to least specific — if you place WHEN monthly_salary_inr > 0 THEN 'Has Salary' first, nothing below it will ever run.

ELSE catches everything that matched no WHEN. Omitting it returns NULL for unmatched rows.

⭐ Simple CASE = exact value match. Searched CASE = full condition. Both end with END.
4

NULL Handling Inside CASE WHEN 🕳️

CASE WHEN can check for NULL directly — making it a flexible, context-aware alternative to COALESCE or IFNULL when a NULL needs its own distinct business label rather than just a generic fallback value.

MANAGER
The manager_id column is NULL for the top-level staff member who reports to no one. In my report, I want them to show 'No Manager' instead of blank.
📄 Query 4.1 — CASE WHEN to handle NULL manager
SELECT  staff_id,
        first_name,
        manager_id,
        CASE
          WHEN manager_id IS NULL  THEN 'No Manager  (Top Level)'
          ELSE 'Has Manager'
        END  AS  manager_status
FROM    leela_palace.staff
LIMIT   10;
🗣️ Reads as: For each staff member, check if manager_id is NULL. If yes, label them as top-level. Otherwise mark them as having a manager.
📄 Query 4.2 — CASE with NULL and value conditions combined
SELECT  staff_id,
        first_name,
        status,
        manager_id,
        CASE
          WHEN status = 'inactive'     THEN 'Inactive  —  skip'
          WHEN manager_id IS NULL      THEN 'General Manager level'
          ELSE 'Standard staff'
        END  AS  staff_flag
FROM    leela_palace.staff
LIMIT   10;
🗣️ Reads as: First check if inactive — those get flagged. Among active staff, check if they have no manager — that is the General Manager. Everyone else is standard.
🧠 CASE WHEN vs COALESCE / IFNULL
  • COALESCE(manager_id, 'NONE') — simple replacement, one fallback value.
  • CASE WHEN manager_id IS NULL THEN 'Top Level' ELSE 'Has Manager' END — full label control.
  • Use COALESCE/IFNULL when you just need a default value.
  • Use CASE WHEN IS NULL when you need different outputs depending on context.
COALESCE is a quick patch for a default value. CASE WHEN IS NULL is a context engine — a whole new analytical label

IF() Function — The Compact Two-Outcome Shortcut ⚡

IF() is a compact conditional: one condition, two outcomes. If the condition is true — return value A. If false — return value B. Nothing more.

MANAGER
I want a simple flag on each staff member — 'FT' if full-time, 'CT' if contract. Nothing more.
📄 Query 5.1 — IF() for employment type flag
SELECT  staff_id,
        first_name,
        employment_type,
        IF(employment_type = 'full-time', 'FT', 'CT')  AS  emp_flag
FROM    leela_palace.staff
LIMIT   10;
🗣️ Reads as: If employment_type equals 'full-time' — return 'FT'. Otherwise (any other value including contract) — return 'CT'.
IF() is a binary switch: one condition, an illuminated TRUE path, a dimmed FALSE path — nothing more
📄 Query 5.2 — IF() for salary threshold
SELECT  staff_id,
        monthly_salary_inr,
        IF(monthly_salary_inr >= 200000, 'High', 'Standard')  AS  salary_flag
FROM    leela_palace.staff_salaries
LIMIT   10;
🗣️ Reads as: If monthly_salary_inr is 200,000 or above — flag as 'High'. Everything else is 'Standard'.
📄 Query 5.3 — IF() for NULL check
SELECT  staff_id,
        first_name,
        manager_id,
        IF(manager_id IS NULL, 'Top Level', 'Reports to someone')  AS  mgr_flag
FROM    leela_palace.staff
LIMIT   10;
🗣️ Reads as: Two labels — one if the manager is missing, one if not. Functionally similar to a simple COALESCE.
6

CASE vs IF() — When to Use Which ⚖️

Both produce conditional output. The choice comes down to how many outcomes are needed, and how many columns or conditions are involved.

IF()CASE WHEN
OutcomesExactly 2 (true / false)2 or more (unlimited branches)
SyntaxIF(condition, true_val, false_val)CASE WHEN … THEN … ELSE … END
Multiple conditionsNot supported directlyEach WHEN can be any condition
NULL handlingIF(col IS NULL, …)CASE WHEN col IS NULL THEN …
ReadabilityGreat for simple flagsBetter for 3+ outcomes
SupportMySQL, BigQueryAll major SQL databases
📌 Decision rule
  • Exactly 2 outcomes, simple condition → use IF() (shorter, more readable)
  • 3 or more outcomes → use CASE WHEN (IF cannot be nested cleanly beyond 2 levels)
  • Conditions involving multiple columns or ranges → always CASE WHEN
  • Cross-platform SQL (not just MySQL) → CASE WHEN is safer
Rule of thumb: 3+ outcomes, or conditions spanning multiple columns → CASE WHEN is mandatory
⭐ IF() for two outcomes. CASE WHEN for everything else.

Conditional COUNT — Pivot-Style Reporting 📊

Wrapping CASE WHEN inside COUNT() counts only the rows that match a condition. Multiple conditional COUNTs in one query build a pivot table — without needing any pivot tool.

MANAGER
How many active full-time staff do we have? How many active contractors? How many are inactive? I want all three numbers in one row.

The trick: CASE WHEN evaluates to a non-NULL value when the condition is true, and NULL when it isn't. COUNT ignores NULLs. So only matching rows get counted.

📄 Query 7.1 — conditional COUNT (3 categories in one query)
SELECT  COUNT(*)  AS  total_staff,
        COUNT(CASE WHEN status = 'active'
                    AND employment_type = 'full-time'
               THEN 1 END)  AS  active_fulltime,
        COUNT(CASE WHEN status = 'active'
                    AND employment_type = 'contract'
               THEN 1 END)  AS  active_contractors,
        COUNT(CASE WHEN status = 'inactive'
               THEN 1 END)  AS  inactive_staff
FROM    leela_palace.staff;
🗣️ Reads as: Total staff. Among them — count active full-timers, count active contractors, count inactive. All four numbers in one row.
StepWhat happens for staff member ST07 (active, full-time)
active_fulltime CASECondition TRUE → THEN 1 → COUNT sees 1 → increments
active_contractors CASECondition FALSE → no THEN → CASE returns NULL → COUNT ignores it
inactive CASECondition FALSE → NULL → COUNT ignores it
Note: The 1 in THEN 1 can be any non-NULL value — THEN staff_id works identically.
This is why COUNT(CASE WHEN) works: NULL exclusion in COUNT is the mechanism.
🎮 SIMULATOR — Build a Conditional COUNT!
Pick a status and an employment type. Rows that match stay highlighted (COUNT sees 1) — everything else dims (COUNT sees NULL, ignored).
📄 Query 7.2 — conditional COUNT with GROUP BY
SELECT  department_id,
        COUNT(*)  AS  total,
        COUNT(CASE WHEN employment_type = 'full-time'
               THEN 1 END)  AS  fulltime_count,
        COUNT(CASE WHEN employment_type = 'contract'
               THEN 1 END)  AS  contract_count,
        COUNT(CASE WHEN status = 'inactive'
               THEN 1 END)  AS  inactive_count
FROM    leela_palace.staff
GROUP BY department_id
ORDER BY department_id;
🗣️ Reads as: For each department — total headcount, full-timers, contractors, and inactive staff. Four numbers per department row.
⭐ COUNT(CASE WHEN) = count only the rows that match the condition. NULL exclusion makes it work.

Conditional SUM — Split Totals in One Query 💰

Summing only the values that meet a condition is the standard tool for split payroll, segmented revenue, and department-specific totals.

MANAGER
What is the total monthly payroll for senior staff (≥ ₹2,00,000) versus standard staff (< ₹2,00,000)? And what percentage of total payroll goes to senior-band staff?
📄 Query 8.1 — conditional SUM on single table (no JOIN needed)
SELECT  COUNT(*)                                         AS  total_records,
        SUM(monthly_salary_inr)                          AS  total_payroll,
        SUM(CASE WHEN monthly_salary_inr >= 200000  THEN monthly_salary_inr
                 ELSE 0 END)                            AS  senior_payroll,
        SUM(CASE WHEN monthly_salary_inr < 200000   THEN monthly_salary_inr
                 ELSE 0 END)                            AS  standard_payroll,
        ROUND(SUM(CASE WHEN monthly_salary_inr >= 200000 THEN monthly_salary_inr
                       ELSE 0 END)
              / SUM(monthly_salary_inr) * 100, 1)                   AS  senior_pct
FROM    leela_palace.staff_salaries;
🗣️ Reads as: Total payroll split into senior-band and standard-band amounts, plus the percentage that senior-band represents.
🧠 ELSE 0 vs ELSE NULL in conditional SUM
  • SUM(CASE WHEN condition THEN monthly_salary_inr ELSE 0 END) — non-matching rows contribute 0 (clean total)
  • SUM(CASE WHEN condition THEN monthly_salary_inr END) — no ELSE defaults to NULL for non-matches
  • Both give the same SUM result because NULL + number — SUM ignores NULL.
  • ELSE 0 is slightly clearer for readers. Both are correct.

Bucket + GROUP BY — Salary Band Analysis 📈

Create buckets with CASE WHEN in SELECT, then GROUP BY the result. This is the pattern behind every histogram-style HR report.

MANAGER
How many staff fall into each salary band? Give me a distribution.
📄 Query 9.1 — CASE WHEN bucket + GROUP BY (single table)
SELECT  CASE
          WHEN monthly_salary_inr < 70000               THEN 'Entry  (< 70K)'
          WHEN monthly_salary_inr BETWEEN 70000
                           AND 150000        THEN 'Mid  (70K – 1.5L)'
          WHEN monthly_salary_inr BETWEEN 150001
                           AND 250000       THEN 'Upper-Mid  (1.5L – 2.5L)'
          WHEN monthly_salary_inr > 250000              THEN 'Senior  (> 2.5L)'
          ELSE 'Uncategorised'
        END                                  AS  salary_band,
        COUNT(*)                             AS  staff_count,
        ROUND(MIN(monthly_salary_inr), 0)                AS  band_min,
        ROUND(MAX(monthly_salary_inr), 0)                AS  band_max,
        ROUND(AVG(monthly_salary_inr), 0)                AS  band_avg
FROM    leela_palace.staff_salaries
GROUP BY  CASE
            WHEN monthly_salary_inr < 70000             THEN 'Entry  (< 70K)'
            WHEN monthly_salary_inr BETWEEN 70000
                             AND 150000      THEN 'Mid  (70K – 1.5L)'
            WHEN monthly_salary_inr BETWEEN 150001
                             AND 250000     THEN 'Upper-Mid  (1.5L – 2.5L)'
            WHEN monthly_salary_inr > 250000            THEN 'Senior  (> 2.5L)'
            ELSE 'Uncategorised'
          END
ORDER BY  band_min ASC;
🗣️ Reads as: Create a salary band label for each salary row. Group all rows that share the same label. For each band — count staff, show the min, max, and average salary.
First, CASE defines the bucket. Then, GROUP BY groups the rows into those exact buckets.
🎮 SIMULATOR — Build the Full Distribution Report!
Move the three band-boundary sliders. Watch staff_count, min, max, and avg recompute live for every band — exactly what GROUP BY on a CASE expression produces.
Why repeat the CASE expression twice? SELECT aliases like salary_band cannot be used in GROUP BY in standard SQL — execution order runs GROUP BY before SELECT. BigQuery allows the alias as an exception, but the safe, portable practice is to repeat the full expression.
🧠 The key insight
  • GROUP BY does not have to be a raw column name — it can be a CASE expression.
  • Every row is assigned a band label by the CASE. GROUP BY then groups rows with the same label.
  • This is how you build any distribution report: create the bucket → group by the bucket.
  • Works for tenure bands, role-level tiers, age groups — any continuous value you want to segment.
⭐ CASE creates the bucket. GROUP BY groups the buckets. Aggregates summarise each bucket.

Interview-Style Questions — Self-Check 🎤

Four questions at interview difficulty, covering everything above. Try answering each before reading the model answer.

Q1. What is the difference between Simple CASE and Searched CASE? Give an example of when you would use each.
Simple CASE: CASE column_name WHEN value THEN result … END — compares one column to exact values. Use it for mapping fixed values, e.g. replacing 'full-time' with 'Permanent'.

Searched CASE: CASE WHEN condition THEN result … END — each branch is a full condition. Use it for ranges, multi-column logic, or NULL checks, e.g. salary bands.
Q2. How does COUNT(CASE WHEN status = 'active' THEN 1 END) work? Why does it count only active staff?
When status = 'active' is TRUE, the CASE returns 1 (a non-NULL value). When it's not, there is no THEN and no ELSE — so the CASE returns NULL. COUNT ignores NULL values — it only counts non-NULL results. So this pattern effectively counts only the rows where the condition is true. THEN 1 can be any non-NULL value — THEN staff_id works identically.
Q3. What is the difference between IF() and CASE WHEN? When should you prefer CASE?
IF(condition, true_value, false_value) handles exactly two outcomes. CASE WHEN supports unlimited branches with different conditions. Prefer CASE WHEN when you need 3+ outcomes, conditions span multiple columns, you need ranges or IS NULL checks, or your SQL runs on databases other than MySQL/BigQuery. IF() is clean for simple binary flags, e.g. IF(status = 'active', 'Active', 'Inactive').
Q4. Write a single query to show: total staff, number of active full-time staff, number of active contractors, and number of inactive staff — all in one row.
SELECT  COUNT(*)                                                        AS  total,
        COUNT(CASE WHEN status = 'active'
                    AND employment_type = 'full-time' THEN 1 END)       AS  active_ft,
        COUNT(CASE WHEN status = 'active'
                    AND employment_type = 'contract'  THEN 1 END)       AS  active_ct,
        COUNT(CASE WHEN status = 'inactive' THEN 1 END)                 AS  inactive
FROM    leela_palace.staff;
Key point: NULL exclusion in COUNT makes this pattern work.

AI Segment — "Write My CASE WHEN Report" 🤖

✈️
The Co-Pilot Analogy: AI can draft the CASE WHEN structure fast — but boundary logic, ELSE handling, and portability are the analyst's responsibility. The pilot (you) is always in charge.

Step 1 — the prompt

📋 Paste this into Claude or ChatGPT
I have a table called leela_palace.staff_salaries with columns staff_id and
monthly_salary_inr. Write a query that classifies each staff member into a
salary band: 'Entry' for below 70000, 'Mid' for 70000 to 180000, 'Senior' for
above 180000. Show staff_id, monthly_salary_inr, and the band label. Also add
a GROUP BY version that shows how many staff are in each band.

Step 2 — what to verify in AI's response

  • Did it use Searched CASE (not Simple CASE)? Ranges require Searched CASE.
  • Are the band boundaries aligned with what you asked? Check the BETWEEN and > values.
  • Is ELSE included? AI sometimes omits it — what happens to a NULL salary if ELSE is missing?
  • Is END present? Missing END is a syntax error AI sometimes produces.
  • In the GROUP BY version — did AI repeat the full CASE, or use an alias? Note the portability implication.
TaskAI's tendency
CASE WHEN structure with correct THEN/ELSE/END✅ Handles well — standard pattern
Boundary conditions (inclusive vs exclusive)⚠️ Watch closely — BETWEEN vs strict >/<
GROUP BY using the alias⚠️ Works in BigQuery, fails in standard SQL
