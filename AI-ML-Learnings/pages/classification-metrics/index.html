Recap from Last Lecture
⏱ 2 min

Previously we introduced classification and its core machinery:

  • Classification predicts discrete categories rather than continuous values
  • Logistic Regression models the probability of belonging to a class
  • The sigmoid function converts raw model outputs into probabilities in [0, 1]
  • A decision threshold (default 0.5) assigns the final class label
📌 Today's Focus
Building a classifier is only half the job. How do we know whether it is actually performing well? Today we explore every major classification metric, understand when each one matters, and learn to read them together.
🏷️
Concept
Multiclass Classification — One-vs-Rest
⏱ 5 min

Standard logistic regression handles two classes. When we have K classes (e.g., Orange, Apple, Banana), we use the One-vs-Rest (OvR) strategy:

  • Train K separate binary classifiers — one per class
  • For each classifier, relabel the target: that class = 1, all others = 0
  • At prediction time, run all K classifiers and pick the class with the highest predicted probability — regardless of whether it exceeds 0.5

Example: 3-Class Fruit Classifier

ModelTaskRelabelling
Model 1Orange vs RestOrange = 1, Apple = 0, Banana = 0
Model 2Apple vs RestApple = 1, Orange = 0, Banana = 0
Model 3Banana vs RestBanana = 1, Orange = 0, Apple = 0

Given a new fruit, all three models produce a probability. The class corresponding to the highest score wins — even if the winning score is below 0.5.

💡 Sklearn Implementation
Pass multi_class='ovr' to LogisticRegression(). Sklearn handles the K-model training and prediction automatically.

Math
Log-Odds Interpretation of Logistic Regression
⏱ 5 min

Logistic Regression is called "linear" internally. Here's the mathematical reason.

From Probability to Log-Odds

If p is the probability of belonging to class 1:

odds = p / (1 − p)
log(odds) = log(p / (1 − p)) = z = w₀ + w₁x₁ + w₂x₂ + …

The log-odds is a linear function of the features. That's why logistic regression is "linear" — the linearity lives in log-odds space, not in probability space.

Back to Probability

Solving for p from the log-odds equation gives us the familiar sigmoid:

p = 1 / (1 + e⁻ᶻ)
📌 Sigmoid and Logit are Inverses
The logit function (log-odds) maps probabilities to real numbers: logit(p) = log(p/1-p). The sigmoid function maps real numbers back to probabilities. They are exact inverses of each other.

Quiz 4
Interpreting a Negative Log-Odds
⏱ 1 min
If log(odds) is negative, which of the following is true?
  • 1 − p > p
  • p > 1 − p
  • p = 1 − p
💡 Explanation
log(odds) < 0 means odds = p/(1−p) < 1, so p < 1−p. The probability of class 0 exceeds class 1 — we're in negative class territory. Geometrically, the point is on the class-0 side of the decision boundary.

Concept
Why Accuracy Alone Is Not Enough
⏱ 3 min

The Spam Detection Problem

Imagine a dataset where only 10% of emails are spam and 90% are not. You build a model and it achieves 90% accuracy.

🤔 Is this a good model?
No. A completely dumb model that predicts every single email as "not spam" would also achieve exactly 90% accuracy — because 90% of the data actually is not spam. The model has learned nothing useful.

Accuracy hides the important question: what kinds of mistakes is the model making? A model can be 90% accurate while completely failing to detect any spam at all.

This is the core problem with imbalanced datasets — we need metrics that look beyond the aggregate correct count.

Confusion Matrix
⏱ 10 min

The Confusion Matrix gives a granular breakdown of predictions. For binary classification, it's a 2×2 grid:

Predicted: 0
Predicted: 1
Actual
TN — True NegativePredicted 0, Actually 0 ✓
FP — False Positive (Type I)Predicted 1, Actually 0 ✗
Actual
FN — False Negative (Type II)Predicted 0, Actually 1 ✗
TP — True PositivePredicted 1, Actually 1 ✓

Diagonal cells (TN, TP) = correct predictions. Off-diagonal (FP, FN) = errors. An ideal model has FP = 0 and FN = 0.

Dumb Model (Predicts Everything as 0)

On 400 emails (360 non-spam, 40 spam), a model that predicts all as non-spam gets:

CellValueWhy
TN360All 360 non-spam correctly predicted as non-spam
FP0No non-spam predicted as spam
FN40All 40 spam misclassified as non-spam
TP0Zero spam correctly detected

Accuracy = (360 + 0) / 400 = 90% — but TP = 0. The model catches zero spam.

Metric
Precision
⏱ 8 min

Fishing Analogy — Precision

You're fishing in a lake with 100 fish and 100 turtles. You throw a net and catch 60 fish and 20 turtles. Precision asks: of everything I caught, what fraction was actually fish?

Precision = 60 / (60 + 20) = 75%

Turtles in the net lower your precision. Precision penalizes false positives.

Formal Definition

Precision = TP / (TP + FP) = True Positives / Predicted Positives

Precision tells us: of all the points the model called positive, how many actually were?

When to Prioritize Precision

📧 Spam Detection Scenario

Which is worse: a spam email reaching your inbox (FN), or an important email from your manager going to spam (FP)?

The second — missing an important email is more costly. So we want low FP → high precision.

Code

from sklearn.metrics import precision_score

# Dumb model — all zeros
y_pred_dumb = np.zeros(len(data.y))
print("Dumb model precision:", precision_score(data.y, y_pred_dumb))   # 0.0

# Random model
print("Random model precision:", precision_score(data.y, data.y_pred)) # 0.187
Output
Dumb model precision: 0.0 Random model precision: 0.1870748299319728

Even the random model (0.187) vastly outperforms the dumb model (0) on precision — confirming that accuracy was lying about the dumb model's quality.

Metric
Recall (Sensitivity)
⏱ 8 min

Fishing Analogy — Recall

Same lake, 100 fish total. You caught 60. Recall asks: of all the fish in the lake, what fraction did I actually catch?

Recall = 60 / 100 = 60%

Three Fishing Attempts — Precision-Recall Tradeoff

Net SizeFish CaughtTurtles CaughtPrecisionRecall
Normal602075%60%
Bigger808050%80%
Smaller200100%20%

As you try to catch more fish (higher recall), you inevitably catch more turtles (lower precision). This is the precision-recall tradeoff.

Formal Definition

Recall = TP / (TP + FN) = True Positives / Actual Positives

When to Prioritize Recall

🏥 Cancer Detection Scenario

Which is worse: flagging a healthy person as potentially cancerous (FP → more tests), or missing a cancer patient entirely (FN → no treatment)?

Missing cancer is catastrophic. We want low FN → high recall.

Code

from sklearn.metrics import recall_score

print("Dumb model recall:  ", recall_score(data.y, y_pred_dumb))  # 0.0
print("Random model recall:", recall_score(data.y, data.y_pred))  # 0.55
Output
Dumb model recall: 0.0 Random model recall: 0.55

Movie Recommendation — What to Prioritize
⏱ 1 min
You are building a movie recommendation model. What should you prioritize more?
  • High recall
  • High precision
💡 Explanation
Missing a good film is acceptable — the user can still scroll. But recommending bad films drives users away. False positives (bad recs) hurt engagement more than false negatives (missed gems). Prioritize precision.

Metric
F1-Score — Harmonic Mean of Precision & Recall
⏱ 10 min

When You Need Both

A fintech company building a loan repayment predictor faces two types of mistakes:

  • Give a loan to someone who can't repay (FP) — financial loss
  • Deny a loan to someone who could repay (FN) — missed revenue

Both FP and FN matter equally. We need a single metric that captures both precision and recall.

Why Not Arithmetic Mean?

ModelPrecisionRecallArith. MeanHarmonic Mean
Case 10.70.70.7000.700
Case 20.90.50.7000.642 ↓

Arithmetic mean gives the same score to both — it fails to penalize Case 2's poor recall. The Harmonic Mean is the fix: it drops to 0.642, reflecting the imbalance.

F1-Score Formula

F1 = 2 · Precision · Recall / (Precision + Recall) = 2 / (1/P + 1/R)

The harmonic mean pulls the score toward the lower of the two values. A model with Precision = 1.0 and Recall = 0.01 gets F1 ≈ 0.02 — almost useless, as expected.

💡 Memory Hack
We use the Harmonic Mean because we're trying to find harmony between precision and recall. The "H" in Harmonic stands for how Harshly it penalizes imbalance between the two.

Code

from sklearn.metrics import f1_score

print("F1 (random model):", f1_score(data.y, data.y_pred))
Output
F1 (random model): 0.27918781725888325

F1 = 0.279 — even though accuracy was 97%. Low precision (0.187) is dragging the F1 score down, which is exactly the right behaviour.

Quiz 7
Why Harmonic Mean for F1?
⏱ 1 min
Why does the F1-score use the Harmonic Mean (HM) instead of the Arithmetic Mean (AM)?
  • HM penalizes models the most when either Precision or Recall is low.
  • AM penalizes models the most when either Precision or Recall is low.
  • HM penalizes models the most when both Precision and Recall are high.
  • AM penalizes models the most when both Precision and Recall are high.
💡 Explanation
The Harmonic Mean is always ≤ the Arithmetic Mean, and the gap is largest when the two values are very different. A model with P=1.0, R=0.01 has AM=0.505 (looks okay!) but HM≈0.02 (correctly terrible).

When to Use Each Metric

📧 Spam → Inbox Filter
Precision
Can't afford to block legitimate emails (FP). A spam email slipping through is less harmful.
🏥 Cancer / Disease Screening
Recall
Missing a sick patient (FN) is catastrophic. False alarms lead to more tests — acceptable.
🏦 Loan Approval / Fraud Detection
F1-Score
Both FP (giving bad loans) and FN (missing fraud) hurt the business. Balance both.
🎬 Movie Recommendations
Precision
Bad recommendations drive users away. Missing a good film is fine — there are plenty more.

Implementation
Classification Report
⏱ 5 min

Instead of computing each metric separately, Sklearn's classification_report prints them all at once — per class and aggregated.

from sklearn.metrics import classification_report
print(classification_report(data.y, data.y_pred))
precision recall f1-score support 0.0 1.00 0.98 0.99 10000 1.0 0.19 0.55 0.28 100 accuracy 0.97 10100 macro avg 0.59 0.76 0.63 10100 weighted avg 0.99 0.97 0.98 10100

How to Read This

ColumnMeaning
supportNumber of actual samples for that class in the test set
macro avgSimple average across classes — treats all classes equally regardless of size
weighted avgAverage weighted by support — dominated by the majority class

Example: macro avg precision = (1.00 + 0.19) / 2 = 0.59. Weighted avg precision = (1.00×10000 + 0.19×100) / 10100 = 0.99 (dominated by class 0's size).

📌 Use Macro for Imbalanced Problems
Weighted average looks great here (0.99) — but only because class 0 dominates. For imbalanced problems, use macro average or look at per-class metrics to get the true picture.

Metric
ROC Curve & AUC
⏱ 10 min

So far we've used a fixed threshold (0.5) to make class predictions. But the threshold is a choice — and different thresholds give different tradeoffs. The ROC curve visualizes all these tradeoffs at once.

Key Terms

TermFormulaMeaning
TPR (True Positive Rate / Recall)TP / (TP + FN)Fraction of actual positives caught
FPR (False Positive Rate)FP / (FP + TN)Fraction of negatives incorrectly flagged

How the ROC Curve Is Built

Sort all test points by predicted probability (descending). Sweep the threshold from 1.0 down to 0.0, recording (FPR, TPR) at each step. Plot TPR vs FPR:

ThresholdEffectFPRTPR
1.0Everything predicted as 0 — nothing detected00
0.9Only high-confidence positives flaggedLowLow
0.5Default operating pointMediumMedium
0.1Almost everything flagged as positiveHighHigh
0.0Everything predicted as 111

Why Does the Curve Go from (0,0) to (1,1)?

  • (0,0): Threshold = 1.0 — all predicted as 0 — TP=0, FP=0 → FPR=0, TPR=0
  • (1,1): Threshold = 0.0 — all predicted as 1 — all positives found (TPR=1) but all negatives also flagged (FPR=1)

The Perfect and Random Model

  • Perfect model: Curve goes straight up to (0,1) then right to (1,1). TPR=1 at FPR=0.
  • Random model: Curve follows the diagonal (FPR = TPR at all thresholds).
  • AUC (Area Under Curve): A single number [0, 1] summarizing the ROC. AUC=1.0 is perfect; AUC=0.5 is random.
📌 The Key Insight
ROC and AUC are threshold-independent — they evaluate the model's ranking ability across all possible thresholds. A model with AUC=0.90 will correctly rank a random positive above a random negative 90% of the time.

Wrapping Up
⏱ 3 min

Accuracy is the metric everyone starts with — and the first one you should learn to distrust when classes are imbalanced.

OvR for K-class logistic regression
Log-odds = linear function of features
Sigmoid and Logit are inverses
Accuracy fails on imbalanced data
Confusion matrix: TP, TN, FP, FN
Precision = TP / (TP + FP)
Recall = TP / (TP + FN)
F1 = harmonic mean of P and R
classification_report — all metrics at once
ROC curve — TPR vs FPR across thresholds
AUC — single number for model ranking quality
Match metric to the cost of each error type
The choice of evaluation metric depends on the problem you're solving. Healthcare prioritizes Recall. Spam filters prioritize Precision. Loan approval needs both — use F1.
