1Duplicate records

Detecting duplicates with duplicated()

Real survey data almost never arrives clean. The same country-year record can be submitted twice, a form resubmitted, or two sources overlapping. Before McKinsey trusts any average or count, we must make sure we're not silently counting the same record multiple times.

python — add some test duplicates
df.loc[len(df.index)] = ['India',     2000, 13500000,  'Asia', 37.08, 900.23]
df.loc[len(df.index)] = ['Sri Lanka', 2022, 130000000, 'Asia', 80.00, 500.00]
df.loc[len(df.index)] = ['Sri Lanka', 2022, 130000000, 'Asia', 80.00, 500.00]  # exact dup
df.loc[len(df.index)] = ['India',     2000, 13500000,  'Asia', 80.00, 900.23]  # same country/year, diff life_exp
💡 Note the distinction
The two Sri Lanka rows are identical on every column — a true full-row duplicate. The two India rows repeat country, year, population, and continent but differ in life_exp (37.08 vs 80.00) — so as full rows, they are not duplicates of each other. This motivates the subset= parameter we'll see shortly.
python
df.duplicated()
# Returns True when an entire row is identical to a row that appeared earlier
Output (excerpt)
0       False
1       False
...
1704    False   ← first India (unique so far)
1705    False   ← first Sri Lanka (unique so far)
1706    True    ← second Sri Lanka (exact copy of 1705)
1707    False   ← second India (life_exp differs → NOT a full-row duplicate)
dtype: bool

Use loc to extract and inspect only the flagged rows:

python
df.loc[df.duplicated()]   # shows only the duplicate rows

2Duplicate records

      
drop_duplicates() — keep, subset

      
python
df.drop_duplicates()           # default: keep='first'

      
When several rows are identical, keep= decides which copy survives:


      

        

          
keep='first' (default)

          
Sri Lanka 2022KEPT

          
Sri Lanka 2022DROP

        

        

          
keep='last'

          
Sri Lanka 2022DROP

          
Sri Lanka 2022KEPT

        

        

          
keep=False

          
Sri Lanka 2022DROP

          
Sri Lanka 2022DROP

        

      


      
python
df.drop_duplicates(keep='first')   # first occurrence survives
df.drop_duplicates(keep='last')    # last occurrence survives
df.drop_duplicates(keep=False)     # every row that has a duplicate is removed


      
subset= — restrict the check to specific columns

      
Sometimes two rows repeat on the columns we care about even if they differ elsewhere. subset= restricts the uniqueness check:

      
python
df.drop_duplicates(subset=['country'], keep='first')
# Keeps only the first row per country, regardless of other column values

      

        
🌉 SQL bridge

        df.drop_duplicates(subset=['country'], keep='first') ≈ SELECT DISTINCT ON (country) * FROM df ORDER BY country; (PostgreSQL syntax)

3Slicing

      
2D slicing with loc and iloc

      
Both loc and iloc accept two arguments separated by a comma: [rows, columns]. This lets you carve out any rectangle of the DataFrame.


      
python — iloc: rows and columns by position
df.iloc[0:4, 0:3]        # rows 0-3, columns 0-2 (end exclusive)
df.iloc[[0, 10, 100], [0, 2, 3]]   # non-consecutive rows and columns
df.iloc[1:10:2]          # every other row from position 1 to 9


      
python — loc: rows and columns by label
df.loc[1:5, ['country', 'life_exp']]   # specific column names
df.loc[1:5, 'year':'life_exp']         # column range by label (end inclusive)
df.loc[1:10:2]                         # step slicing also works with loc


      

        
⚠️ loc rejects integer positions for columns

        df.loc[1:5, 1:4] → TypeError: cannot do slice indexing on Index with these indexers [1] of type int
        

loc works with labels, not positions. The column labels here are strings ('country', 'year', …), not integers. Use iloc for positional column slicing, or name the columns explicitly with loc.
      


      

        
NeedUse

        
Rows 0-3, columns 0-2 (by position)df.iloc[0:4, 0:3]

        
Rows labeled 1-5, named columnsdf.loc[1:5, ['country','life_exp']]

        
Specific row positions, specific column positionsdf.iloc[[0,10,100], [0,2,3]]

        
Every other rowdf.iloc[1:10:2] or df.loc[1:10:2]

4Built-in operations

      
Aggregate functions

      
Slicing shows raw values. Aggregates collapse many values into one summary — answering McKinsey's questions like "what is the average life expectancy across all countries?"


      
python
le = df['life_exp']

le.mean()    # average
le.sum()     # total
le.count()   # number of non-null values
le.min()     # smallest value
le.max()     # largest value
le.std()     # standard deviation


      

        
.mean()
arithmetic average

        
.sum()
total of all values

        
.count()
non-null rows

        
.min()
smallest value

        
.max()
largest value

        
.std()
standard deviation

      


      

        
💡 Sanity check: mean = sum / count

        le.sum() / le.count() gives the same result as le.mean(). This is a useful mental model — and a quick way to verify that mean makes sense on your data.
      

      

        
🌉 SQL bridge

        le.mean() ≈ SELECT AVG(life_exp) FROM df; · le.count() ≈ SELECT COUNT(life_exp) FROM df;

Ratio analysis — efficiency metric

      
McKinsey wants a column for life expectancy per unit of GDP — a proxy for how efficiently a country converts economic output into health outcomes. Build it from two existing columns, no loop needed:

      
python
df['life_exp_per_gdp'] = df['life_exp'] / df['gdp_cap']
df['life_exp_per_gdp'].describe()

      
A higher ratio means more life expectancy per unit of GDP — the country translates economic output into health outcomes more efficiently. A lower ratio means additional GDP yields less improvement in life expectancy.

6Built-in operations

      
Conditional filtering — finding the record behind an extreme

      
Aggregates like max() tell us the extreme value. McKinsey usually wants the record behind it: not just "what is the highest GDP per capita" but "which country has it."

      
python
max_gdp = df['gdp_cap'].max()

# Filter rows where gdp_cap equals that maximum
df[df['gdp_cap'] == max_gdp]

# Extract just the country name
country_max_gdp = df[df['gdp_cap'] == max_gdp]['country'].values[0]
print(f"The country with the highest GDP is {country_max_gdp} with a GDP of {max_gdp}")

      
The expression inside the brackets, df['gdp_cap'] == max_gdp, produces a boolean Series — True only where the condition holds. df[...] keeps only the True rows.

    


    
    

      
7Sorting

      
Sorting values

      
python
df.sort_values(['life_exp'])                          # ascending (default)
df.sort_values(['life_exp'], ascending=False)         # descending


      
Multi-column sort

      
python
df.sort_values(['year', 'life_exp'])
# Primary sort: year ascending
# Secondary sort: within the same year, life_exp ascending (ties broken here)


      

        
Multi-column sort: year ↑ then life_exp ↑

The second column (life_exp) only acts as a tiebreaker within rows sharing the same year.

      


      
Mixed sort directions

      
python
df.sort_values(['year', 'life_exp'], ascending=[False, True])
# year: descending (most recent first)

Pass a list of True/False values — one per column — to mix sort directions.


      

        
Quiz 2

        
How do you sort a DataFrame in place on columns country and population in descending order?

        

          
A) df.sort_values(['country','population'])

          
B) df.sort_values(['country','population'], inplace=True)

          
C) df.sort_values(['country','population'], inplace=True, ascending=False)

          
D) df.sort_values(['country','population'], inplace=True, ascending=True)

        

        
"In place" requires inplace=True — rules out A. "Descending" requires ascending=False — rules out B (defaults to ascending) and D (explicitly ascending). Only C satisfies both conditions.

8Combining tables

      
Concatenating DataFrames

      
In practice, McKinsey's information is spread across multiple tables. Two ways to combine them: concat() stacks, merge() relates. We start with stacking.


      
python — the two tables
users = pd.DataFrame({"userid": [1, 2, 3],
                       "name":   ["sharadh", "shahid", "khusalli"]})

msgs  = pd.DataFrame({"userid": [1, 1, 2, 4],
                       "msg":    ["hmm", "acha", "theek hai", "nice"]})


      
python — row-wise concat (axis=0, default)
pd.concat([users, msgs])               # stacks rows; NaN for missing columns
pd.concat([users, msgs], ignore_index=True)   # rebuilds a fresh 0,1,2,… index


      
Output — ignore_index=True
   userid      name        msg
0       1   sharadh        NaN
1       2    shahid        NaN
2       3  khusalli        NaN
3       1       NaN        hmm
4       1       NaN       acha
5       2       NaN  theek hai
6       4       NaN       nice


      
How concat works:

      
    
        
  • userid existed in both tables → lines up into one column.
    • 
        
  • Rows from users come first — no msg column → NaN.
    • 
        
  • Rows from msgs follow — no name column → NaN.
    • 
      


      
python — column-wise concat (axis=1)
pd.concat([users, msgs], axis=1)
# Glues tables side by side by POSITION — not by shared key values


      

        
⚠️ The problem axis=1 concat cannot solve

        "Who sent each message?" needs the name from users matched to the right userid in msgs. concat(axis=1) glues by position — so userid=3 from users sits next to userid=2 from msgs, which is simply wrong. This is the problem that merge() solves.
      

      

        
🌉 SQL bridge

        pd.concat([a, b], axis=0) ≈ UNION ALL — stacks rows regardless of content.
      

    


    
    

      
9Combining tables

      
Merging DataFrames

      
merge() combines DataFrames by matching rows based on the values in a shared key column. It looks at the data, not just the structure.

      
python — inner merge (default)
users.merge(msgs, on="userid")

      
Output
   userid     name        msg
0       1  sharadh        hmm
1       1  sharadh       acha
2       2   shahid  theek hai

      
userid=3 (only in users) and userid=4 (only in msgs) both drop out — only values present in both tables are kept. This is an inner join.

      

        
🌉 SQL bridge

        users.merge(msgs, on="userid") ≈ SELECT * FROM users INNER JOIN msgs ON users.userid = msgs.userid;

11Combining tables

      
Merging when key column names differ

      
In real data, the same information often lives under different column names in different tables. Use left_on and right_on to specify each side separately.

      
python
# Suppose users calls it 'id' but msgs calls it 'userid'
users.rename(columns={"userid": "id"}, inplace=True)

users.merge(msgs, left_on="id", right_on="userid")

      
Output
   id     name  userid        msg
0   1  sharadh       1        hmm
1   1  sharadh       1       acha
2   2   shahid       2  theek hai

      
Both key columns appear in the result. You can drop one with .drop(columns=['userid']) if you only need one.

    


    
    

      
12Combining tables

      
concat vs merge — the decision rule


      

        
concat()merge()

        
What it doesStacks DataFrames along an axis purely by positionMatches rows using a shared key column's values

        
Looks at data values?No — glues tables regardless of contentYes — rows aligned on matching key values

        
Typical useCombining files with the same columns (sales_jan.csv + sales_feb.csv)Combining related tables sharing an ID (users + messages)

        
Mismatched rowsNaN for columns missing on one side; rows never dropped or matchedControlled by how= (inner drops, outer/left/right fill)

        
SQL equivalentUNION ALL (axis=0)JOIN (INNER / LEFT / RIGHT / OUTER)

      


      

        
✓ Decision rule

        Reach for concat() when you're stacking pieces of the same kind of data that happen to live in separate files.

        Reach for merge() the moment you need information from one table to correctly label or enrich rows in another based on a shared key — that's a real relationship between tables, not just physical stacking.
      


      

        
Quiz 3

        
What is the shape of the output?

df1 = pd.DataFrame({'A':[10,30], 'B':[20,40], 'C':[30,60]})
df2 = pd.DataFrame({'A':[10,30], 'C':[30,60]})
df2.merge(df1, on='A', how='outer')

        

          
A) (3, 4)

          
B) (2, 4)

          
C) (3, 2)

          
D) (4, 2)

        

        
The merge key A has values {10, 30} in both tables — an outer join on matching keys gives exactly 2 rows. For columns: A is the shared key (appears once). df2 also has C; df1 also has B and C. Since C appears in both, Pandas disambiguates as C_x and C_y. Result columns: A, C_x, B, C_y = 4 columns. Shape: (2, 4).
