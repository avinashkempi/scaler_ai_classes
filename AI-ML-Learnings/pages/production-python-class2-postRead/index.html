Where does a value come from?

  
When a setting exists in more than one place, the higher layer wins.

  

    
1. Environment variableTyped for one run, such as MERIDIAN_BATCH_DATE=2025-03-13. Wins over everything below.

    
2. The .env fileLocal to your machine and never shared. load_dotenv does not override a variable that is already set.

    
3. config/settings.tomlThe shared default. It lives at the bottom.

Rebuild it

  
The stranger's setup, in order

  
Your README tells a stranger how to set up the project. Put the commands in the right order. Click them one at a time, from first to last.

  

    

      
      
    

    

    

    

    

  

  
Why this order?Each step needs the one before it. You cannot enter the folder before you clone it. You cannot activate an environment that does not exist yet. You cannot install into an environment you have not activated. And you cannot run the program before it is installed.

Terminal 2: your first commit

  
This terminal starts inside the project folder. It holds a secret file (.env) and a virtual environment (.venv) on purpose. Your job is to commit the project without them.

  
    
    
  • Tell Git who you are: git config --global user.name "Your Name" and git config --global user.email "you@example.com"
    • 
    
  • Start the repository: git init -b main
    • 
    
  • Look: git status. Do you see .env and .venv/ in the list?
    • 
    
  • Ignore them. Write both into .gitignore: echo ".venv/" > .gitignore, then echo ".env" >> .gitignore
    • 
    
  • Stage everything safe: git add ., then check with git status
    • 
    
  • Save the snapshot: git commit -m "Create Workbench V0"
    • 
    
  • See it in the history: git log --oneline
    • 
    
  • Publish: git remote add origin https://github.com/your-username/meridian-workbench.git, then git push -u origin main
    •

Git

  

  

    
CommandWhat it does

    
git config --global user.name "Your Name"Sets the author name. Once per computer.

    
git config --global user.email "you@example.com"Sets the author email. Once per computer.

    
git init -b mainStarts a repository with a branch called main.

    
git statusShows what changed and what is staged. Run it before and after everything.

    
git add .Stages all changes in this folder.

    
git commit -m "message"Saves a snapshot on your computer, with a message.

    
git log --onelineShows the history, one line per commit.

    
git remote add origin URLSaves the address of the online copy.

    
git push -u origin mainSends commits to GitHub the first time. Later, just git push.

    
git clone URL folderMakes a full copy from GitHub. Once.

    
git pullBrings new commits from GitHub into your folder. Often.

    
git check-ignore -v .envShows which .gitignore line ignores a file.

    
git rm --cached FILEStops tracking a file you staged by mistake, without deleting it.

  

  

  
  
The Git rhythmClone once, pull often. Commit, then push. Run git status before every commit and read the list.
