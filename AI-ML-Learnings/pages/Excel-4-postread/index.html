Foundations

01 Pivot Tables — the four zones

Business problem

The head of sales walks up and says: "Give me total revenue by region — I need it in 2 minutes." Writing =SUMIF(Region,"West",Sales) four times works until a new region appears — then it breaks. A Pivot Table groups and summarises dynamically, no formulas needed.

A Pivot Table takes your flat dataset — one row per transaction — and collapses it into a grouped summary. The word "Pivot" comes from the ability to rotate dimensions: swap what sits in Rows and Columns with one drag. Four zones do all the work:

Rows
Left-side labels — your categories
Columns
Top-side headers — a second dimension
Values
The numbers in each cell — must be a metric
Filters
A global filter on the entire table

Try it: total revenue by Region

This is exactly the business problem above, solved live from your dataset: drag Region → Rows, Sales → Values (SUM).

Beyond SUM

02 Aggregations — SUM, COUNT, COUNTA, AVERAGE

Business problem

The Finance team wants to know: (a) total revenue by City, (b) how many orders each City received, (c) the average sale value per City.

Class discussion

Instructor: In SQL we'd write SELECT City, SUM(Sales), COUNT(*), AVG(Sales) FROM orders GROUP BY City. How do we do this in a Pivot Table?

Learner: Drag City to Rows, then drag Sales three times into Values and change the aggregation each time?

Instructor: Exactly right. You can add the same field multiple times with different aggregations.

City pivot — Revenue, Order Count, Avg Sale Value

Why COUNTA, not COUNT? COUNTA counts all non-empty cells (text + numbers). COUNT only counts numeric cells. Order IDs are text — always use COUNTA for them.

SYNTAX
In the Values zone → click the field's dropdown → "Summarise by" → SUM · COUNT · COUNTA · AVERAGE · MAX · MIN · MEDIAN · STDEV

03 Grouping — dates to year level

Business problem

The VP of Sales asks: "Show me how revenue trended across years." Your Order Date column has full dates (YYYY-MM-DD) — dragging it into Rows as-is gives one row per unique date, potentially hundreds of rows.

Class discussion

Instructor: If I drag Order Date into Rows, I get one row per date. How do I group them?

Learner: Extract the Year first using YEAR() and use that?

Instructor: That works too — but Pivot Tables have a built-in grouping feature. Right-click the Rows field → "Group by" → Year. It's faster and cleaner.

Custom Metrics

04 Calculated fields

Business problem

Your manager asks: "What is the Revenue per Order for each City?" You already have Total Revenue (SUM of Sales) and Order Count (COUNTA of Order ID) in your pivot. Can you divide them inside the pivot itself?

SYNTAX
=SUM(Sales) / COUNTA('Order ID')

In the Pivot Table editor → Values zone → click "Add" → "Calculated field" → name it "Revenue per Order" → enter the formula above and choose "Custom" as the summarise-by. Calculated Fields use field names, not cell references, and recalculate automatically when a Filter or Slicer changes what's visible. Toggle it on in the City pivot table above (Section 02) to see it appear as a live column.

FormulaGives you
=Sales / QuantityAverage revenue per item
=Sales * 0.10Estimated 10% tax
=(Sales - Cost) / SalesGross margin % (if Cost exists)
Limitation: Calculated Fields cannot use cell references (like B2/C2) — only column names from the source data.
Show As

05 % of Row / Column / Grand Total

Business problem

The Category Manager wants to know: "What percentage of our total revenue comes from each City?"

Class discussion

Instructor: We could divide each cell by the Grand Total manually. But if I change a filter, the Grand Total changes and my percentages break. Is there a better way?

Learner: Maybe there's a built-in percentage option in the Values zone?

Instructor: Yes — GSheets calls it "Show as". It converts any value field into a percentage automatically.

Toggle togglePct on the City pivot in Section 02 to see this live — a "% of Revenue" column appears next to Total Revenue, always in sync with the visible rows.

  • % of grand total — each cell as % of the entire table total
  • % of row total — each cell as % of its row's total
  • % of column total — each cell as % of its column's total
% of row total is most useful when Regions are Rows and Categories are Columns — it shows category mix within each region, not just overall share.
Dashboard-Ready Filtering

06 Interactive slicers

Business problem

Your pivot table showing Revenue by City is complete. Your manager says: "I want to click and see only the West region. Then switch to South without touching any formulas." How do you add that interactivity?

Class discussion

Instructor: We've used the Filter zone in our Pivot Table. Isn't that enough?

Learner: The Filter zone requires opening the editor — not very user-friendly for non-technical people.

Instructor: Exactly. A Slicer is a floating visual button panel that anyone can click. No editor needed. Perfect for dashboards.

A Slicer shows every value of a chosen column as clickable buttons. Clicking one filters the entire Pivot Table — and every chart connected to it — instantly. This filter is global: it drives the City pivot above, the aggregation playground, and the Mini Dashboard below all at once.

Slicer field: Region
Slicer vs. Filter vs. Pivot Filter
Filter (Data menu)Filters rows in the raw data. Affects the whole sheet.
Pivot Filter zoneFilters inside one specific pivot. Requires editor access.
SlicerVisual button filter. Works on any pivot. Non-technical friendly.
Always test every combination before sharing a dashboard. Slicers that interact unexpectedly with FILTER() formulas can return empty results.

Automation

08 Macros — record once, replay forever

Business problem

Every Monday morning you apply the same 5 steps to a new Superstore export: remove duplicates, trim whitespace, sort by Order Date, filter for the current year, format Sales as currency. This takes 8 minutes a week. Can it become one click?

A Macro is a recorded sequence of actions. GSheets saves what you do as JavaScript (Google Apps Script) behind the scenes — when you run the macro, it replays every step exactly as recorded.

Recording "Weekly Cleanup"

Extensions → Macros → Record macro, then perform these steps in order. Press play to watch the replay.

  1. Select column A (Order ID) → Data → Remove duplicates
  2. Select all text columns → Data → Trim whitespace
  3. Click Sales header → Format → Number → Currency
  4. Click any cell in row 1 → Data → Sort range → by Order Date, ascending
  5. Save → name it "Weekly Cleanup" → assign Ctrl+Alt+1
Macro vs. Formula: a Formula calculates a value that updates when data changes (=SUM(Sales)). A Macro performs a sequence of UI actions (click, sort, format) you'd otherwise do by hand. Rule of thumb: if you're doing the same series of clicks more than twice a week, it's a Macro candidate.
Macros record UI interactions, not formulas. If a formula recalculates, the macro won't re-run it — macros automate clicks, formatting, sorting, and filtering, not dynamic calculations.

Check Yourself

11 Quick quiz

1. Which Pivot Table zone is responsible for showing summarised numeric values such as Total Revenue or Order Count?
The Values zone is where numeric calculations such as SUM, COUNT, COUNTA, and AVERAGE are performed inside a Pivot Table. Example: Sales → SUM → Total Revenue; Order ID → COUNTA → Order Count.
2. A recruiter asks: "Why are Pivot Tables preferred over multiple SUMIF formulas for reporting?" Which statement is MOST correct?
Pivot Tables dynamically summarize large datasets without writing separate formulas for every category. If new categories or rows are added, the pivot can refresh automatically.
3. Your Pivot Table shows one row for every individual Order Date, making the report difficult to analyze. What is the BEST solution?
Pivot Tables allow built-in grouping for date fields. Grouping by Year or Month helps summarize trends over time instead of showing individual dates.
4. Inside a Pivot Table, which feature should be used to calculate Revenue per Order = Sales ÷ Order Count?
Calculated Fields allow you to create custom metrics directly inside the Pivot Table using source column names. Example: =Sales / COUNTA('Order ID')
