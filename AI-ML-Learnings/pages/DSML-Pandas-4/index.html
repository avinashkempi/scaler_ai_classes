2Reshaping

Melting — wide to long

pd.melt() unpivots a DataFrame from wide format to long format: each timestamp column becomes a row, identified by the columns we choose to keep fixed.

Wide format
Drug1:302:303:30
Aspirin22.523.1—
Ibupro.30.131.030.5
⇒
melt()
Long format
Drugtimereading
Aspirin1:3022.5
Aspirin2:3023.1
Ibupro.1:3030.1
Ibupro.2:3031.0
Ibupro.3:3030.5
Bookshelf analogy: Wide format = many short shelves, each labeled with a time, books (readings) spread across them. Melting takes every book off every shelf, stacks them into one tall pile, and tags each book with the shelf it came from.
python
data_melt = pd.melt(
    data,
    id_vars=['Date', 'Drug_Name', 'Parameter'],  # columns that stay fixed
    var_name='time',                              # name for the old column labels
    value_name='reading'                          # name for the cell values
)
data_melt.head()

What happened:

  • The timestamp column labels (1:30:00, 2:30:00, …) are now values in the time column.
  • All readings are collected into the reading column.
  • Date, Drug_Name, and Parameter repeat for each reading.
  • 18 rows × 12 time columns → 216 rows (18 × 12).
💡 id_vars — the anchor columns
id_vars are the columns that stay as they are and repeat for each melted row. Everything not in id_vars gets melted — its column name becomes a row value and its cell value goes into the value_name column.

3Reshaping

      
Pivoting — long to wide (and tidy)

      
pivot() is the exact reverse of melt(): it takes values from one column and spreads them into new columns.


      
python — restore wide format
data_melt.pivot(
    index=['Date', 'Drug_Name', 'Parameter'],  # become the row labels
    columns='time',                             # unique values → new column names
    values='reading'                            # fill the cells
).reset_index()


      
Tidy format — Parameter values become separate columns

      
Currently two rows per experiment (one for Temperature, one for Pressure). A tidy format puts each measurement in its own column instead:

      
python — tidy pivot
data_tidy = data_melt.pivot(
    index=['Date', 'time', 'Drug_Name'],
    columns='Parameter',    # 'Temperature' and 'Pressure' become column names
    values='reading'
)
data_tidy = data_tidy.reset_index()
data_tidy.columns.name = None   # remove the 'Parameter' label on the column axis
data_tidy.head()

      
Result: every row is one observation — one drug, one date, one time — with separate columns for Temperature and Pressure. This tidy format is far easier to filter, plot, and model from.

4Reshaping

      
pivot_table — handling duplicate entries

      
Pfizer wants the day-wise mean temperature per drug — a cross-tabulation. Plain pivot() fails because multiple readings exist per drug per date.


      
Error
ValueError: Index contains duplicate entries, cannot reshape

      
pivot() expects exactly one value per cell. Multiple readings per cell → ambiguity → crash. The fix is pivot_table().


      

        

          
⚠️ pivot() — one value per cell only

          
Fails when the (index, column) combination maps to multiple rows. Use only when you're certain each combination is unique.

        

        

          
✓ pivot_table() — aggregates duplicates

          
Adds aggfunc= to collapse multiple values into one (mean, min, max, etc.). Uses groupby under the hood.

        

      


      
python
# Mean temperature per drug per date
pd.pivot_table(data_tidy, index='Drug_Name', columns='Date',
               values=['Temperature'], aggfunc='mean')

# Min of both Temperature and Pressure per drug per date
pd.pivot_table(data_tidy, index='Drug_Name', columns='Date',
               values=['Temperature', 'Pressure'], aggfunc='min')

      

        
💡 pivot_table uses groupby internally

        The result could also be obtained with .groupby(...).mean(), but pivot_table arranges the output as a cross-tabulation (dates as columns), while groupby gives a long table. Choose the shape that suits your next step.
      


      

        
Quiz 1

        
A DataFrame has columns Date, Product, Quantity, Revenue. After pivot(index='Date', columns='Product', values='Revenue'), which statement is true?

        

          
A) The resulting DataFrame will have more rows than the original

          
B) Each unique value in Product becomes a separate column

          
C) Total revenue across all products is guaranteed to be unchanged

        

        
By definition of pivot: the unique values from the columns= parameter each become their own column in the result. Option A is wrong — pivoting typically reduces rows (wide format has fewer rows than long). Option C depends on the aggregation used and is not guaranteed.

Binning with pd.cut()

      
Pfizer classifies temperature severity into bands rather than tracking exact degrees. pd.cut() converts a continuous column into labeled categorical bins.


      

        
Temperature severity bands (5 – 60 °C)

python
temp_points = [5, 20, 35, 50, 60]
temp_labels = ['low', 'medium', 'high', 'very_high']

data_tidy['temp_cat'] = pd.cut(
    data_tidy['Temperature'],
    bins=temp_points,
    labels=temp_labels
)
data_tidy['temp_cat'].value_counts()


      

        
💡 Interval notation: (x, y]

        By default, pd.cut() creates intervals of the form (x, y] — the left endpoint is excluded, the right endpoint is included. So a temperature of exactly 20 falls in low (the interval (5, 20] includes 20), and 20.1 falls in medium ((20, 35]).

6Missing values

      
None vs NaN

      
Two kinds of missing values exist in Python and Pandas. They look similar but behave differently depending on the column type.


      

        

          
None — Python built-in

          
type(None) → NoneType

Python's general-purpose "nothing." Works in any context but is not a number.

        

        

          
NaN — NumPy float

          
type(np.nan) → float

The numeric world's missing marker. import numpy as np to use it. Type is float.

        

      


      
Behaviour in a numeric Series

      
python
import numpy as np
pd.Series([1, np.nan, 2, None])

      
Output
0    1.0
1    NaN
2    2.0
3    NaN
dtype: float64

      
In a numeric Series, Pandas converts None to NaN. Both become the same thing internally — you can no longer tell which started as which.


      
Behaviour in an object (text) Series

      
python
pd.Series(["1", "2", None, np.nan])
# None is preserved as None in an object Series (not converted to NaN)

      

        
⚠️ "np.nan" (string) vs np.nan (object)

        "np.nan" — in quotes — is a regular string containing the literal text. Only unquoted np.nan (the actual NumPy object) is a real missing-value marker. Mixing these up is one of the most common confusion points when first working with nulls.

7Missing values

      
Detecting nulls: isna() and isnull()

      
isna() returns a boolean DataFrame — True where a value is missing. isnull() is an identical alias (same function, two names).


      
python
data.isna().head()      # True/False per cell

data.isna().sum()       # count missing per COLUMN (axis=0, default)
data.isna().sum(axis=1) # count missing per ROW


      

        
💡 Why two names?

        isnull() was the original name inherited from early Pandas. isna() was added later as a more consistent alias (matches notna()). They are byte-for-byte identical — pick whichever you prefer and be consistent.
      

      

        
🌉 SQL bridge

        data.isna().sum() ≈ SELECT COUNT(*) - COUNT(col) AS nulls FROM data; (NULL rows are excluded from COUNT of a column)

8Missing values

      
Removing and filling null values


      
dropna() — remove rows or columns

      
python
data.dropna()          # drop every row with even one missing value
data.dropna(axis=1)    # drop every column with even one missing value

      

        
⚠️ The cost of dropping

        In a drug stability test, throwing away an entire day's readings because one hourly slot was missed is a heavy price. We lose valid readings along with the missing ones. Filling is usually the better choice.
      


      
fillna() — replace nulls with a value

      
python
# Replace with a constant
data.fillna(0)

# Replace with the column mean (smarter — representative of typical readings)
data['3:30:00'] = data['3:30:00'].fillna(data['3:30:00'].mean())

# fillna() returns a copy by default — assign back or use inplace=True
data = data.fillna(data.mean(numeric_only=True))

      

        
💡 Mean vs median vs mode

        Mean works for symmetric numeric columns without extreme outliers. Median is more robust when outliers are present (e.g. extreme temperature spikes). Mode fills categorical or text columns. Always consider why a value is missing before choosing a fill strategy — blindly filling the mean can mask a real sensor malfunction.

Extracting year from a date string

      
python
data_tidy['Date'].str.split('-')
# → ['2020', '10', '15'] per row

data_tidy['Date'].str.split('-').apply(lambda x: x[0])
# → '2020' for each row

      

        
⚠️ Why this approach is fragile

        This works only because we happen to know the format is YYYY-MM-DD. If a source system sends MM-DD-YYYY, the year is now at index 2, not 0 — and this code silently grabs the wrong piece with no error. For robust date handling, use pd.to_datetime() (next section).

10Text & time

      
Datetime values

      
pd.to_datetime() converts date/time strings into proper datetime objects that Pandas understands natively — enabling sorting, extraction, and arithmetic that string splitting cannot do reliably.


      
Create and convert a timestamp column

      
python
# Combine Date and time into one string column
data_tidy['timestamp'] = data_tidy['Date'] + " " + data_tidy['time']
data_tidy.drop(['Date', 'time'], axis=1, inplace=True)

# Convert string → datetime
data_tidy['timestamp'] = pd.to_datetime(data_tidy['timestamp'])
data_tidy.info()
# timestamp    108 non-null    datetime64[ns]  ← no longer 'object'


      

        Calendar analogy: Converting a string date to datetime is like scanning a handwritten date into a calendar app. The handwriting (string) is just characters. Once the app (Pandas) recognizes it as an actual date, it can do "show me all entries from October" or "sort by date" without you parsing the text yourself.
      


      
Extracting components from a single Timestamp

      
python
ts = data_tidy['timestamp'].iloc[0]
# Timestamp('2020-10-15 10:30:00')

ts.year, ts.month, ts.day     # (2020, 10, 15)
ts.month_name()               # 'October'
ts.hour, ts.minute, ts.second # (10, 30, 0)

11Output

      
Writing to a CSV file

      
The last step of any data pipeline: save the clean, transformed DataFrame so others can use it.

      
python
data_tidy.to_csv('pfizer_tidy.csv', sep=',', index=False)
# index=False — don't write the row numbers as a separate column

      

        
💡 Always set index=False

        Without index=False, Pandas writes the row index as an extra column called Unnamed: 0 — which is exactly the column we removed at the start with index_col=0. The pipeline closes the loop here.
