Bagging's opposite number

Bagging trained many trees independently, in parallel, each on its own bootstrap sample, then let them vote. Boosting takes a completely different approach: learners are built one after another, and each one is aimed at what the models before it got wrong.

Why Boosting starts with weak learners

A single deep tree already fits the training data closely: low bias, but high variance. Boosting starts from the opposite end. It picks a model so simple that it barely fits anything on its own, a decision stump (a tree with max_depth=1), which has high bias and low variance. Then, deliberately and repeatedly, it corrects that model's mistakes.

Why not just add each stage at full strength?

The obvious next step looks like F1(x) = F0(x) + h1(x). But adding a freshly fitted model at full strength, every stage, tends to overcorrect and overfit quickly, chasing every bit of noise in the residual. The fix is a learning rate (also called shrinkage), a small number η, typically well under 1, that scales down each stage's contribution.

A smaller η means each stage nudges the prediction only a little, so more stages are needed to fit the data, but the final model tends to generalise better. It is the same idea as the regularization strength used elsewhere, applied stage by stage instead of all at once.

The residual always comes from the cumulative model

For Stage 2 it is tempting to think the new residual comes from just h1, or just the first model on its own. It does not. The residual at every stage is calculated against the current cumulative model, which already includes F0's contribution plus η·h1. Using anything else would double-count or ignore part of what has already been corrected.

residuali(2) = yi − F1(xi)

At any stage M, the whole model is:

FM(x) = F0(x) + η Σm=1M hm(x)

Each hm is trained on the residual left by Fm−1, and every new stage is added on top, scaled by the same learning rate.

Watch it happen, stage by stage

Every stage is a depth-1 stump fitted to the residual of the current model. The data are the notebook's own (random seed 7), and the boosting runs live in your browser.

This is the error on the training data. It always falls as stages are added; what matters for real data is how the model behaves on unseen rows, and that is where the learning rate earns its keep.

  • Stage by stage, the line hugs the true pattern more closely, even though every stump is a weak, depth-1 tree on its own.
  • The remaining MSE shrinks. That number is the same idea as the residual tracked by hand.
  • No single stump can produce a curve like the one after six stages. Weak learners, added up carefully, become strong.

Try η = 1: the fit improves faster on the training points, but each stage takes the full step toward the current residual, which is exactly the overcorrection that shrinkage is there to prevent.

View the notebook code 
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.tree import DecisionTreeRegressor

# A toy 1-feature regression problem: some wavy pattern plus noise
rng = np.random.default_rng(7)
X_toy = np.linspace(0, 10, 120).reshape(-1, 1)
y_toy = np.sin(X_toy).ravel() + 0.3 * X_toy.ravel() + rng.normal(0, 0.3, size=120)

eta = 0.3         # learning rate
n_stages = 6

F = np.full_like(y_toy, y_toy.mean())   # Stage 0: predict the mean, for every point
stumps = []

fig, axes = plt.subplots(2, 3, figsize=(16, 9))
axes = axes.ravel()

for stage in range(n_stages):
    residual = y_toy - F                     # residual against the CURRENT cumulative model
    stump = DecisionTreeRegressor(max_depth=1, random_state=7)  # a genuinely weak learner
    stump.fit(X_toy, residual)
    stumps.append(stump)

    F = F + eta * stump.predict(X_toy)       # add this stage's (shrunk) contribution

    ax = axes[stage]
    ax.scatter(X_toy, y_toy, s=10, alpha=0.4, label='True y')
    ax.plot(X_toy, F, color='red', linewidth=2, label='F so far')
    ax.set_title(f'After stage {stage + 1}  |  remaining MSE = {np.mean((y_toy - F)**2):.3f}')
    ax.legend(fontsize=8)

plt.tight_layout()
plt.show()

Beyond squared error: pseudo-residuals

Everything so far assumed squared error, where the residual y − F(x) happens to point exactly in the direction that reduces the loss fastest. Boosting is not limited to squared error, or even to regression.

For any differentiable loss function L(y, F(x)), compute the negative gradient of the loss with respect to the current prediction:

ri = − ∂L(yi, F(xi)) / ∂F(xi)

This ri is called a pseudo-residual. It tells each new weak learner which direction would reduce the loss fastest, generalising the simple "y minus prediction" idea to any loss function.

Squared error: the gradient is the residual

Illustrative single point

The gold arrow shows the direction that lowers the loss. Its length is the pseudo-residual. Because the loss is ½(y − F)², the negative gradient works out to exactly y − F, which is the residual used throughout this read.

For log loss (used in classification, like the attrition problem), the pseudo-residual formula is more involved, since it works with probabilities rather than raw values.

Whatever the loss function, at every stage a new weak learner is trained to predict the pseudo-residual, and its shrunk prediction is added to the running total.

That is why the technique is called Gradient Boosting.

There is a gap between train and test accuracy, similar in shape to what an unpruned single decision tree shows, though not nearly as extreme.

A genuine warning. Boosting is a particularly easy technique to overfit. Every stage is built specifically to reduce whatever error remains, including noise in the training data. With enough stages (a high n_estimators) and deep enough learners, a boosted model can chase noise as eagerly as it chases real signal. Proper regularisation comes next.

Summary

Bagging vs Boosting

Bagging trains learners independently and averages them, mainly reducing variance. Boosting trains learners sequentially, each one correcting the last, mainly reducing bias.

Weak learners

Boosting deliberately uses weak, high-bias, low-variance learners, often decision stumps, as its building blocks.

The stage-by-stage recipe

The process starts from a simple baseline, F0(x), often just the mean of the target. Each new stage fits a weak learner to the residual left by the current cumulative model, not by any single previous stage in isolation.

The learning rate

Adding each new stage at full strength overfits quickly, so a learning rate (shrinkage factor η) scales down each contribution: FM(x) = F0(x) + η Σ hm(x).

Pseudo-residuals

For squared error, the residual y − F(x) already points in the loss-reducing direction. For other losses this generalises to the pseudo-residual, the negative gradient of the loss with respect to the current prediction, which is why the technique is called Gradient Boosting.

Hyperparameters

GradientBoostingClassifier's key hyperparameters (n_estimators, max_depth, learning_rate, loss) map directly onto these concepts.

Overfitting risk

Boosting is powerful but easy to overfit, since every stage is built specifically to chase whatever error remains, including noise.
