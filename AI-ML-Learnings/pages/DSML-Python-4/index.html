1The hook

Building a Portfolio Tracker

A customer holds multiple stocks. For each, the bank tracks daily closing prices:

example
Stock A closing prices over 10 days:
[142, 145, 138, 150, 155, 148, 160, 158, 165, 170]

The customer also holds Stock B and Stock C, each with their own 10-day history. The job is to build a system that:

StepWhat it does
StoreDaily prices in a list — no more 365 separate variables
AccessA specific day's price
UpdateAdd today's price, remove an erroneous entry
CheckWas a target price ever hit?
SliceDate ranges — last 5 days, every alternate day
ManageMultiple stocks in a 2D list (rows = stocks, columns = days)
IterateCompute summaries — max price per stock, daily totals
🌉 SQL bridge
In SQL you'd store this as a table: SELECT stock_name, day, closing_price FROM portfolio WHERE stock_name = 'Stock A' ORDER BY day; A Python list is like a single column from that table. A 2D list is like the entire table.
2Why lists

Motivation, and list creation

Imagine storing every run Virat Kohli has scored across ~370 international matches, to find the min, max, and average. Without lists:

python
match_1 = 67
match_2 = 54
match_3 = 12
# ... 367 more lines
match_370 = 45

Absurd. You can't write 370 variable names, can't loop over them, can't do anything useful. The same problem shows up storing 365 days of stock prices in 365 separate variables. We need one variable that holds multiple values — a list.

List creation

A list is an ordered collection of data — a structure that can store multiple values, with no limit on how many.

Syntax: square brackets [] with comma-separated values.

python
runs_virat = [67, 54, 12, 34, 77, 89, 101]
runs_virat  # to display the output
Output
[67, 54, 12, 34, 77, 89, 101]

Banking version:

python
stock_prices = [142, 145, 138, 150, 155, 148, 160, 158, 165, 170]
stock_prices  # to display the output
Output
[142, 145, 138, 150, 155, 148, 160, 158, 165, 170]

370 matches, or 365 days, in one variable. That's the power of lists.

Lists can hold any data type, even mixed types:

python
mixed = [42, "hello", 3.14, True, None]

In practice, though, most lists hold values of a single type (all integers, all strings).

List methods

      
Strings are immutable (Lecture 3) — lists are mutable, meaning they CAN change in place. We can add, remove, and modify elements directly. Here's what makes that possible.


      
append() — add a single element to the end

      
python

runs.append(71)
runs

      
Output
[45, 67, 89, 12, 34, 56, 100, 71]

      
Banking tie-in: market just closed — stock_prices.append(172).

All these methods modify the list in place — same memory location, same id(). That's mutability in action. Contrast this with string methods like .replace() (Lecture 3), which always return a brand-new string at a brand-new address.


      

        
💡 Prompting tip

        With six similar-looking methods (append, insert, extend, pop, remove, count), it's easy to blank on which one fits. The real skill is recognizing which method fits a described task yourself; knowing remove() deletes by value (not position) is what lets you trust that it's the right call here, rather than just running whatever comes back.

8Motivation

      
Why slicing?

      
Problem: given Virat Kohli's runs, create a new list of runs from odd matches (even indices: 0, 2, 4, …).

      
python
def odd_runs(runs):
    result = []
    for i in range(len(runs)):
        if i % 2 == 0:
            result.append(runs[i])
    return result

runs = [62, 85, 74, 10, 12, 101, 122, 99, 81, 55]
odd_runs(runs)

      
Output
[62, 74, 12, 122, 81]

      
That's 6 lines for something that should be simple. Python offers a one-liner. Let's learn how.

    


    
    

      
9Lists

      
List slicing (positive)

      
List slicing uses the exact same syntax as string slicing from Lecture 3: list[start:end:step]. Returns elements from index start to end − 1 — end is always excluded, just like range().

      
python
runs = [62, 85, 74, 10, 12, 101, 122, 99, 81, 55]


      

        
Basic slicing on runs (index 0–9)

        

          
runs[5:]
from index 5 to end
[101, 122, 99, 81, 55]

          
runs[:5]
from start to index 4
[62, 85, 74, 10, 12]

        

        

          
runs[::2]
every other element (step 2)
[62, 74, 12, 122, 81]

        

      


      
python
runs = [62, 85, 74, 10, 12, 101, 122, 99, 81, 55]
print(runs[5:])   # from index 5 to end
print(runs[:5])   # from start to index 4
print(runs[::2])  # every other element (step of 2)

      
Output
[101, 122, 99, 81, 55]
[62, 85, 74, 10, 12]
[62, 74, 12, 122, 81]

💡 Key insight

        runs[::2] is the one-liner answer to the odd-match problem — it replaces the entire 6-line function. The original list is not modified by slicing; slicing always creates a new list.

Just like negative indexing, we can use negative values in slices. This is where it gets tricky — let's go carefully.

Step directionDefault startDefault endDirection

Positive step = left to right. Negative step = right to left.

python
print(a[-2:-5:-1])

        The lecture leaves a[-2:-7], a[-2:], and a[-8:5:-1] as practice: trace them on paper using the rules above, then check below.
      

      

        

          

            

              
ExpressionResultWhy

              
a[-2:-7][]Positive step (default) only goes left→right; start (−2) comes after end (−7) in that direction, so nothing is collected

              
a[-2:][90, 100]Start at −2, no end given → goes to the end of the list, left to right

Debugging an empty slice

      
python
prices = [100, 110, 105, 120, 115, 130, 125, 140]
recent = prices[5:2]
print(recent)

      
Output
[]

      

        
⚠️ A mistake that trips up almost everyone the first time

        Empty — but some prices were expected back! With a positive step (the default), slicing only moves left to right. Since start (index 5) comes after end (index 2) in that direction, there's nothing to collect between them, so Python returns an empty list rather than an error — unlike indexing out of range, which raises IndexError.
        
Fix — correct order, or a negative step to go backwards:

        
python
print(prices[2:5])    # correct order
print(prices[5:2:-1]) # negative step, goes backwards

        
Unlike IndexError, an empty slice never crashes your program — it just silently gives you nothing. Always sanity-check slice results, especially when start and end come from a calculation rather than a literal number.

11Two dimensions

      
2D lists

      
Lists are heterogeneous — they can store elements of any type, including other lists. A list of lists is a nested or 2D list, visualized as a matrix with rows and columns.

      
python
a = [[1, 2, 3],
     [4, 5, 6],
     [7, 8, 9]]
print(a)

      
Output
[[1, 2, 3], [4, 5, 6], [7, 8, 9]]


      

        
2D list as a grid

        

          
Column 0Column 1Column 2

          
Row 0123

          
Row 1456

          
Row 2789

        

        
a[0] = [1, 2, 3] (entire first row)  ·  a[1][2] = 6 (row 1, col 2)  ·  a[2][0] = 7 (row 2, col 0)

      


      

        
🌉 Banking + SQL tie-in

        
portfolio = [
    [142, 145, 138, 150, 155],  # Stock A prices (5 days)
    [230, 228, 235, 240, 238],  # Stock B prices
    [95, 98, 92, 100, 103]      # Stock C prices
]

        Row 0 = Stock A, Row 1 = Stock B. Column 0 = Day 1, Column 3 = Day 4. A 2D list is like a SQL table — each row is a record (one stock), each column is a field (one day). a[0][2] is like accessing row 1, column 3 in SQL (1-based).
      


      
Indexing in 2D lists

      
Use two indices: a[row][column].

      
python
a = [[1, 2, 3],
     [4, 5, 6],
     [7, 8, 9]]
print(a[0][2])

      
Output
3

      
python
print(a[1][1])  # row 1, column 1

      
Output
5

      
Banking tie-in: "Stock B's price on Day 3?" → portfolio[1][2] (row 1 = Stock B, column 2 = Day 3, zero-based).


      
Iterating over 2D lists

      
A nested for loop (Lecture 2) — outer loop through rows, inner loop through columns.

      
python
a = [[1, 2, 3],
     [4, 5, 6],
     [7, 8, 9]]
rows = len(a)       # number of rows
columns = len(a[0]) # number of columns (length of first row)
for i in range(rows):
    for j in range(columns):
        print(a[i][j], end=" ")
    print()

      
Output
1 2 3
4 5 6
7 8 9

      
Same nested-loop pattern from Lecture 2 (star patterns, multiplication table) — now applied to real data. Banking tie-in: print all prices for all stocks in a formatted table.

12Putting it together

      
Capstone: the Portfolio Tracker

      
Time to build the system from the opening scenario.

      
python
# ============================================
# PORTFOLIO TRACKER
# ============================================

# Step 1: Create 1D list of daily prices for Stock A
stock_a = [142, 145, 138, 150, 155, 148, 160, 158, 165, 170]

# Step 2: Append today's new price (list method: append)
stock_a.append(172)
print(f"Stock A after today: {stock_a}")

# Step 3: Remove an erroneous entry (list method: remove)
stock_a.insert(3, 999)  # simulate error
print(f"With error: {stock_a}")
stock_a.remove(999)
print(f"Error removed: {stock_a}")

# Step 4: Check if target price was hit (membership)
target = 160
if target in stock_a:
    print(f"Target price {target} was hit!")
else:
    print(f"Target price {target} was NOT hit.")

# Step 5: Slicing for analysis
print(f"\nLast 5 days: {stock_a[-5:]}")
print(f"First week: {stock_a[:5]}")
print(f"Alternate days (sampling): {stock_a[::2]}")

# Step 6: 2D list - multiple stocks
portfolio = [
    [142, 145, 138, 150, 155],  # Stock A (5 days)
    [230, 228, 235, 240, 238],  # Stock B
    [95, 98, 92, 100, 103]      # Stock C
]
stock_names = ["Stock A", "Stock B", "Stock C"]

# Step 7: Iterate with nested loop to find max price per stock
print("\n" + "=" * 40)
print(" PORTFOLIO SUMMARY")
print("=" * 40)
for i in range(len(portfolio)):
    max_price = portfolio[i][0]
    for j in range(len(portfolio[i])):
        if portfolio[i][j] > max_price:
            max_price = portfolio[i][j]
    print(f"{stock_names[i]}: Max price = {max_price}")

# Step 8: Compute daily portfolio total (column-wise sum)
print("\nDaily Portfolio Totals:")
days = len(portfolio[0])
for j in range(days):
    daily_total = 0
    for i in range(len(portfolio)):
        daily_total += portfolio[i][j]
    print(f"  Day {j+1}: Rs.{daily_total}")

Target price 160 was hit!

Last 5 days: [160, 158, 165, 170, 172]

🌉 Compare to the SQL version

        
-- Max price per stock
SELECT stock_name, MAX(closing_price)
FROM portfolio
GROUP BY stock_name;

-- Daily total
SELECT day, SUM(closing_price)
FROM portfolio
GROUP BY day;

        
The SQL version is concise for table data. The Python version handles dynamic data, allows real-time updates (append, remove), and gives full control over the processing logic. Both skills complement each other.
