2. The big idea: write it once, then prove nothing changed

A chain of 40 shops paints its opening hours on 40 doors. When the hours change, someone must visit 40 doors, and one is always missed. A better chain keeps the hours in one place and prints every sign from it. The shops open at the same time as before. Only the way the signs are made has changed. That is a refactor: change how the code is built, not what it does.

5. Functions are values, and closures

In Python a function is a value, like a number or a string. You can put it in a variable, hand it to another function, and return it from a function. You have already done this: in Class 4 a test used sleep=waits.append, so the code recorded each wait instead of really waiting. Think of a recipe card. Handing over the card is different from handing over the finished dish.

The card or the dish?

No brackets after a name means the function itself. Brackets mean it runs, and you get its result. Click an item, then click the bin it belongs in.

A function that remembers: a closure

A closure is a function together with the outside variables it uses. The variables travel with it, even after the function that created them has finished. Think of a tiffin box packed at home. When it reaches the office, the lunch is still inside.

A counter that remembers (you will type this in class)
def make_counter():
    count = 0

    def bump():
        nonlocal count
        count += 1
        return count

    return bump


a = make_counter()
b = make_counter()
print(a(), a(), a(), "|", b())
What Python prints
1 2 3 | 1

Two counters made by the same function do not share their count. Each call to make_counter packs its own count. Click a case to see what happens.

Click a case above.
Why this matters today Every decorator you write in class is a closure. When we write retry_transient(max_attempts=3, ...), the number 3 is packed inside the function it returns. No global variable is needed.

6. Two kinds of wrapper: decorators and context managers

Both add behaviour around something without changing what is inside. A decorator wraps a function: the extra behaviour runs on every call. Think of gift wrap: the gift is unchanged, and the wrap adds a ribbon or a note. A context manager wraps a block of lines with with: its clean-up runs when the block ends, even after an error. Think of a hotel door that locks behind you whether you leave happily or in a hurry.

A decorator, and why functools.wraps matters
def shout(function):
    def wrapper(*args, **kwargs):
        """wrapper doc"""
        return function(*args, **kwargs).upper()
    return wrapper

@shout
def greet(name):
    """Say hello."""
    return "hello " + name

print(greet("Asha"), greet.__name__, greet.__doc__)
# HELLO ASHA wrapper wrapper doc

The greeting is upper case, so the wrapper ran. But the function's name and docstring have been replaced by the wrapper's. Adding @functools.wraps(function) above def wrapper keeps greet and Say hello.. The @shout line is simply a shortcut for greet = shout(greet).

A context manager: the clean-up runs on both roads
with Stopwatch():
    time.sleep(0.05)
# enter
# exit, error was: None

with Stopwatch():
    raise ValueError("boom")
# enter
# exit, error was: ValueError
# ... and the ValueError still escapes to the caller

Retry only what waiting can fix

A transient error may pass if you wait and try again. A permanent one will not. Retrying a permanent error wastes time and hides the real problem. Click an item, then click the bin it belongs in.

A trace without the text

A trace is a record of one model call that lets you find it again and explain it. To keep it safe, it holds a short hash of the prompt (a one-way fingerprint), the prompt version, the model settings, the number of attempts, the time and the token counts. The proof: fingerprints and counts

How do you show that a refactor changed nothing? Before touching any code, take a picture: the test count, the evaluation result, and a short fingerprint of three files a run writes. After every change, take the picture again. If one byte of a file differs, its fingerprint differs.
