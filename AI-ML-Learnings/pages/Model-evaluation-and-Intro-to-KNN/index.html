Review
Recap of Classification Metrics
⏱ 2 min

Last lecture we covered the full toolkit for evaluating binary classifiers:

  • Confusion Matrix — TP, TN, FP, FN at a fixed threshold
  • Accuracy — misleading on imbalanced data
  • Precision — of all predicted positives, how many are correct
  • Recall (Sensitivity) — of all actual positives, how many did we find
  • F1-Score — harmonic mean of Precision and Recall
  • ROC Curve — TPR vs FPR across all thresholds
📌 Today's Focus
We complete the metrics picture with AUC and a clean cheatsheet for which metric to use. Then we introduce a fundamentally different classification algorithm — K-Nearest Neighbors — that makes no linearity assumptions at all.
📐
Metric
AUC — Area Under the ROC Curve
⏱ 8 min

The AUC (Area Under the Curve) collapses the entire ROC curve into a single number. It approximates the area under the TPR vs FPR plot by summing small rectangles formed at each threshold step.

Interpreting AUC

AUC ValueMeaningImplication
1.0Perfect modelPasses through (0,1) — catches all positives with zero false alarms
0.9–0.99ExcellentVery strong discriminating power
0.7–0.9GoodSolid model — works well in most real scenarios
0.5Random modelNo discriminating power — equivalent to flipping a coin
< 0.5Worse than randomInvert predictions → AUC becomes 1 − current AUC
0.0Worst possibleEvery positive predicted as negative and vice versa

Comparing Two Models with AUC

When two ROC curves are plotted together, the model whose curve is further toward the top-left corner (closer to point (0,1)) has a higher AUC and is the better model — it achieves higher TPR for the same FPR across all thresholds.

A Key Property: AUC is Order-Dependent, Not Value-Dependent

AUC doesn't care about the absolute values of predicted probabilities — only their ordering. Models M1 (probabilities: 0.95, 0.92, 0.80, 0.76, 0.71) and M2 (0.20, 0.10, 0.08, 0.06, 0.01) will produce the same ROC curve and AUC if they rank the same points in the same order.

⚠️ AUC Limitation
AUC works well for slightly imbalanced data but fails for severely imbalanced datasets (e.g., 1 positive in 1000). In those cases, use Precision-Recall AUC (PR-AUC) instead, which focuses only on the positive class.

Code

from sklearn.metrics import roc_curve, roc_auc_score
import matplotlib.pyplot as plt

fpr, tpr, thr = roc_curve(data.y, data.proba)

plt.plot(fpr, tpr)
plt.title('ROC Curve'); plt.xlabel('FPR'); plt.ylabel('TPR')
plt.show()

print("AUC:", roc_auc_score(data.y, data.proba))
Output
AUC: 0.9377570000000001

AUC = 0.938 — a strong result. This means the model correctly ranks a random positive above a random negative 93.8% of the time.

Quiz 1
Shape of the ROC Curve
⏱ 1 min
For the ROC curve (TPR vs FPR), which of the following is true about its shape?
  • The curve is always concave.
  • The curve is never concave.
  • The curve may or may not be concave.
💡 Explanation
A ROC curve can be concave, convex, or mixed. An ideally performing model produces a concave curve bowing toward (0,1). A convex ROC (bowing away) implies TPR + FPR are both low — the model is worse than random in those threshold regions.

Concept
Performance Metrics vs Loss Functions
⏱ 2 min

These terms are often confused. They serve different purposes in the ML workflow.

Loss FunctionPerformance Metric
PurposeUsed to train the model (optimization target)Used to evaluate the model (human-interpretable score)
Differentiable?Yes — gradient descent requires itNot required — may be discrete (e.g., accuracy)
ExamplesMSE, Binary Cross-Entropy, Log LossAccuracy, Precision, Recall, F1, AUC
Overlap?Yes — MSE and Log Loss can serve as both (with regularization)
📌 Key Distinction
The optimizer minimizes the loss function during training. The performance metric tells you how well the final model actually performs on your task. They don't have to be the same — you might train with cross-entropy but evaluate with F1-score.

Case Study
Evaluating a Classifier — Pima Diabetes Dataset
⏱ 8 min

Dataset: 768 patients, 7 features (glucose, BMI, age, etc.), binary target: diabetic (1) or not (0).

Build & Evaluate Logistic Regression

import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn import metrics

col_names = ['pregnant','glucose','bp','skin','insulin','bmi','pedigree','age','label']
pima = pd.read_csv('pima-indians-diabetes.csv', header=1, names=col_names)

feature_cols = ['pregnant','glucose','bp','skin','insulin','bmi','age']
X = pima[feature_cols]; y = pima.label

X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=1)
logreg = LogisticRegression()
logreg.fit(X_train, y_train)

y_pred = logreg.predict(X_test)

Confusion Matrix Values

🤔 Is Recall of 48.4% acceptable here?
For diabetic screening, recall (sensitivity) is critical — missing a diabetic patient can have serious health consequences. A recall of only 48.4% means we're missing more than half of actual diabetic patients. This suggests we should lower the threshold to improve recall, even at the cost of more false positives.

Changing the Decision Threshold
⏱ 5 min

The default threshold of 0.5 is not always optimal. Lowering the threshold makes the model more sensitive to the positive class — useful when recall matters more than precision.

Threshold = 0.5 (Default) vs Threshold = 0.3

ThresholdSensitivity (Recall)SpecificityTradeoff
0.50.4840.883Conservative — fewer false alarms
0.30.7420.695Aggressive — catches more diabetics, more false positives
from sklearn.preprocessing import binarize

y_pred_prob = logreg.predict_proba(X_test)[:, 1]

# Lower threshold to 0.3 → more diabetics flagged
y_pred_03 = binarize([y_pred_prob], threshold=0.3)[0]

print("Sensitivity at 0.3:", 46/(46+16))   # 0.742
print("Specificity at 0.3:", 80/(80+50))   # 0.615
📌 Key Insight
There is no universally correct threshold. The ROC curve lets you explore all possible threshold tradeoffs visually — you pick the operating point that best balances the costs of false positives and false negatives for your specific use case.

ROC Curve & AUC — Diabetes Model
⏱ 4 min
fpr, tpr, thresholds = metrics.roc_curve(y_test, y_pred_prob)

plt.plot(fpr, tpr)
plt.xlim([0, 1]); plt.ylim([0, 1])
plt.title('ROC — Diabetes Classifier')
plt.xlabel('FPR (1 - Specificity)')
plt.ylabel('TPR (Sensitivity)')
plt.grid(True)
# AUC score
print(metrics.roc_auc_score(y_test, y_pred_prob))   # 0.805

# Cross-validated AUC (more reliable)
from sklearn.model_selection import cross_val_score
cv_auc = cross_val_score(logreg, X, y, cv=10, scoring='roc_auc').mean()
print("CV AUC:", cv_auc)   # 0.824
Output
AUC (test): 0.80517578125 AUC (10-fold CV): 0.823920227920228
✅ Why Cross-Validated AUC Is More Reliable
A single train-test split might give an optimistic or pessimistic AUC depending on which points ended up in the test set. 10-fold cross-validation averages over 10 different splits — the result of 0.824 is a much more trustworthy estimate of real-world performance.

Algorithm
K-Nearest Neighbors — Introduction
⏱ 6 min

Logistic Regression requires a linear decision boundary. Not all real-world problems are linearly separable. KNN takes a completely different approach — it makes no assumptions about the shape of the boundary at all.

The Core Idea: Similarity by Proximity

Imagine a new student joins your school. You know nothing about their interests — so you look at the students sitting closest to them. If most nearby students are into sports, you'd guess the new student probably is too. That's KNN.

In our reseller classification problem: when a new reseller joins, compare their order pattern to existing resellers. If 4 of their 5 closest neighbors belong to Class 1, predict Class 1.

Learning Type
Supervised
Uses labeled training data
Training Phase
Lazy Learner
Just stores data — no model fitting
Parametric?
Non-parametric
No assumptions about data distribution
Tasks
Classification & Regression
Majority vote (class) or mean/median (regression)
📌 Why "Lazy Learner"?
KNN does zero work during training — it simply stores all data points. All computation happens at prediction time, when it calculates distances to every training point. This is the opposite of algorithms like Logistic Regression, which front-load all work into training.

KNN Applications
⏱ 2 min

KNN's strength lies in finding similar items. Any time you need "find things like this one," KNN is a natural fit.

Geometric Intuition & The KNN Algorithm
⏱ 4 min

How K Controls the Prediction

Suppose a query point x_q has 3 negative neighbors and 1 positive neighbor nearby.

  • With K=4: majority is negative → predict negative
  • With K=1: nearest neighbor is positive → predict positive

The value of K fundamentally changes what "neighborhood" means. Larger K = smoother, more global decisions. Smaller K = more local, sensitive to individual points.

The KNN Algorithm (Pseudocode)

1

Compute Distances

For each training point xᵢ, compute distance(xᵢ, x_q). Store all results in a distance vector D.

2

Sort by Distance

Sort vector D in ascending order — closest points first.

3

Select K Nearest Neighbors

Take the top-K points with smallest distance to x_q.

4

Majority Vote

Count class labels among K neighbors. Return the class with the most votes.

💡 Practical Tips
  • Prefer odd values of K to avoid ties in binary classification
  • When a tie occurs (e.g., equal distances), KNN defaults to random choice — rare in practice but worth knowing
📏
Concept
Distance Metrics
⏱ 5 min

The choice of distance function is itself a hyperparameter in KNN. Different distance metrics suit different data types and problem geometries.

Euclidean Distance
d = √(Σ (x1ⱼ − x2ⱼ)²)
The straight-line "as the crow flies" distance between two points. The most intuitive and commonly used metric.
⚠️ Fails in high dimensions (Curse of Dimensionality)
Manhattan Distance
d = Σ |x1ⱼ − x2ⱼ|
The "city block" distance — travel only along axes, like navigating a grid of streets. Sum of absolute differences per dimension.
✅ More robust in high dimensions than Euclidean
Minkowski Distance
d = (Σ |x1ⱼ − x2ⱼ|ᵖ)^(1/p)
A generalization: p=1 gives Manhattan, p=2 gives Euclidean. Choosing p is another hyperparameter.
✅ Flexible — subsumes both above
Cosine Similarity
sim = (x1·x2) / (|x1||x2|)
Measures the angle between two vectors, not their absolute distance. Direction matters more than magnitude.
✅ Best for text/NLP and sparse data
⚠️ Always Scale Before KNN
Distance metrics are sensitive to feature scale. A feature in thousands (salary) will dominate one in single digits (number of children). Always apply StandardScaler or MinMaxScaler before running KNN.

Technique
Weighted KNN
⏱ 4 min

Standard KNN gives every neighbor an equal vote. But what if 2 very close negative neighbors are outvoted by 3 distant positive ones? The majority can overrule proximity — leading to wrong predictions.

The Problem with Equal Weighting

K=5: 2 negative neighbors (very close, distance ≈ 0.1) and 3 positive neighbors (far away, distance ≈ 0.5). Standard KNN votes: +3, −2 → predicts positive. But the closest points are negative!

Weighted KNN: Weight = 1/distance

Assign each neighbor a weight inversely proportional to their distance. Closer neighbors count more:

NeighborClassDistanceWeight (1/d)
N1Negative0.110
N2Negative0.110
N3Positive0.52
N4Positive0.52
N5Positive0.52

Weighted scores: Negative = 10+10 = 20, Positive = 2+2+2 = 6. Predict: Negative ✓

w_knn = KNeighborsClassifier(n_neighbors=5, weights='distance', metric='euclidean')
w_knn.fit(X_train, y_train)

print("Weighted KNN score:", w_knn.score(X_test, y_test))
Output
Weighted KNN score: 0.9253731343283582

Weighted KNN improves from 90% → 92.5% — closer neighbors now carry the influence they deserve.

Concept
KNN Assumptions & Time Complexity
⏱ 3 min

Core Assumption

Similar data points exist in close proximity. Neighborhoods are homogeneous — things that are near each other tend to have the same class label. If this isn't true in your data (e.g., overlapping or interleaved classes), KNN will struggle.

Compare: Logistic Regression vs KNN
Logistic Regression assumes a linear decision boundary exists. KNN assumes local homogeneity — no global shape requirement. This makes KNN more flexible but more sensitive to local noise.

Test-Time Complexity

KNN does no training — but at prediction time it must:

  1. Compute distance from x_q to all n training points (each d-dimensional) → O(n·d)
  2. Sort the distance array → O(n·log n)
  3. Pick top-K → O(k) (negligible)
Total: O(n·d + n·log n) = O(n · (d + log n))
⚠️ Scalability Concern
For large datasets (n = millions) and high-dimensional data (d = hundreds), KNN becomes extremely slow at prediction time. Approximation methods (KD-trees, Ball trees, FAISS) are used in production.
⚖️
Concept
Bias-Variance Tradeoff in KNN
⏱ 5 min

In KNN, there's no model to train — the only hyperparameter is K. And K entirely controls the bias-variance tradeoff.

K valueBehaviorBiasVarianceRisk
K = 1Each neighbor is a single point — highly sensitive to noise and outliersLowHighOverfitting
K = moderate (e.g., 5–15)Balanced neighborhood — generalizes wellMediumMediumBest ✓
K = n (all points)Always predicts the majority class regardless of positionHighLowUnderfitting

How to Find the Best K

Plot the validation error (or F1/accuracy) against different K values. The best K is where the validation error is minimized — not the training error, which always improves as K decreases.

📌 Important
Always do K-selection on the validation set, never the test set. Using the test set to pick K leaks information and gives an overly optimistic estimate of generalization.

Quiz 2
KNN — Training vs Testing Computation
⏱ 1 min
The k-Nearest Neighbors algorithm performs more computation during test time than during training time. True or False?
  • True
  • False
💡 Explanation
KNN's training phase is just storing the dataset — O(1). All the real work happens at test time: computing distances to every training point, sorting, and selecting K neighbors. This makes KNN a "lazy learner" — it defers computation until prediction.

Quiz 3
K and Bias-Variance in KNN
⏱ 1 min
Which of the following is true about increasing k in k-Nearest Neighbors with respect to bias and variance?
  • When you increase k, both bias and variance increase.
  • When you increase k, bias increases and variance decreases.
  • When you increase k, bias decreases and variance increases.
  • When you increase k, both bias and variance decrease.
💡 Explanation
Large K → model consults more neighbors → smoother, more "average" predictions → high bias, low variance (underfitting). Small K → each prediction depends on very few neighbors → highly sensitive to local noise → low bias, high variance (overfitting).

Quiz 5
KNN — Classification and Regression
⏱ 1 min
Which of the following is true about the k-NN algorithm?
  • It can only be used for classification.
  • It can only be used for regression.
  • It can be used for both classification and regression.
💡 Explanation
For classification: take majority vote of K neighbors' class labels. For regression: take mean or median of K neighbors' target values. The distance-finding step is identical — only the aggregation changes.
