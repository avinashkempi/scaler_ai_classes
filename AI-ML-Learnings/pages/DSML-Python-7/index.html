1The hook

Transaction File Processor

Every morning a CSV file arrives with the previous day's transactions. Some rows have bad data. If you process this file without error handling, one bad row crashes the program and the rest of the good transactions never get processed.

transactions.csv — the input file
txn_id,account,amount,fee_percent
TXN001,ACC101,5000,2.5
TXN002,ACC102,,1.5        ← missing amount
TXN003,ACC101,7000,0      ← zero fee — valid! not an error
TXN004,ACC103,3000,abc    ← non-numeric fee_percent
TXN005,ACC101,10000,1.0
TXN006,ACC102,BAD_DATA,2.0  ← non-numeric amount
TXN007,ACC103,8000,3.0
TXN008,ACC101,15000,1.5
TaskTool
Read the CSV filecsv module + with statement
Process each row: fee = amount × fee_percent / 100, net = amount − feefloat() conversions
Handle bad data without crashingtry / except
Write clean transactions to output CSVcsv.writer()
Write errors to a separate log fileopen() in write mode
💡 The deliberate edge case
TXN003 has fee_percent = 0. This is valid — no fee was charged that day. Good error handling must not accidentally reject this row. We include it to make sure the logic distinguishes "missing or bad data" from "a legitimate zero."
🌉 SQL bridge
In SQL you'd write: SELECT txn_id, amount * fee_percent/100 AS fee FROM transactions WHERE amount IS NOT NULL AND ISNUMERIC(fee_percent) = 1; That works when the data is already in a database. When it arrives as a raw CSV file from an API or a batch export, you need Python to process it on the fly.

3Modules

The random module and reproducibility

Random numbers in computers are generated by an algorithm starting from a seed value. By default Python uses the current timestamp, giving different numbers each time. Set the seed manually and you get the same sequence every time — this is reproducibility.

python
import random

random.seed(100)
print(random.randint(0, 10))
print(random.randint(0, 10))
print(random.randint(0, 10))
print(random.randint(0, 10))
print(random.randint(0, 10))
Output
2
7
7
2
6

Run random.seed(100) again before the five calls — you get exactly the same sequence.

python — different seed
random.seed(10)
print(random.randint(0, 10))  # 9
print(random.randint(0, 10))  # 0
print(random.randint(0, 10))  # 6
print(random.randint(0, 10))  # 7
print(random.randint(0, 10))  # 9
🌉 Banking tie-in
When building a fraud detection model, you randomly split transaction data into training and testing sets. random.seed(42) ensures the split is identical every time you run the code, so results are shareable and verifiable.

⚠️ The problem with import *

        If two modules define a function with the same name and you from module import * both, the second silently overwrites the first. You lose access to one without any warning. This is why aliased imports are preferred in practice.

5File handling

      
open(), read(), write(), and file modes

      
All data so far has been hardcoded inside our scripts. Real-world data lives in files. Python's built-in open() is the gateway.


      
Creating and writing a file

      
python
file = open("sample.txt", "w")     # open in WRITE mode
file.write("Hello, this is line 1.\n")
file.write("This is line 2.\n")
file.write("And this is line 3.\n")
file.close()                        # always close!
print("File created successfully!")

      
Output
File created successfully!


      
Reading a file

      
python
file = open("sample.txt", "r")
content = file.read()
print(content)
file.close()

      
Output
Hello, this is line 1.
This is line 2.
And this is line 3.


      
File modes

      

        
ModeMeaningIf file existsIf file missing

        
"r"ReadOpens for readingRaises FileNotFoundError

        
"w"WriteOverwrites the file — data is lost!Creates new file

        
"a"AppendAdds to end (data preserved)Creates new file

      

      

        
⚠️ "w" mode is destructive

        Opening a file in "w" mode erases all existing content before writing. If you want to keep the original content and add more, use "a" (append) mode instead.
      


      
Reading line by line (memory-efficient)

      
python
file = open("sample.txt", "r")
for line in file:
    print(line.strip())  # .strip() removes the trailing \n
file.close()

      
Looping over a file gives one line at a time. Unlike .read(), this doesn't load the entire file into memory — essential for large transaction logs.


      
Appending to a file

      
python
file = open("sample.txt", "a")
file.write("This line was appended later.\n")
file.close()

      

        
⚠️ The danger of manual close()

        What if your code crashes between open() and close()? The file stays open — data may not be saved, or the file may be locked. The safe solution is the with statement.

8Exception handling

      
Common exception types

      
When Python encounters an error it recognizes, it raises a specifically-named exception. If unhandled, execution stops immediately — and all remaining code is skipped.


      

        
ZeroDivisionError
Dividing by zero: 1 / 0

        
ValueError
Bad conversion: float('abc')

        
NameError
Undefined variable: print(x) before assigning x

        
FileNotFoundError
Opening a non-existent file in "r" mode

        
AttributeError
Calling a method that doesn't exist: "hello".sort()

        
ModuleNotFoundError
Importing a module that isn't installed

      


      
The critical behaviour: exceptions stop everything

      
python
def something():
    1 / 0
    print("A")   # never reached

something()
print("B")        # never reached either

      
Error
ZeroDivisionError: division by zero
Neither "A" nor "B" is printed. The program crashes completely. This is exactly the problem with our transaction CSV: one bad row kills the entire pipeline.


      

        
Without try/except vs with try/except

        

          

            
✗ Without try/except — crashes

            
Line 1: runs fine
Line 2: runs fine
Line 3: EXCEPTION!
Line 4: never runs ← skipped
Line 5: never runs ← skipped

          

          

            
✓ With try/except — recovers

            
try:
  Line 1: runs fine
  Line 2: runs fine
  Line 3: EXCEPTION!
except:
  Handle the error
Line 4: runs normally ✓
Line 5: runs normally ✓

          

        

      

    


    
    

      
9Exception handling

      
try / except

      
Code that might fail goes inside try. The recovery plan goes inside except. If an exception occurs, Python immediately jumps to except — the rest of try is skipped.


      
python — basic
try:
    1 / 0
    5 + 4   # this line never runs
except:
    print("Why are you dividing by zero?")

      
Output
Why are you dividing by zero?


      
Getting the exception message with except Exception as exp

      
python — loop continues even after exceptions
l1 = [2, 0, "hello", None]

for e in l1:
    try:
        print(f"Current element - {e}")
        result = 5 / int(e)
        print(f"Result - {result}")
    except Exception as exp:
        print(f"Exception - {exp}")
    print("-" * 50)

print("Execution Successful!")

      
Output

--------------------------------------------------

--------------------------------------------------
Execution Successful!

      
The loop continues even after exceptions. Every element gets processed. "Execution Successful!" confirms the program completed normally — this is exactly what our transaction processor needs.

10Exception handling

      
Exception ordering: specific before general

      
Always put specific exceptions before general ones. Think of it like a funnel — narrow at the top, wide at the bottom. If you put the wide one at the top, nothing reaches the narrow ones below.


      

        
✓ Correct order (specific → general):

        
    except ZeroDivisionError:   ← catches only this type

        
    except ValueError:          ← catches only this type

        
    except Exception:           ← catches everything else

        

        
✗ Wrong order (general first):

        
    except Exception:           ← swallows everything!

        
    except ZeroDivisionError:   ← unreachable — never runs

      


      
python — different exceptions handled differently
l1 = [2, 0, "hello", None]

for e in l1:
    try:
        print(f"Current element - {e}")
        result = 5 / int(e)
        print(f"Result - {result}")
    except ZeroDivisionError as z:
        print(f"You divided by zero. Number is {e}!")
    except Exception as exp:
        print(f"Exception - {exp}")
    print("-" * 50)

print("Execution Successful!")

11Exception handling

      
The finally block

      
finally runs no matter what — whether an exception occurred or not. Its most common use is cleanup: closing files or releasing resources.


      
      

        
Step through try / except / finally

        

          

          

            
Execution path
—

            
Click "Step" to begin…

          

        

        

          
          
          
        

      


      
python — with exception
try:
    print("I am trying!")
    1 / 0              # exception here
except:
    print("Exception")
finally:
    print("FINALLY")   # always runs

      
Output

Exception

python — without exception: except is skipped, finally still runs
try:
    print("I am trying!")
    print(1 / 2)       # no exception

finally:
    print("FINALLY")   # still runs

0.5

💡 Why finally exists when you could just add code after try/except

        If return is used inside try or except, code after the block never runs — but finally still does. And if except itself raises another exception, code after the block is skipped — but finally still runs. It's the guaranteed safety net.
        

This is actually what the with statement implements internally — with open(...) adds a finally block that calls file.close().

raise and custom exceptions

      
So far, Python has been raising exceptions for us. Sometimes you want to raise one deliberately — to pull the fire alarm when you detect a problem.


      
python — raise with a message
raise Exception("This password is incorrect!")
# → Exception: This password is incorrect!

Custom exception classes

      
python
class MyCustomException(Exception):
    def __init__(self, message):
        super().__init__(message)

name = "Sach"
try:
    if len(name) < 5:
        raise MyCustomException("Length of name must be >4 characters")
    else:
        print("Name:", name)

except MyCustomException as e:
    print(e)

Create your own exception types by inheriting from Exception. In large projects, domain-specific exceptions like InvalidTransactionError or InsufficientFundsError make error logs far more informative than generic exceptions.

Step 1: Read and process (try/except inside the loop)

      

        
💡 Placement of try/except is critical

        The try/except must go inside the loop, not around it. Outside the loop means one bad row kills everything. Inside the loop means each row gets its own chance.
      

      
python
import csv
import math

clean_transactions = []
error_log = []

with open("transactions.csv", "r") as file:
    reader = csv.reader(file)
    header = next(reader)   # skip header

    for row in reader:
        try:
            txn_id     = row[0]
            account    = row[1]
            amount     = float(row[2])       # raises ValueError on '' or 'BAD_DATA'
            fee_percent = float(row[3])      # raises ValueError on 'abc'

            fee        = amount * fee_percent / 100
            net_amount = amount - fee

            # Round using math module
            fee        = math.floor(fee * 100) / 100
            net_amount = math.ceil(net_amount * 100) / 100

            clean_transactions.append([txn_id, account, amount, fee_percent, fee, net_amount])
            print(f"  [OK] {txn_id}: amount={amount}, fee={fee}, net={net_amount}")

        except ValueError as ve:
            error_log.append([txn_id, str(ve)])
            print(f"  [ERROR] {txn_id}: ValueError - {ve}")

        except ZeroDivisionError as ze:
            error_log.append([txn_id, str(ze)])
            print(f"  [ERROR] {txn_id}: ZeroDivisionError - {ze}")

        except Exception as e:
            error_log.append([row, str(e)])
            print(f"  [ERROR] Row {row}: {e}")

print(f"\nProcessed: {len(clean_transactions)} clean, {len(error_log)} errors")
