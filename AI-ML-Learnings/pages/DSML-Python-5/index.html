1The hook

Fraud Detection Flag System

You're a Data Analyst at a bank. A batch of transaction records arrives daily — each with a transaction ID, account number, and amount. Here's the sample batch:

2Tuples

Why tuples?

Can we always trust that data in a list stays unchanged?

python
a = [1, 2, 3, 4, 5]
a[0] = 10
a
Output
[10, 2, 3, 4, 5]

Lists are mutable — any element can be changed at any time. That's useful, but sometimes dangerous. Now with parentheses:

python
a = (1, 2, 3, 4, 5)
a[0] = 10
Error
TypeError: 'tuple' object does not support item assignment

A tuple is like a list, but immutable. Once created, its elements cannot be changed.

Creating, indexing, and slicing

      
Creating a tuple uses parentheses () instead of square brackets []. Indexing and slicing work identically to lists — same rules, different brackets.

      
python
a = (1, 2, 3, 4, 5, 6, 7, 8, 9, 0)


      
      
Positive and negative indexing — same rules as lists and strings. The element at index i is the same as the element at negative index i − 10.


      
Slicing:

      
python
a[2:8]

      
Output
(3, 4, 5, 6, 7, 8)
Slicing a tuple gives you a tuple (parentheses, not brackets).

      
python
a[-1:-8]

      
Output
()
Empty — default step is +1 (left → right), but −1 to −8 goes leftward. Fix: a[-1:-8:-1].

4Tuples

      
The single-element gotcha

      
This catches almost everyone the first time. It's also a common interview question.

      
python
t = ()
type(t)  # tuple - empty parens = empty tuple

      
Output
<class 'tuple'>

      
python
# This will NOT be a tuple
t = (45)
type(t)

      
Output
<class 'int'>
Python sees (45) as just the number 45 in parentheses, like math: (2 + 3) is just 5, not a tuple.

      

        
⚠️ The fix — add a trailing comma

        
python
# This WILL be a tuple
t = (45,)
print(type(t))  # <class 'tuple'>

t = 45,  # without parentheses - also a tuple!
print(type(t))  # <class 'tuple'>

        The comma is what makes it a tuple, not the parentheses.

5Tuples

      
Packing, unpacking, and multiple returns

      
Packing creates a tuple; unpacking extracts the values into separate variables:

      
python
a = (1, 2, 3)    # packing
x, y, z = a      # unpacking
print(x, y, z)

      
Output
1 2 3

      
The number of variables on the left must match the number of elements. Mismatch → ValueError: too many values to unpack or not enough values to unpack.


      
Python uses tuples internally for multiple return values

      
python
def foo():
    return 200, 300, 400

bar = foo()
print(bar)

      
Output
(200, 300, 400)
When a function returns multiple comma-separated values, Python automatically packs them into a tuple. That's why unpacking works so naturally with function returns — this is what Lecture 3's min_and_max() was doing internally.

6Sets

      
Sets: introduction

      
We can store transactions as tuples. But how do we find duplicate IDs efficiently? We could loop and compare every pair — slow and tedious. What if a data structure automatically eliminated duplicates? That's exactly what sets do.

      
A set is a collection of unique elements, using curly braces {}:

      
python
s = {1, 2, 3, 4, 5, 5, 5, 5, 4, 4, 4, 7, 7, 7}
s

      
Output
{1, 2, 3, 4, 5, 7}
14 values in, 6 out. Duplicates removed automatically.

      

        
⚠️ Sets are unordered — no indexing

        s[0] → TypeError: 'set' object is not subscriptable. There is no "first" or "second" element in a set.
      

      

        
💡 Creating an empty set

        You must use set(), not {}. Using {} creates an empty dictionary.
        
s = set()
print(s)  # set()

      

      
Sets can store strings, tuples, integers, floats, and booleans. They cannot store lists, other sets, or dictionaries — because those are mutable, and set elements must be hashable (immutable). Same rule applies to dictionary keys.


      
      

        
List vs Tuple vs Set — the most important comparison in today's lecture

        
      


      

        
🌉 SQL bridge

        set(column_values) in Python is like SELECT DISTINCT column FROM table in SQL. Uniqueness is enforced automatically.

8Sets

      
Set operations

      
Sets support mathematical operations directly useful for data analysis. Given:

      
python
s1 = {2, 3, 4, 5}
s2 = {1, 3, 4, 6, 7, 8}


      
Intersection — elements common to both

      
python
s1.intersection(s2)  # or: s1 & s2

      
Output
{3, 4}


      
Union — all elements from both (no duplicates)

      
      
      
Union: all elements from either set — duplicates collapsed automatically.

      
python
s1.union(s2)  # or: s1 | s2

      
Output
{1, 2, 3, 4, 5, 6, 7, 8}


      
Difference — elements in s1 not in s2

      
python
s1.difference(s2)  # or: s1 - s2

      
Output
{2, 5}
s1 - s2 is NOT the same as s2 - s1. Difference is directional.


      
Symmetric difference — everything in the union except the overlap

      
      
      
Symmetric difference: all elements that are in either set, but not in both. s1 △ s2 = (s1 − s2) ∪ (s2 − s1).

      
python
s1.symmetric_difference(s2)  # or: s1 ^ s2

      
Output
{1, 2, 5, 6, 7, 8}

🌉 SQL + fraud tie-in

        Python set operation → SQL equivalent: s1 & s2 → INTERSECT · s1 | s2 → UNION · s1 - s2 → EXCEPT / NOT IN.
        

In our fraud system: if all_ids is the set of all transaction IDs and duplicate_ids is the set of IDs that appeared more than once, then all_ids - duplicate_ids gives the clean transactions.

9Sets

      
Binary string problem & subset check

      
Problem: given a string, determine whether it contains only '0' and '1' characters (a binary number).

      
python — loop approach
def check_binary(string):
    for i in string:
        if not (i == "0" or i == "1"):
            return "Not Binary!"
    return "Binary!"

print(check_binary("adasfafasfas"))
print(check_binary("01010101010"))
print(check_binary("11111"))

      
Output
Not Binary!
Binary!
Binary!

      
This works, but there's a more elegant approach using sets:

      
python — set subset approach
def check_binary_cool(string):
    s = set(string)
    if s <= {"0", "1"}:  # is s a subset of {"0", "1"}?
        return "Binary!"
    return "Not Binary!"

print(check_binary_cool("adasfafasfas"))
print(check_binary_cool("01010101010"))
print(check_binary_cool("11111"))

      
Output
Not Binary!
Binary!
Binary!

      

        
💡 Key insight

        set(string) extracts all unique characters. The <= operator checks if one set is a subset of another. If all unique characters in the string are within {"0", "1"}, the string is binary. One-line check instead of a loop — sets turn a multi-step problem into a direct comparison.

10Dictionaries

      
Dictionaries: motivation

      
Sets solved duplicate detection. But the bank needs a report: for each account, how many transactions were flagged and what was the total? We need something that maps each account number to its summary — that's a dictionary.


      

        
📖
Language dictionary
"random" → "something which is not well defined"

        
=

        
🗂️
Python dict
key → value. Access by name, not by position.

      


      
Why not just use nested tuples? To access Mumbai's population from a list of tuples, you need to know it's at index 1:

      
python
city_wise_data_tup = [("Delhi", 450), ("Mumbai", 400), ("Bengaluru", 325)]
city_wise_data_tup[1]  # have to know the index

      
Output
('Mumbai', 400)
You must remember the position — and you get back the whole tuple, not just the value.

      
With a dictionary, access by key, not position:

      
python
city_wise_data = {
    "Delhi": 450,
    "Mumbai": 400,
    "Bengaluru": 325
}
city_wise_data["Bengaluru"]

      
Output
325


      
      
      
Dictionary structure — access by key name, not by position number. The mental model shift: lists are "access by position," dictionaries are "access by name."


      

        
🌉 SQL bridge

        dict["key"] → SELECT value FROM table WHERE key = 'key'

        dict[key] = value → INSERT or UPDATE

        Key-value pairs → column name and column value in a row.
      

    


    
    

      
11Dictionaries

      
Creating, accessing, and .get()

      
Direct bracket access crashes with KeyError when the key doesn't exist. .get() returns None instead:

      
python
random = {"a": 1, "b": 2, "c": 3}

print(random.get("a"))  # 1
print(random.get("d"))  # None - safe
print(random["d"])      # KeyError - crash!

      
Output
1
None
Error (third line)
KeyError: 'd'

      
.get() also accepts a default value as a second argument — returned instead of None when the key is missing:

      
python
data = {"a": 10, "b": 20, "c": 30}
result = data.get("d", 0)  # missing key → return 0
print(result)

      
Output
0

      

        
💡 Key insight — the two-argument .get()

        data.get(key, 0) is extremely useful for building frequency counters or accumulators: count = data.get(item, 0) + 1. This is the exact pattern we'll use in the capstone to accumulate flagged amounts per account.

15Dictionaries

      
Sorting by keys and values

      
Python dicts maintain insertion order (Python 3.7+), but sometimes you need a different order.

      
python
my_dict = {'banana': 3, 'apple': 2, 'orange': 5, 'grape': 1}

# Sorting by keys
sorted_keys = dict(sorted(my_dict.items()))
print("Sorted by keys:", sorted_keys)

      
Output
Sorted by keys: {'apple': 2, 'banana': 3, 'grape': 1, 'orange': 5}
.items() → list of tuples → sorted() sorts by first element (the key) → dict() converts back.

      
Sorting by values needs a lambda to tell sorted() which element to sort by:

      
python — recall from Lecture 3
# Regular function and lambda equivalent — same result
def get_value(item): return item[1]
get_value_lambda = lambda item: item[1]

print(get_value(("banana", 3)))       # 3
print(get_value_lambda(("banana", 3)))  # 3

      
python
sorted_vals = dict(sorted(my_dict.items(), key=lambda item: item[1]))
print("Sorted by values:", sorted_vals)

      
Output
Sorted by values: {'grape': 1, 'apple': 2, 'banana': 3, 'orange': 5}
lambda item: item[1] extracts the value (second element of each tuple) for the sort key.

16Putting it together

      
Capstone: Fraud Detection Flag System

      
All three tools, solving the problem introduced at the start.

      

        
1TuplesTransaction recordsImmutable — cannot be tampered with after creation

        
2Sets (seen + duplicate)Detect duplicatesseen set + duplicate set pattern

        
3Set differenceSeparate clean from flaggedall_ids − duplicate_ids

        
4DictionaryAccount summaryaccount → {flag_count, total_amount}

        
5.get(key, default)Safe accumulationInitialize missing keys to 0

        
6.items() + f-stringsPrint the reportkey, value unpacking

      


      
python
# The transaction data — each record is a tuple (immutable)
transactions = [
    ("TXN001", "ACC101", 5000),
    ("TXN002", "ACC102", 12000),
    ("TXN003", "ACC101", 7000),
    ("TXN001", "ACC101", 5000),   # <-- duplicate
    ("TXN004", "ACC103", 3000),
    ("TXN002", "ACC102", 12000),  # <-- duplicate
]

# Step 1: Find duplicate transaction IDs using sets
seen_ids = set()
duplicate_ids = set()
for txn_id, account, amount in transactions:
    if txn_id in seen_ids:
        duplicate_ids.add(txn_id)
    else:
        seen_ids.add(txn_id)

print("Duplicate (flagged) IDs:", duplicate_ids)

# Step 2: Separate flagged from clean IDs using set difference
clean_ids = seen_ids - duplicate_ids
print("Clean transaction IDs:", clean_ids)

# Step 3: Build account summary dictionary for flagged transactions
account_summary = {}
for txn_id, account, amount in transactions:
    if txn_id in duplicate_ids:
        if account not in account_summary:
            account_summary[account] = {"flag_count": 0, "total_amount": 0}
        account_summary[account]["flag_count"] += 1
        account_summary[account]["total_amount"] += amount

# Step 4: Print the fraud report
print("
" + "=" * 45)
print(" FRAUD DETECTION REPORT")
print("=" * 45)
for account, summary in account_summary.items():
    print(f"Account: {account}")
    print(f"  Flagged transactions: {summary['flag_count']}")
    print(f"  Total flagged amount: Rs.{summary['total_amount']}")
    print("-" * 45)

      
Output
Duplicate (flagged) IDs: {'TXN002', 'TXN001'}
Clean transaction IDs: {'TXN004', 'TXN003'}

 FRAUD DETECTION REPORT
=============================================
Account: ACC101
  Flagged transactions: 2
  Total flagged amount: Rs.10000
---------------------------------------------
Account: ACC102
  Flagged transactions: 2
  Total flagged amount: Rs.24000
