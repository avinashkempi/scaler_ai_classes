It's parent-teacher day at Greenfield High. Mr. Arjun, the class teacher, needs to analyze the whole class's subject scores tonight. He's stored them as a plain Python list — but the moment he tries any math, Python throws errors or gives nonsense.

Mr. Arjun calls his student Riya for help. She shows him why a list fails — and fixes everything with NumPy.

# Mr. Arjun's data — 8 students' Maths scores
maths = [78, 45, 92, 34, 67, 88, 56, 91]

# Try: add 5 bonus marks to everyone
maths + 5        # ❌ TypeError: can only concatenate list to list

# Try: double all scores
maths * 2        # 😬 [78,45,92,...,78,45,92,...] — repeats the list!

The list treats +5 as "append the number 5" (which fails) and *2 as "duplicate the list" — both completely wrong for math. The only workaround is a loop, which is slow and verbose.

# Old way — loop over every student
bonuses = []
for m in maths:
    bonuses.append(m + 5)
# Works... but slow at scale & ugly every time

01
What is NumPy?

NumPy is Python's core numerical computing library. Its star feature is the ndarray — a typed, contiguous block of numbers in memory that makes math on entire datasets as simple as math on a single variable.

import numpy as np

# Convert the Python list to a NumPy array
marks = np.array(maths)
print(marks)
▶ OUTPUT
array([78, 45, 92, 34, 67, 88, 56, 91])

Now every arithmetic operation works element-wise — no loops needed:

marks + 5   # [83, 50, 97, 39, 72, 93, 61, 96]  ✅ bonus marks
marks * 2   # [156, 90, 184, ...]               ✅ double (not repeat!)
02
Creating Arrays — 5 Ways

NumPy gives you five array constructors. Each solves a different problem:

import numpy as np

# 1. From a list — convert existing data
marks = np.array([78, 45, 92, 34, 67, 88, 56, 91])

# 2. arange — evenly-spaced integers (stop is EXCLUDED)
roll_numbers = np.arange(1, 9)         # [1 2 3 4 5 6 7 8]

# 3. zeros — placeholder / initialise blank
remedial = np.zeros(8)                # [0. 0. 0. 0. 0. 0. 0. 0.]

# 4. ones — flag / binary initialise
attendance = np.ones(8, dtype=int)   # [1 1 1 1 1 1 1 1]

# 5. linspace — n evenly-spaced floats (stop IS included)
grade_bands = np.linspace(0, 100, 5) # [  0.  25.  50.  75. 100.]

03
Lists vs Arrays — Vectorization

The same operator does completely different things depending on whether you're using a list or a NumPy array:

OperationPython ListNumPy Array
+ 5 ❌ TypeError ✅ adds 5 to every element
* 2 😬 duplicates the list ✅ doubles every element
+ another_list concatenates ✅ element-wise addition
> 60 ❌ TypeError ✅ boolean mask per element
Math in bulk need a for-loop ✅ one expression

This is vectorization — applying an operation to every element at once, with no Python loop in your code (the loop runs in optimized C under the hood).

⚠️
Type Promotion — the silent gotcha

NumPy silently upgrades the whole array to the "highest" type to fit all values: bool → int → float → string. Put a single string in an int array and every number becomes a string.

Why NumPy is Faster

The speed difference is dramatic. For 10 lakh marks (1 million values), Python loop takes ~52 ms while NumPy takes ~623 µs — about 85× faster.

# Timing comparison on 10 lakh (1M) values

%%timeit

05
Dimensions, Shape & Size

Three attributes tell you everything about an array's structure:

export = np.array(['78', '45', '92', ...])  # 24 string elements

export.ndim   # 1   → 1-dimensional (a single row)
export.shape  # (24,) → 24 elements, no second axis
export.size   # 24  → total element count
📐
shape = (rows, cols)

For a 2D array (8,3): 8 rows, 3 columns. For 1D: (24,) — the trailing comma means "1 dimension".

🔢
size = rows × cols

Always the total element count. For (8,3): size = 24. For (24,): size = 24.

# 2D example — two students, three subjects
two_students = np.array([[78,45,92],[34,67,88]])
two_students.shape   # (2, 3)
two_students.ndim    # 2
two_students.size    # 6
🗄️ SQL Analogy

shape ↔ table dimensions (rows, cols). ndim ↔ always 2 for a table (rows + columns). size ↔ SELECT COUNT(*) FROM table × number of columns.

06
dtype & astype — Type Conversion

NumPy's silent type promotion can bite you. The export array came from a CSV where every value was read as a string:

export.dtype       # dtype('<U2')  → Unicode string, max 2 chars

# Trying to add: string + string = concatenation!
export + "5"       # ['785', '455', '925', ...]  😱 WRONG
# '78' + '5' = '785' — the number 78 became 785 !
🚨
Silent wrong answer — no error, just garbage

Python doesn't complain when you add strings — it concatenates them. '78' + '5' = '785' looks like 783 at a glance but is completely wrong.

Fix: convert to int with astype:

marks_all = export.astype(int)   # '78' → 78  ✅
marks_all.dtype                   # dtype('int64')

# ⚠️ Gotcha: astype(int) TRUNCATES floats, not rounds!
np.array(['3.7']).astype(int)  # Error — go via float first
np.array(['3.7']).astype(float).astype(int)  # 3 (truncated!)

07
1D Indexing & Slicing

Once you have a valid array, you can pull out any element or range in one expression.

marks = np.array([78, 45, 92, 34, 67, 88, 56, 91])
#  idx:   0    1    2    3    4    5    6    7
#  neg:  -8   -7   -6   -5   -4   -3   -2   -1

marks[0]           # 78  — first student
marks[-1]          # 91  — last student

# Fancy indexing — pick multiple by position (double brackets!)
marks[[2, 5, 7]]  # [92 88 91] — top 3 students

# Slicing — start:stop (stop excluded)
marks[2:6]         # [92 34 67 88] — students 3–6
marks[::2]         # [78 92 67 56] — every other student
marks[::-1]        # [91 56 88 67 34 92 45 78] — reverse
⚠️
Fancy indexing needs double brackets [[]]

marks[2,5,7] would try to index a 3D array. marks[[2,5,7]] passes a list of indices — the outer [] is the index operator, the inner is a Python list.

08
2D Arrays — reshape, Indexing, Slicing, Transpose

The 24-element string array becomes an 8×3 marks table with one reshape:

marks_all = export.astype(int)         # shape (24,)
report    = marks_all.reshape(8, 3)    # shape (8, 3)
# 8 students × 3 subjects = 24 total ✓

# Use -1 to let NumPy compute one dimension automatically
marks_all.reshape(8, -1)   # same as (8, 3)
marks_all.reshape(-1, 3)   # same as (8, 3)

2D Indexing

report[4, 1]     # row 4, col 1 — preferred single-step access
report[4][1]    # same result — but two separate index operations
🚨
Critical Gotcha — [:, 1] vs [:][1]

report[:, 1] → all rows, column 1 — the entire second-subject column ✅
report[:][1] → report[:] returns the whole array, then [1] picks row 1 — completely different result ❌

2D Slicing

report[:4, :2]   # first 4 students, first 2 subjects
report[:, 1]    # ALL students' second subject scores (column slice)
report[0, :]    # student 1's all subjects (row slice)

Transpose

report.T         # shape (3, 8) — subjects become rows, students become cols
report.T.shape   # (3, 8)
