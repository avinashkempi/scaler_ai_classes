How a used-car marketplace teaches a straight line to guess a fair price — encoding, splitting, fitting, and scoring, explained end to end.

Arjun has just joined the pricing team at a used-car marketplace. On his first day, his manager hands him a spreadsheet of past listings — make, model, age, kilometers driven, fuel type, and the price each car eventually sold for — and asks him to stop pricing cars by gut feeling. What follows is the same sequence of decisions anyone building a regression model has to make, told through Arjun's spreadsheet.

01

What are we even predicting?

Before writing a line of code, Arjun has to name the problem correctly. His spreadsheet holds a car's make, model, age, kilometers driven, and fuel type — and one more column: the price it eventually sold for. His manager wants that price predicted from everything else.

Five columns of information go in; one continuous number comes out.

Quiz

What kind of problem is this?

We're predicting a continuous numeric value — the selling price — rather than assigning a data point to one of a fixed set of categories, or grouping unlabeled data together. That makes it a regression problem.

Two of those columns are trouble waiting to happen: make and model are text — "Maruti", "Hyundai", "Honda" — and a model that only does arithmetic can't learn from words directly. That's Arjun's next problem.

02

Getting the data ready

Arjun can't feed the word "Maruti" into a mathematical model. He also notices his numeric columns aren't on the same footing — a car's age is a small number, its kilometers driven is not. Both problems need to be solved before any training happens.

Turning categories into numbers

There are dozens of distinct makes in the data, and thousands of distinct models. One-hot encoding would create a column for every single one of them — unmanageable at that scale. Label encoding would assign each category an arbitrary number, implying an order between "Maruti" and "Hyundai" that doesn't actually exist. Arjun reaches for a third option: target mean encoding.

Analogy

Think of it as a resale-reputation score. If cars from a certain make have historically sold for a high average price, that make gets a high score. If another make historically sells for less, it gets a lower one.

encode(category) = mean of selling_price for all rows in that category

Here, category is a single value from the make or model column — say, "Maruti" — and the encoded number simply replaces that text label with the average selling price seen for that category in the data.

Illustrative example — the exact numbers come from each make's rows in the training data.

Quiz

How should we handle the large number of categories in make and model?

One-hot encoding would create one column per category — with hundreds of models that becomes unmanageable. Label encoding assigns arbitrary numbers that imply an order that doesn't exist. Target mean encoding instead replaces each category with a number that's directly meaningful: its average selling price.

Putting every number on the same footing

Arjun then notices something else: km_driven is measured in the tens of thousands, while age is measured in single or double digits.

Analogy

Imagine comparing a person's height in centimeters to their weight in kilograms, and trying to say which one "matters more" just by looking at the raw numbers. The units aren't comparable, so the bigger number would unfairly dominate. Scaling brings every column onto the same footing before comparison.

Min-max scaling squeezes every column into the same range:

x' = x − xminxmax − xmin
  • x — the original value in a column
  • x_min, x_max — the smallest and largest values that column takes across the data
  • x' — the rescaled value, always between 0 and 1

Illustrative example — two differently-scaled columns land on the same 0–1 range after min-max scaling.

Min-max scaling is one option among several worth trying on a given dataset.

03

Splitting the data the right way

Arjun now has clean, numeric data. But before he trains anything, he needs a way to check his work honestly — and a common language to describe his data.

A shared vocabulary

X is everything used to predict with; y is the single column being predicted.

The real goal: generalization

Arjun's manager won't judge the model on cars it has already seen. She'll judge it on brand-new cars arriving next week. That's the real goal of machine learning — performing well on data the model has never encountered, not simply memorizing the data it was trained on.

To measure this honestly, Arjun holds back a portion of his data that the model never sees during training, and uses it only at the very end to test performance. We'll divide the data into a 70:30 split — 70 percent for training, 30 percent for testing.

Analogy

Think of the training set as practice questions and the test set as the exam. If exam questions leak into your practice material beforehand, your score stops meaning anything — it no longer tells you how you'd perform on a genuinely new problem. Information from the test set must never influence how the training set is prepared.

Quiz

When should you split your data into training and testing sets?

Preprocessing steps like encoding and scaling calculate statistics — averages, minimums — from the data. Calculate them before splitting, and information from the test set quietly leaks into training, a problem known as data leakage. Splitting first keeps the test set genuinely unseen.

Encoding and scaling without leakage

For the training rows, Arjun replaces each category with its category-wise average selling price — calculated only from training rows. For the test rows, he reuses those exact training averages; he never recalculates them from the test data. Reusing the training set's own statistics is what keeps the test set honest, the same way a student shouldn't see the exam's answer key while practicing.

A wrinkle: a model of car might appear in the test data but never in training. There's no training average to map it to, so that value goes missing — Arjun fills it with the global mean, the average selling price across the entire training set, the most reasonable guess available with no category-specific information. Scaling follows the same rule: fit only on the training data, then apply those same statistics to the test data.

What's left is one output to predict, selling_price, from seventeen input features — everything else in the sheet.

04

The mathematics of a straight line

With clean, well-split data in hand, Arjun is ready to describe the relationship between a car's features and its price. Start with the simplest possible version, using just one feature.

One feature: univariate regression

Suppose Arjun uses only age to predict selling_price. He's looking for the straight line that best fits the relationship between the two.

ŷ = b₀ + b₁x
  • x — the input feature, e.g. the car's age
  • ŷ — the predicted selling price
  • b₀ — the intercept: the predicted price when x is zero
  • b₁ — the slope: how much the predicted price changes for every one-unit increase in x
Analogy

Think of a taxi fare. There's a base fare you pay just for getting in — that's the intercept, b₀. Then there's a rate charged per kilometer travelled — that's the slope, b₁. The total fare is the base fare plus the rate times distance, exactly the shape of our equation.

Moving b₀ shifts the whole line up or down; changing b₁ tilts it.

Training the model simply means finding the values of b₀ and b₁ that make this line fit the data as closely as possible.

Quiz

How many parameters do you need to estimate in a simple linear regression with one independent variable?

A simple regression line, ŷ = b₀ + b₁x, has exactly two unknowns to estimate — the intercept b₀ and the slope b₁.

Many features: multivariate regression

Arjun's manager wants the price predicted from all seventeen features, not just one. The same idea extends naturally.

ŷ = b₀ + b₁x₁ + b₂x₂ + ⋯ + bdxd
  • x₁, x₂, … x_d — the individual input features, e.g. age, kilometers driven, make
  • d — the total number of features
  • b₁ … b_d — one coefficient per feature, describing how much it pulls the predicted price up or down
  • b₀ — still the intercept: the predicted price when every feature is zero
Analogy

Think of the price as a recipe. Each ingredient — age, mileage, brand reputation — contributes its own amount to the final dish. Each coefficient is like the "quantity" of that ingredient's influence: some contribute a lot, some very little, and some might even subtract from the total.

With more than one feature, the "line" becomes a flat hyperplane through a higher-dimensional space. Fitting it needs one coefficient per feature, plus one intercept — d + 1 parameters in total.

05

Teaching the model with code

It's time to let the computer search for the best b₀ and b₁ values itself, rather than guessing them by hand. Arjun starts with a single feature.

One feature
from sklearn.linear_model import LinearRegression

model = LinearRegression()
model.fit(X1_train, y_train)

model.coef_       # the fitted slope, b1
model.intercept_  # the fitted intercept, b0

Plotting the model's predictions against the actual test prices shows the points lining up along a straight line — exactly the shape described by b₀ + b₁x. Now Arjun generalizes to all seventeen features at once:

All features
model = LinearRegression()
model.fit(X_train, y_train)

model.coef_       # one coefficient per feature
model.intercept_  # a single intercept

The model now has one coefficient per feature, plus a single intercept — exactly the d + 1 parameters the maths predicted.

06

Is the model any good?

Arjun's model now produces predictions. But a prediction on its own says nothing about quality — he needs a way to measure how far off those predictions are.

Mean Squared Error (MSE)

MSE = 1nnΣi=1(yi − ŷi)²
  • y_i — the actual selling price of the i-th car
  • ŷ_i — the model's predicted price for that same car
  • n — the total number of cars evaluated
  • the difference (y_i − ŷ_i) is called the residual, or error, for that car
Analogy

Think of a game of darts. Each throw that lands off the bullseye is an error. Squaring that error before averaging punishes wild misses far more harshly than near misses — a model with a few very bad predictions will have a much higher MSE than one that's consistently just slightly off, even if their average raw error looks similar.

Mean Absolute Error (MAE)

MAE = 1nnΣi=1|yi − ŷi|

The symbols mean the same as above. The only difference from MSE is that MAE takes the absolute value of the error instead of squaring it, so every miss counts in direct proportion to its size, without punishing large misses extra harshly.

Why not just sum the errors?

Positive and negative errors can cancel each other out:

(+3) + (+4) + (−7) = 0

A model with large errors could appear to have zero error. We need a metric that prevents this cancellation — which is exactly what squaring (MSE) or taking the absolute value (MAE) does.

Three real mistakes, summing to a deceptive zero.

R-squared, the coefficient of determination

R² = 1 − SSresSStot
  • SS_res — the sum of squared residuals, the same total error behind MSE
  • SS_tot — the total variance in the actual data, regardless of any model
  • R² — a single score, typically between 0 and 1, describing what fraction of that variance the model explains
Analogy

Think of it as a report-card percentage for how much of the story the model has learned. A score of 0.85 means the model accounts for 85 percent of why prices differ from one car to another — the remaining 15 percent is variation it hasn't captured, perhaps from features not in the data, like a car's condition or a seller's negotiating skill.

Quiz

In a multiple linear regression with five features, R² comes out to 0.85. What does that mean?

R² measures the proportion of variance in the target that the model accounts for. It isn't an accuracy score, and it says nothing about confidence or the probability of being correct — it purely describes how much of the spread in the actual values lines up with what the model captures.

Checking generalization

Scikit-learn's .score() for LinearRegression reports R² by default. Arjun runs it on both the training set and the held-out test set, and compares the two.

Training and test scores landing close together tells Arjun the model is generalizing — not simply memorizing the training data.

Key takeaways

Predicting a continuous price from a car's features is a regression problem, not classification or clustering.

Categorical columns like make and model can be turned into numbers with target mean encoding; numeric columns can be put on equal footing with min-max scaling.

Data must be split into training and test sets before any preprocessing, to avoid data leakage.

The linear regression equation extends naturally from one feature (ŷ = b₀ + b₁x) to many (ŷ = b₀ + b₁x₁ + … + b_dx_d).

Scikit-learn's LinearRegression fits the model and exposes its learned coefficients and intercept directly.

MSE, MAE, and R² each measure error differently — squared, absolute, and as a share of explained variance, respectively.
