2. The big idea: say what things are

Here is a case as the Class 2 program holds it, a dictionary:

A case as a dictionary
case = {"case_id": "C-1002", "order_status": "SHIPED", "promised_date": "2025-03-08"}

Look closely. Nothing stops "SHIPED" with one letter missing. The date is text, so nobody can ask how many days late it is. And if the model's answer is stored in the same dictionary, nobody can tell which values came from the file and which came from a guess.

Programmers call the fix making the shape explicit. A case gets named fields with types, a status can only be one of a few allowed values, and a model's answer gets its own type that cannot be mixed with facts.

5. Blueprints: classes and objects

A class is a blueprint. An object is one filled-in form made from it. The blueprint says which boxes exist. Each object holds one case's values. You write the blueprint once and make as many objects as you need.

A small class, written by hand
class Case:
    def __init__(self, case_id, order_status):
        self.case_id = case_id
        self.order_status = order_status

c = Case("C-1002", "SHIPPED")
print(c.order_status)     # SHIPPED

__init__ is the setup method. Python calls it when you write Case(...). self means "the object being built right now". Every field is typed out by hand, and that is where typos hide.

The shortcut you will use

Python can write the setup, the printout and the equality check from a short list of fields. This is a dataclass, marked with one line above the class:

The same record as a dataclass
from dataclasses import dataclass

@dataclass
class Case:
    case_id: str
    order_status: str
Two words you will see @dataclass is a decorator: a line placed above a class that adds behaviour to it. case_id: str is a type hint: a note that says the field should hold text. Python does not enforce hints when the program runs. Tools such as mypy read them before the program runs, and that is the point.

6. Facts, evidence, suggestions and decisions

The Workbench handles four kinds of thing that must never be mixed up. A fact is what the source file says. Evidence is what a person wrote in a note. A suggestion is what a model proposes. A decision is what the Python rules compute. Each one gets its own type, so the program and mypy keep them apart.

Why keep them apart?

A suggestion from a model can be wrong. If it sat in the same record as the order status, a wrong guess would look like a fact. So the model's answer gets its own type, and the rule that a suggestion can never be written back as a fact is checked by the program and by mypy.

The sentence to remember The rules decide whether a case needs attention. The model only suggests. A person confirms.

7. Tests, and one careful door to a model

Tests are promises

pytest runs every function whose name starts with test_, and tells you which promises still hold. A test is a short, named promise about the program. When someone breaks the promise, the test says which one. You will write your first one in class, with a single assert, which means "this must be true".

A test you will write in class
def test_two_identical_cases_are_equal():
    assert Case("C-1002", "SHIPPED") == Case("C-1002", "SHIPPED")

One rule about the model

Class 3 adds a model, and it is kept behind one thin door. Three rules hold from the first line of code:

The rules never import it

The model code sits in its own files. The rules file knows nothing about it, so the rules can be tested with no key and no internet.

The call is bounded

A hard limit on reply length, on waiting time and on retries. One request per flagged note.

A fallback is always there

If the key is missing or the call fails, the program uses a saved answer and says so in the output.

A key is a secret

It lives in a local .env file that Git ignores, never in code, never in chat and never in a terminal history.

Never paste a key into chat Chats, slides and terminal histories get copied and shared. A key that appears there must be replaced at once. Your instructor will show the safe way to set it up, and you can do the whole class without one.
