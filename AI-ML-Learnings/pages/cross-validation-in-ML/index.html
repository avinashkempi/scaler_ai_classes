Recap
Regularization Recap
5 min

In the last class, we saw that Ridge and Lasso regression add a penalty term to the loss function to control overfitting:

Ridge Loss = Σ(yᵢ − ŷᵢ)² + λ Σβⱼ²
Lasso Loss = Σ(yᵢ − ŷᵢ)² + λ Σ|βⱼ|

The hyperparameter λ (alpha) controls the strength of regularization:

λ valueEffectResult
Very small (≈0)Almost no penaltyOverfitting
OptimalBalanced penaltyBest generalization
Very largeCoefficients forced to ~0Underfitting
🧠 The Big Question
We know λ needs to be "just right" — but earlier we picked it by trying a few values against one train-test split. Is that reliable? That's exactly what today's class questions.
❓
Concept
Why Do We Need Cross Validation?
10 min

Suppose we split our data once into train and test sets, and select λ based on the test set performance. The problem: that one split is just one random sample of the data.

🤔 Ask Yourself
If you re-shuffled the data and split it again, would you get the same "best" λ? Try it — the answer is usually no.

This happens because:

  • Some splits may accidentally put "easy" points in the test set → inflated performance.
  • Some splits may put outliers/noisy points in test set → deflated performance.
  • Model selection based on one split is essentially tuning to the noise of that split — a subtle form of overfitting to the test set.
Split AttemptTrain R²Test R²Best λ Selected
Split 10.910.860.1
Split 20.900.791.0
Split 30.920.6810.0

Notice how the "optimal" λ changes depending on which random split we happened to use. We need a method that is less sensitive to any single split — that's Cross Validation.

K-Fold Cross Validation
12 min

Instead of a single split, K-Fold CV divides the dataset into K equal parts (folds). The model is trained K times, each time using a different fold as the test set and the remaining K−1 folds as the training set.

This is a 5-Fold CV (K=5). Each row is one "iteration" — after all K iterations, we average the scores:

CV Score = (1/K) × Σᵢ₌₁ᴷ Scoreᵢ

This average is a much more stable and reliable estimate of model performance than any single split, because every data point gets to be in the test set exactly once.

Code: K-Fold CV with scikit-learn

from sklearn.model_selection import KFold, cross_val_score
from sklearn.linear_model import Ridge

kf = KFold(n_splits=5, shuffle=True, random_state=42)
model = Ridge(alpha=1.0)

scores = cross_val_score(model, X, y, cv=kf, scoring='r2')
print("Fold scores:", scores)
print("Mean R²:", scores.mean())
print("Std Dev:", scores.std())
Output
Fold scores: [0.81 0.77 0.85 0.79 0.83] Mean R²: 0.81 Std Dev: 0.028

Note how much more informative this is: we not only get an average performance but also the variance across folds, telling us how stable the model is.

Core Concept
Grid Search CV
10 min

Now that we can reliably evaluate one hyperparameter value using K-Fold CV, we need a way to try multiple candidate values and pick the best one. That's GridSearchCV.

It works by:

  1. Defining a "grid" of hyperparameter values to try (e.g., λ = [0.001, 0.01, 0.1, 1, 10, 100])
  2. For each value, running full K-Fold CV and recording the average score
  3. Selecting the hyperparameter value with the best average CV score
  4. Refitting the model on the entire training data using that best value

Code: GridSearchCV for Ridge

from sklearn.model_selection import GridSearchCV
from sklearn.linear_model import Ridge

param_grid = {'alpha': [0.001, 0.01, 0.1, 1, 10, 100]}

grid = GridSearchCV(Ridge(), param_grid, cv=5, scoring='r2')
grid.fit(X_train, y_train)

print("Best alpha:", grid.best_params_)
print("Best CV score:", grid.best_score_)
Output
Best alpha: {'alpha': 1.0} Best CV score: 0.834
🤔 Think About It
If we have 6 alpha values and use 5-Fold CV, how many total model fits does GridSearchCV perform? (Answer: 6 × 5 = 30 fits!)

Hands-on
Tuning Ridge & Lasso with GridSearchCV
15 min

Let's tune both Ridge and Lasso on the same dataset and compare which regularization + λ combination performs best.

from sklearn.linear_model import Ridge, Lasso
from sklearn.model_selection import GridSearchCV

models = {
    'Ridge': (Ridge(), {'alpha': [0.01, 0.1, 1, 10, 100]}),
    'Lasso': (Lasso(max_iter=5000), {'alpha': [0.001, 0.01, 0.1, 1, 10]})
}

results = {}
for name, (model, grid_vals) in models.items():
    grid = GridSearchCV(model, grid_vals, cv=5, scoring='r2')
    grid.fit(X_train, y_train)
    results[name] = (grid.best_params_, grid.best_score_)

for name, (params, score) in results.items():
    print(f"{name}: best_params={params}, cv_score={score:.3f}")
Output
Ridge: best_params={'alpha': 1.0}, cv_score=0.834 Lasso: best_params={'alpha': 0.1}, cv_score=0.828

Both models perform comparably here — Ridge has a slight edge. In practice, we'd also inspect the coefficients Lasso zeroed out to understand feature selection benefits.

🧠 Key Takeaway
GridSearchCV doesn't just tune a single number — it lets us objectively compare entire modeling strategies (Ridge vs Lasso vs ElasticNet) on equal footing.

Housing Price Prediction

Let's apply everything so far to a housing price dataset with features like square footage, number of rooms, and location. We'll build a pipeline that scales features, then applies Ridge with tuned λ.

from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import Ridge
from sklearn.model_selection import GridSearchCV

🧠 Why Pipeline + GridSearchCV?

Polynomial Regression Pipeline
10 min

Sometimes the relationship between features and target isn't linear. We can add polynomial features and still use Ridge/Lasso to prevent overfitting from the added complexity.

ŷ = β₀ + β₁x + β₂x² + β₃x³ + ... + βₙxⁿ

from sklearn.preprocessing import PolynomialFeatures
from sklearn.pipeline import Pipeline

pipe = Pipeline([
    ('poly', PolynomialFeatures()),
    ('scaler', StandardScaler()),
    ('ridge', Ridge())
])

param_grid = {
    'poly__degree': [1, 2, 3, 4],
    'ridge__alpha': [0.1, 1, 10, 100]
}

grid = GridSearchCV(pipe, param_grid, cv=5, scoring='r2')
grid.fit(X_train, y_train)

print("Best params:", grid.best_params_)
Output
Best params: {'poly__degree': 2, 'ridge__alpha': 10}
🤔 Ask Yourself
Why do we tune poly__degree together with alpha instead of separately? Because a higher-degree polynomial needs a different optimal λ — the two hyperparameters interact!

Recursive Feature Elimination (RFE)
10 min

RFE is a feature selection technique that recursively removes the least important features and rebuilds the model, until the desired number of features remains.

  1. Train model on all features
  2. Rank features by importance (e.g., coefficient magnitude)
  3. Remove the least important feature
  4. Repeat until target number of features is reached
from sklearn.feature_selection import RFECV
from sklearn.linear_model import Ridge

estimator = Ridge(alpha=1.0)
selector = RFECV(estimator, step=1, cv=5, scoring='r2')
selector.fit(X_train, y_train)

print("Optimal number of features:", selector.n_features_)
print("Selected features:", X_train.columns[selector.support_].tolist())
Output
Optimal number of features: 7 Selected features: ['sqft_living', 'grade', 'lat', 'bathrooms', 'view', 'waterfront', 'yr_built']
🧠 RFECV vs RFE
Plain RFE requires you to specify the number of features to keep. RFECV uses Cross Validation internally to automatically find the optimal number of features — no guessing needed!

Discussion
Problems With Skipping Cross Validation
8 min

What happens when a model is built without proper cross-validated hyperparameter tuning?

IssueConsequence
Hyperparameter chosen on 1 splitModel may perform very differently on unseen data
Feature scaling fit on full datasetData leakage — test set statistics leak into training
Feature selection done before splittingSelection bias — test set influenced feature choice
No repeated evaluationCan't estimate model's variance/stability
🤔 Ask Yourself
If you scale your entire dataset with StandardScaler before splitting into train/test, have you leaked information? Yes — the mean and std used for scaling were computed using test data too.

This is why we always wrap preprocessing + model into a single Pipeline, and pass the whole pipeline into GridSearchCV/cross_val_score — ensuring every fold's preprocessing is learned only from that fold's training data.

✅
Quiz
Quick Check: Data Leakage
2 min
Which of the following correctly avoids data leakage during Cross Validation?
  • Scale the entire dataset once, then perform K-Fold CV
  • Perform feature selection using the full dataset, then run CV on selected features
  • Wrap scaling and modeling into a Pipeline, and pass the pipeline into cross_val_score/GridSearchCV
  • Fit the scaler on the test set, transform the train set
💡 Explanation
A Pipeline ensures that for every CV fold, the scaler (or any preprocessing step) is fit only on that fold's training portion, and then used to transform the corresponding test portion — no information from the test fold ever influences training.

Concept
Types of Cross Validation Schemes
12 min

K-Fold isn't the only CV strategy. Depending on your data, other schemes may be more appropriate:

K-Fold CV

Standard approach. Splits data into K equal folds. Good default choice for i.i.d. tabular data.

Stratified K-Fold

Preserves the class distribution in each fold. Essential for imbalanced classification problems.

Leave-One-Out (LOOCV)

Each fold has just 1 test sample. Very thorough but computationally expensive for large datasets.

TimeSeriesSplit

Respects temporal order — training always precedes testing chronologically. Used for time-series data.

SchemeBest Used ForComputational Cost
K-FoldGeneral i.i.d. tabular dataLow
Stratified K-FoldImbalanced classificationLow
LOOCVVery small datasetsVery High
TimeSeriesSplitSequential / time-dependent dataMedium
from sklearn.model_selection import StratifiedKFold, TimeSeriesSplit, LeaveOneOut

# Stratified — preserves class ratio in classification
skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)

# Time series — no shuffling, respects chronological order
tscv = TimeSeriesSplit(n_splits=5)

# Leave-one-out — extreme case where K = number of samples
loo = LeaveOneOut()

Hyperparameter Tuning Strategies
10 min

Grid Search checks every combination — thorough, but can be slow with many hyperparameters. Alternatives include:

MethodHow it WorksTrade-off
GridSearchCVTries every combination exhaustivelySlow but thorough
RandomizedSearchCVSamples random combinations from the gridFaster, may miss optimal combo
Bayesian OptimizationUses past results to intelligently choose next paramsEfficient, more complex to set up
from sklearn.model_selection import RandomizedSearchCV
import numpy as np

param_dist = {'alpha': np.logspace(-3, 3, 50)}

random_search = RandomizedSearchCV(
    Ridge(), param_distributions=param_dist,
    n_iter=15, cv=5, scoring='r2', random_state=42
)
random_search.fit(X_train, y_train)

print("Best alpha:", random_search.best_params_)
Output
Best alpha: {'alpha': 4.7148663634573895}
🧠 When to Use What
Use GridSearchCV for small, discrete grids. Use RandomizedSearchCV when the search space is large or continuous — it often finds near-optimal values much faster.

Quiz
Quick Check: CV Schemes
2 min
You're building a model to predict tomorrow's stock price using historical daily data. Which CV scheme should you use?
  • Standard K-Fold with shuffling
  • Stratified K-Fold
  • TimeSeriesSplit
  • Leave-One-Out
💡 Explanation
Stock price data is sequential/time-dependent. Shuffled K-Fold would let the model "see the future" during training (using tomorrow's data to predict yesterday), causing leakage. TimeSeriesSplit ensures training always happens on past data only.

Case Study
Car Price Prediction — End to End
15 min

Let's bring everything together: numeric + categorical features, a ColumnTransformer for preprocessing, Ridge regression, and GridSearchCV — all wrapped in one pipeline.

Numeric Cols
→ StandardScaler
→
Categorical Cols
→ OneHotEncoder
→
ColumnTransformer
(merge)
→
Ridge +
GridSearchCV
from sklearn.compose import ColumnTransformer
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.pipeline import Pipeline
from sklearn.linear_model import Ridge
from sklearn.model_selection import GridSearchCV

numeric_features = ['mileage', 'engine_size', 'age']
categorical_features = ['brand', 'fuel_type', 'transmission']

preprocessor = ColumnTransformer([
    ('num', StandardScaler(), numeric_features),
    ('cat', OneHotEncoder(handle_unknown='ignore'), categorical_features)
])

pipe = Pipeline([
    ('preprocess', preprocessor),
    ('ridge', Ridge())
])

param_grid = {'ridge__alpha': [0.1, 1, 10, 50, 100]}
grid = GridSearchCV(pipe, param_grid, cv=5, scoring='r2')
grid.fit(X_train, y_train)

print("Best alpha:", grid.best_params_)
print("CV R²:", grid.best_score_)
print("Test R²:", grid.score(X_test, y_test))
Output
Best alpha: {'ridge__alpha': 10} CV R²: 0.812 Test R²: 0.804
🧠 Why CV & Test scores are close here
Because we tuned hyperparameters properly using CV (not by peeking at test data), our CV score (0.812) and final test score (0.804) are close — a sign of a trustworthy, well-generalizing model.

Summary
Wrap Up
5 min
  • A single train-test split gives an unreliable estimate for choosing hyperparameters like λ.
  • K-Fold CV averages performance across multiple splits for a stable estimate.
  • GridSearchCV / RandomizedSearchCV automate hyperparameter search using CV internally.
  • Always use Pipelines to prevent data leakage from preprocessing steps.
  • RFECV combines feature selection with cross validation to find the optimal feature subset.
  • Choose the right CV scheme based on your data: K-Fold, Stratified K-Fold, LOOCV, or TimeSeriesSplit.
