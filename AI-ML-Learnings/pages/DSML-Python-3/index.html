2Reusable logic

What are functions?

In Lectures 1–2, loan eligibility logic was written inline. If the bank needs that same 15-line check in 10 different parts of their software, do we copy-paste it 10 times? That's a maintenance nightmare — change the rules once, and you'd have to update 10 copies.

A function solves this: a reusable set of instructions you define once and call whenever needed.

📦
Independent logic
15 lines of eligibility checks
→
🧰
Packaged into one reusable unit
call it from anywhere, as many times as needed

This is encapsulation: packaging independent logic into a reusable unit to avoid duplication. Write once, use everywhere.

5Functions

      
Positional and keyword arguments

      
python
def introduce_family(my_name, sibling_name, father_name, mother_name):
    print("My name is", my_name)
    print("My sibling's is", sibling_name)
    print("My father's is", father_name)
    print("My mother's is", mother_name)

# Giving arguments in INCORRECT order
introduce_family("Nilesh", "Deepak", "Deepa", "Vidhi")

      
Output
My name is Nilesh
My sibling's is Deepak
My father's is Deepa
My mother's is Vidhi

      

        
⚠️ Common pitfall

        The code runs without error, but the output is wrong — "Deepak" was meant to be the father, not the sibling. Positional arguments depend entirely on order, which is error-prone. No exception is raised, so this bug can slip through silently.
      


      
Fix: keyword arguments.

      
python
introduce_family(my_name="Bipin",
                 father_name="Deepak",
                 mother_name="Deepa",
                 sibling_name="Vidhi")

      
Output
My name is Bipin
My sibling's is Vidhi
My father's is Deepak
My mother's is Deepa

The global keyword

      
To explicitly modify the global variable from inside a function, use global:

      
python
a = 10

def random_fn():
    global a
    a = 20
    print(a)

random_fn()
print(a)

      
Output
20
20

      

        
⚠️ Generally bad practice

        Modifying global state from inside a function makes code harder to debug — the function's behavior now depends on (and changes) something outside itself. Prefer passing values as parameters and using return.
      

      

        
🌉 Fintech tie-in

        A global variable might hold the bank name or currency symbol. Each function processing a different loan should have its own local variables for that loan's details — mixing them up would be a disaster.
      


      
A classic scope mistake

      
python
balance = 1000

def deposit(amount):
    balance = balance + amount
    return balance

deposit(500)

      
Error
UnboundLocalError: cannot access local variable 'balance' where it is not associated with a value

      

        
⚠️ Why this confuses even people who understand scope

        It looks like it should just read the global balance. It doesn't. The moment Python sees balance = … anywhere inside a function, it decides balance is local to the entire function — even on the line before the assignment. So balance + amount tries to read a local variable that doesn't have a value yet. This differs from the earlier random2() example, where there was no assignment to a at all inside the function.
        
Fix — pass balance in and return the new value, rather than reading and writing a global:

        
python
def deposit(balance, amount):
    return balance + amount

balance = deposit(1000, 500)
print(balance)

A lambda is a small, anonymous function defined in a single line.

Lambda equivalent:

ASCII, ord(), chr()

      
We saw that "a" > "A" is True. But characters aren't numbers... or are they? A computer doesn't understand characters directly — every character maps to a number internally. This mapping is ASCII (American Standard Code for Information Interchange).

      
Why does a standard mapping matter? If different platforms used different mappings, sending a message from Android to iOS could produce garbled text. ASCII ensures consistency.

'A'–'Z'
65 – 90

          
'a'–'z'
97 – 122

        

        
'a' (97) > 'A' (65) — that's why "a" > "A" is True.

      


      
ord() gives the ASCII value of a character:

chr() converts an ASCII value back to a character:

Mutability and immutability

      
This is a concept Python interviews almost always test.

      
    
        
  • Mutable: the value can be changed in place (same memory location).
    • 
        
  • Immutable: the value cannot be changed in place — any "change" creates a new object at a new memory location.
    • 
      

      
Python's id() returns the memory address of an object. Let's investigate.

        Transaction records should be immutable — once logged, a transaction shouldn't be altered in place. Python strings enforce this by design. That's a feature, not a limitation. Returning multiple values

      
Every function so far has returned a single value. But a function can return several values at once, separated by commas — Python automatically packages them together. You then "unpack" them straight into separate variables, in the same order, on the left of =.

      
python
def min_and_max(a, b):
    if a < b:
        return a, b
    return b, a

smaller, larger = min_and_max(50000, 10000)
print(smaller, larger)

Here's the complete program, built exactly to that specification:

      
python
def parse_transaction(txn_string):
    # def, parameters, split(), returning multiple values
    prefix, year, txn_type, amount, category = txn_string.split("-")
    return prefix, year, txn_type, amount, category

def categorize_transaction(amount, threshold_high=50000, threshold_medium=10000):
    # default arguments, if/elif/else
    if amount >= threshold_high:
        return "HIGH-VALUE"
    elif amount >= threshold_medium:
        return "MEDIUM-VALUE"
    else:
        return "LOW-VALUE"

# lambda, f-string
format_summary = lambda txn_id, status, amt: f"[{txn_id}] {status} | Rs.{amt}"

transactions = [
    "TXN-2024-CREDIT-75000-SAVINGS",
    "TXN-2024-DEBIT-5000-CURRENT",
    "TXN-2024-CREDIT-25000-SAVINGS",
]

print("=" * 45)
print(" DAILY TRANSACTION REPORT")
print("=" * 45)

for txn in transactions:
    prefix, year, txn_type, amount_str, category = parse_transaction(txn)
    if not amount_str.isdigit():           # .isdigit() validation
        print(f"INVALID AMOUNT in: {txn}")
        continue                            # skip invalid transactions
    amount = int(amount_str)
    value_category = categorize_transaction(amount)
    txn_id = f"{prefix}-{year}"
    print(format_summary(txn_id, value_category, amount))
    print(f"   Type: {txn_type.upper()} | Account: {category.lower()}")
    print("-" * 45)
