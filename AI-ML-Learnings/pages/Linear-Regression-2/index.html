Problem Setup
From Data to Prediction: Problem Formulation
⏱ 4 min

Data Notation

Assume we are given n car data points as historical data, each with d features:

  • f1, f2, ..., fd — features of each car (e.g., engine size, mileage, year)
  • xi — the d-dimensional feature vector for car i
  • yi — the actual selling price for car i

Our goal: find a Model that maps any input x → output y (a real number).

Making Predictions

Once the model is trained on historical data, we pass a new query car xq to it. The model outputs a predicted price ŷq (read: "y-hat"). The closer ŷq is to the real price yq, the better our model.

A Worked Example

x1x2y
124
226
237
3410

The model discovers the pattern: y = 2x1 + x2. Given a new query point, it uses this learned formula to predict.

Train-Test Split

To verify model quality, we split the data:

  • Training set: used to learn the model's parameters
  • Test set: held out, used only to evaluate how well the model generalizes
⚠️ Golden Rule
Never train on test data. The test set must remain "unseen" throughout training — otherwise your evaluation is meaningless.

The Workflow

1

Historical Data → Split

Divide into Train and Test sets

2

Train Data → Model Building

Algorithm learns patterns and produces a Model

3

Test Data → Predictions

Feed unseen inputs to the trained Model

4

Predicted vs Actual → Evaluation

Measure how close our predictions are to the true values

🤔 Regression or Classification?
Since we're predicting a continuous numeric value (car price), this is a regression task. The approach: check how Y depends on X and fit a trend line.

Linear Regression Intuition & Line Equation
⏱ 10 min

The Equation of a Line

Every straight line on an X-Y plane is described by:

y = mx + c
  • m = slope — how steeply the line rises or falls
  • c = y-intercept — where the line crosses the Y-axis (when x = 0)

The slope m is calculated as:

m = tan θ = Δy / Δx

That is, the ratio of vertical change to horizontal change between any two points on the line.

Simple Examples

EquationSlope (m)Intercept (c)Passes through origin?
y = x10Yes
y = 2x20Yes
y = 2x + 323No
y = 0.5x − 10.5−1No

Connecting to Linear Regression

In Linear Regression, we use exactly this line equation to model the relationship between one feature and the target. For our car dataset:

price = w × max_power + b

where w (weight/slope) and b (bias/intercept) are what the model learns from data.

📌 Terminology Map
In ML, the line parameters are called weights (w) and bias (b). The feature column values are inputs, and the target column values are targets or labels.

Finding the Best Fit Line & Errors
⏱ 4 min

Geometric Intuition

Imagine plotting salary vs. years of experience. When a new data point arrives, we don't know what salary to predict from all the existing values. So we draw a line through the points and use that line.

But many lines can pass through (or near) a cloud of points. Which one should we pick?

🤔 Which line is "best"?
The best fit line is the one where most data points are closest to it. Lines that are far from most points are poor fits.

Errors / Residuals

The error (or residual) for a data point is:

error = y_actual − y_predicted

A positive error means our prediction was too low; negative means too high.

Problem with Summing Raw Errors

You might think: just minimize the sum of all errors. But there's a catch — positive and negative errors cancel each other out. A model could have large individual errors that sum to zero, falsely looking "perfect."

The Solution: Ordinary Least Squares (OLS)

We square each error before summing. Squaring:

  • Eliminates sign cancellation (all squared errors are ≥ 0)
  • Penalizes large errors more heavily than small ones

The method of minimizing the sum of squared errors is called Ordinary Least Squares (OLS) — the foundation of Linear Regression.

Minimize: Σ (y_i − ŷ_i)²

Scatter Plot: max_power vs selling_price

Apart from a few outliers, the scatter roughly follows a linear trend — a good sign that a line can model this relationship.

A Helper Function: estimate_charges

This is our very first model — a simple linear equation:

def estimate_charges(maxpower, w, b):
    return w * maxpower + b

Guessing Initial Parameters

w = 50
b = 100
maxpower = data.max_power
estimated_charges = estimate_charges(maxpower, w, b)

With w=50, b=100 the line is wildly off — clearly our guesses need improvement.

Trying Better Parameters

def try_parameters(w, b):
    maxpower = data.max_power
    target = data.selling_price
    estimated_charges = estimate_charges(maxpower, w, b)
    plt.figure(figsize=(10,6))
    plt.plot(maxpower, estimated_charges, 'r', alpha=0.9)
    plt.scatter(maxpower, target, s=8, alpha=0.8)
    plt.xlabel('MaxPower'); plt.ylabel('Price')
    plt.legend(['Estimate', 'Actual'])
    plt.show()

try_parameters(0.5, 1)   # getting closer...
try_parameters(0.08, 0.5) # closer still...
💡 The Problem with Manual Tuning
Changing w and b by hand is tedious and imprecise. We need a systematic way to:
  1. Measure how well the line fits (numerically)
  2. Automatically adjust w and b to improve the fit

Optimization
MSE & Gradient Descent
⏱ 6 min

Cost Function

A Cost Function quantifies the error between predicted and actual values as a single number. For Linear Regression, we use Mean Squared Error (MSE):

MSE = (1/n) × Σ (y_i − ŷ_i)²
  • n = number of training examples
  • y_i = actual value
  • ŷ_i = predicted value

Our goal: find the values of w and b that minimize the MSE.

Gradient Descent

Instead of trying values randomly, Gradient Descent is a principled algorithm that moves w and b in the direction that reduces the cost function, step by step.

Think of it like being blindfolded on a hilly landscape and always taking a step downhill. Eventually you reach the valley — the minimum of the cost function.

1

Start

Initialize w and b with random values

2

Compute Gradient

Calculate the slope of the cost function at the current w, b

3

Update Parameters

Nudge w and b in the opposite direction of the gradient (downhill)

4

Repeat

Iterate until the cost stops improving — we've found the minimum

📌 Learning Rate
The step size (or learning rate) controls how large each update is. Too large → overshoots the minimum. Too small → takes forever to converge.

Code: Univariate Linear Regression with Scikit-Learn
⏱ 15 min

Scikit-learn handles all the OLS/Gradient Descent internals for us with a clean, consistent API.

Load the Pre-processed Data

import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

df = pd.read_csv('cars24-car-price-clean.csv')
df.head()

Define X and Y

We use model (car model encoding) as our single input feature and selling_price as the target:

X = df["model"].values
Y = df["selling_price"].values
🤔 Independent vs Dependent Columns
Independent columns (features): everything except selling_price — they are the inputs. Dependent column (target): selling_price — it depends on all the others.

Initialize and Train the Model

from sklearn.linear_model import LinearRegression
model = LinearRegression()
model.fit(X, Y)   # ← this will throw a ValueError!
Error
ValueError: Expected 2D array, got 1D array instead. Reshape your data either using array.reshape(-1, 1) if your data has a single feature...

Scikit-learn's fit expects X to be 2D — shape (n_samples, n_features). Fix it:

X = X.reshape(X.size, 1)
Y = Y.reshape(Y.size, 1)
print(X.shape, Y.shape)   # → (19820, 1) (19820, 1)

model.fit(X, Y)   # now works!

Make Predictions

y_hat = model.predict(X)

print('Predicted:', y_hat[:3])
print('Actual:', Y[:3])
Output
Predicted: [[-1.08634131] [-0.32158118] [-0.76220457]] Actual: [[-1.11104589] [-0.22394353] [-0.91505816]]

Retrieve the Learned Parameters

c = model.intercept_
m = model.coef_
print(c, m)
Output
[-1.18731936e-16] [[0.96505112]]

The final learned equation:

selling_price = 0.965 × model − 1.187×10⁻¹⁶

The intercept is essentially 0 (the data was normalized). The slope m = 0.965 means a one-unit increase in the model encoding corresponds to a ~0.965-unit increase in normalized selling price.

Visualize the Fit

fig = plt.figure()
plt.scatter(X, Y, label='data')
plt.scatter(X, y_hat, color='orange', label='prediction')
plt.legend()
plt.show()

Metric
Coefficient of Determination — R² Score
⏱ 12 min

Why Not Just Use Sum of Squared Errors?

SSE is scale-dependent. If one model predicts house prices in dollars and another in rupees, the SSE values are incomparable even if both models are equally accurate. We need a scale-independent metric.

The Baseline: Mean Model

The worst viable model is one that simply predicts the mean of y for every input, ignoring features entirely. This is our baseline to beat.

Two Key Quantities

TermFormulaMeaning
SS_residualΣ(y_i − ŷ_i)²Error of our model
SS_totalΣ(y_i − ȳ)²Error of the mean model (total variance in Y)

The R² Formula

R² = 1 − (SS_residual / SS_total)

R² measures how much better our model is compared to simply predicting the mean every time.

Interpreting R²

R² ValueMeaning
1.0Perfect model — zero residual error
0.0No better than the mean model
< 0Worse than the mean model (possible but rare)
−∞Theoretical minimum (model is catastrophically wrong)
📌 Intuition
R² tells you what fraction of the total variance in Y is explained by your model. R² = 0.93 means the model explains 93% of the variance — the remaining 7% is unexplained noise or missing features.

Getting R² in Scikit-Learn

model.score(X, Y)
Output
0.9313236629576508
🤔 Is R² = 0.93 good?
Yes — our univariate model (using just one feature) explains 93.13% of the variance in selling price. But relying on a single feature leaves room for improvement. Next, we'll bring in multiple features.
