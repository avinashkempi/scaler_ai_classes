Boosting is accurate, but every stage is built to chase whatever error is left, including noise. This read shows how to keep that in check. After reading it you should be able to:

  • Write out the formal Gradient Boosting algorithm, including how each stage's weight is chosen.

  • Explain shrinkage (the learning rate) as regularization, and its trade-off with the number of stages.
  • Explain Stochastic Gradient Boosting and how row subsampling regularizes further.
  • Explain why Boosting is especially sensitive to outliers, and how a robust loss such as Huber loss helps.
  • Apply all of this to a real classification problem outside HR analytics.

The Gradient Boosting algorithm, written out precisely

The previous read built Gradient Boosting by hand, informally. This is the exact algorithm behind GradientBoostingClassifier. Its reference is the Gradient boosting article.

Input: training data {(xi, yi)}, a differentiable loss function L(y, F(x)), and a number of stages M.

The algorithm, step by step

Step through it

In practice the line search is skipped. Step 2.3 technically calls for an optimisation at every single stage, which is expensive. Most implementations, including scikit-learn's, simply fix γm = η (the learning rate) for every stage. This trades a small amount of per-stage optimality for a lot of speed and, as a side effect, acts as its own form of regularization.

Two hyperparameters, two ways to overfit

Boosting has at least two hyperparameters that both affect the bias-variance trade-off: M, the number of stages, and the depth of each stage's base learner.

Too few stages underfit

With M = 1 the model is the Stage 0 mean model plus a single correction. One correction cannot capture everything the mean model gets wrong, so predictions stay close to the overall mean and the model underfits.

Too many stages, or trees that are too deep, overfit

Every extra stage exists purely to shrink whatever error remains, noise included. Given enough stages, or deep enough individual trees, the model eventually fits the noise too. The notebook shows this by sweeping n_estimators over 1, 5, 10, 25, 50, 100, 200 and 400 (with max_depth=2, learning_rate=0.1), and then max_depth over 1, 2, 3, 5, 8 and 12 (with 100 stages).

The overfitting shape

Schematic of the pattern described in the lecture, not measured data

The curves are drawn to show the described shape only, so the vertical axis carries no numbers. The lecture's plots come from the code below.

  • At the smallest values of M, both train and test accuracy are low: underfitting.
  • As M grows, train accuracy keeps climbing, but test accuracy eventually flattens or drops. The widening gap is overfitting.
  • Depth shows the same shape, and usually faster than M. A deeper base learner is no longer the weak, high-bias learner Boosting is built around: it starts fitting real structure, and noise, on its own at every stage.

Boosting is not like a forest here. Adding more trees to a Random Forest barely hurts it, because the trees are trained independently. Adding more stages to a boosted model behaves very differently, because every stage is chasing whatever error remains. Left untuned, Gradient Boosting overfits easily, which is exactly HR's concern.

Regularizing with shrinkage

The learning rate appeared earlier as the fix for "simple addition overcorrects". Formally, it is also a regularization technique in its own right.

The trade-off

A smaller learning rate means each stage nudges the prediction only a little. To reach the same overall fit, the model needs correspondingly more stages. In exchange, many small steps tend to generalise better than a few large ones, because the model is less likely to overcorrect for noise in any single stage.

The formula

Recall the update rule for stage m:

Fm(x) = Fm−1(x) + γm · hm(x)

Shrinkage replaces the expensive, per-stage optimal weight γm with a single fixed constant ν, the learning rate, used identically at every stage and chosen once, before training starts:

Fm(x) = Fm−1(x) + ν · hm(x),   0 < ν ≤ 1

Why it trades speed for stability

Gradient Boosting is, underneath, a form of functional gradient descent. At each stage hm(x) points in the direction that reduces loss fastest, and ν is the step size along that direction, the same role a learning rate plays in ordinary gradient descent. A smaller ν needs more stages to travel the same distance, but is far less likely to overshoot and lock in a correction for what turns out to be noise.

Step size and number of stages

Illustration, not the Finzo data

Each line shows how much of the distance to the loss minimum has been covered after each stage, if every stage steps a fraction ν of the remaining distance. A large ν arrives almost at once; a small ν needs many more stages but takes only small, safe steps. It is a simplified picture of the idea, not a measurement.

Rule of thumb for the number of stages

This is a rough rule of thumb, not an exact identity: a smaller ν typically needs roughly M0 / ν stages for a similarly good fit.

Stochastic Gradient Boosting: regularizing with randomness

There is a second regularization lever, borrowed from Bagging. Instead of fitting every stage on the entire training set, fit each stage on a random subsample of the rows, typically drawn without replacement, unlike Bagging's bootstrap.

This is Stochastic Gradient Boosting, controlled by the subsample hyperparameter: the fraction of rows used per stage. 1.0 means every row, which is what has been used so far. See the scikit-learn documentation.

Boosting's blind spot: outliers

Does a single unusual data point affect Gradient Boosting more, or less, than it affects a Random Forest?

Why outliers hit Boosting hard

Every stage of Boosting is built specifically to reduce the current residual. If one point is a genuine outlier, its residual is unusually large at every stage, until the model bends itself to fit that one point. With squared error loss the problem compounds: squaring a large residual makes it disproportionately dominate the total loss, pulling each later stage further toward that single outlier.

Random ForestGradient Boosting
How an outlier gets inOnly trees whose bootstrap sample happened to include it are affectedIts large residual is targeted stage after stage
What limits the damageIt is outvoted by all the trees that never saw itNothing, unless the loss function limits how much a large residual can matter

Squared error against Huber loss on one outlier

The notebook builds 60 points along y = 2x with noise, injects one extreme outlier (+40 at index 5), and fits two boosted regressors: one with squared_error loss and one with huber loss (100 stages, max_depth=2). The data and both fits below are regenerated from that code.

One outlier, two very different fits

Toggle the fits

At the outlier's own position (x ≈ 0.85, observed y ≈ 40.7), the squared-error fit follows the outlier almost exactly, while the Huber fit is pulled up far less. Elsewhere the two fits track each other closely.

How Huber loss fixes this

Huber loss behaves like squared error for small residuals, so it stays smooth and easy to optimise, but switches to behaving like absolute error for large residuals. That caps how much a single huge residual can dominate the total loss. Drag the residual to see how each loss treats it.

Loss contributed by one residual

The switch point is illustrative
Squared error, ½r²Huber

Taking the square root of the squared loss (RMSE, rather than the raw squared value) is sometimes mentioned as another partial fix, because large errors then do not explode in magnitude quite as badly. Huber loss remains the more targeted solution.

View the code 
from sklearn.ensemble import GradientBoostingRegressor

rng = np.random.default_rng(7)
X_reg = np.linspace(0, 10, 60).reshape(-1, 1)
y_reg = 2 * X_reg.ravel() + rng.normal(0, 1, size=60)
y_reg[5] += 40   # inject one extreme outlier

gbr_squared = GradientBoostingRegressor(loss='squared_error', n_estimators=100, max_depth=2, random_state=7)
gbr_huber   = GradientBoostingRegressor(loss='huber', n_estimators=100, max_depth=2, random_state=7)

gbr_squared.fit(X_reg, y_reg)
gbr_huber.fit(X_reg, y_reg)

Removing the outlier, or using a robust loss? A robust loss such as Huber is usually the safer default, since it does not require deciding by hand which points count as outliers. Removing a point can be reasonable too, when it is clearly a data-entry error rather than a real, rare event worth learning from. Ignoring the issue is the one option that is not reasonable.

Summary

The formal algorithm

Gradient Boosting initialises with the loss-minimising constant, then repeatedly computes pseudo-residuals, fits a weak learner to them, finds a weight for that learner, and adds it to the running model. In practice the weight is simplified to a fixed learning rate.

Stages and depth

Both the number of stages (M) and the depth of each base learner control the bias-variance trade-off. Too few or too shallow underfits; too many or too deep overfits. Boosting overfits noticeably faster with these than Bagging does.

Shrinkage

Shrinkage trades speed for stability: a smaller learning rate needs more stages to converge, but tends to generalise better.

Stochastic Gradient Boosting

Bagging-style row subsampling is a second, independent regularization lever.

Outliers and robust loss

Boosting is unusually sensitive to outliers, since every stage keeps targeting whatever residual remains, including one dominated by a single unusual point. A robust loss such as Huber loss fixes this by capping how much large residuals can dominate the total loss.

The Pay Band case study

In the EMG-based gesture classifier the same pattern held: Decision Tree fastest, Random Forest balanced, Gradient Boosting most accurate but slowest to tune.
