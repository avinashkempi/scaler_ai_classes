5. A contract for every record

A data contract is a short, written promise about what a record must look like: which fields, what type each one is, which values are allowed and how recent the data must be. Think of the rules on a train ticket form: a name, an age between 0 and 125, a seat that really exists. The form refuses what breaks the rules, and tells you which box was wrong.

Two different questions

Class 4 asked "can I read this?" That is parsing. Class 5 adds "is it allowed?" That is validation. A value can pass the first and fail the second. Try it: click an item, then click the question it answers.

Pydantic: the contract, written in Python

Pydantic is a Python library that checks a record against a class you write. You list each field, its type and its rules. It returns a clean record, or a list of exactly what is wrong. This is a shortened version of what we write in class:

A shortened contract (you will not type this before class)
class CaseContract(BaseModel):
    model_config = ConfigDict(frozen=True, extra="forbid")

    case_id: str = Field(pattern=r"^C-\d{4}$")   # C- and four digits
    order_id: str = Field(pattern=r"^O-\d{4}$")
    order_status: OrderStatus                    # only the allowed words
    promised_date: date                          # a check keeps it in 2020 to 2035

Fed the contract failure file, the program now says exactly why each row was refused:

What the class sees
accepted: ['C-4001', 'C-4005', 'C-4006']
line 3  CONTRACT   case_id: String should match pattern '^C-\d{4}$'
line 4  CONTRACT   promised_date: must be between 2020-01-01 and 2035-12-31
line 5  MALFORMED  promised_date '07/03/2025' is not YYYY-MM-DD
input 6 = accepted 3 + quarantined 3

Notice two categories. MALFORMED means the text could not be read. CONTRACT means it was read, and it broke the written promise. The person fixing the file needs different help in each case, so we keep them apart. The count still balances: 6 = 3 + 3.

Lax or strict?

A forgiving checker quietly turns the text "12" into the number 12. That is lax mode. A strict checker refuses it and says so. Strict is safer, because it is what tells you that a number arrived as text. Click a value to see each mode.

Click a value above.
Like a metal detector The detector at an airport gate does not care who you are. It checks the same standard, the same way, for everyone, and it says which item set it off. A contract does that for data.

6. Logs, and a report anyone can read

A log is a file the program writes while it runs, so you can investigate later. A structured log writes every entry with the same named fields, as one line of JSON. That lets a computer search it: "show me every step that failed". Think of an aircraft's flight recorder. It stores the same readings on every flight and never the passengers' conversations.

One log line from a real run (shortened)

7. A checked AI reply, and a screen on the web

A model's reply is just text

It might be perfect, half a sentence, or perfectly formatted nonsense. So we describe the reply with a contract too, and check three things in a row: the right shape, allowed values, and came from this note. The model must quote the note and name it. A model can hallucinate, which means it writes something confident that the note never said. We cannot stop that, but we can catch it. A quote that is not in the note is INVALID_REPLY.

Measuring the AI

One reply can look fine. Ten replies, asked the same way every time, tell you more. An evaluation runs a fixed set of test cases with known right answers and reports four numbers, never one blended score:

MeasureThe question it answers
Structural validityWas the reply the right shape?
Category correctDid it pick an acceptable issue family?
GroundedIs the quoted evidence really in the note?
Abstention correctDid it stop exactly when it should?

A score only means something with its versions: the prompt version and a fingerprint of the test set. Without them, nobody can repeat or challenge "90 percent".

The screen, and putting it on the web

Streamlit is a Python library that turns a Python file into a web page. The file runs top to bottom, and every click runs it again. Our screen only reads files the program already wrote. It never runs a batch and never calls a model. Deploying means putting it on a computer other people can reach, so a colleague can open a link at 2 a.m.

Your laptopRun the program. Push to GitHub
→
GitHubHolds the code and a small sample of results. Never a password
→
Streamlit Community CloudRuns the screen. Holds the password as a secret
Two rules about secrets A secret is anything that gives access: a password or an API key. It never goes into a file in the repository, and it never goes into a chat. A key pushed to a public repository can be found and misused within minutes. The app's password lives in the cloud's secrets box.
