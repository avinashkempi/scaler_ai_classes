Tableau · Session 4

Table Calculations & Analytics

How to reshape a finished view — percentages, rankings, running totals — without ever going back to the data source. Plus tooltips, reference lines, and trend lines that turn a chart into a decision-making tool.

Working dataset: Sample Superstore
1Why this matters

The view is already built. Now what?

In the last session, LOD expressions let you tell Tableau to compute something at a different grain before the view was drawn — down in the data itself. This session solves a different problem: reshaping numbers that are already on the screen.

◆

Picture a retail analyst presenting a clean bar chart — Sales by Quarter by Region — to her leadership team. The response: "Show me each quarter as a percent of the year, rank the quarters best to worst, and give me a running total." She re-imports the data and rebuilds the whole view. It takes two hours. Every one of those requests could have been answered in under a minute, without touching the data source — because none of them change what is being measured, only how the numbers already in the view are read.

The tool for that job is the table calculation. This article covers how table calculations work, the eight built-in calculation types, the difference between Index and Rank, and three features that make a finished view easier to read and act on: tooltips, reference lines, and trend lines.

2Core concept

Table calculation vs. calculated field: it's about timing

Both create new numbers. The difference is when Tableau does the math.

▪ Calculated field — cooked in the kitchen

A calculated field like Profit Ratio = SUM([Profit]) / SUM([Sales]) is computed at the data level, row by row, before the visualization is drawn. It behaves exactly like any other field in the data source.

▫ Table calculation — seasoned at the table

Tableau builds the view first — say, Sales by Month — and only then applies the table calculation on top of the values already showing on screen. You're adjusting what's already been served, not returning to the kitchen.

Rule of thumb: if the calculation needs to know about values already displayed elsewhere in the view (a total, a previous row, a rank among the visible marks), it's a table calculation. If it only needs the data source, it's a calculated field.
3The mechanics

Scope and direction: how table calculations move

Every table calculation needs two settings for each dimension in the view: is this dimension part of the scope (the boundary the calculation resets at) or the direction (the path it steps through)? There's no third option — every dimension gets assigned to one or the other.

Scope (partitioning) — where does it calculate?

  • Table — the entire visualization is one group.
  • Pane — a sub-section of the view (e.g. one Region's block of columns) is its own group.
  • Cell — a single mark; the calculation never looks beyond it.

Direction (addressing) — in what order?

  • Down — top to bottom within each column.
  • Across — left to right within each row.
  • Down then across / across then down — finish one pass, then move to the next column or row.

The simplest way to see scope and direction in action is with INDEX() — a calculation that does nothing but number the marks in view order: 1, 2, 3, 4… It has no business logic of its own, which is exactly why it's useful here: when the numbering pattern rearranges, you're watching scope and direction change in real time.

▣

Think of a teacher grading three classes. Ranking students within each class separately makes each class a scope (Pane). Ranking every student in the school together makes the whole school one scope (Table). The order she works through the papers — row by row, or column by column — is the direction.

Knowledge check 1

In Tableau table calculations, what happens when a dimension is selected for addressing (direction)?

Addressing defines the direction the calculation steps through. Tableau moves through the members of the addressed dimension while every other dimension in the view defines the partition (scope).

Index vs. Rank: position vs. value

Once you've used both, the obvious question is: what's the difference? They both assign numbers to rows.

▤

Five people are in a queue for movie tickets: A first, B second, C third, D fourth, E fifth. Index is their position in line — it doesn't care who's tallest or richest, only the order they appear: A=1, B=2, C=3… Now line the same five people up by height instead, tallest to shortest. That's Rank — it cares about the value being compared, not where someone happened to be standing.

INDEX()

  • Depends on the addressing direction — the order marks are physically processed.
  • Does not consider ties; every mark gets a unique number.
  • Changes when sort order or Compute Using changes.
  • Typical use: building custom sequences, calculations that need position, not value.

RANK()

  • Depends on the values in the partition, regardless of where the marks sit in the view.
  • Handles ties based on a chosen ranking method.
  • Typical use: top-N analysis, leaderboards, "best/worst" questions.
Same values, two calculations
SUM(Sales)10,00040,00020,00030,000
INDEX()1234
RANK()4132

INDEX() simply counts left to right: 1, 2, 3, 4. RANK() looks at the values and gives the $40,000 mark the #1 rank — regardless of the fact that it sits second in the row.

6Shortcut

Quick Table Calculation

Creating a table calculation the "full control" way — build the calculated field, then set Compute Using by hand — gives maximum flexibility. Tableau also ships a two-click shortcut for the most common calculation types: right-click the measure pill → Add Table Calculation (or the Quick Table Calculation submenu). It's the microwave-meal version: fast, with fewer knobs to turn. Understanding the Compute Using settings underneath still matters, because that's what you'll need to adjust when the default result isn't the one you expected.

Knowledge check 3

What is the primary difference between a calculated field and a table calculation in Tableau?

Calculated fields are evaluated before the visualization is rendered and become part of the data model. Table calculations are computed after the view is created, and depend on the layout and level of detail of that worksheet.
8Reading aids

Tooltips & reference lines

Tooltips: a chart inside a chart

A tooltip is the detail that appears when you hover a mark. Beyond plain text, Tableau can embed an entire second worksheet inside a tooltip — so hovering one mark reveals a nested visualization for just that mark. A common build: a map colored by state profit, where hovering a state shows a bar chart of that state's profit by sub-category, without leaving the map.

Source sheet — Profit by State (map), tooltip = Target sheet

Try it — hover or tap a state below. Two of these carry the exact total-profit figures from the worked example; the nested bar pattern illustrates how the embedded worksheet renders inside the tooltip.

Command buttons available from any tooltip: Keep Only (filter to just this selection), Exclude, Group Members, Create Set, and View Data.

Reference lines: a fixed benchmark

A reference line is a benchmark drawn on the chart — a target, an average, a threshold — that stays fixed regardless of which mark you're looking at, so you can instantly see what's above or below it.

▲

It's the height-requirement board at an amusement park ride: "You must be this tall to ride." The line doesn't change based on who's standing there — it just tells each person, instantly, whether they clear the bar. In Tableau, Reference Lines live in the Analytics pane, alongside Reference Bands and Trend Lines.

Business scenario: find the sub-categories with above-average sales, for every category and year. Dragging a table-scoped Average Line from the Analytics pane onto the view draws one benchmark per pane — instantly showing which sub-categories clear their own category's average.

Controlling a reference line with a parameter

Reference lines don't have to be static. Business scenario: set next year's sales target as this year's total profit multiplied by an adjustable target percentage — and let a parameter control that percentage live.

9Forecasting the shape

Trend lines

A reference line marks a fixed point. A trend line answers a forward-looking question instead: given the pattern so far, where is this data going? Tableau fits a mathematical model to the marks in view and draws the resulting trajectory — requiring a continuous (green) field on both axes, with one exception: a discrete date field is allowed on one axis.

Illustrative — house size vs. price

Linear

Use this model when you'd expect price to increase at a roughly constant rate as size increases — each extra square foot adds about the same amount of value.

Real figures from Tableau's Describe Trend Model dialog for a year-wise sales trend — reached via Analytics → Trend Lines → Describe Trend Model.

Two more factors shape a trend line: the fields defining the X/Y coordinates (both must be continuous, with the date-field exception above), and any discrete field placed on Rows, Columns, or Color — which splits one trend line into several distinct ones, one per member.
Knowledge check 4

Which condition must generally be satisfied before Tableau can create a trend line?

Trend lines model the relationship between X and Y coordinates, so both axes generally need continuous fields — though a discrete date field is allowed as an exception.
10Wrap-up

Key interview takeaways

  • "What's the difference between a calculated field and a table calculation?"Data level vs. view level — before aggregation vs. after.
  • "What are scope and direction in table calculations?"Scope defines the boundary a calculation resets at; direction defines the path it steps through.
  • "What's the difference between Index and Rank?"Index = position in the view. Rank = position by value.
Across this session: table calculations compute on top of an already-built view, governed by scope and direction. Percent of Total and Rank turn raw numbers into share-of-whole and best-to-worst comparisons. Tooltips, reference lines, and trend lines then layer reading aids onto the finished chart — a benchmark, a trajectory, and drill-down detail — without a single trip back to the data source.
