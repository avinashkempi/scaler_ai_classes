The Big Idea

00 The lookup family

Every lookup function answers the same question — "I have a known key, find it in a list, return the matching detail." They differ only in how flexible that search can be.

Why not just search manually? The manual method — press Ctrl+F, search for an Order ID, locate the row, read off the Ship Mode — works fine for one lookup. But if a manager asks for the same detail across 50 Order IDs, manually searching 50 times doesn't scale. Instead of searching by hand every time, a lookup function makes the sheet search for you — and in SQL terms, a lookup across two tables is exactly what a JOIN does.
FunctionWhat it does
LOOKUPSearches a single row or column. Limited, rarely used today.
VLOOKUPSearches a table vertically, top to bottom. Most common. Leftmost-column only.
INDEX & MATCHTwo-step lookup. Searches and returns in any direction.
XLOOKUPModern replacement for both. Any direction, built-in error handling.

Within Sheet

02 VLOOKUP

Search the leftmost column of a range, then jump right to fetch an answer from the same row. Think of it as "search the left column → find the row → go right to get the answer."

SYNTAX
=VLOOKUP(lookup_value, table_range, col_index, FALSE)
=VLOOKUP(...)

match_type: FALSE = exact match — always use FALSE for IDs, never TRUE. And always lock table_range with $ (e.g. $A$1:$H$20) so it doesn't shift when the formula is dragged down to other rows.

DomainReal-world use case
E-commerceLook up a product name from its Product ID
HRRetrieve an employee's department from their Employee ID
FinanceFetch the account manager's name from an Account Number
LogisticsPull delivery status from a tracking code
SalesGet customer contact details from a Customer ID
Error Handling

03 IFERROR

Type an Order ID that does not exist above, and the raw VLOOKUP breaks. Wrap it in IFERROR for a clean fallback message instead.

SYNTAX
=IFERROR(value, value_if_error)
Without IFERROR
With IFERROR
Error IFERROR catchesMeaning
#N/AValue not found — the most common error with VLOOKUP
#DIV/0!Division by zero
#REF!Invalid cell reference
#VALUE!Wrong data type used in the formula
Rule of thumb: always wrap VLOOKUP — and every lookup function — with IFERROR in a production dashboard. The custom message can be anything: "Not Found," "Check ID," an em dash, or even an empty string "", which returns a blank cell instead of any visible message — useful when you don't want the absence of a match to draw attention at all.
Across Sheets

04 VLOOKUP across sheets — the JOIN

In the real world, data is rarely one flat table — orders live in one sheet, customer details in another, just like separate tables in a SQL database. The Segment column lives only in Customer_Info. Reference it with SheetName!Range — the formula shape never changes, only the table_range does.

SQL
SELECT orders.*, customers.Segment FROM orders JOIN customers ON orders.Customer_ID = customers.Customer_ID
GSHEETS
=VLOOKUP(C2, Customer_Info!$A$1:$E, 3, FALSE)
Segment (from Customer_Info)

Revenue by segment — SUMIF on the joined column

VLOOKUP's three limitations — (1) always returns the FIRST match if a key repeats, (2) can only search the LEFTMOST column of the range, (3) the column index is a hardcoded number that breaks if a column gets inserted or deleted. These three problems are exactly why INDEX & MATCH and XLOOKUP exist.
Any Direction

05 INDEX & MATCH

In Orders_Info, Order Date sits to the LEFT of Order ID — VLOOKUP cannot fetch it. Frame it as a two-step process: MATCH finds the ROW number, INDEX fetches the VALUE from that row. Understand each half separately before combining them.

StepWhat it does
=MATCH(lookup_value, lookup_array, 0)Does NOT return the value — it returns the POSITION. match_type 0 = exact match; always use 0 for IDs.
=INDEX(array, row_number)Does NOT search — it fetches whatever sits at a specific row position inside array.
SYNTAX — COMBINED
=INDEX(return_range, MATCH(lookup_value, lookup_range, 0))
=MATCH(...)
=INDEX(...)
Key insight: the return range (Order Date, column A) and the search range (Order ID, column B) are different columns — something VLOOKUP simply cannot do.
DomainReal-world use case
FinanceLook up an account holder's name from an account number when the name column sits to the left
HRRetrieve a joining date for an employee ID when the date column precedes the ID column
InventoryFetch a supplier name where the supplier table is ordered differently than expected
SalesReturn a previous quarter's data by matching on a key sitting in the middle of the table
Why it survives change: INDEX & MATCH doesn't depend on a hardcoded column number — it uses actual ranges, so inserting or deleting a column elsewhere in the sheet never breaks it. That resilience, plus the ability to search in any direction, is why analysts prefer it over VLOOKUP in large production dashboards, even though it takes two functions instead of one.
Modern Replacement

06 XLOOKUP

The flexibility of INDEX & MATCH with the simplicity of VLOOKUP — plus a built-in "not found" message, no separate IFERROR required.

SYNTAX
=XLOOKUP(lookup_value, lookup_array, return_array, [if_not_found])
Order Date (left of Order ID)
Sales (right of Order ID)

Both lookups search the SAME Order ID column but return from opposite directions — identical, readable syntax either way, and "Order ID not found" is built in.

FeatureVLOOKUPINDEX & MATCHXLOOKUP
Search directionRight onlyAnyAny
Lookup columnMust be leftmostAny columnAny column
Built-in error handlingNo — needs IFERRORNo — needs IFERRORYes — if_not_found
Column index requiredYes, hardcodedNoNo
Survives column insertsNo, breaksYesYes
Two extra arguments worth knowing: match_mode (0 = exact default, -1 = next smaller, 1 = next larger, 2 = wildcard) and search_mode (1 = first-to-last default, -1 = last-to-first, useful when you want the most recent matching row instead of the first one). Both are optional, but they're what let XLOOKUP absorb edge cases that would otherwise need a separate formula.
Dynamic Extraction

07 UNIQUE + FILTER

The manual approach to "give me the unique Customer IDs from the South region" is to apply a filter, copy the column, paste it elsewhere, then run Remove Duplicates. That works once — but if the region needs to change, or the data updates daily, you'd be repeating those three steps every time. FILTER and UNIQUE replace that entire manual routine with one formula that never goes stale.

FunctionWhat it does
FILTER(range, condition1, ...)Returns only the rows or columns that satisfy the condition — the result is a "spill range" that automatically fills as many rows as needed.
UNIQUE(range, [by_column], [exactly_once])Returns distinct values from a range, removing duplicate entries.
SQL EQUIVALENT
SELECT DISTINCT Customer_ID FROM orders WHERE Region = 'South'
GSHEETS
=UNIQUE(FILTER(range, condition))
=UNIQUE(FILTER(...))

Step by step: FILTER runs first and selects every Customer ID where Region matches — this may still contain duplicates. UNIQUE then wraps that result and removes them. The formula auto-updates whenever the underlying data changes, with no manual steps required.

DomainReal-world use case
SalesGet a unique list of customers who placed orders in a specific region or month
HRList the distinct job titles in a department that changes monthly
FinanceExtract unique vendor names from a transactions log
OperationsIdentify distinct product categories from a live inventory feed
MarketingPull unique campaign IDs that met a conversion threshold
Scale

08 ARRAYFORMULA

The normal approach — write =F2*G2, then drag it down to row 9,994 — has two hidden problems: if 500 new rows are added tomorrow, you have to drag again, and if someone deletes a row in the middle, the formulas below it can break. ARRAYFORMULA lets a single formula apply to an entire range at once, so it scales with the data instead of needing maintenance. Toggle the method below, then add a row to Orders_Info above and watch what happens to Revenue.

SYNTAX
=ARRAYFORMULA(F2:F * G2:G)
Order IDSalesQuantityRevenue
Handling empty rows: wrap it as =ARRAYFORMULA(IFERROR(G2:G * H2:H, "")) to prevent #VALUE! errors from appearing in rows that don't have data yet.
When to useWhen NOT to use
The formula needs to apply to a whole column and scale automatically with new dataIndividual rows need to reference their own row differently — array logic assumes the same pattern everywhere
You want one cell to maintain, not hundreds of dragged copiesFILTER and UNIQUE are already array-based — wrapping them in ARRAYFORMULA is unnecessary

Keyboard shortcut: Ctrl + Shift + Enter wraps whatever you just typed in ARRAYFORMULA automatically.

Check Yourself

09 Quick quiz

1. A dataset has Customer_ID | Customer_Name | Segment. You need to search using Segment and return Customer_ID. Why will VLOOKUP fail?
VLOOKUP always searches the leftmost column of the range and can only return values to its right — it cannot look backward at Customer_ID once Segment is the search column.
2. Why do analysts prefer INDEX & MATCH over VLOOKUP in large production dashboards?
INDEX & MATCH supports left lookups, is more flexible, doesn't depend on a hardcoded column number, and survives column insertions or deletions.
3. Which statements about XLOOKUP are correct? (1) can search left and right, (2) requires a hardcoded column index, (3) has built-in if_not_found error handling, (4) can replace most VLOOKUP/INDEX&MATCH use cases.
XLOOKUP searches either direction (1) and has built-in if_not_found handling (3), and is a modern replacement for VLOOKUP and most INDEX & MATCH cases (4) — but unlike VLOOKUP it does NOT need a hardcoded column index (2 is false).
4. Why is ARRAYFORMULA considered more scalable than dragging formulas row by row?
ARRAYFORMULA lets one formula process an entire column or range at once, dynamically expanding when new data is added — no dragging, no maintenance.
