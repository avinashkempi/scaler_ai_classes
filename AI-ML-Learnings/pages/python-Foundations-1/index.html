What this post-read covers

Variables and why we name data, Python's four basic data types, the difference between = and mathematical equality, type(), comments, input() and its one big surprise, type casting, and a debug clinic on the three errors you're most likely to hit this week.

01 · variables

Giving data a name

On its own, 25 is just a number — is it an age, a price, a score? A variable solves that by attaching a name to a value, so age = 25 means "store 25 under the name age."

Analogy A variable is a name tag on a box. The box — the value — is what actually matters, but the tag is how you find the right box again later without opening every one.

Here's the part that trips people up: in math, = means "is equal to." In Python it doesn't.

🔮 Predict: does age = age + 1 work, or does it error like it would in math class? 
age = 20
print(age)
age = age + 1
print(age)

20
21

💬 No error. Python evaluates the right side first — age + 1 using the current value 20 — and only then stores the result back into age. Think of = as an arrow: variable ← value, not a claim that two things are equal.

✅ Takeaway = assigns a value to a name — it never claims mathematical equality. A variable can always be reassigned, including in terms of itself.
02 · data types

The four basic data types

Not all data is the same kind of thing. Python sorts every value into a type, and it decides the type using strict rules — not how the value "feels" to us.

TypePython nameExampleMeaning
Integerint25Whole numbers
Floating-pointfloat25.5Numbers with decimals

Try sorting these five values into their types. One of them is designed to catch you out.

✅ Takeaway Quotes (or their absence) and the decimal point are what Python actually looks at to decide a value's type — not what the characters look like.
03 · type() & comments

Asking Python what something is

type() tells you what kind of data a value is. Its answer comes wrapped in a particular format — that's normal, not an error.

🔮 Predict: will print(type(age)) just print int, or something else? 
print(type(age))

<class 'int'>

💬 Slightly more than just the word int. Python is saying the value belongs to a category it calls a "class" — you don't need to unpack what a class fully is yet, just recognise <class '...'> as type()'s normal answer format.

Comments are notes for humans, not Python. Anything after # on a line is ignored.

# This is my age
age = 25  # Student's age
✅ Takeaway Use comments with purpose — to explain a decision or leave a reminder — not on every single line.
04 · input()

The big surprise

We use input() to get information from the user. This next question is the most counterintuitive idea in the whole class — vote before you scroll to the answer.

If someone types 25 when asked for their age, what type does Python actually store it as?

age = input("What is your age? ")
print(age)
print(type(age))

25
<class 'str'>

💬 Even though the user typed 25, input() hands it back as a string. Everything a user types arrives as raw keystrokes — as text — no matter what it looks like. Python never guesses that it "should" be a number.

✅ Takeaway input() ALWAYS returns a string. If you want a number, you have to convert it yourself.
05 · type casting

Fixing the problem input() just created

🔮 Predict: what happens when we try age + 1 right after age = input(...)? 
age = input("What is your age? ")
next_year = age + 1

TypeError: can only concatenate str (not "int") to str

💬 Python refuses outright — you can't combine text and a whole number with + without telling it how. It's a specific, readable error, and reading it is worth practicing.

🤖 AI moment Paste that exact error into a general-purpose AI assistant and ask it to explain the error in plain English — but tell it not to give you the fix yet. Compare its explanation to your own guess first.

The fix is type casting — converting a value from one type to another.

age = int(input("What is your age? "))
print(type(age))

<class 'int'>
FunctionDoes what
int("25")→ 25
float("99.5")→ 99.5
str(100)→ "100"
Note bool() exists too, but its rules for what counts as "false-looking" are genuinely surprising — that's getting its own focused lesson later, not skipped by accident.
✅ Takeaway int(input(...)) is the standard pattern for turning user input into a number you can calculate with.
06 · debug clinic

Three snippets, three errors

For each one, form a prediction before you reveal — the goal is reading the error type first, before guessing or asking AI.

🔮 name = Aradhya — no quotes. What happens? 
NameError: name 'Aradhya' is not defined

💬 Without quotes, Python assumes Aradhya is the name of a variable — and none exists. This is exactly why strings need quotes: the quotes tell Python "this is data, not a name."

🔮 age = input("Age: ") then print(age + 1) — we've seen this shape before. Where? 
TypeError: can only concatenate str (not "int") to str

💬 Same root cause as the type casting card: input() always returns a string, and + can't silently combine text with a number. Fix: age = int(input("Age: ")).

🔮 Print("Hello") — capital P. What will Python make of it? 
NameError: name 'Print' is not defined

💬 Python is case-sensitive: print, Print, and PRINT are three different names. Only lowercase print is the built-in function — same category of error as the first snippet.

✅ Takeaway Reading the exact error type and message — before guessing, before asking AI, before changing random things — is the single most transferable debugging skill from this class.
