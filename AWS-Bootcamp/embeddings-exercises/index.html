The big idea in one picture

Computers compare numbers, not meanings. So we first turn text into numbers that capture meaning, and then compare the numbers.

Text"I want a refund"
→
Embedding modellearned from lots of text
→
Vector[0.12, -0.53, 0.88, ...]
→
Comparecosine similarity

Everyday analogy: think of each sentence as a pin on a giant map of meanings. "Train ticket refund" and "cancel my IRCTC booking" land close together. "Recipe for paneer tikka" lands far away. Search becomes: find the pins nearest to the question's pin.

TODO 4 — Write a cosine_similarity(a, b) function using numpy

Solution for TODO 4
def cosine_similarity(a, b):
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))
Output (real run)
   king vs queen     -> my answer: 0.784 | gensim: 0.784
cricket vs football  -> my answer: 0.696 | gensim: 0.696
   king vs banana    -> my answer: 0.221 | gensim: 0.221

Reading the formula: np.dot(a, b) is large when the two lists of numbers go up and down together. Dividing by the two lengths (np.linalg.norm) removes the effect of size, so we only measure direction. The result is between −1 and 1: near 1 = same meaning, near 0 = unrelated.

"""
Exercise 1.2 — Similarity Search App (Top-K retrieval)
Created by Shivank Agarwal

What this app does
------------------
You paste some documents (one per line) and type a question.
The app turns every line and the question into embeddings (lists of numbers)
and shows the K documents whose meaning is closest to the question.

This is the "R" (Retrieval) in RAG.

Run it:
    python 2_similarity_search_app.py
Then open the link printed in the terminal (usually http://127.0.0.1:7860).
"""

import gradio as gr
import numpy as np
from sentence_transformers import SentenceTransformer

# A small, free embedding model that runs on your laptop (no API key needed).
# It turns any sentence into a list of 384 numbers.
# The first run downloads it (about 90 MB).
model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")

SAMPLE_DOCS = """The cat sat on the mat.
A dog ran in the park.
The stock market crashed today.
Bananas are a great source of potassium.
Apples and oranges are healthy fruits.
Sensex fell 800 points after the RBI announcement.
Virat Kohli scored a century in the final."""


# ----- TODO 1 (solved): Write the cosine similarity formula -----
def cosine_similarity(a, b):
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))


def retrieve_top_k(documents_text, query, k):
    """Return the top-k documents as rows: [document, score]."""
    # 1. One document per non-empty line
    docs = [line.strip() for line in documents_text.strip().splitlines() if line.strip()]
    if not docs or not query.strip():
        return []

    # ----- TODO 2 (solved): Embed all documents and the query -----
    doc_embeddings = model.encode(docs)
    query_embedding = model.encode([query.strip()])[0]

    # ----- TODO 3 (solved): Score every document against the query and sort best-first -----
    scores = [(doc, cosine_similarity(query_embedding, emb)) for doc, emb in zip(docs, doc_embeddings)]
    scores.sort(key=lambda pair: pair[1], reverse=True)

    # 4. Keep only the first k results and format the score nicely for the table
    top = scores[: min(int(k), len(docs))]
    return [[doc, f"{score:.4f}"] for doc, score in top]


# ----------------------------------------------------------------------------
# The web page (Gradio builds it for us from Python)
# ----------------------------------------------------------------------------
with gr.Blocks(title="Similarity Search") as demo:
    gr.Markdown("# Similarity Search (Top-K)\nCreated by Shivank Agarwal")
    gr.Markdown("Enter documents (one per line), type a query, and get the K most similar documents.")

    with gr.Row():
        documents_input = gr.Textbox(label="Documents (one per line)", lines=12, value=SAMPLE_DOCS, scale=2)
        with gr.Column(scale=1):
            query_input = gr.Textbox(label="Query", value="fruit and nutrition", lines=2)
            k_input = gr.Slider(label="K — number of results", value=3, minimum=1, maximum=20, step=1)
            retrieve_btn = gr.Button("Retrieve Top K", variant="primary")

    results_table = gr.Dataframe(headers=["Document", "Similarity Score"], label="Top-K Results", interactive=False, wrap=True)

    # When the button is clicked: call retrieve_top_k(documents, query, k) and show the result in the table
    retrieve_btn.click(fn=retrieve_top_k, inputs=[documents_input, query_input, k_input], outputs=results_table)

if __name__ == "__main__":
    demo.launch()

A reranker (a cross-encoder) reads the question and each document together and gives a sharper relevance score. Real systems do both: retrieve many quickly, then rerank the few that came back.

Step 2: Rerankcross-encoder, slow, precise

Final orderbest answer first

Bi-encoder (Step 1)

Embeds the query and each document separately, then compares vectors. Document vectors can be computed once and stored in a vector database, so searching millions is fast. But the model never sees the query and the document together.

Cross-encoder (Step 2)

Reads (query, document) as one input and outputs a relevance score. Much more accurate, because every word of the query can be matched against every word of the document. But nothing can be pre-computed, so it is slow. Use it only on the top K.

Analogy: hiring for a job. Step 1 is the resume filter that scans 5,000 resumes in seconds and keeps 20. Step 2 is the interview: slow and careful, but you only do it for those 20.

TODO 1 — Embed the documents and the query, score them with cosine similarity, sort, keep top k

Solution for TODO 1
doc_embeddings = bi_encoder.encode(documents)
query_embedding = bi_encoder.encode([query])
scores = cosine_similarity(query_embedding, doc_embeddings)[0]

pairs = list(zip(documents, scores))
pairs.sort(key=lambda pair: pair[1], reverse=True)
return pairs[:k]

scikit-learn's cosine_similarity(A, B) compares every row of A with every row of B. With one query row we get one list of scores, hence [0].

TODO 2 — Score every (query, document) pair with the cross-encoder and sort best first

Solution for TODO 2
pairs = [(query, doc) for doc in documents]
scores = cross_encoder.predict(pairs)

ranked = list(zip(documents, scores))
ranked.sort(key=lambda pair: pair[1], reverse=True)
return ranked

The cross-encoder model cross-encoder/ms-marco-MiniLM-L6-v2 was trained on MS MARCO, a large set of real web search questions with the passages that answered them. Its scores are not between 0 and 1. They can be negative. Only the order matters: bigger = more relevant.

What you should see

  • Before reranking: short sentences that simply repeat the query words (COVID-19 has many symptoms., COVID-19 symptoms are bad.) score near the top, even though they tell you nothing.
  • After reranking: the sentences that actually list symptoms (fever, chills, cough, loss of smell) move to the top. The Dementia sentence stays near the bottom.

Scores differ slightly by machine. Look at how the order changes.

Design choice in this app

The Rerank button reranks exactly the rows shown in the Top-K table (the table is an input to on_rerank). So if you change K and retrieve again, the reranker works on the new list. If you click Rerank first, the app shows a friendly error.

"""
Exercise 1.3 — Retrieve, then Rerank
Created by Shivank Agarwal

Two-step search, exactly like production RAG systems:

  Step 1  RETRIEVE (fast, rough)   -> bi-encoder: embed query and documents SEPARATELY,
                                      compare with cosine similarity, keep the top K.
  Step 2  RERANK   (slow, precise) -> cross-encoder: reads the query AND one document TOGETHER
                                      and gives a relevance score. Re-sort the K results.

Run it:
    python 3_reranking_app.py
Then open the link printed in the terminal (usually http://127.0.0.1:7860).
"""

import gradio as gr
import pandas as pd
from sentence_transformers import CrossEncoder, SentenceTransformer
from sklearn.metrics.pairwise import cosine_similarity

# Bi-encoder: turns each text into a vector on its own (fast, good for searching many documents)
bi_encoder = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")

# Cross-encoder: looks at (query, document) as a pair and scores how well the document answers the query.
# It was trained on MS MARCO, a large dataset of real search queries and answers.
cross_encoder = CrossEncoder("cross-encoder/ms-marco-MiniLM-L6-v2")

SAMPLE_DOCS = """COVID-19 has many symptoms.
COVID-19 symptoms are bad.
COVID-19 symptoms are not nice
COVID-19 symptoms are really bad.
COVID-19 is a disease caused by a virus. The most common symptoms are fever, chills, and sore throat, but there are a range of others.
COVID-19 symptoms can include: a high temperature or shivering (chills); a new, continuous cough; a loss or change to your sense of smell or taste; and many more
Dementia has the following symptom: Experiencing memory loss, poor judgment, and confusion.
COVID-19 has the following symptom: Experiencing memory loss, poor judgment, and confusion."""


# ----------------------------------------------------------------------------
# Core search logic (no UI code here)
# ----------------------------------------------------------------------------
def get_top_k(query: str, documents: list[str], k: int) -> list[tuple[str, float]]:
    """Step 1: bi-encoder retrieval. Returns [(document, cosine_score), ...] best first."""
    # ----- TODO 1 (solved): Embed the documents and the query, score them with cosine similarity, sort, keep top k -----
    doc_embeddings = bi_encoder.encode(documents)
    query_embedding = bi_encoder.encode([query])
    scores = cosine_similarity(query_embedding, doc_embeddings)[0]

    pairs = list(zip(documents, scores))
    pairs.sort(key=lambda pair: pair[1], reverse=True)
    return pairs[:k]


def rerank(query: str, documents: list[str]) -> list[tuple[str, float]]:
    """Step 2: cross-encoder reranking. Returns [(document, relevance_score), ...] best first."""
    # ----- TODO 2 (solved): Score every (query, document) pair with the cross-encoder and sort best first -----
    pairs = [(query, doc) for doc in documents]
    scores = cross_encoder.predict(pairs)

    ranked = list(zip(documents, scores))
    ranked.sort(key=lambda pair: pair[1], reverse=True)
    return ranked


# ----------------------------------------------------------------------------
# Button handlers (connect the UI to the logic above)
# ----------------------------------------------------------------------------
def to_table(results):
    return pd.DataFrame([(doc, round(float(score), 4)) for doc, score in results], columns=["Document", "Score"])


def on_retrieve(documents_text, query, k):
    docs = [line.strip() for line in documents_text.splitlines() if line.strip()]
    if not docs or not query.strip():
        raise gr.Error("Please enter some documents and a query.")
    return to_table(get_top_k(query.strip(), docs, int(k)))


def on_rerank(query, top_k_table):
    # We rerank exactly the documents shown in the Top-K table
    docs = [] if top_k_table is None else [str(d) for d in top_k_table["Document"].tolist() if str(d).strip()]
    if not docs:
        raise gr.Error("Click 'Retrieve Top K' first.")
    return to_table(rerank(query.strip(), docs))


# ----------------------------------------------------------------------------
# The web page
# ----------------------------------------------------------------------------
with gr.Blocks(title="Retrieve and Rerank") as demo:
    gr.Markdown("# Retrieve, then Rerank\nCreated by Shivank Agarwal")

    with gr.Row():
        documents_input = gr.Textbox(label="Documents (one per line)", lines=10, value=SAMPLE_DOCS, scale=2)
        with gr.Column(scale=1):
            query_input = gr.Textbox(label="Query", value="COVID-19 Symptoms")
            k_input = gr.Number(label="K (number of results)", value=8, precision=0)

    retrieve_btn = gr.Button("1) Retrieve Top K", variant="primary")
    top_k_table = gr.Dataframe(label="Top-K Results (bi-encoder, cosine similarity)", headers=["Document", "Score"], interactive=False, wrap=True)

    rerank_btn = gr.Button("2) Rerank", variant="primary")
    reranked_table = gr.Dataframe(label="Reranked Results (cross-encoder)", headers=["Document", "Score"], interactive=False, wrap=True)

    retrieve_btn.click(fn=on_retrieve, inputs=[documents_input, query_input, k_input], outputs=top_k_table)
    rerank_btn.click(fn=on_rerank, inputs=[query_input, top_k_table], outputs=reranked_table)

if __name__ == "__main__":
    demo.launch()

1. Why does the raw vector search return king?

king − man + woman moves the vector only a little, so it is still very close to king. A plain nearest-neighbour search does not know which words you started from. most_similar(positive, negative) removes the input words from the answers.

2. Why cosine similarity instead of subtracting the numbers?

Cosine measures the direction of the vectors and ignores their length. A long sentence and a short sentence about the same thing point the same way but can have very different lengths. Direction is what carries meaning.

3. Why not run the cross-encoder on all documents?

It has to run the full model once per (query, document) pair, every time a user asks something. One million documents would mean one million model runs per question. The bi-encoder's document vectors are computed once and reused, so retrieval takes milliseconds.

4. Did the reranker push down the "COVID-19 causes memory loss" sentence?

Look at where it landed: it usually does not sink to the bottom, because it looks like an answer to "COVID-19 symptoms" (right topic, right shape). A reranker judges relevance, not truth. Checking facts needs trusted sources, which is why RAG systems care so much about what goes into the knowledge base.

5. K = 2: can the reranker still find the best document?

Only if the best document is already in the top 2 of Step 1. The reranker can only re-order what retrieval gives it. In practice we retrieve more (for example 20–50) and rerank down to the best 3–5.
