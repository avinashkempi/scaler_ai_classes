JOIN ... ON s.sku_id = p.sku_id glues each product row to the supplier row with the same sku_id. p and s are short nicknames for the tables.

TODO 2 — Fetch ONE product (joined with its supplier) by sku_id; return it as a dict, or None if not found

row = cur.execute(
    "SELECT p.*, s.lead_time_days, s.supplier_name "

"""
Step 01 — SQLite basics: store and query inventory data
Created by Shivank Agarwal

Goal: keep structured data (products, suppliers) in a real SQL database and read it back.
SQLite comes built into Python, so there is nothing to install.

Run it:
    python 01_sqlite_basics.py
"""

import sqlite3

# ":memory:" = a temporary database that lives in RAM and disappears when the script ends
conn = sqlite3.connect(":memory:")
conn.row_factory = sqlite3.Row  # lets us read columns by name: row["sku_name"]
cur = conn.cursor()             # the "pen" we use to run SQL

# 1) Create two tables linked by sku_id (a FOREIGN KEY)
cur.executescript("""
CREATE TABLE products (
    sku_id   TEXT PRIMARY KEY,
    sku_name TEXT NOT NULL,
    stock    INTEGER NOT NULL
);

CREATE TABLE suppliers (
    sku_id         TEXT PRIMARY KEY,
    supplier_name  TEXT NOT NULL,
    lead_time_days INTEGER NOT NULL,   -- days between placing an order and receiving it
    FOREIGN KEY (sku_id) REFERENCES products(sku_id)
);
""")

# 2) Insert rows. executemany runs the same INSERT once per tuple. "?" = safe placeholder.
cur.executemany("INSERT INTO products VALUES (?, ?, ?)", [
    ("SKU-001", "Wireless Headphones", 150),
    ("SKU-002", "Paracetamol 500mg",   800),
    ("SKU-003", "Instant Noodles",     300),
])
cur.executemany("INSERT INTO suppliers VALUES (?, ?, ?)", [
    ("SKU-001", "TechImports Ltd", 21),
    ("SKU-002", "MedSupply Co",     7),
    ("SKU-003", "FoodDist Pvt",     4),
])
conn.commit()

# 3) Read both tables together with a JOIN
# ----- TODO 1 (solved): Write a JOIN query that returns sku_id, sku_name, stock, lead_time_days, supplier_name for every product -----
rows = cur.execute("""
    SELECT p.sku_id, p.sku_name, p.stock,
           s.lead_time_days, s.supplier_name
    FROM   products p
    JOIN   suppliers s ON s.sku_id = p.sku_id
    ORDER  BY p.sku_id
""").fetchall()

print(f"{'SKU':<10} {'Name':<22} {'Stock':>6} {'Lead (days)':>12}  Supplier")
print("-" * 70)
for r in rows:
    print(f"{r['sku_id']:<10} {r['sku_name']:<22} {r['stock']:>6} {r['lead_time_days']:>12}  {r['supplier_name']}")


# 4) A reusable lookup function: one SKU in, one dict out (or None)
def fetch_product(sku_id: str) -> dict | None:
    # ----- TODO 2 (solved): Fetch ONE product (joined with its supplier) by sku_id; return it as a dict, or None if not found -----
    row = cur.execute(
        "SELECT p.*, s.lead_time_days, s.supplier_name "
        "FROM products p JOIN suppliers s ON s.sku_id = p.sku_id "
        "WHERE UPPER(p.sku_id) = UPPER(?)",
        (sku_id,),
    ).fetchone()
    return dict(row) if row else None


print("\nLookup sku-002:", fetch_product("sku-002"))
print("Lookup SKU-999:", fetch_product("SKU-999"))

"""
Step 02 — Embeddings basics: find the most relevant passage for a question
Created by Shivank Agarwal

Goal: turn short inventory notes into vectors and find the best ones for a question.
No database and no LLM yet: just an embedding model + numpy.

Run it:
    python 02_embeddings_basics.py
"""

import numpy as np
from sentence_transformers import SentenceTransformer

# Our tiny "knowledge base": six facts about inventory planning
PASSAGES = [
    "Safety Stock = Z-score * demand_std_dev * sqrt(lead_time_days)",
    "Reorder Point = (avg_daily_demand * lead_time_days) + safety_stock",
    "Electronics: lead times 14-30 days, high obsolescence risk.",
    "Pharma: strict FIFO, 99%+ service level, expiry management.",
    "FMCG: short lead times 3-7 days, high steady demand.",
    "ABC Analysis: A-items need tight control, C-items tolerate bulk orders.",
]

# Free local model: every text -> 384 numbers
model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")

print("Embedding passages...")
# normalize_embeddings=True makes every vector length 1,
# so cosine similarity becomes a simple dot product
passage_vectors = model.encode(PASSAGES, normalize_embeddings=True)
print(f"Passage matrix shape: {passage_vectors.shape}  (6 passages x 384 numbers)\n")


def top_k(query: str, k: int = 3) -> list[tuple[float, str]]:
    """Return the k passages most similar to the query as (score, passage), best first."""
    # ----- TODO 1 (solved): Embed the query, score it against every passage, and return the top k -----
    qv = model.encode(query, normalize_embeddings=True)
    scores = passage_vectors @ qv              # one score per passage
    ranked = np.argsort(scores)[::-1][:k]      # biggest first
    return [(float(scores[i]), PASSAGES[i]) for i in ranked]


queries = [
    "How do I calculate safety stock?",
    "What should I know about electronics inventory?",
    "Tell me about demand patterns for consumer goods.",
]

for query in queries:
    print(f"Query: {query!r}")
    for score, passage in top_k(query):
        print(f"  {score:.3f}  {passage}")
    print()

"""
Step 03 — ChromaDB: a real vector database with metadata filters
Created by Shivank Agarwal

Goal: store passages + their vectors + tags (metadata) in ChromaDB, then search by meaning
and optionally filter by tag, e.g. "only search the formulas".

Run it:
    python 03_chromadb_retrieval.py
"""

import chromadb
from langchain_huggingface import HuggingFaceEmbeddings

# Same local model as Step 02, wrapped by LangChain
embed = HuggingFaceEmbeddings(
    model_name="sentence-transformers/all-MiniLM-L6-v2",
    model_kwargs={"device": "cpu"},
    encode_kwargs={"normalize_embeddings": True},
)

client = chromadb.Client()  # in-memory ChromaDB (nothing saved to disk)
collection = client.create_collection("inventory_kb", metadata={"hnsw:space": "cosine"})

docs = [
    {"id": "ss-formula",  "text": "Safety Stock = Z * demand_std_dev * sqrt(lead_time). Z=1.65 for 95%, Z=2.33 for 99%.", "meta": {"topic": "formula"}},
    {"id": "rop-formula", "text": "Reorder Point (ROP) = (avg_daily_demand * lead_time) + safety_stock.",                 "meta": {"topic": "formula"}},
    {"id": "electronics", "text": "Electronics: lead times 14-30 days, service level 95-99%, high obsolescence risk.",     "meta": {"topic": "category"}},
    {"id": "pharma",      "text": "Pharma: lead times 7-21 days, service level 99%+, strict FIFO and expiry management.", "meta": {"topic": "category"}},
    {"id": "fmcg",        "text": "FMCG: lead times 3-7 days, high steady demand, service level 95-98%.",                 "meta": {"topic": "category"}},
    {"id": "raw-mat",     "text": "Raw materials: lead times 10-45 days, service level 90-95%.",                           "meta": {"topic": "category"}},
    {"id": "abc",         "text": "ABC Analysis: A-items need tight control and high service levels.",                      "meta": {"topic": "best_practice"}},
    {"id": "variability", "text": "High demand variability requires more safety stock to maintain service level.",          "meta": {"topic": "best_practice"}},
]

print("Embedding and storing documents...")
# ----- TODO 1 (solved): Embed every text and add ids, vectors, texts and metadata to the collection -----
vectors = embed.embed_documents([d["text"] for d in docs])
collection.add(
    ids=[d["id"] for d in docs],
    embeddings=vectors,
    documents=[d["text"] for d in docs],
    metadatas=[d["meta"] for d in docs],
)
print(f"Collection has {collection.count()} documents\n")


def retrieve(query: str, n: int = 3, where: dict | None = None) -> list[str]:
    """Return the n most similar texts. `where` is an optional metadata filter, e.g. {"topic": "formula"}."""
    # ----- TODO 2 (solved): Embed the query and search the collection (apply the filter only if one is given) -----
    qv = embed.embed_query(query)
    kwargs = {"query_embeddings": [qv], "n_results": n}
    if where:
        kwargs["where"] = where
    results = collection.query(**kwargs)
    return results["documents"][0]


print("=== Query: 'pharma reorder safety stock' ===")
for chunk in retrieve("pharma reorder safety stock"):
    print(" •", chunk)

print("\n=== Query: 'how to calculate stock' (formulas only) ===")
for chunk in retrieve("how to calculate stock", where={"topic": "formula"}):
    print(" •", chunk)

print("\n=== Query: 'electronics inventory management' (categories only) ===")
for chunk in retrieve("electronics inventory management", where={"topic": "category"}):
    print(" •", chunk)

The lesson of this step

The LLM usually gets close, but square roots and decimals are where it slips (for example writing √21 ≈ 4.6 and ending at 186.86). For inventory, money or medicine, "usually close" is not acceptable. That is why Step 06 moves every calculation into Python tools.

"""
Step 04 — Your first LLM chain:  prompt | llm | parser
Created by Shivank Agarwal

Goal: send a reusable prompt (with {variables}) to the LLM and get plain text back.
The formulas are written inside the prompt and the LLM does the maths itself.
We also compute the exact answer in Python, so you can check whether the LLM got the maths right.

Run it:
    python 04_llm_chain.py
"""

import math

from dotenv import load_dotenv
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI

load_dotenv()

llm = ChatOpenAI(model="gpt-6-luna", reasoning_effort="none")

# A prompt template = a message with blanks ({...}) that we fill in on every call
prompt = ChatPromptTemplate.from_messages([
    ("system", """You are an inventory planning expert.

Given these parameters, compute the desired stock level step by step.

Formulas:
  Safety Stock  = Z * demand_std_dev * sqrt(lead_time_days)
  Desired Stock = (avg_daily_demand * lead_time_days) + Safety Stock

Z-scores: 90% -> 1.28 | 95% -> 1.65 | 97% -> 1.88 | 98% -> 2.05 | 99% -> 2.33

End your response with exactly:
DESIRED_STOCK: <number>"""),
    ("human",
     "SKU: {sku_id} ({sku_name})\n"
     "Lead Time      : {lead_time_days} days\n"
     "Daily Demand   : {avg_daily_demand} units/day\n"
     "Demand Std Dev : {demand_std_dev} units/day\n"
     "Service Level  : {service_level}%"),
])

# ----- TODO 1 (solved): Build the chain: prompt -> llm -> StrOutputParser -----
chain = prompt | llm | StrOutputParser()

@tool
def calculate_safety_stock(demand_std_dev: float, lead_time_days: float, service_level_pct: float) -> float:
    """
    Calculate safety stock (extra buffer units).
    safety_stock = Z * demand_std_dev * sqrt(lead_time_days)
    Z-scores: 90%->1.28, 95%->1.65, 97%->1.88, 98%->2.05, 99%->2.33

    """
    Calculate the reorder point (ROP): reorder when stock falls to this level.
    ROP = (avg_daily_demand * lead_time_days) + safety_stock

    return round(avg_daily_demand * lead_time_days + safety_stock, 2)

def fetch_sku(sku_id: str) -> dict | None:
    row = cur.execute("""
        SELECT i.sku_id, i.sku_name, i.category, i.current_stock, i.service_level,
               l.lead_time_days, l.supplier_name,
               d.avg_daily_demand, d.demand_std_dev
        FROM inventory i
        JOIN lead_time l ON l.sku_id = i.sku_id
        JOIN demand    d ON d.sku_id = i.sku_id
        WHERE UPPER(i.sku_id) = UPPER(?)
    """, (sku_id,)).fetchone()
    return dict(row) if row else None


def list_skus() -> list[dict]:
    rows = cur.execute("SELECT sku_id, sku_name, category, current_stock FROM inventory ORDER BY sku_id")

@tool
def compute_stock_metrics(avg_daily_demand: float, demand_std_dev: float, lead_time_days: float,
                          service_level_pct: float, current_stock: float) -> dict:
    """
    Compute safety stock, desired stock level, and reorder quantity with exact arithmetic.
    Returns: z_score, safety_stock, desired_stock, reorder_quantity, reorder_needed.
    """
    z = Z_TABLE.get(round(service_level_pct), 1.65)
    safety_stock = round(z * demand_std_dev * math.sqrt(lead_time_days), 2)
    desired_stock = round(avg_daily_demand * lead_time_days + safety_stock, 2)
    reorder_quantity = max(0, math.ceil(desired_stock - current_stock))
    return {
        "z_score": z,
        "safety_stock": safety_stock,
        "desired_stock": desired_stock,
        "reorder_quantity": reorder_quantity,
        "reorder_needed": reorder_quantity > 0,
    }

    return "Sorry, I could not finish this request. Please ask about fewer SKUs at a time."

Think about it

  1. Step 04: did the LLM's DESIRED_STOCK exactly match the Python check? Why is "close enough" not good enough here?
  2. Step 05: which parts of the RAG answer could only come from the retrieved notes?
  3. Step 06 vs Step 07: one lets the LLM choose the order of tools, the other has a fixed order. Give one advantage of each.

  5. In Step 08, the agent only gets the 3 most relevant notes, not all 13. Why not send all of them every time?

Show the answers
1. Did the LLM's number match the Python check?

Often close, sometimes off in the decimals, occasionally clearly wrong. LLMs predict likely text; they do not calculate. A small error times hundreds of SKUs means real money: lost sales or cash stuck in stock. Exact maths belongs in code.

2. What could only come from the retrieved notes?

Our business rules: "Pharma: 99%+ service level, strict FIFO, expiry dates" and the exact Z values. A general LLM may know similar ideas, but it cannot know your company's rules unless you give them.

3. Agent vs pipeline advantages?

Agent: flexible, handles questions you did not plan for. Pipeline: predictable, easy to test, fixed cost. Many real systems use a pipeline for the core flow and an agent only at the edges.

4. Why MAX_STEPS?

If the LLM keeps asking for tools (for example, a tool keeps returning an error and the LLM keeps retrying), the loop would never end, burning money and time. A step limit is a simple safety net.

5. Why only 3 notes, not all 13?

Fewer tokens = cheaper and faster. Irrelevant notes can also distract the LLM. With 13 notes you could send all of them, but a real knowledge base has thousands, so retrieval is the habit to build.

6. SKU-009 with 120 in stock and a desired stock of 119.14?

The formula says no reorder, but there is less than one unit of margin. A manager would want: upcoming sales or festival season, supplier reliability, minimum order size, and whether an order is already on its way. Tools give exact numbers; people still make the judgement call.
